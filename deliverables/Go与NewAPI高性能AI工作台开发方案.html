01 技术决策与方案边界

推荐采用 Go 作为核心后端，建立独立的流式执行服务、异步任务中枢和媒体资产流水线。现有二开 New API 继续负责模型供应与渠道接入；产品业务、项目工作流、前端状态和用户权限由新平台掌握。

确定条件

用户已经确认：面向公众长期运营；现有供给为二次开发版或自定义接口的 New API；LLM采用实时连接请求；图片、视频采用异步提交并通过结果接口轮询。本方案不以成本作为取舍依据，优先保证性能、可靠性、可维护性和体验。

待联调确认：网关版本和部署拓扑、真实接口路径、鉴权作用域、请求/响应样例、流格式、幂等和取消能力、状态刷新周期、限流、结果保留时长。本文自有接口均为建议设计，不是对你现网接口的断言；未访问你的网关配置、代码或生产数据。

参考站的暗色工作台、模型侧栏、自然语言创作入口、画布、漫剧/PPT和任务体验沿用上一份报告的实地观察。这里只借鉴交互组织与视觉方向，不推断其后端架构，不复制品牌素材或源码。

05 LLM流式链路与断线恢复

默认采用“创建运行＋订阅运行事件”两步：POST创建run并持久化意图，GET订阅SSE。刷新、切页和重新打开都围绕同一个run_id恢复，不重新调用模型。交互聊天采用立即分配Stream Owner和有界的短准入等待；满载时明确返回限流/繁忙及可重试时间，不能进入媒体长队列后仍假装实时。对只需一次性响应的集成可提供POST fetch流接口，但不能把它的重连简化成再次POST。

POST /runs保存run与输入快照Stream Owner连接New API解析并编号增量短窗口回放日志SSE显示终态保存与用量核实

心跳采用SSE注释，不增加业务进度或伪造模型内容。

同一个run的seq严格递增，前端按seq去重。事件只表达上游允许返回的内容；工具调用参数完整并验证后才能执行，不将不完整JSON直接调用工具，也不展示平台内部系统提示或隐含推理。

恢复分三层

  • 浏览器短断线：携带Last-Event-ID或after游标重连同一run，回放最近事件后接实时流。原生EventSource适合同源HttpOnly会话，不能任意加Authorization头；需要自定义头可用fetch读取SSE。
  • 日志窗口已过：返回明确的snapshot_required语义，读取累计消息快照和checkpoint_seq，再从该边界恢复。定义订阅前后事件缓冲，避免快照与实时交接遗漏。
  • 持有上游连接的进程死亡：可恢复已持久化内容和状态；若网关不支持独立任务ID和后续取回，无法原样续接未完成模型输出，标记interrupted。用户“继续生成”必须是新的、有父运行关系的操作。

建议默认聊天在订阅者短暂断开后保留30秒宽限，允许重连；随后根据产品配置取消上游。工作流LLM属于后台任务，可继续到自身deadline。用户按“停止”调用服务端取消接口，不能只abort浏览器fetch。取消上游是否停止计费由网关实际行为决定。

日志与延迟的明确选择

首版选独立NATS JetStream流日志集群，FileStorage、跨可用区三副本、固定数量分片，与业务Outbox事件隔离。每条业务记录含run_id、owner_epoch、seq与类型；按run固定分片，在一个有效Owner内顺序写入。分片聚合器将多个run的增量装入5—10ms批次，批次持久确认后才逐run推送浏览器。十万业务增量事件/秒不等于十万日志消息/秒。强耐久模式在独立集群配置并验证sync_interval: always；FileStorage与三副本本身不代表每次ACK前已经fsync，具体版本和存储硬件必须故障验证。Redis只保存run序号到日志位置及批内偏移的索引和短缓存，丢失后从保留的分片日志重建，期间降级为快照或明确的短暂重试。禁止每个token写PostgreSQL，也禁止每个run创建无限期消费者。NATS官方持久化说明（归档文档，需对照选型版本验证）

消息快照保存checkpoint_seq、对应日志位置和owner_epoch；只有已经被持久快照覆盖的事件才能按分片安全水位裁剪，跨run批次须全部覆盖后才能删除。五分钟是目标回放窗口，不允许MaxAge或容量策略提前删除未覆盖数据，容量采用拒绝新写策略。快照落后或日志接近上限时停止新受理、告警并恢复快照消费，同时预留在途流排空空间；既有流采用有界背压，超时取消上游并标记interrupted，未获持久确认的增量不得继续展示。订阅先建立缓冲，再读取快照/历史并按run序号合并。旧Owner的写入须在日志接入层按epoch拒绝，不能只在数据库终态更新时检查；Owner失效后只恢复已记录内容，不自动重发同一次模型生成。

额外延迟初始预算：聚合等待5—10ms、日志持久确认目标≤20ms、解析及路由/写出目标≤20ms，以端到端P95≤50ms验收；各分项分位数不能简单相加当成端到端统计。下游不再叠加另一个50ms固定等待。独立POC验证每秒10万增量事件、10000个run、批量发布与回放并发。如果可靠记录不能达标，应先调整批量和基础设施，再修改并明确验收目标。最终消息与run.completed在业务存储确认后才向用户确认完成，终态事件同样进入持久日志。

长连接服务独立listener；不能把流路由套进普通响应整体超时/压缩缓存中间件。使用ResponseController或具备正确Unwrap的ResponseWriter封装处理flush与逐写deadline，验HTTP/1.1和HTTP/2。客户端Client/Transport复用，连接数按上游活动并发、HTTP2流配额和实际FD计算，不能直接设默认值或极大值。

解析器要覆盖跨TCP包的UTF-8、CRLF、多行data、空行、超长事件、工具参数分片、非JSON错误、提前EOF。使用Scanner时显式设置token上限；大媒体不通过SSE传Base64。遇到上游部分输出后失败，保留部分结果并显示中断，禁止拼上另一模型的回答假装同一输出。

每条下游流只允许一个writer；模型增量、心跳和终态通过同一有界发送通道调度，禁止并发写ResponseWriter。单次请求正文、单事件大小、单run累计输出和最大生命周期均设模型级上限；例如普通JSON起点2MiB、单事件256KiB、普通聊天10分钟，经真实工具参数和长推理样本修订。达到上限返回可解释的截断/中断状态，不静默丢数据；诊断接口仅在受控管理网络开放。

应用幂等键与网关相关ID分开。Go Transport对带特定幂等头的请求存在条件性自动重试语义，因此不能把内部Idempotency-Key盲目透传给没有幂等承诺的生成接口；并检查Ingress、SDK和网关重试配置。Transport重试说明

不为每个流持有数据库连接；鉴权和持久化时短暂借用。缓冲池按大小分级，防止超大请求污染池。监控goroutine、堆、GC暂停、分配率、FD、socket、网络出口和连接等待，用pprof/trace定位后优化。HTTP2可减少TCP连接，但不取消并发限制，也不消除共享连接拥塞。

接入层与停机

SSE路由关闭代理缓冲/缓存和会聚输出的压缩设置，区分读取空闲超时与最大请求时长，确认CDN是否透传长流。NGINX配置需专项路由验证。滚动升级先移除readiness，停止接新run，保留已运行连接到排空期限；超限主动标记中断并保存快照。Kubernetes宽限期与LB排空一致，不能用“优雅关闭”字样承诺上游TCP连接跨Pod迁移。NGINX代理配置

08 后端集中轮询与高性能调度

前端读取平台任务快照并订阅工作区事件；Go调度器统一查询你的网关。如果网关自己后台轮询模型厂商，平台只查它的状态快照，不能再跨层查询厂商。查询刷新周期、批量能力和配额决定合理轮询频率。

默认方案

PostgreSQL任务与调度记录为权威来源，Go按分片领取到期任务，使用有界Worker执行短查询。任务长时间等待不占用一个永久睡眠goroutine，更不占用一个HTTP连接或数据库事务。热调度表与历史任务表分离。

WITH picked AS (
  SELECT task_id FROM task_poll_schedule
  WHERE shard_id=$1 AND enabled AND available_at <= now()
  ORDER BY available_at, task_id
  FOR UPDATE SKIP LOCKED LIMIT $2
)
UPDATE task_poll_schedule s
SET lease_epoch=s.lease_epoch+1,
    owner_id=$3,
    lease_until=now()+interval '20 seconds',
    available_at=now()+interval '20 seconds'
FROM picked WHERE s.task_id=picked.task_id
RETURNING s.task_id,s.lease_epoch;
-- 领取后立刻提交事务，再进行网络查询。
-- 写回必须匹配task_id与lease_epoch，防止过期Worker覆盖新结果。
CREATE INDEX task_poll_due_idx
ON task_poll_schedule(shard_id,available_at,task_id) WHERE enabled;

20秒是示意租约，应大于查询超时与写回余量。领取时把available_at推至租约到期，避免已领取项一直堵住到期索引。所有更新带epoch并在事务内验证合法迁移；租约过期可能产生重复GET，但不能重复结算和重复发布作品。PostgreSQL队列式锁定语义

首版由PostgreSQL权威领取并持有epoch；Redis ZSET只可作为可重建的到期索引加速，实际领取仍须数据库条件更新，不能独立宣告任务归属。每次轮询仍更新PG时，加Redis不会消除WAL与vacuum写压力。若压测确认写放大成为瓶颈，单独提交调度升级ADR，明确分片所有权、权威epoch、检查点周期、旧Worker拒绝与索引恢复协议；迁移时停用旧调度或提升调度世代，禁止两套系统同时独立领取。本地时间轮只加速计时。Redis丢失后限速重建，避免恢复请求风暴。Redis有序集合

10 事件系统 数据一致性与账务边界

任务状态更新与Outbox在一个数据库事务提交，发布器发送业务事件后标记完成；重复投递通过event_id与aggregate_version去重。NATS JetStream采用有界pull consumer、显式ACK和可观测重投；不要宣称消息中间件自动解决跨网关的exactly-once。NATS消费者文档

工作区SSE每个会话维持一条或少量复用连接，承载任务更新、作品可用、系统通知；不为每张卡片开一条连接。LLM文本与任务事件使用分开的队列和优先级，防止token洪峰淹没任务终态。交付日志分配的游标只负责回放；aggregate_version负责同一个task/asset的状态去重，二者分开。不同任务的Outbox可乱序发布，不能因看到更大的事件ID而丢弃另一任务稍后到达的合法更新，也不能把时间戳、ULID或数据库自增ID直接当作已提交/已发布高水位。

首次加载采用“先订阅并缓冲→读取一致快照及资源版本→按每个资源版本合并缓冲→实时接收”。回放窗口外重新取快照；终态可由任务API补齐，事件不是唯一事实来源。实时、回放和快照执行相同的资源鉴权。弱网可降级为针对本地任务快照的批量查询，绝不降级为浏览器直接轮询New API。

不讨论成本也必须保留的正确性

New API上游消耗记录与网站用户账户分开。网站账本是用户权益的权威，网关usage用于核对，不能同时扣两套余额又无法解释。使用固定精度整数或decimal；冻结、释放、结算、冲正是独立记录，关联run/task/attempt。实时usage可能缺失，先记pending，核实后结算，不能用浏览器字符数当最终token账单。

资源上限依然必要：每用户/工作区/模型并发、任务数量、输入大小、最大运行时长与工作流扇出保护系统稳定；不因为本次“不考虑成本”就取消隔离、限流和熔断。

16 部署 高可用与可观测

同区域多可用区部署，PostgreSQL按目标配置同步复制/故障转移，Redis与事件集群独立；Kubernetes按API、流、调度、媒体分资源池。后台报表和批量导出不占用在线库连接预算。总连接池大小必须受数据库连接上限约束，Pod扩容时同步约束，不能每个Pod都开数百连接。

HPA分别观察活跃流、堆/网络、队列年龄、调度滞后和CPU，不能只看CPU。保持可处理突发的热容量；连接数在已有Pod上不会因新Pod出现自动均衡，采用接入层新连接分配和渐进排空。网关也要压测数据库、连接池、渠道配额与内部轮询，平台扩容不代表网关同步扩容。

一条可追溯链

trace_id → workspace → project → run/task → attempt → gateway_request_id → artifact → settlement。OpenTelemetry贯穿HTTP、消息和Worker；Prometheus/Grafana承载指标，日志/trace单独存储。指标label不使用用户ID、task_id和完整模型动态字符串等高基数值，具体ID放日志与trace。token不逐条完整记录，防泄漏与日志洪峰。

看板必须看到

异步提交等待、未知受理、轮询滞后、最长未查询、网关429、任务年龄分布
资产即将过期URL、导入积压字节、损坏率、审核、转码和首预览耗时

告警以症状和持续时间组合：如P99持续恶化、最老任务超阈值、未知提交数量增长。每个告警关联处置手册、负责人和降级按钮，不能只有一堆曲线。

跨区域容灾

为工作区和任务分配home_region，单任务只有一个写入主区域与有效epoch。区域切换先隔离旧主，再提升新主、重建调度、核实外部任务后接新提交。异步复制丢失已受理记录时，需要通过请求ID和网关日志找回；不能一键把所有在途任务重提。若要求跨区域RPO=0，需要相应同步协议并接受时延/可用性权衡，不能只用“多活”一词解决。

数据对象同区域保障前提跨区域恢复边界
业务PostgreSQL已提交事务在同步副本确认、正确隔离旧主时目标RPO=0异步WAL复制，目标RPO≤5分钟；故障演练验证实际可用恢复点
已确认流日志采用三副本＋always同步落盘，按约定单节点/单可用区故障模型验RPO=0；不承诺任意多重故障无损异步复制或快照，目标≤5分钟；目标区域没有的尾部不能承诺回放
原始媒体对象独立验证对象存储多可用区持久性与校验；PG提交不代表原件已经复制记录复制状态；目标≤5分钟需实测大文件和积压，未满足时明确降级并补导入
Temporal历史验证其持久库高可用；工作流历史和业务PG不是同一事务按选定部署与复制能力演练，目标≤5分钟；恢复需对照活动外部执行核实
New API自身任务记录由二开网关提供任务与请求ID持久性、查询保留保证单独约定并实测；平台切主不能恢复网关已丢失的记录

整体区域恢复目标RTO≤30分钟只是验收目标，取决于上述所有依赖。恢复门禁检查数据库、对象、日志和网关记录的一致边界；未核实的在途任务先隔离，不能只恢复PG就自动开放全部提交。

17 安全隔离与生产控制面

  • HttpOnly/Secure/SameSite会话，变更接口做CSRF与Origin校验；SSE同源授权，URL不放长期令牌；授权变更后可撤销运行订阅和协作连接。
  • 工作区RBAC＋资源归属校验；模型权限、下载、任务查询和管理接口全部服务端校验，隐藏按钮不能代替权限。
  • 网关密钥由KMS/密钥服务管理，按能力分权；轮换保留在途任务查询身份，不写入浏览器、日志、原型或报错。
  • 支付回调、模型Webhook、后台操作分开认证；后台管理员MFA，敏感变更审计与复核。
  • 输入输出审核、文件恶意内容、Markdown/XSS与链接协议验证；SVG/HTML生成内容隔离域或sandbox预览，不能直接注入主站DOM。
  • 模板与Skill有版本、签名/来源、权限和审核；用户上传内容不能修改工具白名单、越权读取项目或触发任意外网请求。
  • 独立控制台提供模型/渠道熔断、停止新提交、暂停批量、关闭某模板、限制单租户与只读模式；在途任务保持可查询和可恢复。

安全开关要以可恢复操作为主，保留原因和操作者。审核、封禁、删除与数据保留规则进入服务端状态机；生成标识应在编辑、转码、导出后仍满足适用要求。开源依赖和二开New API版本建立SBOM及许可证审查，架构分离本身不自动免除原有授权义务。

多模型对照实验相同输入在多个模型并排比较，选择结果继续工作流独立任务、并发配额、真实等待状态，禁止隐性无限fan-out
自然语言编辑画布“把这三张图变成竖屏短片”生成可审阅节点计划工具白名单、变更预览和确认；不让Agent直接任意改数据库
智能等待体验展示真实阶段、经验等待区间、已完成产物与可做的下一步没有真实进度就显示阶段，不能伪造百分比
自动质量检查检测错字、尺寸、字幕越界、商品不一致、黑帧、静音给出可解释提示；模型质量检测仍需误报与人工复核
个人素材知识库从授权文档提取脚本、品牌规范与参考风格数据隔离、检索权限、来源引用、可删除和防提示注入
实时协作与审稿多人光标、批注、选片、审批与客户只读分享CRDT和业务权限分开，分享撤销与版本边界清楚
开发者开放能力将项目与任务API开放，提供Webhook/SDK/CLI单独令牌范围、配额、幂等、签名、审计与版本策略
多区域工作区用户就近访问，区域归属和素材存储明确先同区高可用，再做home_region路由和可验证容灾
桌面/PWA本地素材拖入、系统通知、项目快捷入口Web稳定后再封装；离线可编辑草稿，离线不能调用云模型

首批技术验证建议只抓五件事：真实二开接口契约；一万条模拟LLM流；六万在途任务的集中轮询；五百节点画布；从任务完成到原件可下载的恢复链路。它们通过后，再扩展功能，才能让界面丰富度和平台可靠性一起增长。

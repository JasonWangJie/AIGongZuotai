# V04：事务业务审计与活动记录

本模块完成批次 **V04**，任务登记见[横向模块与纵向批次清单](../planning/tasks.json)，实现证据见 [012 台账](../changes/2026-11-13-012-transactional-audit.md)。它提供已授权业务动作的活动记录，**不是消费账单、计费账本或完整安全审计系统**。

## 当前覆盖

| 动作 | 何时记录 | 不重复的情况 |
| --- | --- | --- |
| `project.created` | 用户创建项目；注册事务中创建默认项目 | 启动时固定 demo 项目不是用户动作，不补写历史事件。 |
| `run.accepted` | 首次受理一个 LLM Run | 相同幂等键重放、同键异参拒绝、队列满均不新增受理事件。 |
| `task.accepted` | 首次受理媒体 Task | 相同幂等键重放不再记录。 |
| `run.cancelled` | 非终态运行实际转为 CANCELLED | 已终态重复取消不记录；PG 先提交后才取消运行 context。 |
| `task.cancelled` | 支持取消的非终态任务实际转为 CANCELLED | 已终态重复取消、真实供应商不支持取消时不记录。 |
| `task.reconcile_requested` | 对已保存的原 handle 恢复查询 | 无 handle、权限不足、冷却拒绝不记录；不代表再次生成。 |
| `reference.uploaded` | 私有参考素材元数据首次提交 | 原上传键重放不重复；元数据/幂等/审计同事务，不记录文件名或图像内容。 |
| `draft.saved` | 云草稿新修订成功提交 | 幂等重放原修订不增加保存事件；正文、修订、幂等与审计同事务。 |

没有登录成功/失败、密码变更、会话注销、供应商每次轮询、LLM 每 token、自动恢复、媒体完成、支付或结算审计。注册仅覆盖其**默认项目创建**，不把它描述为完整账户安全事件。失败和越权请求不会进入此业务活动列表；后续安全监控应另行设计。

## 数据最小化

每条记录只有：事件 ID、工作区/项目 ID、操作者 ID 与类型、固定动作、资源类型/ID、时间、受限 details。

`actor_type=user` 表示认证账户；actor_id 是内部用户 ID，不返回邮箱。`actor_type=local` 表示关闭认证的本地模式，actor_id 为空。details 是封闭 Go 结构，仅允许 `from_status / to_status / model_id / kind / revision / node_count`。空的可选字段可能省略。

记录不包含 prompt、output、节点标题/正文、项目名称、邮箱、密码、网关 API key、cookie、session token、幂等键、上游完整请求或原始错误体。禁止将 details 改为直接复制请求的任意 map。读取时也解码为封闭结构，未知 JSON 字段不透传给前端。

## PostgreSQL 原子性

新增 [002 审计迁移](../../db/migrations/002_audit.sql) 建立 `studio_audit_events`。工作区/项目复合外键保证所属关系，动作和资源类型有数据库约束，索引覆盖工作区/项目与 `(created_at DESC,id DESC)` 分页。

状态或资源变更与审计 INSERT 在**同一个 pgx 事务**中完成：

1. 创建运行/任务时，资源行、幂等记录和受理审计一起提交。
2. 项目创建与项目审计一起提交；注册创建账户、工作区、默认项目、项目审计和会话一起提交。
3. 取消/重新核对的状态、版本、冷却时间与审计一起提交。
4. 云草稿的 CAS、不可变修订、幂等和保存审计一起提交，详见[云草稿模块](drafts.md)。
5. 006参考素材元数据、上传幂等与reference.uploaded一起提交；编辑任务的有序引用与受理事件同事务，见[参考素材](references.md)。原件写盘先于PG，失败可能留下计入容量的孤立文件。

任一审计 INSERT 明确失败会回滚对应数据库事务，返回 503，并沿用数据库故障停止执行机制。不会先返回成功再异步补写审计。若 COMMIT 回包期间连接中断，结果可能未知，503 不等于未受理；资源与审计仍作为一个事务处理，生成受理重试须保留原幂等键并在恢复后查原记录。取消任务和重新核对使用候选副本，事务确认成功后才替换内存 Task/NextPoll 并广播；未确认成功时保持原内存状态、不发布新状态。Run 终态同样先持久 next 副本再发布。这里保证的是这些已覆盖业务动作的原子性，不泛称所有后台内存更新都具备数据库事务回滚。

应用对外只提供读取入口；没有修改/删除审计 API。但数据库管理员仍能改变数据，本轮没有防篡改签名、WORM 存储、专用审计角色、跨系统不可抵赖或自动保留/归档策略，不能宣称为合规认证的不可篡改日志。

## Memory 行为

默认 memory 模式也显示业务活动，使用固定容量 **512 条**的循环缓冲，覆盖最旧记录。工作区/项目筛选逻辑与 PG 相同。内存活动随进程退出丢失，不冒充持久审计；响应 `storage=memory` 明确表示这一点。PG 不将全部审计历史加载到内存，按页查询。

## 只读 API

`GET /api/v1/audit?scope=project&limit=50&cursor=...`

- `scope`：`project`（默认）或 `workspace`；workspace 也只能读当前认证工作区。
- 项目使用已有 `X-Project-ID` 或 project_id 查询上下文；无权限项目仍返回 404。
- `limit`：1–100，默认 50。
- `cursor`：不透明 base64url 游标，最大 1024 字符，包含当前工作区/项目作用域及 `(created_at,id)`；不能跨项目、跨 scope 或跨账户复用。
- 返回 `{items:[AuditEvent...],next_cursor?:string,storage:'memory'|'postgres'}`。没有下一页时省略 next_cursor。

使用复合 keyset 排序，PG 时间统一到微秒，ID 用于相同时间戳的稳定排序。获取下一页使用排他条件 `(created_at,id)<cursor`，不会像 offset 分页一样因新插入行整体移动而重复旧行。同时间戳事件和翻页间新插入均有测试。新活动位于当前游标之前时，需要刷新第一页才能看到，游标不是数据库快照锁。

API 继承 HttpOnly 会话、Origin/Host 与工作区边界。PG 不可用时返回 503，不回落到本地缓存。界面只读展示动作白名单，不将活动记录当成费用、token 用量或供应商完成凭据。[OpenAPI](../api/openapi.yaml) 包含实际结构。

## 迁移与回滚限制

启动加载编译进二进制的 `migrations/*.sql`，按版本文件顺序检查 `studio_schema_versions`，只执行未应用版本。所有待执行脚本与版本登记处于启动事务；遇到当前二进制不认识的已应用版本拒绝启动。V04 的 002 与云草稿 003 共用该加载器。

这不是自动降级系统，也不提供 down migration。已升级数据库不能直接配旧二进制运行；旧代码可能不理解新审计或修订约束。需要回退时先停止写入、保留当前数据库/资产备份，再用匹配版本的备份恢复到独立数据库并验证。不能通过删除版本行、审计表或修订表来伪造回滚。

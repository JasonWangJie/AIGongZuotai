# ADR 0005：私有资产目录、可恢复删除与离线回收

日期：2026-11-13。状态：v0.7本地实现，独立最终集成证据见030；不代表公网生产灾备或分布式生命周期已放行。

## 背景

V07先发布图片/缩略图/精确multipart文件，再提交PG记录，避免大正文进入JSONB。事务失败、重试竞争和异常退出可能留下孤立文件。V08还需要独立资产检索、名称/标签历史、回收站和可替换的私有内容后端。

仅按artifact ID建立目录会合并不同演示任务的同名产物；仅按文件年龄或回收站状态删除，会破坏原任务、恢复操作及重复请求核对。仅拿数据库锁也不能阻止另一数据库或memory进程写同一目录，更不能证明操作者选中了这些文件所属的数据库。

## 决策

资产目录身份使用reference ID或task+artifact组合。来源/原内容不可变，名称、标签、active/trashed状态采用CAS、幂等和不可变元数据修订；业务状态与目录登记同PG事务，元数据变更、修订、幂等响应和闭集审计同事务。公开目录隐藏存储locator，内容经同源鉴权代理。

软删除只撤销普通访问与新引用，不删除原文件、不改已受理任务的不可变正文和handle。旧下载接口也查询active目录，历史修订不返回可绕过trash的URL。恢复需要保留源内容；修订容量为每个trash预留恢复名额。

回收采用离线管理工具，默认dry-run，不放在请求路径或后台自动定时执行。数据库可达集合遍历所有引用与所有任务，包括trash和终态；只考虑旧、不可达、严格命名且通过文件身份/摘要验证的本地文件。远端S3对象删除与永久删除另行设计。

应用和维护共同使用两层互斥：私有目录的跨进程OS租用锁，以及PG session advisory单writer锁。007增加数据库storage UUID，私有目录owner marker记录UUID与references/assets角色。首次绑定只接受空目录或全部已发布文件都有对应元数据的目录；维护必须已绑定，不自动接管。memory拒绝写PG拥有的目录。

apply需要审阅过的plan_digest。工具重新扫描可达集合和候选，确认摘要一致，逐项再次核对后才开始移除；schema版本、路径、文件身份、内容、大小或mtime变化均不能静默忽略。删除阶段允许返回部分完成计数，不伪称跨文件事务。

## 替代方案与取舍

- 把文件清理接在HTTP事务失败后：无法证明文件没有被另一并发准备采用，也不处理进程崩溃；采用受控离线可达性判定。
- 回收站立即物理删除：无法可靠恢复且会破坏任务历史，因此trash仍属于可达集合。
- 只看磁盘年龄：旧文件可能仍被引用，时间不是所有权或可达性证明。
- 只拿PG锁：memory或不同DB仍可写同一目录，因此另加OS目录锁和storage UUID。
- 自动把无marker目录归给当前DB：空库可能把别人的文件全当孤立垃圾，因此首次绑定必须核对已发布内容，未知来源拒绝。
- 在线/分布式GC与远端对象清理：需要租约、事务事件、对象版本、保留策略及生产恢复验证，本批不冒充已经具备。

## 后果与边界

软删除不减少磁盘或对象存储占用；旧任务正文和历史作品会持续保留。维护需停写、保留配套备份并人工检查计划，换来可审核的删除边界。首次升级遇到已有未知文件会阻止自动绑定，需要先恢复元数据或人工核对隔离；不能删marker绕过。

当前仅扫描直接目录，最低年龄24小时、最多100000枚举/可达项、单候选256MiB，CLI总时限两分钟；超过预算拒绝，不是大规模性能承诺。OS锁只约束遵守协议的本机进程，不是跨主机fencing。apply中途失败可能部分完成，恢复依靠文件备份。

007及owner marker要求PG、两个私有目录和对象/收据成套备份。旧二进制无法识别新数据时拒绝启动；回退用独立匹配备份，禁止修改schema登记或owner绕过。详细操作与限制见[离线维护](../storage-maintenance.md)。

## 验证

普通测试覆盖实际子进程互斥、部分锁释放、候选分类和取消读取；真实PG测试覆盖错库/错目录拒绝、memory拒绝持久目录、dry-run、错误/过期计划拒绝以及临时fixture的可达保留和孤立删除。资产CAS/同键并发、元数据不可变与故障事务回滚见026。符号链接子例受当前Windows权限限制，生产恢复/容量与远端GC未验收。

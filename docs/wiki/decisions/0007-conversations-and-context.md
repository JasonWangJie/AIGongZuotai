# ADR 0007：持久会话、分支与上下文预算

日期：2026-11-13。状态：已采纳并完成V10本地验收，证据见[038](../../changes/2026-11-13-038-conversation-integration.md)。

## 背景

既有Run只有一条用户输入，历史列表不是供应商上下文。多轮对话需要明确会话/分支归属、提交并发、历史裁剪和流中断后如何继续，同时保持已经验证的幂等、事务事件和权限边界。

## 决定

新增项目私有会话和不可变消息节点树。用户节点保存原始输入，assistant节点关联Run，输出及状态从Run快照读取；不在每个检查点重复更新整份会话JSON。旧单轮Run保留原接口和历史，不擅自转成多轮。

会话版本用CAS控制受理，同会话只允许一个活跃Run。新一轮受理将会话版本/头节点、两个节点、Run及冻结上下文、幂等、审计和Outbox写入同一事务。相同原键先重放，不因今天的版本/模型目录变化重新生成。跨会话/项目的父节点拒绝，不相信浏览器上传的历史正文。

历史编辑创建兄弟分支，不改旧消息。继续生成是用户显式创建新轮，使用已有输出作为上下文和固定继续指令，可能消耗模型额度；无法恢复已经断开的上游连接。刷新、断线补齐和进程恢复只读取/标记已有Run，禁止自动重新发送。

模型声明上下文窗口和输出预算，供应商输出参数字段由私有配置明确选择。消息以role/content数组发送，服务端只从当前祖先路径按完整旧轮裁剪；保留最新用户输入及输出预算，不跨分支混入内容。预算使用保守文本估算及固定余量，响应明示估算方式与纳入/省略数；不用于账单或宣称等同供应商tokenizer。

分页、节点数、消息正文、上下文请求与前端加载均有界。事件和审计只写ID/状态/闭集动作，不泄漏标题、用户输入或回答。运行实时输出继续复用原Run SSE，恢复继续使用V09持久元数据和快照补读。

## 替代方案

- 浏览器把整个聊天记录拼成一个prompt：角色和归属无法验证，跨分支内容易串入，且会把历史用户数据作为新单条输入。采用服务端构造结构化messages。
- 每轮复制整棵消息树：写放大与缓存冲突明显，采用不可变节点和Run引用。
- 修改原消息/重跑原Run表示编辑或继续：破坏幂等和历史事实，采用显式新分支/新Run。
- 自动总结被裁剪历史：需要额外模型调用与可追踪摘要版本；本批只裁剪并明确告知，后续单独设计摘要策略。

## 后果与边界

010为新格式，旧程序拒绝新库。升级/回滚须匹配数据库与私有文件联备，维护工具同样校验001—010。控制写者锁仍保留，本批不实现协作实时编辑、工具调用、附件上下文、精确供应商tokenizer、收费账本或多实例流日志。

V10实现、故障注入、上下文fixture、页面及文档已验收；真实供应商调用仍由V15单独验收。

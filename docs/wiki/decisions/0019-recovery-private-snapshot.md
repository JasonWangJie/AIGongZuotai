# ADR 0019：恢复私有元数据使用有界只读快照

日期：2026-11-15。状态：批读实现并接入原恢复入口；完整 A4.1 协调器待完成。

## 原因

逐任务查询 018/019/016 私有状态使恢复有 N+1 往返。仅改成 ANY(ids) 仍可能把大正文一次拉入内存；先算体积、后普通读取又可能被旧执行器的辅助连接更新，令两次读取事实不一致。

## 决策

每页最多 128 个 ID，在 REPEATABLE READ、READ ONLY 事务里先计算最多每任务八行私有数据的 JSON 文本总长度，16 MiB 内再进行四次批量读取。逐件收据保留行形式及顺序，审核解码复用原函数。全部校验及 COMMIT 确认后才修改传入对象。预算不足可缩小只读页，其他错误保守返回，不重试外部副作用。

## 替代项

保留逐项查询容易实现但增加往返；一条大 JSON 聚合缺乏传输前的整体字节门禁；READ COMMITTED 预检和正文可能看见不同快照；锁住全部任务会延长锁持有及增加与旧 worker 的冲突。因此选择有界 MVCC 只读快照，generation 栅栏仍需在下一步协调器提前建立。

## 后果及实施状态

一个成功非空页有 5 次 SELECT 加 BEGIN/COMMIT，边界是私有编码数据，不是 Go 堆、全缓存或媒体字节；普通 5 秒事务不放宽。数据库行 JSON 估算包含额外列及 bytea 十六进制，偏保守。SQL 格式不变，无新迁移。原写事务钩子继续逐资源核验，不以启动快照授权未来写入。A4.1 整批未验，详见 [085](../../changes/2026-11-15-085-recovery-private-phases.md)。

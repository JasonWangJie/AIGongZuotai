# 0023 · 项目内固定版本的工作流与人工选图

## 交付范围

第一个可执行模板有三个节点。文本输出通过审核并完成后成为图片提示词的一部分，图片任务交付的同项目候选供用户选择。每步由已登录用户确认，运行详情、重新登录和 GET 收据都只读取。设计依据见[工作流契约](../../planning/v19-contract.md)。

## 决策与原因

在现有单控制写者、PostgreSQL 和私有目录锁的范围内，把流程定义版本、运行、节点的子资源身份、操作收据和人工选择存入业务库。将节点与子 Run/Task 的关联写在普通生成受理事务内；公开终态、权益、项目通知和流程阶段同事务推进。确认图片时锁定原候选，复核项目归属、任务与产物身份、内容版本、当前资产修订和可见性。

保存与启动分别使用自己的幂等键。启动时冻结图、定义版本、运行输入、渠道模式、模型能力与参数。每个生成节点有私有子键，提交时使用既有审核、额度与幂等路径。在尚未受理的节点上，原模型绑定若已不可用，用户可读取冲突并核对配置；工作流不会自行更换模型或收费。待选集合来自已批准的原产物，原图内容身份与素材的可变名称、标签和元数据修订独立。

## 方案取舍

总体方案中的 Temporal 适用于跨服务长流程。当前三个节点的外部执行已有受理、查询、交付和恢复能力，加入独立编排服务会增加业务库与编排历史之间的提交边界。使用同库事务可在领取不明或重启后凭原键读取原子资源，人工等待期间无需驻留的工作协程。只在浏览器串联请求无法跨登录恢复，也无法在收费步骤的受理事务检查原流程的授权。

## 兼容与限制

023 仅增加工作流表及索引，原画布草稿保留自己的修订和权限。用户可以选用草稿中的文字作为节点配置。工作流需要 PG 与账户会话；memory 模式继续提供本地草稿。首批的模板仅支持文本、图片生成与人工选图，视频输入、显式节点重跑和取消分别由后续子批验收。升级与回退继续联备数据库、私有目录及 owner、已启用的密钥和对象版本。[109 集成记录](../../changes/2026-11-21-109-workflow-integration.md)

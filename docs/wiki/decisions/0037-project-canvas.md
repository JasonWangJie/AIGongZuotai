# 037　项目自由画布

## 入口与保存

在「创作草稿 → 自由画布」编辑自己当前工作区项目的节点、关联和分组。每个项目有一套画布修订，每版容纳最多 2,000 个节点、4,000 条有向关联、128 个组。可移动节点、添加或删除关联、折叠分组，再保存并重新打开原版。用户也可以显式绑定当前项目的私有图片或已有聊天运行。

服务用已登录的会话重核项目和工作区权限，比较预期修订并保存完整画布、来源、审计和项目通知。初始修订为 0，每项目最多保存 64 个不可变修订。满额会保留历史并拒绝新保存。使用原保存键可读回当次修订。请求是否成功不明时，在原项目查询原键回执；编辑内容和新旧分支需由用户核对。

## 来源与执行

每版最多绑定 16 个图片节点和 16 个 Run 节点。绑定图片时核对库修订、内容版本、项目和审核可见性，读取预览时再次核对当前权限。元数据改名可保留同份已登记原图；回收后，旧修订入口与原键回执均停止提供缩略图。Run 节点只展示当前允许读取的真实状态和序号。平移、连线、布局和保存只修改画布文档，模型执行仍走现有业务入口。只获得文字草稿共享权限的人，其读取范围继续由原授权决定。

## 设计取舍

003 文字草稿和 V19 工作流已经冻结各自的数据与执行契约。单独的图文档能把布局、关联与模型请求分开，保留原草稿和工作流的版本，也允许画布引用真实运行和预览。采用坐标及邻接索引、裁剪和折叠来控制视口中的详细节点数，按同一真实项目读取状态变化，无需为画布的每条边发起请求。

## 升级、备份和恢复

037 从 036 增量建立画布修订与来源记录。现有项目可创建首版，旧文字草稿或工作流不会被自动写入新图。升级前停写，并联备数据库、私有目录、原 owner、密钥与已登记对象版本。原版本的恢复需要对应版本的数据库和私有资产。匹配的离线工具继续核对完整迁移序列。恢复后以原用户、原项目、修订和原保存键核对当前版与历史，再验证原图字节及回收后的权限。

## 037 画布实际平移验收

在本机 Intel 集显、Chromium 157、1920×1080 下，两档各实际拖动平移 60 秒，期间私有缩略图已解码、已受理 Run 持续活动。500 节点/1,000 边的 3,599 个帧间隔 P95 为 16.8 毫秒，最多 25 个详细节点；2,000 节点/4,000 边的 3,601 个间隔 P95 为 16.8 毫秒，最多 100 个详细节点。两个项目实际保存并重开 4 个修订，编辑与平移新增生成 POST 为零。 两组最大间隔分别为 67.2 和 33.3 毫秒。137.271 秒专项通过。报告使用前台浏览器 rAF 间隔，系统可用内存约 31.5 GiB；当次网络按 20 Mbps / 80 ms 配置，实际往返与吞吐校准单列。桌面与 390 CSS 像素截图已人工核对。 [全部帧间隔与逐秒样本](../assets/performance-canvas-037.json)。

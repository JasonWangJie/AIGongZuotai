# 033 · 购买意向、商品快照与本人记录

## 如何使用

登录后从侧栏进入订单页面。管理员配置商品目录后，用户可核对商品名、币种、标价及拟购的 CREDIT 数量，然后登记一笔意向。待处理的意向可由本人取消。创建和取消各有独立的操作键，响应中断时按原键核对。详情展示当前状态；原创建收据保留创建时的状态和条款。

服务器通过 `ORDER_CATALOG_FILE` 读取可信本地 JSON 文件，需要 PostgreSQL 及 `AUTH_MODE=required`。配置样例中的商品和价格仅用于本地演练。管理员复制后应填写自己的条款，重启以加载目录。默认关闭新建。移除目录后仍可读取或取消此前的订单意向。[目录示例](../../../config/order-catalog.example.json)

## 金额和权益

价格使用币种、货币小数位和最小货币单位的整数字符串。CREDIT 使用单独的六位微单位整数字符串。目录样例的 `CNY`、`currency_exponent=2`、`amount_minor="1200"` 显示为 12.00 元，`credit_micros="10000000"` 单独显示为 10 CREDIT。应用不自行换算外汇、网关 quota 或实际支付手续费。

一次新建只接受商品 ID 和两个摘要。服务器核验当前目录、计算并冻结最终条款。目录或商品变化后，新的意向需重新确认；原键重放和旧记录查询仍使用最初快照。每个账户最多 32 笔待处理意向，历史记录按用户和工作区隔离、索引分页。

## 状态与实际支付

本阶段支持 `PENDING` 和 `CANCELLED`。创建意向没有付款指令、渠道交易号或权益凭证。取消未付款意向没有资金退款。订单写入与保存收据在同一事务，不能通过客户端输入声明已收款。未来支付、退款、原交易查询和对账需建立在所选商户的真实协议、商户沙箱和受控验收之上。[V13 任务](../../planning/TODO.md)

## 数据兼容

033 增量只增加本人订单意向及操作收据两表。既有 012 CREDIT 账本和 032 共享草稿保留原义。回到 032 需要恢复升级前的配套备份并核对其后的意向、取消、草稿、权益等写入。[数据库迁移](../database-migrations.md)

## 商户资料只读比对

财务人员可在本机对已归一的商户资料执行只读核对。使用与数据库格式匹配的核对工具（035 制品检查连续 001—035），并使用仅具备所需 SELECT 权限的数据库账号，在进程环境设置 `DATABASE_URL`。工作台可继续运行。准备单个商户、环境、工作区和不超过 31 天的半开时间窗口。命令、文件头和事件时间均使用带明确时区的 RFC3339，秒小数最多 9 位。输入为本地 JSON 普通文件，最多 1 MiB、2000 项，使用归一的交易编号、订单编号与最小货币单位。可参考[合成文件](../../../config/order-reconciliation.example.json)。

使用适配自己工作区和文件的参数运行。下面是基于合成样例的命令。

```powershell
go run ./cmd/order-reconcile -statement config/order-reconciliation.example.json -merchant synthetic-shop -environment test -workspace ws_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa -from 2026-11-01T00:00:00Z -to 2026-11-02T00:00:00Z
```

范围内的事件只与文件实际引用、也属于所选工作区的订单比较。报告给出匹配线索、缺证和矛盾三类订单数量、细分问题和摘要；归一资料的来源真实性须由经办方另行确认。完全未出现在资料中的订单不在这次抽取中。重复、乱序、跨单、取消后记录和退款差异供后续核对，工具不登记资金实收或调整 CREDIT。[实现、验证和回滚](../../changes/2026-11-22-173-offline-order-reconciliation.md)

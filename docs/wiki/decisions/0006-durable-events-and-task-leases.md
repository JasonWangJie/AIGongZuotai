# ADR 0006：持久通知与任务租约

日期：2026-11-13。状态：V09本地集成验收通过，依据见[034](../../changes/2026-11-13-034-durable-execution-integration.md)与任务源；多实例生产放行未包含。

## 背景

进程内任务InFlight标记和channel广播不能证明宕机后继续处理，也不能隔离已经超时但稍后返回的执行者。移除全局写锁之前，先把提交、领取、完成、恢复与通知的正确性固定下来。

## 决定

继续保持一个持有PG advisory lock的控制写连接和独占私有目录。固定数量的worker连接只领取和续约；任务状态、原handle、资产注册、审计与Outbox仍通过控制连接事务提交。这是受控执行基础，不是多主业务服务或无状态媒体worker发布。

任务租约采用数据库时钟、每任务单调epoch、控制面generation与业务版本。完成写入同时检查全部条件，失败不改共享缓存/目录归属。取消、核对和重启恢复撤销旧租约。领取可以SKIP LOCKED，完整事件回放不能跳过尚未提交的事件。

发送生成POST前，先持久提交SUBMITTING及通知。租约到期或进程中断但没有上游handle时，保留SUBMIT_UNKNOWN，不自动重发；有handle只查询原任务。数据库fencing不能撤销已经发到供应商的请求，取消context只是尽力停止网络工作。失效结果可能留下不可变孤立文件，但不得注册业务资产或发成功通知。

Outbox与业务状态同事务；项目counter行锁保证事务序号，消费者持久feed投影、去重及checkpoint同事务。内部checkpoint不表示浏览器已收到。全局pending计数行提供有界背压，满时拒绝本次业务事务并允许消费者排空，健康数据库不被永久熔断。当前串行控制连接和counter仍是扩容前要测量的边界。

PG工作区SSE使用绑定数据库/用户/工作区/项目的opaque游标，持久事件只含资源元数据。保留窗口外发reset，客户端补读状态，不重新生成。run专用SSE继续传输token，持久逐token日志与跨实例扇出由V16处理。

## 替代方案

- 直接移除控制面锁、把现有完整JSON更新放入连接池：无法阻止旧缓存覆写新任务，且本地存储尚未支持独立多机worker，暂不采用。
- 只使用内存消息或先提交状态再发布消息：存在提交成功但通知永久丢失窗口，不能满足故障恢复。
- 用全局自增ID作为提交游标：序列分配顺序不等于事务提交顺序；项目事务counter保证所需顺序，跨项目不承诺业务顺序。
- 直接引入NATS/Redis并声称可靠消费：仍需明确事务边界、去重和过期执行者；当前先用PG证明语义，扩容时再测选型。

## 后果与实施边界

业务状态需要额外事件事务写入，租约需要有界独立连接和周期续约。性能必须按实际PG/事件负载验收；Go语言或本机demo QPS不能证明生产容量。

008/009为新格式，旧程序遇到新迁移必须拒绝。目录数据库UUID保持不变；升级和回退联合备份DB、私有文件及对象收据，不删除schema/owner来强行兼容。维护工具同步校验001—009，默认不删除。

验证需要包含实际进程Kill、COMMIT确认丢失、Outbox满/消费失败、租约过期/旧完成/取消、跨项目cursor、重复与窗口重置。完整状态只在034、README、Wiki和TODO证据齐备后勾选。

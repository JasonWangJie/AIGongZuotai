# 0018 · 媒体公平游标与持久退避

状态：2026-11-15已实施，V16-A3.3本地联合验收通过。依据[A3.3契约](../../planning/v16a33-contract.md)，联合事实以[083台账](../../changes/2026-11-15-083-media-scheduler-integration.md)为准。

## 原因

四阶段隔离已经避免慢下载或审核占满查询通道，但旧到期查询没有证明工作区公平和积压扫描成本。当前模型别名不应绕过同一冻结凭据的执行限制；单任务NextPoll不足以表达同渠道冷却、退避次数和恢复探测。审核参考输入和输出共享两槽，也需要防止一方长期占用另一方的机会。

## 选择

使用020私有关系投影表达任务当前lane、冻结channel、eligible_at及单次观察身份，维护固定页大小的工作区/任务轮转游标。任务仍是业务权威，投影与状态同事务；选择事务只锁游标并确认提交，后续严格领取再核验原任务、阶段、due、冷却及lease。领取前获取workspace/channel预算，候选选择失败不能消耗生成请求或写STARTED。

持久渠道状态按固定作用域和lane隔离。正常200、显式Retry-After、取消、协议故障和存储故障分别处理；指数退避和正向抖动只生成一次。恢复探测只用已受理原handle的GET，没有handle时不POST探测；已STARTED审核不重新外发。当前实现仍单网关配置，私有channel键只是已冻结身份的分组，不是路由功能。

审核许可采用有界等待与类别/工作区轮转，保持原两槽，不能把容量不足写成审核内容决定。前端继续收到明确的受理错误；原幂等重放优先于当前容量。指标只使用固定lane/类别，显示本进程调度事实。

## 替代方案

- 全局ORDER BY next_poll LIMIT N再过滤：小工作区可能被深队列遮住，通道不符/未来任务导致反复扫描；不采用。
- 仅进程内轮转与退避：重启丢失服务端等待时间和探测所有权，可能突发查询；memory demo可展示有限排队，但不能替代PG验收。
- 新增Redis作为执行权威：当前业务与权益仍在PG，同步双写增加确认不明与恢复边界；本批保持同库事务。未来多实例仍需独立方案及故障验收。
- 多开审核池：会突破原渠道实际并发，本批采用共享池公平仲裁。
- 自动换凭据/模型、POST探测或重新审核STARTED：会改变已受理请求或重复执行计费/审核动作，不采用。

## 后果与验收

新增投影和游标有维护成本，必须测量完整选取循环和实际SQL计划，不能仅证明某一条索引可用。固定页限制单次工作量，轮转公平不等于无限工作区下的恒定最大等待。020迁移与离线CLI精确栅栏、停写联备一起更新，不能删迁移或投影强行降级。

升级保留原19SQL字节、冻结请求/收据/候选及权益；旧无身份数据采用明确保守分组或隔离，禁止当前目录猜测。确认不明、旧epoch、迟到成功、Outbox背压、旧候选、取消和共享许可退出均须真实测试。至少十万积压及大量终态历史测custom/generic/auto计划；本机结果不能成为生产容量或全站多实例结论。

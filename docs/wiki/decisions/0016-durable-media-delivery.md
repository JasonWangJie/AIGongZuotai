# ADR0016：先提交私有描述，再独立交付

状态：2026-11-14已实施并通过本地联合验收，见[075](../../changes/2026-11-14-075-media-delivery-integration.md)。完整边界见[契约](../../planning/v16a31-contract.md)。

## 原因与决定

原Query同步下载与审核，长下载仍占查询预算。简单把URL放进内存队列不能在重启后保持原集合，也不能保护“文件已写、PG收据尚未确认”的窗口。原生异步适配器改为QueryStatus取得并校验清单，原有效租约事务先保存加密描述和计划资产ID，确认提交后由第三通道处理逐件下载、完整收据及当前B2审核。

签名URL可能就是访问凭证，使用独立32字节密钥和AES-GCM，绑定稳定数据库UUID/任务/交付/原handle/清单身份；不复用网关或邮件凭据。资产ID由delivery+slot确定。PG完整收据、磁盘完成标记和实际字节必须匹配，损坏不能用重新下载替换。原件、缩略图及S3指定版本均校验。

## 替代方案

- 仅增加下载信号量：等待仍占query步骤，且不解决宕机交接。
- 明文持久URL或用Task JSON存描述：扩大凭证可见面，容易进入公共事件/日志。
- 重启重新Query并按handle下标复用旧文件：协议没有可信产物版本，可能混合两次回应。
- 每次Query前登记持久意图：增加所有轮询写入，不是本批必要条件。无已提交清单、无候选、零下载时可重查原handle；已有清单一律不换批。

## 后果与实施

新增018及离线精确栅栏，联备涵盖独立密钥。GC区分计划保护与必须存在的完整收据，所有终态继续可达。当前禁止改迁已登记交付的存储定位；普通旧资产保留受控迁移。默认2+2+2容量，取消/失租/背压不提前释放尚在工作的槽。

PG原生phased provider自动使用该链路，缺key在迁移前拒绝；已有交付需原key，READY需兼容provider。memory也分阶段但不能恢复关闭后的数据。旧demo SVG没有真实下载，保留原接口。交付仍含审核，旧候选不自动重审；A3.2首次审核分派、A3.3渠道公平退避、持久token与跨实例能力继续独立实施。

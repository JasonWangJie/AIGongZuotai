# 031 · 项目漫剧分镜本与作者确认

## 从哪里开始

已登录的 PostgreSQL 项目用户从工作台侧栏进入「漫剧分镜」。填写故事梗概，建立角色与场景卡，再为每个镜头选场景和出场角色，填写动作和对白。镜头可以复用角色、场景和同一张项目私图。在本页调整顺序后，保存为指定项目的新版本。

一个项目有一本分镜本，含 1—16 个角色、1—16 个场景和 1—12 个镜头。每镜可选 0—8 个不同角色，整版最多四个带图镜头。单原图最多 8 MiB，计入各镜引用后总计最多 32 MiB。正文 JSON 最多 256 KiB。每个项目最多 128 个不可变版本。

## 为什么要冻结角色与场景

同一角色在多个镜头中使用稳定 ID。某次保存将卡片内容、镜头顺序、指向关系、素材修订与原件身份一起固定。后续修改角色名或移动镜头，查询旧版仍能还原当时的剧本。把镜头仅存为一组可变化的当前卡片引用，会使已经确认和下载的旧稿难以核对。

031 增加项目头、不可变版本、私有素材绑定、保存与确认收据四张表。保存以预期版本作并发检查，先查原操作键。两个作者窗口有竞争时，只有一个新版本可以提交。未知保存或确认先用原键读取对应操作的收据，操作类别、项目和原操作者共同限定作用域。

## 确认与私图下载

作者打开已保存的当前版，显式确认后可以导出该固定版本。旧版已有的确认继续有效。首次确认只能针对当前版，由该版本的保存者进行。作者确认记录表达创作决定。素材按项目归属和平台审核规则独立判断，作者确认不能让隔离、回收或内容身份变化的原图重新可读。

导出清单通过项目 API 返回各镜、原角色名与场景、动作和对白。导出的文件为可编辑 PPTX。每镜首张放该镜的选图，长文按真实版面续页。故事和卡片说明随页保留为演讲者备注。导出使用已批准原图和当时的角色/场景快照，写出下载件前再次核对确认版本及存取授权。导出不创建媒体任务、报价或权益冻结。

## 兼容与后续范围

031 与旧库使用增量升级。降级时必须恢复升级前的整套数据库、私有目录、对应对象版本与已启用密钥，旧程序和离线维护工具使用精确格式栅栏。保留升级后的联备供核对恢复点以后的写入。

本子批交付故事、角色、场景、分镜到人工确认的图文分镜稿。逐镜调用真实生成模型、配音、字幕和视频合成分别需要明确的模型能力或对应媒体验收。团队邀请和跨账户项目角色另行跟踪。接口与历史记录见 [OpenAPI](../../api/openapi.yaml) 和 [迁移说明](../database-migrations.md)。

## 已确认镜头的视频尝试

在「漫剧分镜」中打开已确认版本，选择一个镜头和视频规格，预览该版的完整提示词与适用报价，再显式确认生成。来源限定为固定版本的文字。用户可以在本镜头的尝试列表中核对任务与已交付产物；生成和替换剪辑各自保留原操作收据。[038 设计与集成进度](0038-panel-videos.md)

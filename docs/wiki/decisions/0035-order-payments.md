# 035 本人订单的资金记录与购入权益

## 决策与实现范围

033 订单记录购买意向与冻结条款。035 在单独的表中记录账户、工作区、原订单与收款来源的绑定、事件回执、交易或退款事实及购入权益分录。单库在第一次显式绑定时固定为测试或正式环境。升级只根据旧意向建立等待容量，不给旧单创建收款绑定、支付事件或 CREDIT。

站内用户可在「本人订单」打开原单，查看收款、退款和权益三个独立状态。没有绑定或核实事实时，页面说明当前没有已核实收款。接口只返回本人原单的环境、固定币种与汇总金额，以及已入和已冲回的 CREDIT。目录关闭后仍可查看。实际用户不能通过工作台提交支付成功声明。

## 收款、退款与权益

私有事务入口处理未来商户适配器已经认证并解析的事实。当前只有测试程序能向它送入合成事件。测试资料和生产语义分开记录，173 对账文件保持只读。使用相同事件原标识可查询其原处理结果；同一经济交易被不同的通知重复交付也只能产生一次购入权益分录。

完整金额及币种符合原条款、原单处于可受理状态、没有已知冲突或退款的收款，可将冻结的 CREDIT 计入原工作区钱包。原资金事实、权益和可追溯回执由同一数据库事务提交。取消后迟到的收款、身份或金额矛盾、已有退款以及权益容量不足均有独立核对状态。操作者在资料里声称已付款不能建立这一事实。

退款事实可先于付款到达。系统分别记录已核实退款与权益处置；已发放的 CREDIT 及原分录可回查，已花、已冻结、部分退款或归属不明的权益等待业务核对。当前没有自动负余额、扣回其他购买、释放旧生成冻结或生产退款请求。新取消动作在原单已有资金证据时拒绝，旧操作原键仍能读到原收据。完整购入分录可释放待处理意向名额，尚未处置的意向继续占用。

## 选择与后果

若把资金状态回填到 033 的意向状态或用用户上传对账资料作为到账证明，将破坏原收据含义，且不能说明资金来源。追加独立记录保留了意向、收款、退款及权益之间的对应关系。要开放正式支付，仍需选定渠道和测试商户、接入真实签名与交易查询、明确退款政策及舍入和已履约权益的处理，然后单独受控验证。当前状态页可以使用，实际商户写入入口尚待接入。

035 升级前停写并联备数据库、私有目录、对象版本及启用的密钥。离线维护工具使用与数据库匹配的版本；034 旧工具和制品需与原备份配套。恢复后在目录关闭状态核对原订单、付款、退款、购入分录、原通知的去重与用户范围。[035 迁移](../../../db/migrations/035_order_payments.sql) · [集成验收](../../changes/2026-11-22-177-order-payment-integration.md)

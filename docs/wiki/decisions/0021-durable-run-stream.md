# 0021 · 已公开聊天增量的持久化与断线回放

## 背景

020 的非审核聊天可以先把文字显示在浏览器，再异步保存检查点。两者之间崩溃时，浏览器已经看到的后缀只能由重启快照重置。旧记录缺少逐段证据。

## 决策

021 为新受理聊天建立独立流记录。开始事务分配单次执行身份，确认提交后才能请求模型。未启用输出审核时，每个非空供应商文本块在自己的事务中登记执行身份和连续序号，随后才通知浏览器。聊天受理、增量、终态和项目通知各沿用相应的权限与事务边界。启用审核时，待审正文保存在该次执行的有界内存中，只有整段允许、运行完成并提交后，正文才出现在持久快照中。

流记录保存持久水位、回放窗口下界和快照序号。每个 Run 的窗口最多 256 个事件，登记的正文载荷最多 1 MiB；原输出限制为 128 KiB。窗口裁剪前先确保快照已覆盖裁剪范围。普通追加只写入新文字和水位，避免每个块重写完整会话或新增一条项目通知。执行中的取消要等待已经发起的本次增量事务确定结果。

SSE 继续使用 Run 的数字游标。客户端按已确认的原游标重连，每页最多 32 条，窗口过期时读取带当前序号的授权快照。旧 020 记录沿用原快照和恢复间隔。新增量的启动恢复从已提交水位继续一个中断序号，保留原键和原模型调用次数。数据库、私有目录和已启用密钥须在同一备份点恢复。

## 替代方案与后果

只扩大进程内回放窗口无法保留崩溃前已经公开的内容。把增量写入项目通知表会把项目游标、文本访问范围和积压额度绑定在一起。独立流表使聊天游标与项目通知保持独立，代价是每个已公开块增加一次数据库提交。本轮使用本机单控制写者。租约过期、跨执行者隔离和混合负载成本分别由 B2 和 C 验证。

实现与真实故障验收见 [B1 集成台账](../../changes/2026-11-21-099-run-stream-integration.md)。

## 037 的可选回放读连接

在 PostgreSQL 服务进程设置 `RUN_REPLAY_READ_CONNECTIONS=1` 至 `4` 并重启，可以给 Run 事件的持久回放页分配相应数量的额外数据库会话。未设置或设为 `0` 时，回放仍使用原控制连接。开启前应在数据库连接预算中预留这些会话。内存演示只接受默认值。

新读连接使用控制连接的数据库配置，在主库目标检查通过后将会话设置为默认只读。每页在同一只读可重复读事务中先核对数据库、schema、存储 UUID、执行代次与原控制会话的独占锁，再按原项目和工作区读取水位、快照或连续事件。连接只在读取页面时占用。等待连接、建立连接和读取每页共用五秒期限，浏览器断开或服务关闭也会取消等候和读取。开始发送 SSE 前的短暂故障返回 `503 RUN_REPLAY_UNAVAILABLE`；已开始的 SSE 会结束，可以用最后收到的游标重新 GET。若返回的身份或日志有矛盾，服务停止执行，需先核对匹配的数据库、进程和备份再重启。[204 台账](../../changes/2026-11-22-204-run-replay-read-pool.md)

## 可选的跨运行批量提交

RUN_DELTA_BATCHING_ENABLED 默认 false，开启时需要 PostgreSQL。单控制写者按不同运行收集短批，每次事务最多 32 项/256 KiB，单个运行只保留一项等待原库确认。原租约、期满核验、审核隔离、已确认才公开、序号与回放窗口继续适用。受锁、需要裁剪或检查点的项按实际判据处理；每个运行以上一次实际收据为准。进程停止或提交确认丢失按原库状态核对。[存储](../../changes/2026-11-22-209-batched-run-delta-store.md) · [协调器](../../changes/2026-11-22-210-run-delta-coordinator.md) · [业务对照](../../changes/2026-11-22-211-batched-delta-acceptance.md)。

## 037 跨运行增量提交的验证

本机 PostgreSQL 的两组独立新 schema 各运行 64 条正常模型流，每条 12 个增量。开关两侧各有 768 条增量按原序通过授权 SSE 和数据库回放，模型请求各 64 次。事件行的 xmin 显示，关闭时为 768 次写入事务，开启时为 24 次，每次包含 32 个不同 Run，少 744 次（96.875%）。从模型写出前到普通客户端读完相应 SSE 的 P95 分别为 52.28 和 6.83 毫秒，P99 为 73.50 和 8.10 毫秒。在本机控制的 12 个波次下测得，事务计数只覆盖增量插入。8 路试跑 26.606 秒，64 路含业务边界专项共 28.722 秒。 六项原库专项全部通过，共 13.794 秒，覆盖同事务分组与逐项授权、保留窗口与输出上限、并发取消、失期回滚、服务器明确回滚和提交应答丢失后的停写。 [报告](../assets/performance-batched-deltas-037.json)。

## 扩展订阅的会话复核

全局订阅数由 ADMISSION_GLOBAL_STREAMS 控制。扩展到 129–256 时启用鉴权 PostgreSQL、单独的运行回放读连接和一个专用于复核账户的只读连接。相同会话的多名读者共享一次数据库身份复核，每个订阅仍单独验证用户、工作区和资源，分别持有自己的游标与带宽。复核连接通过与回放池相同的控制者身份检查，故障时只要该轮无法确认会话，便撤销其采样的读者。默认128沿用原路径。[218](../../changes/2026-11-22-218-stream-session-batches.md)。

# ADR 0004：私有参考素材与不可变编辑请求

日期：2026-11-13。状态：v0.6本地实现；真实供应商验收与对象存储迁移未完成。

## 背景

图片编辑允许多张参考图。供应商按原始请求体判断幂等；重新生成multipart边界，即便原图和提示词相同，也会改变原始字节。将最多四张8MiB图片编码为Base64写入任务JSONB，会增加请求复制、数据库体积和全局锁持有时间。

## 决策

平台先接收单文件上传，校验PNG/JPEG/WebP真实编码、像素/维度/字节上限，保留原件并生成不超过512px的缩略图。公开引用是项目内的reference ID，内容哈希与磁盘身份仅服务端可见。原件和缩略图都在鉴权后读取。

编辑受理按有序引用列表打开校验后的原件，使用有界并发在全局状态锁外生成一次multipart文件。PG事务保存任务、精确正文文件身份、上游幂等键、模型快照、引用顺序及审计；重新取得锁时再次核验幂等和准入。提交worker打开同一文件描述符并校验长度/哈希后发送，不重新编码，不猜测补齐缺失文件。

文件先持久化再提交数据库事务。事务失败可能遗留孤立文件，但不会提交指向半个文件的正常新任务。孤立文件、临时文件和正文文件都计入磁盘容量；自动回收留给V08，必须先建立引用和保留规则。当前单目录最大2GiB/4096文件，工作区参考素材最大128MiB/100条（原件加缩略图逻辑字节）。

006迁移是引用关系和数据格式栅栏；旧程序拒绝写新库。数据库、REFERENCE_DIR、ASSET_DIR需要协调备份。只恢复数据库无法恢复已受理任务的正文；此时应待核实，不能换新请求再次收费。

## 替代方案与取舍

- Data URI/大JSONB：协议可接收，但本平台不作为浏览器输入或持久正文方案，避免多份大内存和数据库膨胀。
- 供应商file_id：现有编辑文档未提供可依赖的私有文件生命周期契约，因此不猜测实现。
- 外部图片URL：会增加SSRF、过期和可变内容问题；本批只接受私有上传ID。
- 直接对象存储：适合后续共享存储，但不能跳过精确字节、授权、引用关系和回收一致性；V08通过存储接口迁移。

## 后果与验证边界

上传解码和缩略图需要有界内存，不宣称零分配；大multipart正文采用磁盘流式处理，代价是校验读盘和额外磁盘容量。当前2个编辑准备槽、4个存储操作槽保护单机，并非分布式配额。未知受理不重发，停用目录不改变旧任务身份。

验证入口见[参考素材](../references.md)、[媒体网关](../media-gateway.md)与[025集成台账](../../changes/2026-11-13-025-reference-integration.md)。fixture证明协议与权限链，不能证明真实模型效果。mask、视频编辑、资产删除/GC、多机对象存储和真实供应商验收仍独立排期。

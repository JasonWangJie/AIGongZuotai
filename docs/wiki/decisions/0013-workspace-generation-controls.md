# ADR 0013：工作区新生成限制与用户复核

- 日期：2026-11-14
- 状态：已实施并通过本地验收，V14-C1；真实渠道和C2/C3另行验收，见062台账
- 模块：H01/H03/H05/H06/H08/H09

## 原因

已交付的内容审核控制单次内容交付，运营工单核对已有执行与权益；二者都不应自动变为账户封禁或全工作区惩罚。需要可追溯、可复核的后续生成准入控制，同时保护用户仍在执行的任务和受理不明请求。

## 决策

控制对象为工作区的新生成，状态OPEN/RESTRICTED。读取缺行视作OPEN/version1，不创建默认记录；每轮限制有独立episode，原始限制事实不改写，解除时间只能由有效解除事务写入一次。申诉、公开答复、控制修订、审计及不可变回执同事务提交。旧episode的计划或申请不能解除新限制。

使用稳定workspace行锁覆盖首次缺行竞争：受理FOR SHARE，限制变更FOR UPDATE；在受理事务中先锁工作区再访问会话、报价和钱包。幂等重放先于新限制，锁外审核和文件准备之后复查，最终事务再核查。拒绝不新建业务对象、不冻结或消耗报价；不在worker、保存、恢复或结算途中增加此门禁。

新增显式moderator角色，旧observer/operator/finance不扩大权限。预演执行真实SQL后回滚，绑定当前凭据、授权、控制和全部未完成申请版本；执行需当前密码并重核权限。解除预演有独立恢复容量，同一工作区新解除预演替换旧未消费预演；已消费计划和回执保留。执行响应不明只查询原计划回执。

本批使用可见页面有界拉取。既有Outbox仅属于项目，不伪造项目来广播工作区控制，不把服务器消费checkpoint等同用户已读。无需修改既有生成事件语义。

## 替代项

- 账户级全站封禁：范围更大，会混入登录、资产取回及其他工作区，留给C2独立设计。
- 给现有财务或operator隐含权限：会扩大既有授权，因此只增加显式moderator。
- 只在HTTP入口检查：不能覆盖审核、素材准备和首次缺行并发，因此必须有最终事务门禁。
- 限制时取消所有任务：可能已产生供应商费用并破坏原合同，因此既有任务继续原生命周期。
- 自动额度惩罚及内容放行：证据和规则不同，留给C2/C3，不推断现有审核决定或余额。

## 后果及实施边界

016→017需停写联备数据库、私有目录/owner和已启用邮件的队列密钥。三个离线工具要求精确001—017；回退用匹配联备，不删迁移或证据。

用户仅查看自己的复核详情，moderator只看明确scope下的申请；列表不带说明/答复正文，内部证据引用不公开。用户申请未知保留原输入/键，仅当前页面内存；敏感执行密码不进入恢复仓。

解除不放行隔离内容、不自动新生成或退款。尚无账户封禁、内容重审、自动风险策略、邮件通知、分布式多写者或生产容量结论。完整业务与验证见[控制核心](../generation-controls.md)、[受理边界](../generation-admission.md)、[062集成台账](../../changes/2026-11-14-062-generation-controls-integration.md)。

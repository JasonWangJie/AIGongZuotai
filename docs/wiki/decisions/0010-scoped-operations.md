# ADR 0010：工作区运营权限与预演处置

状态：V14-A本地子批次于2026-11-14验收；最终验证见050和任务源，不代表完整审核风控平台完成。

## 原因

V12已有准确的权益账本与停机CLI，但异常需要逐条人工定位。运营人员需要在有限作用域查看异常、留下证据标识，并在清楚实际影响后处理原任务或冻结。

## 决策

默认关闭运营入口。角色与普通工作区所有者身份分开；observer只读，operator核对任务，finance处置REVIEW冻结，可独立授予多个角色。首次授予、改权、撤权仅通过停机工具，默认预演，apply绑定数据库身份与精确计划，操作键重放只恢复旧回执。新注册不会自动变管理员。

在线处置仅开放原handle查询、REVIEW证据结算/释放、关闭工单。每次先生成5分钟计划；真正业务在SAVEPOINT执行验证后回滚，保存的是受限计划与审计。执行要求当前密码，bcrypt在业务锁外有界运行；事务内重新核对原密码散列、凭据版本、会话、grant版本、工单/资源/账本版本及摘要。工单、收据、业务、账本、审计、Outbox同事务，提交成功才换缓存。响应不明先GET原工单，不复用密码或自动重发。

运营列表只展示安全元数据，不读取提示词来做“人工内容审核”，不返回邮箱、完整供应商handle或URL。证据仅为安全短标识；此功能本身不能核验供应商外部证据真伪，操作人员必须先完成核实。

## 替代项

- 共享管理员密钥：难以按人员和工作区撤权，也不能提供可靠操作者归属，因此不采用。
- 复用工作区owner作为全局管理员：会让所有注册用户获得运营能力，不采用。
- 直接把离线CLI任意动作暴露到HTTP：会扩展赠额/退款和跨租户影响面，不采用。赠额、一次全额权益冲正仍保留停机CLI。
- 一次点击立即改任务或余额：无法在操作前展示精确影响，也容易在未知响应时重复执行，不采用。
- 本轮同时完成内容审核/封禁/申诉：需要独立的生成前后隔离与用户申诉链路，留作V14-B/C，不把异常核实台冒充内容审核台。

## 后果与实施边界

013/014增加授权、审计、工单、计划及收据表；旧业务和账本保留。升级必须联备PG、私有目录及已启用邮件时的队列密钥，不能删除迁移绕过旧程序栅栏。线上结算使用V12既有冻结规则，人工决定后再找回产物也不会新开冻结补扣。

敏感流程仍受单控制写者、固定容量和当前密码能力限制；尚无MFA、审批人分离或多人双签。数据库管理员能力不由应用角色控制，不能宣称防篡改合规认证。V14整批还依赖V11真实邮件验收及B/C功能；本地fixture不替代外部验收。

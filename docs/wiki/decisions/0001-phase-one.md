# ADR 0001：第一阶段采用单进程 Go 与内存开发存储

- 日期：2026-11-13
- 状态：第一阶段采用；仅适用于本地开发与链路验证
- 关联：[总体开发方案](../../deliverables/Go与NewAPI高性能AI工作台开发方案.html)、[001 台账](../../changes/2026-11-13-001-foundation.md)

## 背景

用户的供给是二次开发 New API：LLM 为实时连接，图片和视频为自定义异步提交与结果查询。当前没有完整的真实异步接口 fixtures，也没有已验证的生产部署环境。先需要可运行的工作台与纵向接口，明确真实实现边界，再推进可靠性和性能目标。

## 决策

第一阶段使用 React + TypeScript 工作台与一个 Go 进程。HTTP API、流式 run 和媒体任务调度在进程内合并部署，数据保存在内存开发 store。默认 demo Provider，不需要网关密钥即可验证流式展示、任务状态、幂等和取消。live LLM 必须显式配置；媒体接口在未确认契约前明确返回未配置，不猜测官方 New API 或第三方协议。

仓库同时建立 README、Wiki、架构决策和逐项变更台账。自动检查负责文件、链接、台账结构和变更集合中的文档同步；人工评审负责语义真实性与验证证据。

## 考虑过的替代项

| 替代项 | 暂不采用的原因 |
| --- | --- |
| 首轮同时部署 PG、Redis、NATS、Temporal 和 Kubernetes | 契约尚未固定时扩大排错面，容易把环境搭建当成端到端交付；后续仍按方案引入必要组件 |
| 前端直接连接 New API | 会暴露供应凭据，无法建立平台权限、幂等、取消和任务归属边界 |
| 按通用异步接口猜测二开协议 | 用户已经确认是自定义接口，错误重试可能造成重复生成和计费 |
| 把 demo 任务当成真实生图和视频成果 | 无法验证供应链路，也会误导用户对能力和交付状态的判断 |

## 后果与限制

- 服务重启后任务、运行、幂等和回放数据丢失；目前不能提供跨重启恢复承诺。
- 多实例共享、可靠租约、生产账户和支付并未实现；当前只适用于本地环境。
- 单进程调度不代表达到方案中的公平配额、持久调度和灾备要求。
- 演示素材必须明确标识；视频封面不等同于真实视频文件。
- 代码与文档需要持续标记差距，不能把总体设计中的性能目标写成已测成绩。

## 退出条件

在对外开放前，完成真实网关契约、PostgreSQL 持久化与恢复、生产身份和权限、资产存储，以及对应的负载和故障测试。是否拆分 Go 部署单元由资源隔离和实测结果决定。升级存储或运行模式需要新 ADR、迁移/回滚方案和台账，保留本决策作为历史。

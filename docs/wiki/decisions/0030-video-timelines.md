# 030 · 项目视频剪辑稿与固定版本成片

## 适用范围

V20-A 允许已登录的创作者在当前 PostgreSQL 项目内组合已交付的 MP4。稿内镜头使用原素材，用户可取片段、命名、排序、播放，在两份固定修订之间比较，并将历史版另存为新的修订。视频生成、供应商延长与本地剪辑分别受理。

## 选择保存镜头清单的原因

用户需要在不重新生成画面的情况下改动裁点，还要知道旧成片使用了哪一份私有原件。只保存下载地址会随临时链接或资产状态变化而丢失来源。030 将稿头、版本、有序镜头和操作键分别保存。镜头绑定本项目库的资产 ID、修订、登记的实际原件和 SHA-256。逐镜记录保留原资产身份，媒体字节位于既有私有存储。

每稿最多 8 镜，累计不超过 30 秒。入点、出点用整数毫秒，出点最多 300000 毫秒。按成片累计时间四舍五入到 24 fps 后，每镜至少占一帧。重复引用同一片源按镜头累计，每源至多 32 MiB，一稿原片总量至多 128 MiB。项目至多 64 稿、全站至多 4096 稿，每稿至多 128 个固定版本。

## 操作、授权与恢复

保存时必须指定资产的当前修订。同一用户、项目、原保存键和请求摘要可读取原版本。在过时版本上修改时保留本页输入，用户可比较最新版、放弃本页编辑或另存新稿。本机整理的未保存内容保留在当前页面内存。

固定版显示原镜头与当下可见性。原件身份相同的元数据改名允许旧版本继续预览；回收、隔离、缺件和内容变化阻止相应原片读取与整稿合成。服务端校验当前会话、项目、任务交付、资产状态和原文件完整性。单镜头预览限定版本与镜头并支持 HTTP Range。客户端不能以路径、外部 URL 或内容摘要替代项目授权。

## 成片生成

用户显式导出选中的已保存版本。配置 Windows 本地 FFprobe 与 FFmpeg 的服务在有界私有临时目录内处理原片，在合成后再次核对授权及素材身份，返回经过验证的 MP4。产出为宽屏 1280×720、24 fps H.264 与 AAC。对无音轨原片补静音。响应给出实际时长、完整字节数和 SHA-256。服务端成片最多 32 MiB；工作台独立限制接收字节并校验摘要后才发起下载。

预览与合成使用独立并发占位。取消、连接断开或服务退出后释放本次计算和临时资源。工作台持有用户与项目隔离的待核对记录，重新进入时只能先读取原版本。再次合成由用户明确启动。关闭本机合成仍可编辑、保存和读取授权原片。导出期间沿用原生成的审核和账务，不创建新的生成任务、资产或冻结。

## 恢复与验收

升级与回退需要保持数据库、私有文件及对象版本、目录归属与启用的独立密钥一致。029 写者和离线工具应按已知格式拒绝 030。[迁移说明](../database-migrations.md)

工作台与浏览器脚本覆盖两个具备音轨的原片、裁点、镜序、旧版、恢复及两个版本的下载。集成人在持久化账户与受控本机编解码环境验证实际原片和输出。供应商参考续写与线上渠道验收另行记录。[工作台台账](../../changes/2026-11-22-145-video-edit-workbench.md)

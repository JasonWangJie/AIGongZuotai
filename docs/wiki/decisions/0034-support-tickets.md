# 034 · 本人工单与独立工作区客服权限

## 账户和授权

用户需要启用 PostgreSQL、`AUTH_MODE=required`，并以可正常使用工作台的账户登录。本人入口按真实账户和当前工作区读取记录，支持新建、补充、关闭及读回原操作。普通用户联系支持的能力独立于运营开关。

客服入口要求启用运营。管理员使用现有停机 CLI 在指定工作区显式授予 `support` 角色，先预演，再以稳定操作键和原计划摘要执行。此角色只提供 `support_ticket`，可以阅读并答复该区工单。读者将接触到用户自述的问题，因此项目所有者或其他运营角色不会自动成为客服。授权撤销后，旧会话的新查询及原回复收据读取也会拒绝。[命令入口](../../../cmd/operations/main.go)

## 对话与原收据

创建时选择账户、权益、生成或其他问题，填写主题与正文。列表按创建时间及 ID 倒序，每页固定 20 条，只有详情和原收据提供对话正文。单账户在同一工作区可同时保有 8 个开放工单。每个工单最多 31 条非关闭消息，另保留一个版本用于关闭。

补充、答复和关闭都要求提供看到的 `expected_version`。并发操作发生冲突时，重新读取工单，核对新增内容后再决定如何处理本地输入。客服回复要求当前密码；同一事务核对会话、凭据和有效角色。写入的业务记录包含消息和版本，口令只用于本次验证。

本人和客服分别通过自己的收据入口，携原操作种类与 `Idempotency-Key` 读取提交当时的对话。收据根据操作者、工作区和操作隔离。网络中断后先用 GET 原收据核对，查询无需密码；后来追加的消息仍可通过当前详情读取。[OpenAPI 契约](../../api/openapi.yaml)

## 存储与恢复

034 增加工单、不可变消息及原键收据表。版本与对应消息、操作收据同事务提交。工单处理只更新服务对话；权益、订单、审核决定、其他工作区或项目数据分别沿各自原入口核验。用户已下载或拍摄的内容仍由用户控制。

升级与恢复沿用配套数据库及私有目录备份。恢复后按原账户与工作区重读已关闭的工单、读回原回复收据，并检查已经撤销的客服授权仍被拒绝。降回 033 时使用升级前配套备份，另行核对其后新增的客服往来。[迁移说明](../database-migrations.md)

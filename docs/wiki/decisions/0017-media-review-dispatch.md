# ADR0017：持久记录首次审核，再执行外部检查

状态：2026-11-14开始实施，2026-11-15本地联合验收通过；[契约](../../planning/v16a32-contract.md)与[079](../../changes/2026-11-14-079-media-review-dispatch-integration.md)记录实际进度。

## 原因与决定

018使慢下载与状态查询分离，但审核仍占delivery。旧B2候选无法区分“未开始”与“已执行后确认丢失”，恢复时只能隔离。独立review worker需要019私有READY/STARTED/FINISHED证据；新READY与首次候选同事务，STARTED提交确认后才能读取字节并审核。

旧候选不回填，新STARTED恢复不重审。每批最多一次启动，没有逐件续审或自动重审；整组决定与资产、权益、Outbox及派发终态同事务。原result_status随交接冻结，保留PARTIAL语义。

## 替代项

- 只将审核放入goroutine：没有恢复证据，容易重审或产生无界等待。
- 所有候选默认READY：会把已执行但结果未知的旧审核再次外发。
- 先写STARTED再等许可：输入占满现有审核器时，会让尚未执行的输出错误进入未知/隔离。
- 输出另建审核并发池：会扩大参考输入与输出合计请求数，绕过原总限额。

## 后果与实施边界

第四lane在claim之前取得固定执行预算和原审核引擎许可，整组复用同一许可，真实输入与输出总并发保持2；review worker显式配置1—2。释放必须等待活动检查真正退出，预算还覆盖最终保存与心跳清理。公平调度和渠道退避由A3.3进一步验收。

单件仍有原读取和审核期限，整组总期限按有界候选数计算，不能用通用短step超时截断正常四件串行审核。取消及失租仍需及时撤销执行，提交背压只保存原决定。

019为正式增量并同步所有离线工具格式栅栏；原001—018不得改写。没有新文件正文，旧候选/交付收据的可达性保持，状态转换使旧维护计划失效。沿用数据库/私有文件/密钥及对象版本联备；不是跨实例控制写、真实审核准确率或云灾备验收。

# ADR 0002：先完成持久单写者与真实协议，再扩展集群

- 日期：2026-11-13
- 状态：v0.2 本地实现与验收通过；具体验证见 004—008 台账
- 延续：[ADR 0001](0001-phase-one.md)

## 问题

内存演示阶段无法保存账户、重启前的任务与幂等键，也无法保证自定义异步网关在异常时不重复创建收费任务。用户已提供 [api.aiimg.lol 文档](https://api.aiimg.lol/async-image-api-docs)，实际协议可实现；直接把当前进程扩成多个副本会制造重复执行与状态覆盖风险。

## 决策

1. 引入 PostgreSQL 事务，将平台意图、任务、精确上游提交体与幂等映射持久化。每个数据库只允许一个有效执行进程，使用数据库 advisory lock；锁连接失效后停止执行，不能静默重连继续写入。
2. 采用 HttpOnly 会话与独立工作区/项目身份；浏览器只访问自有 API，SSE、快照、取消及资产读取使用相同的权限边界。
3. LLM 约一秒检查点与终态写入；重启后保留已有输出并标记中断，不自动请求新的生成。该模式不是逐增量强耐久流日志。
4. 图片/视频按实际文档提交和查询，持久保存任务 ID、凭据身份和请求体。提交受理不明进入待核实；没有结果查找或取消接口时明确呈现限制。
5. 先安全导入本地原件并鉴权读取；对象存储、CDN、转码和审核生命周期留在独立后续阶段。

## 替代方案与后果

直接接入 Redis/NATS/Temporal 并不能替代业务事务或网关幂等语义。先验证单实例状态正确性可减少并行变化，但串行数据库操作与单执行进程限制吞吐和可用性；不能据此宣称极致性能或生产高可用已完成。

后续拆分必须加入持久领取、租约/epoch fencing、资源配额与公平调度，验证失效进程无法继续提交或发布；LLM 使用独立日志或明确可接受的检查点损失。对象存储迁移需保留资产归属与鉴权。每项用真实故障注入和容量结果决定放行。

## 放行边界

本阶段只放行本地开发与契约模拟联调。生产收费还依赖真实网关密钥/模型测试、账户安全补全、账务/支付/退款、内容审核、监控与运营控制面、部署和灾备验收。所有差距继续公开记录在[路线](../roadmap.md)。

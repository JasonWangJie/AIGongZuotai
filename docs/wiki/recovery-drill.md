# 本机工作台恢复演练

V18-A 使用独立的回环服务验证一次完整恢复。准备 Windows PostgreSQL 16 的服务端和客户端工具、该发行包的 basic_archive、Node、Go 与 Python，并提供与脚本校验值一致的 SeaweedFS 4.53 可执行文件。已有项目数据库和对象存储可保持原配置。临时目录应有可用空间，PostgreSQL 私有暂存父路径使用本机 ASCII 路径。

```powershell
node scripts/recovery/workbench-drill.mjs --weed $weedExecutable
```

该命令生成独立账户、库、端口、对象桶、私有目录及临时密钥。先制作物理基础备份，再通过真实平台登记私有参考图、交付图片并完成一次内部额度结算。命名恢复点后会提交第二版草稿，用于证明恢复精确停在原点。

恢复使用独立的数据库基础备份与 WAL、对象服务冷备，以及复制校验后的私有目录和交付密钥。确认回放位置和原集群身份后，启动新的平台进程，以原账户核对草稿版本、生成记录、原对象版本、四份私有内容字节和实际预约。匿名私图下载也须被拒绝。命令输出剔除凭据的 JSON，失败时保留本轮受限目录供检查。

平台可读耗时从开始恢复独立备份计到重新认证并读回私有资产。目标点后故意提交的草稿用于检查 WAL 边界，不能据此推断异地复制的丢失窗口。真实多可用区与线上目标另行验收。[集成台账](../changes/2026-11-22-133-recovery-platform-integration.md)

## 已复验的恢复点

第二次演练把源数据库、原 WAL 归档、工作台私有目录与对象数据目录均移离。使用 PostgreSQL 16.14 命名恢复点后，原账户可以读取第 1 版草稿、私有参考图与交付图片及两份缩略图；第 2 版草稿没有进入恢复库。内部账本保留一笔 0.2 CREDIT 结算。两次从开始恢复到认证读回分别用时 21.016 和 23.910 秒。独立对象冷备专项在同键上按两个原 VersionId 读取并核对 SHA-256。[第二次脱敏报告](assets/recovery-drill-2026-11-22.json) · [对象版本专项](../changes/2026-11-22-132-object-store-cold-backup.md)

## 本机单写者换版演练

将同一迁移格式的两份独立构建分别作为 baseline、candidate；它们各有 Go 二进制、前端文件和校验清单。以下命令使用已经构建好的两个本地目录，在新建的回环 PostgreSQL 上演练，不使用已有业务库。

```powershell
node scripts/release/workbench-release-drill.mjs --previous $baselineDir --candidate $candidateDir
```

统一入口先封流。旧进程正常退出、数据库写锁与两个私有目录锁均可获得后，才启动下一制品。候选探针包括就绪、制品身份、原私图和原保存回执。失败候选保留在仅指定账户可读的检查状态，继续封流后退回原制品。真实生产拓扑和跨区域容灾另行验收。[联合记录](../changes/2026-11-22-142-release-handoff-integration.md)

# 真实异步图片与视频网关

本轮依据用户提供的[公开接口文档](https://api.aiimg.lol/async-image-api-docs)，实现图片生成与文生视频适配器。当前已经通过本地 `httptest` 协议和故障测试，**没有发送真实收费生成请求**；实际模型是否开通、可用参数、生成质量、供应配额和真实结果交付仍需在用户显式配置后联调。它不是对公众生产上线的承诺。

## 文档取证与协议范围

2026-11-13 只读访问公开页面，页面为 SPA，正文来自其公开路由资源 `/static/js/async/6168.9dd1da9042.js`。V06 再次下载此公开资源核验，SHA256 与[fixtures 来源记录](../../internal/studio/testdata/media/source.json)一致。正文显示更新日期为 2026-11-12，标题和内容同时包含图片与视频。没有使用登录 Cookie、历史账号或 API Key，协议样例不是实际模型调用录制。

| 操作 | 已核验协议 | 本轮接入 |
| --- | --- | --- |
| 文生图 | `POST /v1/images/generations_async`，JSON | 已实现；服务端模型、prompt、n、aspect_ratio、可选 size/resolution |
| 文生视频 | `POST /v1/videos/generations_async`，JSON | 已实现；服务端模型、prompt、aspect_ratio、seconds、可选 size/resolution，不传图片 n |
| 任务查询 | `GET /v1/media/tasks_async/{task_id}` | 已实现；必须使用原提交的 API Key |
| 图片编辑 | `POST /v1/images/edits_async`，JSON 或 multipart，至少一张参考图 | V07 适配器使用已授权私有参考图构建不可变 multipart 文件；上传/权限与前端按 V07 整体验收 |
| 视频编辑与延长 | `/v1/videos/edits_async`、`/v1/videos/extensions_async` | 文档有定义；素材与模型能力不同，当前不开放 |
| 取消、按客户端请求 ID 查回 | 文档未给公开接口 | 不猜测路径；真实媒体取消明确不支持 |

提交仅将 HTTP 202 和有效 `task_id` 识别为受理成功。`query_url` 可以为相对或绝对地址；当前使用文档规定的同源统一查询路径和返回任务号，避免把 Bearer Key 发送到服务端返回的任意域名。HTTP 查询成功与生成成功是两件事。

## 配置与能力开关

实际运行入口和环境加载规则见[开发说明](development.md)。V06 的 `PROVIDER_MODE=live` 至少需要一个有效网关，可独立配置聊天或媒体；未配置某类网关时，该类目录模型不开放新生成。真实媒体使用下列服务端变量；客户端不会获得这些变量或供应凭据。

| 变量 | 含义 |
| --- | --- |
| `ASYNC_IMAGE_BASE_URL` | 媒体服务根，例如 `https://api.aiimg.lol`；**不带 `/v1`**，与 LLM 的 API 根配置不同 |
| `ASYNC_IMAGE_API_KEY` | 原提交和后续查询使用的服务端 Key；不能放入 `VITE_*`、源码或日志 |
| `ASYNC_IMAGE_CREDENTIAL_ID` | 运维分配的稳定凭据身份标签，不是 Key 本身 |
| `MODEL_CATALOG_FILE` | 可选的服务端 JSON 模型目录，启动时加载；同一媒体网关可以绑定多个公开模型 ID 与私有 upstream_model，配置见[示例](../../config/models.example.json) |
| `ASYNC_IMAGE_MODEL` | 未指定目录文件时，默认图片目录的上游模型；为空则默认图片项禁用。自定义目录改用其私有绑定 |
| `ASYNC_VIDEO_MODEL` | 未指定目录文件时，默认视频目录的上游模型；为空则默认视频项禁用。自定义目录改用其私有绑定 |
| `ASYNC_VIDEO_SECONDS` | 默认 live 目录配置视频模型时必须显式指定 1—600 整数秒；自定义目录用其逐模型预设，不从该变量补时长 |
| `ASYNC_VIDEO_RESOLUTION` | 默认目录的可选视频规格；自定义目录使用预设。实际值必须受模型支持，720p 不是通用能力 |
| `ASSET_DIR` | 私有素材文件目录；不得位于前端静态目录内，也不能直接作为公网目录提供 |
| `ASSET_ALLOWED_HOSTS` | 逗号分隔的外部结果域名白名单，只接受精确域名，不接受 URL、端口或通配符；默认另允许网关本域 |

平台当前图片每任务 1—4 张、视频每任务 1 个结果，目录还可以进一步降低图片数量。文档允许更多图片，但不是本平台的开放范围。前端使用 bootstrap 和 `/api/v1/models` 的逐模型能力与完整规格预设；真实媒体 `cancel_supported=false`。默认目录保留兼容模型与常用比例，这些默认值不是已对真实供应商验证的能力清单，实际接入需按账户开通模型配置目录。

## 多模型与参数快照

目录公开 ID、展示名称、版本、提示词/数量上限和完整的 `parameter_presets`，不公开 `upstream_model`、地址或密钥。一个预设同时固定 `aspect_ratio/size/resolution/seconds` 的组合，不能任意交叉拼接。图片不带 seconds；视频目录要求 1—600 秒，实际模型支持范围可能更窄。文档的 seconds/duration 是模型相关字段，本实现只发送 seconds；图片 resolution 的大小写也按配置原样保存，不把 1K/2K/4K/AUTO 或个别模型的 0.5K 当作所有模型共同支持项。

平台受理时先验证模型版本和预设，再调用无网络的 `PrepareModel(input, upstreamModel)`，将已经确定的模型和参数一次性编码。此方法不读取默认图片/视频模型、默认时长或分辨率。适配器能够省略可选的 0 秒字段，但平台视频目录当前总是给出明确时长；没有借助该省略行为绕过目录约束。旧 `Prepare` 仅保留默认模型兼容入口，正常新任务使用受理时的显式快照。

同一个 LLM 网关的 `StreamModel` 请求共用一个 HTTP client/Transport，模型在每次请求的局部正文中指定；不会临时改写共享默认模型。同一个媒体网关的多模型提交和查询也共用其连接池。结果下载继续使用独立的受 SSRF 约束客户端，不与携带网关凭据的客户端混用。

目录变化通过重启生效。停用或移除模型只限制新生成；新受理任务的历史展示保留当时的模型名称、版本、能力和有效参数。已保存的提交体、已有 handle 查询以及已导入资产下载不依赖当前目录是否还包含该模型。内部 `AllowNoDefaultModel` 允许仅保留网关配置以处理历史任务，不是对浏览器暴露的配置开关。旧任务若没有可验证的提交快照且没有 handle，live 恢复会停在待核实状态，不能按新目录补参数后重新生成。

## 持久提交与不确定状态

文档的图片和视频 JSON 幂等基于**同一个 API Key、提交路径和完全相同的原始字节**，不是“语义相同的 JSON”。空白或字段顺序变化均可能产生冲突；视频 multipart 另有归一化部分摘要规则，当前只实现 JSON 生成路径，不套用 multipart 语义。

受理阶段的 `PrepareModel` 固定请求体、`Idempotency-Key`、提交路径、服务根、凭据身份、媒体类型、数量和正文摘要。PG 模式将 `MediaSubmission` 与任务、平台幂等记录和受理审计同事务保存，再由 worker 调用 `SubmitPrepared`；memory 模式只有进程内记录，不具备重启恢复。重新加载该记录不重新序列化，也不使用新模型配置重建旧请求。数据库不存原始 Key；提交和句柄保存由服务根、凭据标签及 Key 计算的不可逆 `ProviderIdentity`。该身份不含模型名，模型目录变更不影响旧任务；地址或凭据变化先进入核实，避免查错网关。

平台幂等与上游幂等分开：平台记录原始结构化输入的摘要，先查同键重放，再检查当前目录是否启用或版本是否改变；有效参数快照不反过来覆盖原始摘要。已有任务的重放返回原记录，不能把一次目录更新变成第二次生成。旧版任务按原数量/比例默认规则兼容，旧记录没有展示快照时不能用今天的目录伪造历史配置。

原 Key 超时重放在文档中有定义，但保留时长没有说明。本轮恢复策略更保守：提交响应丢失、202 缺少有效任务号、5xx、409 等进入 `SUBMIT_UNKNOWN`；没有自动换 Key 或重新生成。拿到 handle 后只查询原任务。对已有原 task ID 的核实状态，应用提供显式重新核对入口，继续查询同一任务；没有 handle 的受理不明仍需供应商核对，当前没有按请求 ID 自动查回控制台。

| 观察 | 平台处理 |
| --- | --- |
| `stage=queued/generating/saving` | 对应 QUEUED/RUNNING/INGESTING，继续查询 |
| `completed`、`succeeded`、结果非空 | 导入每个结果；全部保存后发布本地资产 |
| 返回产物数少于请求数 | `PARTIAL`，保留实际可用资产，明确数量不足 |
| 查询网络失败、429、5xx | `Retryable`；保留 task ID 并继续查询，不重新提交 |
| 查询 401/403/404、身份不匹配、未知 stage | `RECONCILE_REQUIRED`，保留记录并暂停自动推进 |
| 图片 608 或 `execution_unknown` | 执行结果未知，不能按普通失败自动重生 |
| 图片 609、`storage_failed`、`billing_failed` | 原任务后处理需要恢复，不重新生成来修复存储或账务 |
| `result_expired` 或存储状态 expired | 原生成可能成功，但结果已不可交付；进入核实，不能宣称获得可下载文件 |
| 明确的生成失败 | FAILED，保留安全错误信息，无自动重提 |

202/200 和临时错误中的 `Retry-After` 支持秒数与 HTTP 日期，最短 3 秒，解析失败回到 3 秒；上限为 24 小时。调度器对 live 模式至少间隔 3 秒。当前没有供应商配额自适应公平调度或生产级分布式租约。

## V07 私有参考图与图片编辑

本轮再次核验同一[公开图片与视频文档](https://api.aiimg.lol/async-image-api-docs)，资源 SHA256 与既有来源记录一致。编辑与生成共用模型、提示词、数量和尺寸字段，但编辑必须有至少一张有效参考图；只传 prompt 或 mask 不构成编辑。JSON 的 `image` 字符串/数组与 `image_urls` 数组可用 URL 或完整 Data URI，`images` 可用 image_url 对象；文档没有 refs 字段，也不支持图片 file_id。本机路径、裸 Base64 和 `@file.png` 不是 JSON 文件上传。multipart 可重复使用 image/image[] 文件部分。

平台选择 multipart：前端只提交归属当前项目的有序参考资产 ID，服务端将已经授权且校验过的私有文件写成 image[] 部分，不向供应商传递需要用户 Cookie 的下载地址。首版平台限制为1—4张、单张8 MiB、PNG/JPEG/WebP、单图1600万像素，拒绝GIF/SVG；这些是平台边界，并非文档承诺的供应商通用上限。图片像素与实际解码由上传存储层验证，适配器再核对源文件长度/摘要及允许的 MIME，不能只靠扩展名。

mask 暂不开放。文档明确要求参考图和模型支持，列出 JSON URL/image_url 对象与 multipart 文件形式，但未给统一的透明通道、尺寸匹配等像素语义；不据此猜测蒙版效果。图片参考数量和单张容量同样没有供应商统一数值；视频64 MiB请求上限不能套用于图片。

`PrepareEditModel` 在平台受理前执行本地流式准备，不访问网关。它接收服务端已验证的有序源文件，按固定字段顺序写 model/prompt/n 和可选 aspect_ratio/size/resolution，参考文件名由服务端生成 reference-1.png 等。multipart boundary 只生成一次，并随 Content-Type 和完整正文固定。准备过程中用32 KiB缓冲逐个读取和核对摘要，取消或引用不完整时不发布可用请求文件。

图片 multipart 的上游幂等与图片 JSON 一样要求同路径、同 Key、**完全相同原始字节**；重新编码产生不同 boundary 也会冲突。平台将最长33 MiB的请求正文写入私有不可变文件，MediaSubmission 仅保存 BodyFileID、BodySize、ContentType、BodySHA256 与既有网关身份/Key标识，避免把参考图再次转为 Base64 写入 JSONB。原小型 JSON Body 记录保持兼容，其128 KiB上限不因编辑而扩大。实际文件原子发布与数据库受理事务不是同一资源事务；并发准备后未被受理事务采用的孤立正文暂保留，计入私有存储2 GiB硬上限，不冒险删除可能被引用的文件，安全回收留给V08。上传/正文归属与全局准备槽由存储和核心模块负责，不能把helper本身描述为完整权限或垃圾回收系统。存储忙和容量耗尽保留安全分类，由core分别返回429/507，不伪称素材格式错误。

`SubmitPrepared` 打开原文件，在同一文件句柄上检查普通文件、长度、boundary前缀及完整SHA256，然后 seek 到起点流式发送，固定 ContentLength、禁用 GetBody 自动重放。文件缺失、同长度篡改、摘要不符或请求类型/路径不匹配均在网络请求前拒绝并要求核实，不重建正文。私有存储必须保证发布后不可变，不能让外部进程原地改写文件。生成API密钥只加入实际HTTP请求头，不进入正文文件或数据库元数据。

大型编辑提交使用预建的2分钟HTTP client，与原媒体client共用同一Transport/连接池；不在运行时修改共享超时。原JSON提交和查询仍是30秒client，等待响应头仍最多20秒。编辑还受worker的2分钟总context限制，较早截止者生效；这不是慢链路上传完成时限的保证。

编辑受理仍是202和原task_id，后续使用统一查询端点与同一APIKey；仍遵守受理不明停核实、查询临时故障只重查、导入结果后授权下载的既有规则。停用或移除编辑模型不会改变已持久的编辑正文，也不阻断已知handle的原任务查询。适配器只验证本地合成协议，尚未实测真实编辑质量或供应商实际素材限制。

## 结果导入与授权下载

文档允许结果来自网关、外部图床或原上游，且可能跳转或携带签名参数；具体 TTL 未给出。网关文件地址是可分享地址，过期后可能 404，重新查询不能保证恢复。平台不能把这些外部 URL 当成永久资产。

服务端逐项使用完整结果 URL，保留查询参数，最多跟随 3 次跳转。下载使用独立 HTTP 客户端，不附加网关 Key、用户 Cookie 或 Referer。每次新连接在 DNS 解析后检查全部 IP，再拨号到已验证 IP；拒绝私网、回环、链路本地、特殊地址和未配置域名。外部结果要求 HTTPS，重定向目标重新校验；不会依赖环境代理。测试中的 HTTP 回环例外只在包内 fixture 配置开启，没有可供运行环境启用的变量。

导入最多 4 路并发，流式写私有临时文件：图片最大 32 MiB、视频最大 256 MiB；单次下载最多 2 分钟。PNG/JPEG/WebP 完整解码校验；GIF 先检查帧和像素预算再解码，最多 16 帧、累计 3200 万像素。单图尺寸最大 16384×16384 且总像素最多 3200 万。SVG 不直接接受或展示，避免主动内容；当前没有 SVG 清洗与栅格化流程。

**视频仅检查 MP4 容器头的 `ftyp` 标识和大小，不等同于完整可播放性、编解码安全、恶意内容扫描或安全转码。** 生产媒体流水线仍需加入隔离的探测、审核与转码。

文件和元数据分别原子发布，保存内容摘要和实际 MIME。`os.OpenRoot` 限制路径及符号链接越界，稳定资产 ID 让重复查询复用已导入结果；对象落盘与数据库写入之间不构成跨资源事务，恢复通过重查与幂等导入收敛。当前为本机文件系统，不是跨节点对象存储，仍需磁盘容量、备份和孤立文件回收策略。

浏览器仅收到 `/api/v1/assets/{asset_id}`。Go HTTP 层先验证用户对任务/项目的归属，再调用独立的 `OpenLocalAssetReader`；reader 不需要网关地址、Key 或当前生成 Provider，因此停用网关或切回 demo 后，已保存资产仍可按原归属下载。它只打开已有私有目录，不创建目录、不发网络请求、明确拒绝 Import；helper 本身不承担账户授权。下载响应使用实际 Content-Type、`nosniff`、私有禁缓存与受限 CSP，支持 GET/HEAD 和 Range。不能另起静态文件服务暴露 `ASSET_DIR`。

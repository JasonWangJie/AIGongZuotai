# 工作区生成权限与复核界面

当前实现为 v0.15 的 V14-C1 前端链路，遵循 [C1 契约](../planning/v14c1-contract.md)。本页区分已实现交互与集成验收：前端 297 项测试、类型检查及构建通过；真实 PG、桌面/手机浏览器完整链由集成人在 [062 台账](../changes/2026-11-14-062-generation-controls-integration.md)记录，本文不提前宣称其通过。

## 用户路径

PG 且启用登录的账户可从“生成权限与复核”进入工作区状态页。当前工作区由登录会话决定，接口不接受浏览器指定别人的工作区，也不携带创作项目头。OPEN 表示可继续发起新请求，仍需满足模型、额度和内容审核规则；RESTRICTED 展示当前限制编号和公开说明。

限制仅阻断新生成和新报价。创作输入保留；原受理不明请求的原键核对、原任务查询、取消、历史与已批准作品访问沿用原规则。多轮对话的普通新回复、编辑分支和继续同样受新请求门禁，但原请求重试不受这个前端开关阻断。解除只重新开放手动提交入口，不自动取报价或发起生成。

用户可对当前限制申请一次复核。原因采用闭集，补充说明可空、最多 1,024 UTF-8 字节；允许换行，拒绝其他控制字符和无效代理码。列表仅显示自身申请元信息，点开详情后展示说明和站内答复。历史申请的“解除”结果不代表后来新一轮限制已解除，始终以当前状态卡为准。

申请受理不明时保留原限制、正文和幂等键。先读取原申请；只有限制编号、原因和说明都与原请求一致，才能清除本页待确认记录。同一次限制下另一标签提交的不同说明不会替代本页未知输入。用户可显式按原键核对，系统不自动重发。每一次实际网络 POST 使用独立 attempt 标记，即便幂等键相同，旧组件的迟到成功或 401 也不能清掉新组件正在核对的请求。

## 运营路径

运营台增加独立“新生成限制与复核”区域。服务端明确授予 `generation_restrict` / `appeal_resolve` 才显示；普通 owner、observer、operator、finance 不因现有身份自动获得这些权限。多角色按同一工作区显式权限合并。创作项目选择不改变运营范围。

- `restrict_future`：限制之后的新请求，公开说明成为当前限制公告。
- `lift_restriction`：解除当前限制，并答复、结束本次限制下全部 OPEN 申请。新解除预演会替换此工作区旧的未执行解除计划。
- `uphold_restriction`：针对选中的当前 OPEN 申请答复并维持限制，其他申请不结束。

表单分开填写内部证据编号和公开说明，内部编号不进入用户视图。预演展示执行前后状态、控制版本、影响的申请数、公开答复和剩余有效期。首次限制的预演由服务端生成新限制 ID，前端验证它与 effect 相同；解除和维持则精确绑定当前限制与申请。预演不自行执行，确认还须勾选影响并输入当前密码。

密码只存当前组件的不可序列化内存容器，发送后立即清空，页面离开或预演改变也清空。它不会进入恢复仓。错误密码不触发自动退出登录。执行确认不明时只保留原计划 ID，只提供 GET 原收据入口；404 不能证明未执行，不自动再次 POST。旧网络响应只能清自己的 attempt，无法覆盖后来处置。预演确认不明可只读核对当前状态后手动重新预演。

本界面不提供候选正文、原提示词、上游地址或身份材料浏览，不放行旧审核决定，不退款，不自动重新生成。用户说明和公开答复只作为文字呈现，不解释为 HTML。

## 刷新、恢复与性能

当前工作区权限在进入创作页/权限页、回到可见页面、恢复焦点及显式刷新时读取；可见时约每 15 秒有界轮询，并遵守冷却。用户申请列表与运营列表也仅可见时读取；列表单页 20、最多加载 200 项，无限滚动和任意范围扫描未开放。运营有未提交说明、预演或待确认处置时暂停后台读取，手动刷新保留说明并使旧预演失效。没有把项目 Outbox 当工作区实时通知，也不外发邮件。

恢复仓位于 App 层，按账户与工作区隔离。申请正文、原键、运营未提交说明及只读核对编号仅在当前 App 生命周期中保留，每类最多 64 个工作区，不静默淘汰未解决请求。离开、切换工作区或退出时有对应提醒，关闭/刷新浏览器仍会丢失本页内存，不能称作离线持久草稿。

用户权限页与运营页改为按需加载。加载失败可重试页面模块，不强制刷新整个 App；恢复仓不随模块卸载。最终构建首页 JS 为 **494.93 kB（gzip 156.88 kB）**，用户页 10.80 kB，运营页 42.06 kB，主 CSS 114.97 kB，运营 CSS 9.68 kB；当前构建没有超过 500 kB 的 chunk 警告。这是构建产物大小，不是浏览器性能或生产吞吐成绩。

## 验证与边界

前端 `test`：28 文件、297 项通过；`typecheck` 和 `build` 通过。新增测试覆盖显式权限、状态/版本/限制绑定、UTF-8 上限、同账户原键恢复和跨账户隔离、未知执行只读入口、密码容器、404 不判未受理、迟到 HTTP 响应、双标签不同正文、真实 App 受限时不构造报价但保留原键按钮，以及解除后不自动发请求。SSR 验证公开文本转义与敏感入口隐藏；该证据不替代真实浏览器点击验收。

独立审阅补齐了首次限制预演新 ID、同 episode 不同申请正文及同键重试不同网络 attempt 三个边界，具体见 [061 台账](../changes/2026-11-14-061-generation-controls-workbench.md)。完整 PG/浏览器验收及后续风险以 062 为准。真实审核商、账户/内容申诉 C2、自动额度风控 C3、跨设备草稿恢复和生产容量仍不在本批已验收范围。

### 初始读取生命周期补强

根浏览器验收发现开发 StrictMode 下首次进入运营复核区有时需等待下一轮读取。共享 boolean 读锁在 effect 清理时没有释放身份，新的 setup 被旧请求挡住；用户申请列表存在同类问题。现改用独立读取 attempt 和 AbortController：清理、筛选改变、发起变更时中止并移除旧 attempt，新 setup 立即读取；旧响应与旧 finally 都只能匹配原 attempt，不能清新锁或覆盖新 scope。用户/运营列表及收据查询向 API 传递 AbortSignal。

新增 `generationLifecycle.test.tsx` 用真实 ReactDOM `createRoot`、`act` 和 `StrictMode` 在 jsdom 中挂载产品组件。修复前 6 项中 4 项失败，修复后全部通过；覆盖首次立即可读、筛选切换后旧 finally、新用户/工作区晚回包，以及重新登录后同键 retry 遭遇旧 POST 成功/401。jsdom **29.1.1** 仅为锁定的开发依赖；其 registry engines 为 `^20.19.0 || ^22.13.0 || >=24.0.0`，与本机 Node 22.18.0 兼容。更高版本 31.0.1 要求 Node 22.22.2 起，未采用。安装完整审计和最终 `npm audit --omit=dev` 均报告 0 漏洞；不将 jsdom 加入生产 bundle。

生命周期依据：[React StrictMode 官方说明](https://react.dev/reference/react/StrictMode)、[Vitest 环境说明](https://vitest.dev/guide/environment.html)、[jsdom 主仓库](https://github.com/jsdom/jsdom)。DOM 模拟回归仍不等同于真实浏览器验收；根继续记录 062。

# 分页恢复与启动背压

2026-11-21 已通过本地完整启动验收，见[089](../changes/2026-11-21-089-recovery-acceptance.md)。对应[A4契约](../planning/v16a4-contract.md)和[086台账](../changes/2026-11-15-086-paged-recovery.md)，复用[085私有阶段批读](recovery-private-phases.md)。

启动先检查控制写锁、私有目录归属与必要密钥，然后用短事务切换媒体 generation，撤销旧执行授权。旧 lease 按稳定 ID 每 128 项独立事务清理。随后分页恢复 Run 与 Task，全部成功后才开放工作线程与 HTTP。A4.2 起，项目在请求时按工作区读取。

每页最多128项，基础JSON与私有元数据累计16 MiB。SQL窗口按ID计算基础正文前缀体积，不合本页的正文返回NULL，下一页从最后实际完成ID继续；单条超限明确失败，不跳过资源。私有阶段预算不足只缩小只读页，不触发数据库熔断或重发外部请求。

每个需要恢复的资源继续使用原事务钩子，在各自5秒内原子保存业务、账务、审核、调度与通知。只有确认提交才安装缓存和推进游标。页间消费Outbox；若保存遇到EVENT_BACKLOG_FULL，先实际回滚、退出store.mu，再排空队列并读取未提交记录，避免重复递增版本。若排空时没有实际事件可投影，报错退出并保留业务记录。提交确认不明立即退出，由下次启动读持久事实，不盲目复用修改后的对象。

未完成LLM仍转INTERRUPTED，未审内容隔离；无handle的SUBMITTING仍转SUBMIT_UNKNOWN。原handle、交付清单、收据、READY/STARTED、原模型及冷却截止时间都保持原规则。恢复不授权重POST、下载替换收据或重审已STARTED候选。

私有 recoveryStats 记录实际页数、最大编码页与缓存条数，供本地验证。A4.1 验收时仍保留全缓存。A4.2 的执行保留、冷读和完整启动结果见本页末节。启动继续检查私有交付所需的密钥。

## PG 媒体任务在缓存已满时的受理

工作区与模型的在途额度从数据库核验。任务、幂等和事件成功提交后即已受理；缓存达到上限时，新任务仍保存在 PG，工作线程从持久调度表领取。冷读、回放和取消按原工作区与项目权限查询；没有空槽时本次读取不会扩大缓存。图片编辑在锁外准备文件后重新检查权限、原键与真实容量。memory 的记录上限继续生效。

双工作区完整启动实验及原 503 见 [090](../changes/2026-11-21-090-pg-media-cache-admission.md)。该次验证覆盖媒体新受理与冷读；091—094 进一步覆盖启动、在途任务、Run、活动订阅与项目查询。

## A4.2 执行占位与启动容量

PG 每类闲置记录受 MaxRecords 限制，排队/在途聊天、实际运行中的媒体领取与仍未退出的订阅可占用额外槽位。资源取消不会让仍在执行的调用提前让位。恢复按页读取完整持久状态，达到缓存上限后继续恢复业务。PG 项目按工作区读取，第 100 个项目的并发创建在事务内核验。单实例 20 万条样本的完整启动、页读耗时与驻留载荷见 [094](../changes/2026-11-21-094-bounded-startup.md)；缓存保留与释放的边界见[架构决策](decisions/0020-bounded-pg-caches.md)。

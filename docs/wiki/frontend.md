## V10 多轮对话与上下文

新会话先明确创建，再发送第一条或下一轮。桌面使用会话栏与消息时间线，窄屏会话列表可展开；选择分支只读取对应祖先路径，不把兄弟消息拼入上下文。编辑历史用户消息发送为兄弟分支，原消息保留；未启用审核的运行在停止／失败／中断后保留部分输出，“从此继续”需再次确认新模型请求。恢复连接只补读原 Run，不自动继续生成。用户向上浏览时不强制滚动，新内容提供回到末尾入口。

创建与每轮运行分别保存原操作键。受理未知保持模型版本、会话版本、父消息、正文和操作；401后同用户同项目可恢复，模型目录改变、切分支和限额反馈不改原请求。CAS冲突保留输入，读取当前版本后由用户明确确认。切换分支时已有输入仍绑定原父消息，需返回原路径或明确清空后回复当前路径；迟到回包不抢当前选择或覆盖后来编辑。

当前对话输入及未知操作只保存在页面内存，刷新／关闭前应发送或复制；关闭提示受浏览器规则限制。localStorage仅保存按用户／项目隔离的会话／叶子ID作为显示偏好，恢复后仍由服务端验证权限，不保存正文、密码、token或生成键。真实存储由bootstrap声明；memory服务重启会清空服务端历史。

每页会话20条、分支20条、消息最多20条且受服务端1MiB预算限制。会话详情与必要分支在持久审计通知或运行终态后合并刷新，逐检查点只更新对应assistant，不全量刷新树。原V09有界补读、40ms流批次及作用域失效继续保留；路径仍是有限DOM分页，未实现虚拟列表。

上下文卡只显示服务端受理快照中的纳入／省略消息数、输入预算估算、预留输出和模型配置窗口；`utf8_bytes_v1`不是精确tokenizer、实际账单或供应商窗口探测。缺少历史Provider信息时标记“来源待核对”，不使用当前模式猜测过去结果。完整实现与实际验证见[037台账](../changes/2026-11-13-037-conversations-workbench.md)。

## V11 账户安全与自助恢复

账户菜单／侧栏进入“账户安全”，查看邮箱验证状态、最多10个未过期登录会话、修改密码及脱敏安全事件。会话只展示真实创建／到期时间和当前标记，不推测设备或位置。改密／重置使全部会话及旧验证／找回链接失效；撤销当前／全部会话前有明确确认与未保存内容提示，处理期间冻结云草稿和新参考图提交，已有页面内恢复仓保留。新请求失效与既有SSE下次身份检查退出分别说明。

登录页提供找回入口。邮件能力来自匿名／已登录session的account_security；未配置时申请按钮禁用，不显示“已发送”。申请202仅说明符合条件时已安排处理，不透露邮箱存在与否，也不保证送达。真实渠道本轮仍待配置与授权验收，fixture不能替代真实渠道证据。

验证／重置fragment在main的一次性启动路径解析并立即清URL，StrictMode重复渲染不会丢失或自动消费；后续hashchange也及时清理。令牌留在不可普通序列化的私有一次性容器中，只在用户确认时取出并清空，不进入URL query、HTML隐藏字段、localStorage、日志或任何草稿／原请求恢复仓。验证链接不切换当前账户；重置双输新密码，服务端仅收到一份。

密码10—72 UTF-8字节，前端拒绝NUL／非法代理项并核对确认输入。敏感表单提交开始或离开时清空，任何网络／提交不明不自动重发、也不提供“原请求重试”。仅保留脱敏错误和可复制请求编号，引导核对账户、重新登录或申请新链接。旧用户／旧代次响应不能影响新登录账户。旧密码错误的401保留安全页并仅核对真实会话，不伪称退出；账户限流使用单独900秒上限，创作请求仍为300秒。不完整的敏感200响应视作未知结果。此前创作请求也修正旧401迟到删除原键、旧同键finally释放新inflight锁的问题。

实现与验证见[041台账](../changes/2026-11-13-041-account-security-workbench.md)。本地前端173项／21文件、TypeScript与生产构建通过；JS433.49kB（gzip136.22kB）、CSS98.68kB（gzip19.80kB）。静态组件测试不是浏览器验收，实际PG／HTTPfixture／CUA由集成人记录，真实邮件仍未验收。

## 运行与构建

建议使用仓库根 README 的统一启动命令。同时也可分别启动 Go 服务，再运行：

```powershell
npm --prefix apps/workbench ci
npm --prefix apps/workbench run dev
```

Vite 固定监听 `127.0.0.1:5173`，启用 `strictPort`，不会静默漂移端口。`/api`、`/healthz`、`/demo-assets` 代理到 `http://127.0.0.1:8080`。构建后由 Go 服务提供静态文件时，浏览器继续使用同源相对 URL。

```powershell
npm --prefix apps/workbench run typecheck
npm --prefix apps/workbench test
npm --prefix apps/workbench run build
npm --prefix apps/workbench audit
```

安装生成的 `package-lock.json` 随源代码保留，`node_modules/`、`dist/` 与 TypeScript 构建缓存不提交。前端子项目独立安装，根目录不使用 npm workspaces。

## API 与恢复行为

### 账户、会话与项目

初始化先读取 `GET /api/v1/auth/session`。`auth_enabled=false` 时进入 demo；启用认证而未登录时显示独立 AuthGate，注册调用 `POST /auth/register`，登录调用 `POST /auth/login`。密码只在表单和请求的瞬时内存中使用，不写入 localStorage、sessionStorage、URL 或日志；认证依赖服务端 HttpOnly Cookie，客户端 fetch 显式使用 `credentials: same-origin`。表单在请求结束后清空密码。

注册校验邮箱、名称及 bcrypt 适用的 10—72 UTF-8 字节密码边界。账户菜单显示当前身份并通过真实 `POST /auth/logout` 退出。API 401 或 SSE 中断后的会话检查发现过期时，立即关闭所有订阅、清除可见项目历史，再回到登录界面。未确认的生成操作与云端草稿保留在本页内存，按身份与项目隔离；同一账户重登后可继续使用原请求，不向其他账户显示。网络故障与认证失效分别显示，不能把请求失败视为退出成功。旧版本没有 `/auth/session` 返回 404 时，仅兼容原无鉴权 bootstrap。

侧栏支持 `POST /projects` 创建项目，以及选择已有项目。项目请求显式携带 `X-Project-ID`，SSE URL 使用 `project_id`；不通过可变全局请求头选择项目。切换时同步关闭旧 SSE、清空运行／任务／提示词，递增请求作用域代次。旧 bootstrap、列表、快照、增量、取消或提交回包不能写进新项目，即使 A→B→A 也会拒绝旧 A 代次。返回的资源还要匹配当前 `project_id`，用户退出使所有未完成代次失效。

最后选中项目仅作为 UI 偏好保存为 `xingtu-last-project-v1:<user-id>`，匿名 demo 使用独立 `:demo` key。刷新／重新登录时，先从真实 `auth/session` 或登录响应取得该用户的项目列表，再核对偏好项目仍在列表内，才请求对应 bootstrap；过期、伪造、其他账户或存储不可用时使用服务端默认项目。偏好不是登录凭据，也不授予权限。

memory 模式的本地文字草稿按 `xingtu-local-draft-v2:<user-id-or-demo>:<project-id>` 分键，避免界面展示另一账户／项目的草稿。它是设备本地草稿，并非加密保险箱；退出不会自动删除此设备已有草稿。PostgreSQL 模式可以显式读取同一用户、同一项目的旧 v2 本地草稿，确认载入编辑区后再手动保存，不会自动覆盖云端。旧 v1 草稿不会自动迁移到任意新用户。

任务与运行历史使用 `?limit=50&offset=N`，读取 `{items,limit,offset,has_more}`；任务／素材页和对话历史显示“已加载”数量，并在有更多记录时提供显式“加载更早记录／对话”。切项目会重置页码与加载锁。新记录插入造成 offset 页面重叠时，按 id 与 seq/version 去重；实时刷新不把已向后加载的页码重置为第一页。此阶段分页不是数据库总数统计，也不是稳定快照游标。

### 持久通知与有界补全（V09）

工作区 SSE 继续使用 `/api/v1/workspaces/{workspace}/events?project_id=...`。PostgreSQL 新增 `stream.reset` 和 `resource.changed`；浏览器原生 EventSource 管理 opaque Last-Event-ID，客户端不解码、持久化或自行拼接通知游标，不把 run 数字 seq 传给工作区流，也不把服务端消费 checkpoint 当作浏览器已收确认。断线重连由原 EventSource 完成，通知不会强制重建连接。memory 模式仍是原有内存广播，不宣称跨重启持久通知。

`onopen` 与首次／过期 `stream.reset` 在 250ms 窗口合并，重新读取近期任务／运行首页，并分批核对已经加载的非终态任务、非终态运行和当前对话；只在原列表上按 version／seq 合并。当前可见的活动、资产、参考素材与干净云草稿收到各自失效信号，合并读取中途到来的刷新意图，不因一次通知重挂编辑器。恢复期间显示简短“正在补齐项目状态”，普通检查点同步不持续闪提示。

任务 `resource.changed` 自身就登记按 ID 的 GET 补全，不能依赖同 cursor 后续兼容 `task.updated` 必达；若快照帧先覆盖需要的版本／状态，可取消尚未执行的冗余读取。两帧之间断线后，已经登记的补全仍能执行。`run.updated` 只读取对应 run snapshot，已有实时文本达到通知版本时跳过；同 seq 的终态变化仍需合并。快照低于通知版本不能被当作已补齐，按只读失败规则重核对。

`audit.created` 只使活动列表失效；draft.saved 另外通知草稿，reference.uploaded／asset.updated／asset.trashed／asset.restored 另外通知素材与参考图，任务终态通知资产库。对话每秒检查点不会触发全量任务／素材／草稿刷新。事件 ID 最多保留 512 条去重、普通事件待补全最多 256、失败原批额外最多 8 项，单批最多 8 资源且并发最多 4、批次启动间隔至少 1.5 秒；队列溢出退回近期历史及当前已加载非终态核对。已加载资源通过独立惰性扫描推进，不再 force 填回 256 项事件队列；每批普通事件最多先取 4 项，其余让扫描补至 8 项，同一次本地读取代次的重试不回到扫描头，后续重置最多合并一轮扫描。读取代次不是 SSE cursor 或消费 checkpoint。页面隐藏停止新增补读，保留有界合并意图，返回后继续，不重开 EventSource。

只读失败按 3／6 秒退避，连续三批失败暂停并提供“恢复同步”；服务端 Retry-After 最多等待五分钟，重连或手动恢复不能绕过当前冷却。切账户／项目／代次关闭原流、停止调度并中止补读，旧响应不会写入新作用域。主动中止不作为新作用域的失败显示。

重置与通知仅执行 GET，不重发生成、上传、草稿保存或资产写入，不清原未知 body/key。草稿 observed 只应用于干净且非冲突状态；资产 observed 保持既有同等保护，编辑期间可以核对列表但不能替换编辑内容或版本基准。云草稿不可见或 dirty／pending 时延后刷新；未确认操作继续由各自原键重试流程处理。通知只包含资源标识、版本／状态和闭集动作，客户端不显示内部 cursor／checkpoint。

客户端测试证据见 [033 台账](../changes/2026-11-13-033-durable-events-client.md)，协议见 [V09 契约](../planning/v09-contract.md)。这些行为不表示浏览器 exactly-once、持久 ACK、跨标签页共享连接或分布式服务已经完成。

### 独立资产库（V08）

作品素材页从“已加载任务的 artifacts 汇总”升级为 `GET /api/v1/library` 独立目录，不依赖浏览器已加载的任务页数。支持名称／标签搜索、精确标签、上传参考／生成结果来源、image／video／poster 类型与正常／回收站状态。每页 24 项，使用绑定当前过滤条件的 opaque keyset cursor；改变过滤条件会清旧页、使旧请求代次失效，项目切换会中止旧读取。列表按资产 ID 与 revision 合并，旧重放不能回退已知版本。恢复操作仅重新插入当前过滤结果实际已加载过的资产，并按完整创建时间／ID 倒序重排；尾游标之外的资产等待正常翻页，不强行插入或改游标。显示“已加载”而非伪造总量。

卡片只懒加载服务端 thumbnail_url；无缩略图时显示占位，不取大原图替代。视频只有在详情点击“播放视频”后才设置 src，列表不预加载视频。生成素材保留逐记录 DEMO 标志；上传参考不标为真实模型结果。详情内的打开与下载仅使用同源 `/api/v1/library/{id}/content?project_id=...`，不暴露磁盘路径、bucket/object_key 或签名 URL。回收条目两个 URL 为 null，界面不提供历史文件地址来绕过回收状态。已回收详情禁用名称／标签编辑、保存和旧元数据载入，历史仍可查看；须先恢复素材再编辑。提交入口及状态机同样执行该限制。

详情用原生 modal dialog 管理焦点，关闭后返回触发卡片；卡片已因回收移走时返回搜索框。名称支持 1–120 Unicode 字符、最多 10 个各 32 字符的标签，标签按逗号／换行拆分、trim、小写和去重，控制字符拒绝。PATCH 使用完整 name/tags、expected_revision 和新 Idempotency-Key；原 File 与二进制内容不可编辑。版本历史每页 20 项，查看旧 name/tags/state 后可载入名称和标签，再手动以当前 revision 另存，绝不把旧状态自动恢复或声称为二进制内容版本。

CAS 409 保留编辑，读取服务端当前版本后明确选择“采用服务器版本”或“保留我的修改”，后者仅更新基准、仍需手动保存。回收／恢复 CAS 冲突必须先采用当前版本，再手动确认原动作。网络、503 和畸形回包等未知结果保留原 kind/body/key，原来未知的操作再次遇到 401／429 也不抹去原身份；显式“原操作重试”先经过有界冷却，不自动发新键。读取当前快照只合并干净编辑器，不能覆盖编辑、冲突或原未知操作。

App 内存恢复仓按 user/project/asset 隔离保留 dirty 或 pending 状态。关闭详情、切换页面、项目及会话过期后，同一账户项目可从“本页未保存／待确认修改”入口恢复；刷新／关闭提示只保护本页，不承诺跨关闭持久化。没有 token、名称、标签或待确认正文写入浏览器持久存储。未保存修改可显式放弃；未知操作不能靠该按钮清掉原键。回收和恢复分别 POST `{expected_revision}`，软回收需要二次明确点击，不永久删除内容或释放文件配额。

V07 参考选择器在完整第一页明确表示无更多记录时核对旧 ready 素材；已回收／不可用项从本次选择移出并显示原因。核对只基于请求开始时已知 ready ID，不误删请求期间刚完成的上传，所有 unknown File/key 和既有任务 pending body 保持原样。

元数据修改、回收和恢复活动映射为中文动作，不展示名称、标签或内容。界面没有 S3 控制台、迁移／孤立文件清理按钮，不把后端对象存储测试当成前端完成的能力。契约见 [V08 接口](../planning/v08-contract.md)，模块验证见 [028 台账](../changes/2026-11-13-028-library-workbench.md)；联合浏览器及 HTTP 验收由集成人记录。

### 私有参考图与图片编辑（V07）

图像工作室新增“文字生成／参考图编辑”切换。编辑模式只选择明确声明 `image_edit_supported` 的图片模型，遵循 `max_reference_images`；旧目录未声明时默认关闭。上传区域支持多选及拖入，按选择顺序占位，完成顺序不会改变参考顺序；前后移动按钮支持键盘。模型变更降低参考数量时保留已有文件并要求手动移出多余选择，不静默删除素材。

`GET/POST /api/v1/references` 带显式 `X-Project-ID`；POST 仅提交 multipart `file` 字段和 `Idempotency-Key`，原文件名与字节保持不变。上传使用 XHR 的真实传输进度；100% 仅代表传输完成，等待服务端校验后才进入可用状态。浏览器最多并发 2 个上传，当前页面所有身份／项目的待处理原文件缓冲上限 64 MiB。前端预校验空文件、MIME／扩展名与 8 MiB 单文件限制，真实格式、像素和尺寸由服务端完整解码校验；PNG/JPEG/WebP、每张 16M 像素、边长 8192、每工作区 128 MiB／100 张为当前平台限制。前端不解码大原图、不使用 data URL，只在成功后显示服务端生成的至多 512px 私有缩略图。

`ReferenceAsset` 包含 id、project_id、name、content_type、byte_size、width、height、created_at、url、thumbnail_url。私有 URL 带素材项目 query，继续由同源 Cookie 及服务端归属检查鉴权；外部 URL 与任意 API 路径不能进入预览。列表按 100 条 offset 分页，按 ID 去重；与上传 acknowledgement 竞态出现同一资产时合并并保留选择顺序。文件名仅通过 React 普通文本显示。

编辑任务沿用 POST tasks，增加顶层 `operation: edit`，输入为提示词及有序 `reference_asset_ids`，同时提交 model_version 和完整规格组合；不会发送供应商地址、客户端本地路径或二进制到任务 API。文字生成不附带参考 IDs，视频不能进入图片编辑。已受理任务展示编辑类型和参考图数量快照。上传动作在项目活动中显示“上传参考图片”，不展示文件名、哈希或路径。

网络中断、超时、停止传输与无法识别的回包均保守标为保存待确认。原 File、名称、项目与幂等键保存在本页内存；手动“原文件重试”保持它们不变，原来未知的上传即使重试收到 429/401 也不丢弃原键。服务端结构化 429 显示有界冷却和可复制请求编号，客户端不自动重发未知请求。明确“放弃本页重试”才释放原文件与当前选择，不删除服务器已存素材，建议先刷新项目素材核对。上传文件从本次选择移出与服务器删除是不同操作，本批没有删除 API。

切项目／账户先中止旧传输，保留原身份和项目的待确认状态，列表旧代次和异项目回包不能进入当前界面；同账户同项目返回后可显式核对。未完成上传触发项目离开提示和刷新／关闭提示；这些 File/key 不写入 localStorage、sessionStorage 或 IndexedDB，关闭或刷新后重试身份会丢失。待确认的生成任务仍使用既有 PendingRequests 独立保留原 body/key，参考选择或目录更新不会改写它。

本批没有 mask、画笔、裁剪、生成结果直接转为参考图、图片编辑 DAG 或原图离线持久化。演示 Provider 接受实际平台上传及任务 API，但输出仍为演示素材。真实网关图片编辑效果和 multipart 全链路验收未执行，不能据本地测试将 V07 整批标为完成。证据见 [024 台账](../changes/2026-11-13-024-reference-workbench.md)。

### 创作请求与事件

- 首次连接读取 `/api/v1/bootstrap`、`/tasks`、`/runs`。模型、演示模式与存储状态来自服务端，未连接时禁止提交。
- 图像／视频通过 `POST /api/v1/tasks` 提交。任务状态通过一个工作区 EventSource 订阅接收 `task.updated`；首次及重连读取任务列表兜底，不按每张卡片轮询 New API。
- 对话通过 `POST /api/v1/runs` 创建。选中运行先请求 `/runs/{id}/snapshot`，再以 `?after=seq` 订阅事件。浏览器原生 EventSource 处理标准 SSE 帧和 `Last-Event-ID`。
- `message.delta` 先累积到局部运行状态，再以 40ms 批次更新 React。检测 seq 缺口时停止当前订阅、读取快照并重新订阅；重放、重复和过期事件不重复追加文本。收到终态事件关闭连接，并补读最终快照以获取完整错误信息。
- 任务按 `Task.version` 合并，忽略重复或旧版本；终态不回退为运行态。运行输出按 seq 合并。切换创作模式不取消后端任务；切换历史对话仅切换订阅。
- 每次创建操作产生一个 `Idempotency-Key`，提交过程使用同步锁防止连续点击。超时、网络错误或 5xx 被标记为受理不明，保留同一个请求体与键；只允许用户显式“原请求重试”，不会自动重发生成。刷新历史不会清掉该不明状态。
- 生成 POST 发出前就在本页内存登记身份／项目及完整原操作，覆盖请求尚在途中但会话已过期的窗口；成功只清理匹配的操作键。首次明确 ADMISSION 限流未受理可保留输入并重新调整；已经受理不明的操作再次 429／401 仍保留原键，不能用后来一次拒绝推断最初请求没有受理。
- 普通 JSON 请求设置 15 秒超时；SSE 不使用这个短超时。错误界面可以恢复连接并刷新历史；浏览器断线不等同于取消生成。
- 新目录的生成开关与参数来自所选 `Model.enabled/capabilities`；旧 `capabilities.chat/image/video` 仅兼容旧服务。历史任务的取消不受当前模型目录启用状态影响：按记录 provider_mode 判断 demo 媒体可取消，live 媒体不支持上游撤回；LLM 本地取消保持可用。缺少 provider_mode 的旧记录才回退到当前模式。
- `INTERRUPTED` 视为已中断终态，`PARTIAL` 视为部分完成终态；`SUBMIT_UNKNOWN` 显示上游受理待核实，`RECONCILE_REQUIRED` 显示需要核对，均不自动新键重生成，不伪装为可立即重试的普通失败。真实视频的时长／分辨率／尺寸来自选中的服务端规格预设，发送 seconds 等实际字段，固定 count=1。
- `RECONCILE_REQUIRED`、`PROVIDER_STATE_UNKNOWN` 或 `SUBMIT_UNKNOWN` 只有在服务端逐任务返回 `can_reconcile=true` 时显示“重新核对”。按钮明确“仅查询原任务，不会重新生成”，调用无生成参数的 `POST /tasks/{id}/reconcile`，返回按 version 合并。客户端不传上游 ID、不新建任务；无原任务 ID 的受理不明状态没有按钮。服务器冷却 429 显示为错误，不自动连发。
- 素材只接受同源 `/demo-assets/` 或 `/api/v1/assets/` 路径，拒绝外站和脚本 URL；新资产路由必须同时更新此允许列表。预览 SVG 用图片元素隔离，不以内联 HTML 注入。
- 历史任务卡、素材预览和历史对话的 Provider 标签优先使用每条记录的 `provider_mode`。切换工作区当前 demo/live 配置不会把历史演示结果重新标为真实；只有缺少该字段的旧记录才兼容回退到当前 bootstrap.mode。

任务与运行记录位于服务端；默认 demo 可用内存，Go 重启后丢失。启用 PostgreSQL 时，前端按 bootstrap 显示持久化状态，运行恢复依照服务端快照而非浏览器本地假历史。客户端恢复不意味着服务端持久化、跨实例恢复或上游模型可续接。受理不明请求只在当前标签页内存保留，刷新页面后只能通过历史对账；生产版本需增加受控的提交登记与审计机制。

### 云端草稿、冲突与版本恢复（V03）

`bootstrap.storage=postgres` 时进入 `CloudDraftCanvas`，侧栏标注 CLOUD；memory 标注 LOCAL，继续使用原本地草稿。云端接口为 `GET/PUT /api/v1/projects/{id}/draft`；空项目返回 revision=0、空节点和空更新时间。界面可以显式载入两节点创意提纲，但只有点击“保存云端版本”才写入服务器。初次加载或读取失败分别显示读取中／读取失败，不会误报已同步。

每次保存携带 `{expected_revision,nodes}` 与一个新的 `Idempotency-Key`。节点仅有 id/title/note，最多 40 个，标题最多 80 个 Unicode 字符、正文最多 5,000 个；浏览器输入框采用更保守的 UTF-16 单元限制，并拒绝重复或不安全 ID 与 NUL。服务端仍是最终校验者，最多保留 1,000 个版本，达到上限不再创建新版。

- 收到确定成功响应后才更新当前版本和同步标识。网络错误、超时或 5xx 保留完整原请求体／原键并冻结修改，只有显式“原请求重试”重放；不会自动创建新的保存请求。
- `409 DRAFT_CONFLICT` 保留当前编辑，另行读取服务器最新版。用户可导出本地内容、明确放弃本地并加载服务器版，或以服务器最新 revision 为基准保留自己的内容，再次手动另存新版。没有隐式合并，也没有静默覆盖。
- 历史列表读取 `/draft/revisions?limit=20&before_revision=N`；旧版通过 `/draft/revisions/{revision}` 只读预览。恢复先替换编辑区，保留当前 expected_revision，再以新键保存为新版本，原历史不改变。即使旧内容与当前相同，也明确保留“另存新版”的意图。
- 切换工具页面时保持编辑器挂载。切换项目、创建并进入新项目或主动退出，遇到未保存编辑会显示原生离开确认；等待创建项目／退出返回期间冻结草稿修改，避免请求中新增编辑被卸载。刷新／关闭页面使用浏览器原生未保存提示。
- 自动会话过期不会将草稿写入浏览器磁盘。App 生命周期内的恢复仓按用户与项目保存未保存状态，401 卸载后只有同一账户、同一项目能恢复；未确认保存仍保留原 body/key，并显示需显式重试。主动确认放弃会删除恢复项，迟到响应不能让它重新出现。登录界面期间若内存仓仍有未保存内容，刷新也会触发提示。
- 恢复仓不是离线持久化：刷新、关闭、页面进程终止或清除页面内存后不能恢复；用户应保存或导出 JSON。文件包含草稿正文，需由用户自行保管。恢复仓不存密码、Cookie 或 token。
- 项目组件按身份与项目重建；读取、历史、旧版预览、保存和冲突快照都有生命周期代次检查。卸载、StrictMode 重建后的旧响应不能覆盖新状态。恢复的旧基准依靠服务端 CAS 再次校验，不假定已经获得最新版本。

### 项目活动记录（V04）

“活动记录”读取 `GET /api/v1/audit?scope=project&limit=50&cursor=...`，携带当前 `X-Project-ID`，按时间倒序展示并显式加载更早记录。切项目后清列表并忽略旧作用域响应；按事件 ID 去重。PG 模式标注持久记录，memory 模式明确最多 512 条且重启清空。

界面只识别创建项目、提交对话／任务、取消、原任务核对、保存草稿等动作；详情只展示允许的状态、媒体类型、revision 和 node_count。任意未知 action/details 不直接输出，不展示提示词、模型输出、节点正文、邮箱、密钥或消费金额。活动页是只读查询，当前不提供实时推送、账务核对或运营审计管理。

### 工作区容量与请求反馈（V05）

设置侧栏通过 `GET /api/v1/runtime` 读取真实快照，携带当前 `X-Project-ID` 验证身份和项目归属，但数据覆盖当前工作区全部项目。只展示 `runs/tasks` 的 active/limit、queued、oldest_queued_seconds 及模型占用，和 `streams` 的 active/limit。active 包含排队、执行、未知和待核实等所有非终态，不能理解为正在生成数量；前端没有用 active 减 queued 推算运行数量，也没有使用已加载的本地任务数量代替容量。工作区的流连接占用与模型生成占用分开显示。

读取仅在设置展开且页面可见时进行，响应完成后等待 15 秒再查询，支持手动刷新；页面隐藏或侧栏关闭会取消定时器、使请求代次失效并中止在途 GET。恢复可见会重新读取，仍遵守已收到的冷却期限。每个身份／项目使用独立组件实例，切换后不会保留另一作用域的旧错误、快照或冷却。响应结构不完整时显示错误，不用默认零值掩盖；刷新失败可保留上次计数，但明确标注可能过期及最后读取时间。

容量是参考快照，不是前端配额授权。服务端最终决定准入；本页不会因为容量满载而禁用原幂等请求核对或重试，也不访问运营指标接口、不持有 metrics token、不展示其他工作区或全局占用。

`ApiError` 从 `X-Request-ID`（优先）或 `error.request_id` 取得请求编号，并解析 429/503 的 `Retry-After` 秒数或 HTTP 日期。冷却有界为 0—300 秒，缺失／无效时使用 3 秒；倒计时根据实际时间计算，页面隐藏时停止秒级更新，恢复时重新计算，不按剩余 tick 误计时。429 明确的 `ADMISSION_WORKSPACE_LIMIT`／`ADMISSION_MODEL_LIMIT`／`ADMISSION_STREAM_LIMIT` 对新操作表示本次未新受理，输入保留；503、网络失败或无法识别的 mutation 响应继续按未知受理处理。此前已经未知的操作再次收到 429／401 不能清掉原 body/key。

生成、云草稿、活动和账户错误页提供明确下一步、冷却提示及可复制请求编号。编号只接受长度最多 128 的字母数字与 `._:-`，通过 React 普通文本呈现，拒绝控制字符和 HTML；复制不可用时可直接选取文本。冷却仅限制显式重试频率，不会自动重发任何生成／保存 POST/PUT。主动刷新容量或历史只读取数据；503 不会据此被伪称为确定未受理。

### 版本化模型目录与完整规格（V06）

新版 bootstrap 返回 `catalog_version` 和新版 models；独立 `GET /api/v1/models` 返回 `{version,models}` 与 ETag。每个模型包含公开 id/name/description/kind、enabled、可选 reason、version，以及 cancel_supported/max_count/max_prompt_bytes/parameter_presets。目录最多 32 个模型；媒体模型每个 1—32 个预设，聊天预设固定空数组。前端验证有限结构、数量与视频 1—600 秒边界后才替换有效目录；图片预设不接受 seconds，但支持 size 和 resolution，视频也可声明 size。

设置侧栏以“模型、创作规格、数量”组织。每个预设是一组确定的 aspect_ratio、可选 size/resolution、视频 seconds；不能在独立下拉框里任意组合出服务端未声明的参数。选择规格后，下方信息卡会展示各项具体值；提交只发送预设的实际参数与 count，不发送预设 id/name，不把展示文案作为供应商参数。模型选项显示可用数，停用模型保留在目录中；disabled_by_operator/provider_not_configured 映射为中文原因，未知内部枚举不直接显示给普通用户。

主动换模型采用新模型的第一项规格，数量保留到新上限；规格或数量变化时提示核对，点击当前模型不会重置规格。目录更新时尽量保留仍存在的规格 ID 与合法数量，不适用时调整到首项／新上限，并提示核对后提交。提示词不会因模型变化静默裁剪。若全部停用或当前模式没有模型，禁用新提交，不偷偷回退到已停用模型或其他模式。

新 LLM／媒体提交都携带所选 `model_version`。提交瞬间还会比较当前目录与界面选择的版本，防止刚刷新目录但旧界面动作发送未经确认的新规格。服务端 `409 MODEL_VERSION_CHANGED`、`422 MODEL_DISABLED`／`INVALID_MODEL_PARAMETERS` 显示刷新目录入口；只有用户确认新的模型与规格后才再次提交，不自动 POST。既有未知操作保存的是原 body/key，刷新目录、停用模型、切换新选项都不重新组装这份请求。错误区明确显示原请求的模型与版本。

ETag 缓存仅保留当前身份／工作区的一份目录，退出清除。bootstrap 版本变化会清旧 ETag；同作用域有缓存时发送 If-None-Match，304 复用原对象，不解析不存在的 JSON body。没有缓存却收到 304 时明确报错，不把空对象当目录。读取带当前项目头及作用域代次；项目／身份切换或页面隐藏会 abort 旧读取并忽略迟到回复。支持手动刷新、页面重新可见刷新、页面可见时每 60 秒校验，并遵守目录错误的 Retry-After。

目录更新仅替换 models/catalog_version，不切项目、不清草稿、不重建历史。两个 SSE effect 依赖稳定的工作区／项目 ID，目录对象变化不会导致任务或对话重连。主流程使用“规格已确认／模型目录”文案，完整版本放在诊断 title；历史使用“受理时规格”标签。任务、素材和历史对话优先使用记录 `model_name/model_version`，旧记录回退 model_id；停用或改名后的当前目录不会替历史改名。Task.parameters 是服务端返回的有效执行快照，可供后续详情功能使用，本批没有宣称新增完整任务参数详情页。

v0.13.0完成文本审核前端及本地核心链路验证。默认关闭；开启时完整生成并经服务端审核后才展示全文，只有`moderation.state=ALLOWED`且运行`COMPLETED`可以开放正文。PENDING、BLOCKED、REVIEW使用安全状态条，隐藏未开放正文、原始错误、复制和“从此继续”；不通过遮罩假装收回已经发送的内容。旧资源或关闭审核时的nil摘要保持原行为，不标为审核通过。

受限的终态回复之后仍可在原分支正常提出新问题：客户端只提交新输入和原消息树父节点ID，服务端从实际模型上下文中略去受限的完整轮次。只有显式“继续”要求可公开的原回复；不能续写被隔离正文。审核version与文本seq分别合并，旧快照、分页、分支预览或缓存Run不能重新显示受限内容。原请求未知时仍保留原body/key/报价，确定前置审核失败保留草稿，不自动生成。

本批只覆盖文本。审核开启时图片和视频的新生成、报价入口禁用；历史任务与原未知请求核对保留，上传和旧素材不因此获得审核标签。`rules`明确标为demo演示规则，`http`只表示协议适配；真实文本审核商尚未选型，多模态B2、人工放行／重审及申诉封禁仍未完成。实现细节见[文本审核工作台](moderation-workbench.md)与[053台账](../changes/2026-11-14-053-moderation-workbench.md)。

本地前端237项／24文件、严格TypeScript和构建通过；根已完成真实PG全量170.241秒，并在隔离demo浏览器中验证输入阻断后0消息节点且草稿保留、输出阻断后正文隔离及冻结REVIEW、随后普通新问题正常完成且上下文纳入1条／省略2条。该fixture中受限轮次冻结0.045056 CREDIT保持待核实，新问题结算0.000384并释放0.044672；这些只是隔离测试价格，不能视为真实模型计费标准。桌面／手机最终布局及完整联合验收由根[054台账](../changes/2026-11-14-054-text-review-integration.md)记录，不以本地规则或HTTP模拟器替代真实审核渠道验收。

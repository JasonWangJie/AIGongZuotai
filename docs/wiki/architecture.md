# 架构与实施边界

总体方向见[开发方案](../../deliverables/Go与NewAPI高性能AI工作台开发方案.html)。本页说明代码当前处于哪个阶段，不替代完整生产架构设计。

## 当前结构

```text
浏览器 React 工作台
        │ 自有 /api 请求与 SSE
        ▼
单个 Go 服务：HTTP API / LLM run / 媒体任务调度
        │
        ├─ 内存开发模式，或 PostgreSQL 持久账户/项目/运行/任务/幂等
        ├─ demo Provider：模拟文本增量、图片与视频任务状态
        ├─ live LLM Provider：按显式环境变量请求网关
        └─ 异步图片/视频 Provider：提交 → 原任务查询 → 私有原件导入
```

API 和调度职责先放在同一进程中，边界以领域和 Provider 接口表达。前端只访问平台接口；New API 地址和密钥由 Go 服务持有。该部署方式方便验证纵向链路，不能通过多开几个进程变成可靠集群。

| 领域 | 当前行为 | 当前限制 |
| --- | --- | --- |
| 身份与项目 | disabled 演示身份或 PostgreSQL HttpOnly 会话；工作区/项目权限 | 邮箱验证/找回/改密、会话撤销本地实现；实际邮件待验收，无MFA/组织成员/公网身份运维 |
| 多轮对话 | 项目会话/不可变消息树、祖先分支、CAS/幂等、冻结上下文与显式继续 | 配置窗口与保守估算；无自动摘要、工具、附件或精确供应商tokenizer |
| LLM 运行 | 创建 run，再以 SSE 订阅；持久快照、取消、重启中断标记 | 增量回放环在内存中，约一秒检查点不是逐 token 强耐久 |
| 媒体任务 | 保存意图、原始提交体和上游 ID，集中查询与恢复 | 单控制写者；数据库租约/epoch隔离执行，受理不明待核实，无自动对账 |
| 请求幂等 | 本地及 PostgreSQL 幂等映射；同键不同内容拒绝 | 上游仍依赖其实际幂等实现和保留期限，不能宣称跨系统 exactly-once |
| 持久化 | PostgreSQL 事务、重启恢复、历史分页与有界终态缓存 | 控制连接持 advisory lock，租约用有界独立连接；无多实例高可用 |
| 模型目录 | 启动加载有界JSON，公开版本/ETag、服务端精确预设验证、任务受理快照 | 不是网关自动发现；配置变化须重启，无管理后台热更新 |
| Provider | 默认 demo；live LLM 与文档定义的图片/文生视频 | 图片编辑已接通本地fixture；未使用真实密钥验收，视频编辑/延长未接入 |
| 资源准入 | 工作区总量、工作区内单模型、工作区SSE上限；PG全量未终态计数 | 单写者内原子检查，尚非分布式配额/付费额度/公平调度 |
| 可观测 | 存活/就绪分离、独立令牌指标、请求编号、当前工作区容量 | 指标进程内累计；缓存指标不等于数据库全量；无供应商健康承诺 |
| 参考素材 | PNG/JPEG/WebP原件与512px缩略图、项目权限、有序引用、精确multipart文件 | 参考和正文仍本地私有；上传/准备有界，未实现mask |
| 资产目录与内容 | 独立搜索、元数据CAS/历史、回收站；本地或S3私有内容后端、鉴权代理 | 无二进制内容替换、转码、病毒扫描或完整审核/永久删除策略 |
| 离线维护 | 目录OS锁+PG锁、storage UUID归属、可达集合与dry-run摘要复核 | 只清理旧不可达本地文件，保留trash/终态任务引用；无远端GC或生产灾备承诺 |

限额判定先处理已有幂等键；同键重试仍返回原资源，不占第二份名额。未知受理和待核实持续占用，不能以本地“取消”释放真实上游不支持取消的任务。资源容量展示是快照，最终以受理API为准，详见[资源准入](admission.md)与[可观测](observability.md)。

具体字段、状态与错误码以 [Go 后端](backend.md) 为当前实现契约，交互范围见[工作台前端](frontend.md)。

## 流与任务分开处理

LLM 由服务端持有上游连接，浏览器通过 run ID 订阅。浏览器断开连接不会自动重新创建运行，也不会直接取消运行；用户主动停止通过取消 API 表达。有限事件窗口过期时，通过运行快照恢复可见状态。PostgreSQL 保存周期检查点与终态，进程中断后标记 INTERRUPTED，不能原样续接供应商连接；不能等同于方案中的持久分片日志。

媒体任务由平台受理后查询本地状态，浏览器不直接轮询 New API。当前[实际异步协议](media-gateway.md)支持幂等键，图片要求保留相同原始请求体字节；没有客户端请求 ID 查找和取消 API。已受理任务只继续查询原 ID，提交受理不明与执行不明明确进入核实状态；UI 按 capabilities 显示操作。

## 数据与权限边界

- 浏览器只能提交模型标识和业务输入，不能决定网关密钥或任意网关地址。
- 平台 run/task ID 与上游 ID 分开；提交体、上游身份和恢复状态持久化，原始 API Key 不写数据库。
- 任务状态、结算和发布应由服务端决定，前端状态不能成为生产事实来源。
- `ws_demo` 仅用于关闭认证的演示。账户模式按工作区/项目检查创建、列表、快照、SSE、取消及资产下载，前端切项目使旧异步结果失效。
- 当前仅允许本地开发；真实供应商调用可能消耗额度，必须由操作者显式配置，不在自动测试中发起真实收费请求。

## 与生产方案的差距

| 计划能力 | 目前状态 | 进入生产前的工作 |
| --- | --- | --- |
| PostgreSQL 业务事务、Outbox 与持久调度 | 单写者事务、Outbox、持久feed与任务租约已实现 | 拆分执行仍需跨实例扇出、共享存储及容量/切换验收 |
| 轮询租约、epoch fencing、配额公平性 | 数据库领取/续约/版本隔离已实现；公平调度未完成 | 按真实网关预算验证多实例、分布式配额与调度公平性 |
| Redis 与 NATS JetStream | 未部署 | 按实际负载验证缓存、日志耐久性、回放、裁剪和容量 |
| Temporal DAG 与人工确认 | 未实现 | 固定工作流版本，处理长运行、取消与节点结果归属 |
| 项目云端草稿与版本 | 已实现文本节点、CAS、不可变历史及恢复为新版本 | 存储配额/归档、差分、实时协作与可执行DAG分批实现 |
| 对象存储、媒体导入与审核 | 私有S3接口、本地迁移和受控离线孤立文件维护已实现 | 生产服务配置/容量、远端GC、转码、内容审核、保留策略与灾备演练 |
| 生产账户、账务、支付与运营后台 | 账户/项目、安全恢复本地链路与业务审计已实现，收费与控制面未实现 | 实际邮件渠道、成员权限、支付回调、账本、退款和运营审计检索 |
| 多可用区与跨区域恢复 | 未实现 | 各存储的 RPO/RTO、单主切换、上游任务核实和演练 |
| 10000 条活跃流和完整 SLO | 未验证 | 固定数据集与测试环境，完成容量、稳态和混沌测试 |

后续按[模块/批次 TODO](../../TODO.md)与[路线](roadmap.md)演进，验收后逐批标记。拆分部署由实际资源隔离和性能数据驱动，不能把新增服务数量当成可靠性提升。第一阶段选择见 [ADR 0001](decisions/0001-phase-one.md)，持久单写者阶段及退出条件见 [ADR 0002](decisions/0002-durable-single-writer.md)。

V06采用[版本化模型目录与执行快照](decisions/0003-versioned-model-catalog.md)：媒体受理时冻结原始提交字节，配置启停只影响新请求；没有可靠历史执行快照的旧live排队任务保守待核实，避免用新映射猜测重提。

V07采用[私有参考素材与不可变编辑请求](decisions/0004-private-reference-bodies.md)：原图/缩略图和编辑正文保存在独立私有目录，PG保存身份和有序引用；受理阶段不把大文件准备放在全局锁中，事务失败的孤立文件仍计入磁盘限额。真实供应商验收未完成，整批保持待条件。

V08采用[私有资产生命周期](decisions/0005-private-library-lifecycle.md)：目录身份与源内容分离，软删除仍保留恢复和任务所需文件；[离线维护](storage-maintenance.md)在双锁及storage UUID核对后，按全部可达引用生成计划并复验。该机制不替代Outbox、跨主机租约或生产RPO/RTO。内容后端详见[对象存储](object-storage.md)，用户操作详见[资产目录](assets.md)。

V09采用[持久通知与任务租约](decisions/0006-durable-events-and-task-leases.md)：业务/审计与Outbox同事务、幂等持久投影和范围游标；租约使用数据库时钟、owner/epoch/generation及预期版本阻止迟到结果。前端补读保留未确认请求及未保存编辑。逐token日志、跨实例全站运行和生产容量仍未完成，验证范围见[034](../changes/2026-11-13-034-durable-execution-integration.md)。

V10采用[持久会话与上下文预算](decisions/0007-conversations-and-context.md)：服务端读取当前分支祖先构造真实messages，原子保存受理及执行快照；编辑创建兄弟分支，继续明确创建新Run。流检查点复用Run，通知只补读元数据，原单轮历史保留。上下文裁剪与费用核算分开；验证见[038](../changes/2026-11-13-038-conversation-integration.md)。

V11采用[账户恢复与加密邮件决策](decisions/0008-account-security-and-mail.md)：凭据版本和用户行锁阻止旧密码验证结果签发新会话；令牌、加密邮件与安全记录同事务，SMTP在事务后执行。SENT仅证明SMTP接受，确认不明不自动重发；实际邮件渠道仍待配置。

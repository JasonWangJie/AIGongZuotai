# 账户安全与自助恢复

V11增加邮箱验证、密码找回与修改、会话查看与撤销、账户安全记录。本地PostgreSQL及TLS SMTP fixture验证与真实邮件渠道验收分开：默认不发送邮件，真实渠道仍待配置和授权验收。当前仍限回环地址、单控制写者，不能直接开放公众注册。基础隔离见[持久化与账户](persistence-auth.md)，精确接口见[V11契约](../planning/v11-contract.md)及[OpenAPI](../api/openapi.yaml)。

## 用户行为

登录及匿名 `/api/v1/auth/session`、bootstrap均返回 `account_security`，说明账户功能和邮件渠道是否配置。User增加 `email_verified` 与 nullable `email_verified_at`。验证标记只说明邮箱所有权，不赋予额外角色、工作区或模型权限，也不剥夺升级前未验证账户已有权限。

|操作|实际行为|
|---|---|
|请求验证邮件|仅已登录账户自身邮箱；202是统一安排回复，不等于送达|
|确认验证链接|用户显式提交一次性token；不建立会话，不切换当前账户|
|请求找回|已存在和不存在地址均统一202；发起请求不撤销会话、不修改密码、不立即废除旧有效链接|
|重置密码|验证token后修改密码，全部会话失效；不自动登录|
|修改密码|重新验证当前密码及当前有效会话；成功后全部会话失效，必须重新登录|
|会话管理|最多10个未过期会话，公开随机ID、当前标记、创建/过期时间；单个或全部撤销|
|安全记录|仅自己可读的游标分页；不是项目活动、费用账单或完整安全监控平台|

邮件链接使用可信配置origin和 `/#auth=verify|reset&token=...`，不以HTTP query发送token。前端取出后清理fragment，必须由用户显式提交；不得存入草稿、localStorage、日志或恢复仓。敏感操作网络失败后不自动重发，不把受理未知描述为取消。token无效、过期、已用、用途或凭据版本不符统一 `400 ACCOUNT_TOKEN_INVALID`。

## 一次性令牌与事务

token为密码学随机32字节，base64url编码43字符；`studio_account_tokens`只保存SHA256、用户、用途、凭据版本及到期/消费时间。验证有效24小时，找回30分钟。每账户同用途60秒冷却、最多3个未过期有效链接；重复请求不立即作废已投递链接。消费后相应用途链接失效；任何密码变更递增凭据版本并使之前所有令牌失效。

密码10至72 UTF-8字节，拒绝NUL及无效UTF-8，bcrypt cost12。bcrypt在数据库锁外执行，受4个并发槽限制。登录验证后不能直接创建session：事务先锁用户行，再核对验证时的密码散列与凭据版本。密码修改/重置使用同样用户锁顺序；登录先提交则改密删掉该会话，改密先提交则旧bcrypt结果不能再签发会话。

修改密码事务还重新检查当前session未撤销/未过期且版本相符。密码、版本、全部session撤销、token作废和安全审计一起提交。验证时间、token消费和审计也一起提交。失败全部回滚；数据库异常令store停止执行并返回503，不降级内存。提交确认丢失不能自动再次消费或签发，客户端通过重新登录/申请新链接核对。

新私有账户路由在handler显式鉴权，不能借原 `/auth/*` 公共入口绕过。会话撤销按当前user约束，跨账户ID返回404。会话ID与token/hash分离；011为旧session随机回填公开ID、凭据版本1，保持兼容。

## 邮件和限流

邮件由独立SMTP适配器及加密持久队列投递，配置前缀 `AUTH_MAIL_*`。只有显式启用且 `AUTH_MODE=required`、PG、TLS SMTP、可信origin、独立32字节AES密钥均有效才开启。配置只在服务端，不得进入 `VITE_*`。详细状态与配置见[安全邮件投递](mail-delivery.md)。

token、AES-GCM密文邮件和安全事件同事务。队列无明文收件人、token或正文；worker只有提交后才读取，SMTP不占DB或全局状态锁。接收不明进入未知状态，重启不自动再次投递。密码改变后旧排队邮件可能到达，但旧版本token不能消费。

公开找回对已知/未知地址使用相同状态码、正文和异步入口；邮箱语法、全局禁用、IP限流和队列容量错误不依赖账户存在性。实现不承诺恒定时间、邮件不可推断或抵抗分布式攻击。既有注册仍对重复邮箱返回409，不可把找回统一响应描述为全站不存在枚举渠道。

进程内限流最多2048个散列/操作键、15分钟窗口，安全操作/IP最多30次、对应身份最多10次。接收方超本地额度继续统一202并抑制排队；60秒/3有效token规则在PG内跨重启保留。429附 `Retry-After`。IP及身份计数重启会清空，无Redis共享限流、CAPTCHA或MFA。

新注册和邮件请求只接受最长254字节ASCII裸邮箱，不支持SMTPUTF8、显示名或含空格quoted local。旧版UTF-8邮箱仍可登录/改密；不支持的旧地址验证返回不可投递，不能擅自改写地址或丢弃旧账户。

## 安全记录与保密

独立 `studio_security_events` 记录成功注册、登录、注销、验证申请/完成、找回申请/完成、改密、单/全部会话撤销，与对应变更同事务；不放入项目Outbox。未覆盖失败登录的持久风险分析、管理员审计或异常告警。

条目仅随机ID、闭集action、时间及私有用户外键。响应无邮箱、密码、token、session hash、IP、UA、提示词或任意details。分页默认20、上限50，以时间+ID复合游标读取，游标绑定当前user，最长512字节。未提供正式安全历史保留/删除策略。

Cookie保持HttpOnly、SameSite=Strict及TLS请求Secure，API为no-store。撤销对之后的API鉴权生效，已有SSE在下一次现有心跳复核时断开；不是公网cookie、代理、风控的完整上线配置。

## 迁移、验证与恢复

[011迁移](../../db/migrations/011_account_security.sql)增加凭据版本/验证时间、session公开ID/版本、用途token、安全事件和加密邮件队列。活动队列/清理有部分索引，容量检查最多统计10000条未过期活跃邮件。旧程序不认识011会拒绝启动，不能删除版本登记绕过。

本模块真实PG专项6函数通过8.537秒，覆盖跨账户/游标、双向独立连接竞争、并发token消费、用途/过期、旧session升级、密码事务与审计/邮件插入失败回滚。普通格式/密码/邮箱/ID/独立密钥2函数通过0.080秒；`go vet ./...`通过。SMTP专项、TLS fixture完整HTTP链及最终联合结果分别由邮件和根台账记录，不代表真实外部邮箱送达。

升级前联合备份PG、私有文件、对象收据及独立邮件密钥。密文队列失去密钥无法还原，更换配置不能改写已排队链接。回退用匹配011前版本的独立备份库和目录，保留升级后原库，无自动向下迁移；主库与真实邮件操作依独立授权执行。

# 性能基线与验收口径

Go 是核心后端实现语言，但使用 Go 本身不能证明性能目标达成。[总体方案](../../deliverables/Go与NewAPI高性能AI工作台开发方案.html)中的万级活跃流、媒体在途量及 P95/P99 指标仍需要固定环境的实测。

## 本地回归基线

```sh
npm run build
npm run perf:local
```

脚本自己启动随机回环端口的 demo 进程，强制关闭数据库与认证，不访问当前开发实例，不发真实 AI 请求。结束后关闭其进程，JSON 报告写入 `.runtime/performance-local.json`。报告包含时间、应用/Go版本、二进制SHA256、OS/CPU/内存/Node、并发数、样本数、耗时、吞吐与 P50/P95/P99。

| 阶段 | 样本和并发 | 测量内容 |
| --- | --- | --- |
| HTTP bootstrap | 1000 请求、32 并发 | 完整响应消费耗时，含本机 Node 客户端开销 |
| 任务创建与取消 | 100 组、8 并发 | 每组包含受理和取消两个请求，吞吐单位为组/秒 |
| LLM demo 流 | 12 运行、4 并发 | 创建到完整 SSE 结束，额外统计创建到第一条 delta |

每次测试先执行 50 次健康检查预热。脚本断言响应码、首增量及完成事件，有错误直接失败，避免把错误响应计为高吞吐。受测状态只保留在临时进程中。

2026-11-13实测：32并发/1000次bootstrap请求P95为22.97ms，2167.93请求/秒；8并发的任务创建+取消P95为12.55ms；4并发demo流首delta P95为56.87ms。完整[原始报告](assets/performance-local-2026-11-13.json)及[008台账](../changes/2026-11-13-008-performance-baseline.md)记录全部口径。不要横向比较不同电脑或不同后台负载下的微小差异；最少固定提交、运行时、负载参数和数据集。

v0.3增量复测（2026-11-13）：相同隔离脚本下bootstrap P95为21.45ms、2291.37请求/秒，任务受理+取消P95为11.16ms，demo首delta P95为57.65ms。独立[版本报告](assets/performance-local-v0.3-2026-11-13.json)保留二进制摘要，未覆盖PostgreSQL草稿和审计的负载；这些同机单次结果只用于回归，不能据微小差异声称性能提升。v0.2原始报告保留。

v0.4增量复测（2026-11-13）：bootstrap P95为21.39ms、2246.08请求/秒，任务受理+取消P95为11.96ms，demo首delta P95为56.48ms。详见[独立v0.4报告](assets/performance-local-v0.4-2026-11-13.json)。相较v0.3未见本地数量级回退，不能据单次测量判断性能提升。新增指标使用固定数组，成功请求默认不逐条写访问日志；大文件保留底层ReaderFrom转发，SSE继续使用Flush与单写deadline。

v0.5增量复测（2026-11-13）：bootstrap P95为20.80ms、2316请求/秒；任务创建+取消P95为12.09ms；demo首delta P95为56.22ms。见[独立v0.5报告](assets/performance-local-v0.5-2026-11-13.json)。目录响应在启动时序列化并缓存，ETag减少重复传输；媒体与LLM映射复用共享HTTP客户端。未独立压测32模型目录或真实PG任务受理，不把这些实现推断成生产容量成绩。前端gzip为JS103.69kB、CSS12.72kB。

v0.6增量复测（2026-11-13）：bootstrap P95为23.10ms、2070.78请求/秒，任务创建+取消P95为14.41ms，demo首delta P95为56.85ms。见[独立v0.6报告](assets/performance-local-v0.6-2026-11-13.json)。与上一版本有单次波动，未做统计显著性或生产负载对比；不能宣称达到总体高吞吐目标。前端gzip为JS109.87kB、CSS13.97kB。

参考上传最多4个存储操作、编辑正文准备最多2个，原件限8MiB/16M像素，缩略图最长边512px。编辑multipart不在内存或JSONB保存整份大正文，流式写入私有文件；校验和准备在全局业务锁外，受理前重新检查。`BenchmarkReferenceBodySpool8MiB -benchtime=1x -benchmem`单次45.11ms、185.97MB/s、112672B/op、164allocs/op，包含该基准的初始化成本。它只测8MiB正文写盘，不包含图片解码、PG、真实网络或并发，不能解释为整体上传吞吐或零内存成本。V08补充停机可达性维护；回收站和已登记任务文件仍保留，不能宣称自动释放容量。

V05的[受保护指标](observability.md)用于运行诊断，HTTP直方图包含SSE整段连接生命期，不等同平台增量转发延迟；`studio_cached_*`只计进程缓存，不能冒充全量持久任务指标。PG准入以工作区完整未终态SQL聚合为准，其吞吐仍需独立生产数据集压测。

当前单进程采用有界 worker、队列、SSE 订阅缓冲、文本长度及缓存。PostgreSQL 版本采用单写者锁，优先验证状态正确性；持久化操作和数据库连接仍是必须进一步压测与优化的边界。V09已完成受控任务租约/旧执行者隔离，但全站多实例、公平调度、独立流日志、跨实例扇出和生产容量验收仍未完成。

v0.7增量复测（2026-11-13）：bootstrap P95为21.80ms、2199.16请求/秒，任务创建+取消P95为12.85ms，demo首delta P95为56.60ms。见[独立v0.7报告](assets/performance-local-v0.7-2026-11-13.json)。新增资产目录采用keyset分页及私有缩略图，列表不回退加载大原件；S3代理复用有界HTTP连接。尚未压测生产量级目录检索或云存储并发，结果只用于本机回归。

v0.8增量复测（2026-11-13）：bootstrap P95为22.05ms、2038.88请求/秒，任务创建+取消P95为14.22ms，demo首delta P95为57.26ms。见[独立v0.8报告](assets/performance-local-v0.8-2026-11-13.json)。前端gzip JS120.11kB、CSS15.90kB。该脚本使用memory/demo，不覆盖PG Outbox、项目counter、租约辅助连接或真实上游；新增正确性机制的实际生产负载成本仍需专项测量。客户端补读限制每批8资源/4并发/至少1.5秒，300/400项扫描收敛已有确定性测试，不能用它代替浏览器性能压测。

## 生产验收需补充的测量

1. 独立压测机、反向代理/TLS/HTTP2、真实鉴权、生产量级数据库和明确网关配额。
2. 受理延迟、上游首字、平台转发增量延迟分别统计，避免把供应商等待误计为平台开销。
3. 稳态及突发下的 CPU、RSS、FD、GC、数据库等待、队列年龄、错误率与慢订阅者。
4. 万级流与目标媒体在途量的持续测试；覆盖连接断开、数据库不可用、进程崩溃、上游429及导入失败。
5. 部分输出恢复、重复提交、任务核实、备份恢复及人工处置闭环，不能仅看 QPS。

测试通过范围与限制必须进入台账。优化前后使用同一基准，先定位瓶颈，再决定连接池、调度分片、日志系统和服务拆分。

## v0.13 本地回归测量

2026-11-14，最终server.exe、五份冒烟JSON与性能报告SHA一致，六套冒烟均通过。bootstrap1000次/32并发P95 22.12ms、2212.55请求/秒；任务创建+取消100组/8并发P95 11.98ms；demo流12条/4并发首delta P95 56.26ms。前端gzip JS156.17kB、CSS23.18kB。见[原始报告](assets/performance-local-v0.13-2026-11-14.json)及[054](../changes/2026-11-14-054-text-review-integration.md)。

父环境开启审核http并提供无效策略/端点，同时启用运营、权益和邮件，脚本仍通过；子进程显式关闭这些能力，使用隔离memory/demo。因此这不是全文审核、PG或真实渠道吞吐成绩，不能据单次波动称为提速。审核HTTP当前有界并发4、10秒超时、8KiB响应，禁止自动重试/跳转；输出候选最多128KiB。输入审核在全局业务锁与事务外，提交前重核摘要。审核启用时首字交付等待整段生成及批准，与本报告的未审核demo首delta口径不同；生产延迟/队列及长稳态仍待V16/V17。

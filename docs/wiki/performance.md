# 性能基线与验收口径

Go 是核心后端实现语言，但使用 Go 本身不能证明性能目标达成。[总体方案](../deliverables/Go与NewAPI高性能AI工作台开发方案.html)中的万级活跃流、媒体在途量及 P95/P99 指标仍需要固定环境的实测。

## 本地回归基线

```sh
npm run build
npm run perf:local
```

脚本自己启动随机回环端口的 demo 进程，强制关闭数据库与认证，不访问当前开发实例，不发真实 AI 请求。结束后关闭其进程，JSON 报告写入 `.runtime/performance-local.json`。报告包含时间、应用/Go版本、二进制SHA256、OS/CPU/内存/Node、并发数、样本数、耗时、吞吐与 P50/P95/P99。

| 阶段 | 样本和并发 | 测量内容 |
| --- | --- | --- |
| HTTP bootstrap | 1000 请求、32 并发 | 完整响应消费耗时，含本机 Node 客户端开销 |
| 任务创建与取消 | 100 组、8 并发 | 每组包含受理和取消两个请求，吞吐单位为组/秒 |
| LLM demo 流 | 12 运行、4 并发 | 创建到完整 SSE 结束，额外统计创建到第一条 delta |

每次测试先执行 50 次健康检查预热。脚本断言响应码、首增量及完成事件，有错误直接失败，避免把错误响应计为高吞吐。受测状态只保留在临时进程中。

2026-11-13实测：32并发/1000次bootstrap请求P95为22.97ms，2167.93请求/秒；8并发的任务创建+取消P95为12.55ms；4并发demo流首delta P95为56.87ms。完整[原始报告](assets/performance-local-2026-11-13.json)及[008台账](../changes/2026-11-13-008-performance-baseline.md)记录全部口径。不要横向比较不同电脑或不同后台负载下的微小差异；最少固定提交、运行时、负载参数和数据集。

参考上传最多4个存储操作、编辑正文准备最多2个，原件限8MiB/16M像素，缩略图最长边512px。编辑multipart不在内存或JSONB保存整份大正文，流式写入私有文件；校验和准备在全局业务锁外，受理前重新检查。`BenchmarkReferenceBodySpool8MiB -benchtime=1x -benchmem`单次45.11ms、185.97MB/s、112672B/op、164allocs/op，包含该基准的初始化成本。它只测8MiB正文写盘，不包含图片解码、PG、真实网络或并发，不能解释为整体上传吞吐或零内存成本。V08补充停机可达性维护；回收站和已登记任务文件仍保留，不能宣称自动释放容量。

V05的[受保护指标](observability.md)用于运行诊断，HTTP直方图包含SSE整段连接生命期，不等同平台增量转发延迟；`studio_cached_*`只计进程缓存，不能冒充全量持久任务指标。PG准入以工作区完整未终态SQL聚合为准，其吞吐仍需独立生产数据集压测。

当前单进程采用有界 worker、队列、SSE 订阅缓冲、文本长度及缓存。PostgreSQL 版本采用单写者锁，优先验证状态正确性；持久化操作和数据库连接仍是必须进一步压测与优化的边界。V09已完成受控任务租约/旧执行者隔离，但全站多实例、公平调度、独立流日志、跨实例扇出和生产容量验收仍未完成。

## 生产验收需补充的测量

1. 独立压测机、反向代理/TLS/HTTP2、真实鉴权、生产量级数据库和明确网关配额。
2. 受理延迟、上游首字、平台转发增量延迟分别统计，避免把供应商等待误计为平台开销。
3. 稳态及突发下的 CPU、RSS、FD、GC、数据库等待、队列年龄、错误率与慢订阅者。
4. 万级流与目标媒体在途量的持续测试；覆盖连接断开、数据库不可用、进程崩溃、上游429及导入失败。
5. 部分输出恢复、重复提交、任务核实、备份恢复及人工处置闭环，不能仅看 QPS。

测试通过范围与限制必须进入台账。优化前后使用同一基准，先定位瓶颈，再决定连接池、调度分片、日志系统和服务拆分。

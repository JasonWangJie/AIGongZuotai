# V05 · 工作区资源准入

本模块限制单个工作区同时占用的生成与流连接资源，关联 [V05 任务登记](../planning/tasks.json)和 [014 台账](../changes/2026-11-13-014-resource-admission.md)。它是单写实例的保护规则，不是会员额度、消费账本、按分钟限流、跨进程共享配额或公平调度。用户身份和工作区来自服务端会话及已经授权的项目；客户端不能通过提交另一个用户 ID 获取额外额度。

## 配置

| 环境变量 | 默认值 | 允许范围 | 作用域 |
| --- | ---: | --- | --- |
| `ADMISSION_WORKSPACE_RUNS` | 64 | 1–4096 | 一个工作区全部项目的非终态 LLM 运行 |
| `ADMISSION_MODEL_RUNS` | 32 | 1–4096 | 一个工作区、一个文本模型的非终态运行 |
| `ADMISSION_WORKSPACE_TASKS` | 128 | 1–4096 | 一个工作区全部图片/视频非终态任务合计 |
| `ADMISSION_MODEL_TASKS` | 64 | 1–4096 | 一个工作区、一个媒体模型的非终态任务 |
| `ADMISSION_WORKSPACE_STREAMS` | 32 | 1–128 | 一个工作区当前打开的运行/任务 SSE 连接合计 |

环境变量未设置才使用默认值；显式空串、0、负数、小数、非数字和超范围值均拒绝启动。Go 内部测试构造 `Config` 时零值表示采用默认值，负值和超上界仍拒绝。更小的工作区总上限自然覆盖模型上限，不要求两者固定比例。

这些上限不改变现有 4 个 LLM worker、4 个媒体 worker、各 32 项执行队列、128 条全局 SSE 上限与缓存保护。上限调大不等于执行能力增加；仍可能先遇到全局队列或存储保护。默认值是本地开发起点，没有据此完成生产容量验收。

## 哪些任务占名额

`active` 表示占用，不表示正在执行模型。所有非终态都计入，包括 QUEUED、SUBMITTING、RUNNING、INGESTING、SUBMIT_UNKNOWN、PROVIDER_STATE_UNKNOWN、RECONCILE_REQUIRED。只有 COMPLETED、SUCCEEDED、PARTIAL、FAILED、CANCELLED、INTERRUPTED 释放。

- 一个媒体任务算一个名额，即使一次请求包含多张图片；这不是 token、图片张数或费用限额。
- 图片和视频共享工作区媒体总额，各自还受模型额度限制。
- 换项目不增加名额；不同工作区独立。当前账户模型仍是一用户对应一个工作区，没有新增成员/RBAC。
- 未知提交、待核实、供应模式切换不能释放名额来无限创建新任务。即使记录从内存缓存淘汰或重启未载入，PG 查询仍计入。
- 已有 handle 的安全“重新核对”只继续查询原任务，不另外占名额；即使当前额度已满也允许执行。没有 handle 的未知提交仍不能重发。
- 正常完成、确定失败或受支持的取消释放名额。真实媒体供应商没有确认取消接口时，取消仍返回 409，不通过本地标记释放真实上游工作。
- 重启后的未完成 LLM 先恢复为 INTERRUPTED，保留检查点而不重提，因此释放 LLM 名额。媒体恢复继续保持原非终态占用。

把配置下调到低于现有占用时，不取消已有任务，也不拒绝服务启动；禁止新受理直到占用低于限额。长期无法核实的未知任务会持续占用，不能靠刷新或改幂等键绕过；当前尚无运营人工确认/结案接口，需按供应商记录核实后由后续控制台流程处理，不建议直接改数据库解除额度。

## 幂等、拒收与持久一致性

受理顺序为：项目归属 → 查幂等键 → 同键异参冲突或原资源重放 → 工作区/模型额度 → 全局容量保护 → 资源、幂等、审计同事务保存 → 发布及执行。

| 返回 | 含义 |
| --- | --- |
| 原 201/202 + `Idempotency-Replayed: true` | 原键原请求返回原资源，额度已满仍可重放，不重复占用 |
| 409 `IDEMPOTENCY_CONFLICT` | 同键不同请求；没有新增占用 |
| 429 `ADMISSION_WORKSPACE_LIMIT` | 工作区达到额度，本次确定未受理 |
| 429 `ADMISSION_MODEL_LIMIT` | 工作区内该模型达到额度，本次确定未受理 |
| 429 `ADMISSION_STREAM_LIMIT` | 当前工作区 SSE 已满，生成本身不受此错误重新执行 |

上述 429 返回 `Retry-After: 3`，只建议再次检查的最短间隔，不承诺三秒内释放。没有为拒绝创建资源、幂等或受理审计行；释放后可以使用原请求/键再次显式提交。客户端不能因为看到限额已满就禁用受理不明请求的原键重试。数据库 503，尤其 COMMIT 回包连接中断，不能推断未受理，仍应保留原请求和幂等键核对。

实现不维护容易漂移的增减计数：memory 在锁内扫描有界缓存；PG 使用已提交持久资源聚合计数。应用全局状态锁覆盖“检查 → 事务受理”，数据库 session advisory lock 排斥第二写实例。数据库受理事务失败不会留一个独立额度预留；数据库错误沿现有机制停止服务，不能静默回退内存或继续放行。它依赖当前单写约束，不能宣称 COUNT 查询本身提供多实例原子配额。

## 查询与性能边界

`GET /api/v1/runtime` 由观测模块提供当前真实工作区快照，`runs`/`tasks` 含 `active`、`limit`、`queued`、`oldest_queued_seconds`、`models`。模型项含 `model_id`、`kind`、`active`、`limit`、`queued`、`oldest_queued_seconds`。同一工作区切项目仍看到同一总量；不会返回其他工作区数据。

`queued` 只统计当前 QUEUED 状态，可能包含已经被媒体供应商接收但仍在排队的任务。年龄取这些记录中最早 `created_at` 至当前的秒数，是当前排队任务自平台受理以来的时长，不是精确的状态停留时间、队列消耗速度或预计完成时间。不能把 `active - queued` 标成真实执行数，因为它还包含未知和待核实任务。

新增 [004 部分索引](../../db/migrations/004_admission_indexes.sql)，只索引非终态资源的 workspace/model，使历史终态增长不会要求准入扫描全部历史。查询每次受理和工作区快照执行，仍复用单个持锁连接，存在串行 SQL 和全局锁成本；未引入分布式信号量、租约或公平轮转。受保护的全局指标使用有界内存缓存快照，因此其媒体占用可能不含已经淘汰的 parked 记录；不能代替用户额度判定。

## 验证与升级

验证覆盖模型与工作区双层、跨项目累计/跨账户隔离、并发竞争、原键重放与409、确定拒收后原键再提交、取消/失败/完成释放、待核实安全续查不重占名额，以及 PG 淘汰/重启/审计故障回滚。实际执行结果见 014 台账；未设置 TEST_DATABASE_URL 的跳过不算数据库验收。

004 会由内嵌迁移加载器在启动事务中应用；升级前备份数据库。旧二进制不认识004将拒绝启动，不能直接换旧程序回退或删迁移登记。确需回退时在独立库恢复对应升级前备份并验证；保持当前原库和资产供核对。未来 V09/V16 才涉及跨实例领取、分布式准入及公平调度。

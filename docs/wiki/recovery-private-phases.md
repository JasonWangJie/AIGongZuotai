# 启动恢复的私有阶段批读

对应 [V16-A4 契约](../planning/v16a4-contract.md)和 [085 台账](../changes/2026-11-15-085-recovery-private-phases.md)。这是 A4.1 已接线的子实现，整批恢复验收尚未完成。

恢复先按任务 ID 排序，将交付头、逐件收据、首次审核派发、冻结媒体/文本策略及私有候选按页读取。每页最多 128 个任务、16 MiB 保守编码元数据；私有字段不进入公开任务或事件。已有媒体真实字节、收据和密钥验证保持原执行入口，不以批读代替。

单页在只读可重复读事务中进行：先以行 JSON 文本长度核算整页体积，再做四次 SELECT，不进行逐任务往返或整页 JSON 数组聚合。体积包含数据库字段名、时间及 bytea 十六进制，是编码上界口径，并非进程内存。超限在传输私有正文前拒绝；恢复入口只缩小读取页，不重做生成、下载或审核。

全部记录先进入本页临时容器。任一解析/身份/收据失败、事务确认不明，调用方对象保持原值；确认 COMMIT 后才统一替换。并发辅助连接更新不会令体积预检和正文读取混用新旧快照。缺席的历史私有记录保持 nil，不虚构候选或审核通过。

真实 PG 专项已经覆盖 128 个完整交付头、计划项与密文绑定，完整 READY 候选/收据、预算刚好足够及差一字节、末段失败、并发提交快照和 ACK 丢失。固定 5 次 SELECT 不含 BEGIN/COMMIT，也不等于固定网络包数。详见 [ADR 0019](decisions/0019-recovery-private-snapshot.md)。

后续仍需拆除整个 restore 的 5 秒范围、实现页间 Outbox 排空和 generation/lease 分批处理，再验证超过万条实际 New 与进程故障。全量缓存和跨 512 条缓存的准入问题归 A4.2；不宣称本页上界等于完整启动内存有界。

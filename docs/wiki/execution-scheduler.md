# 文本执行公平调度

V16-A1 聚焦单控制写者下的文本执行调度，覆盖旧单轮 Run 与多轮会话生成。调度实现及普通回归已通过，数据库联合验证由集成人串行执行；本页记录实际执行契约，验证结果以 [065 台账](../changes/2026-11-14-065-execution-scheduler.md)为准。V16 整批状态仍由[任务源](../planning/tasks.json)决定，本子项不代表分布式执行或生产容量已经验收。

## 配置与容量含义

Go 配置入口为 `Config.ChatScheduling`，服务端环境变量映射到 `ChatSchedulingConfig`。未设置环境变量时使用下表默认值；显式设置必须为合法范围内的十进制数字，空串、空白、符号、小数或越界值使启动失败，错误不回显原配置值。

| 环境变量 | Go 字段 | 未设置时默认 | 合法范围 | 约束对象 |
| --- | --- | --- | --- | --- |
| `CHAT_WORKERS` | `Workers` | 4 | 1—64 | 全局同时占用文本执行预算的 Run |
| `CHAT_QUEUE_SIZE` | `QueueSize` | 32 | 1—4096 | 全局已受理、等待执行的 Run |
| `CHAT_WORKSPACE_CONCURRENCY` | `WorkspaceConcurrency` | `min(2, Workers)` | 1—64 | 同一工作区同时执行的 Run |
| `CHAT_MODEL_CONCURRENCY` | `ModelConcurrency` | `Workers` | 1—64 | 同一冻结上游模型跨工作区的同时执行数 |
| `CHAT_WORKSPACE_QUEUE_SIZE` | `WorkspaceQueueSize` | `min(8, QueueSize)` | 1—4096 | 同一工作区等待执行的 Run |

各上限同时生效。显式工作区或模型并发上限大于全局 worker 数时，不会增加实际总容量；工作区队列上限大于全局队列时仍受全局上限约束。示例 `.env` 写出的数值是显式配置，修改 worker 或全局队列后，其他已填写值不会自动随之变化。

直接构造 Go `Config` 的既有调用在 `ChatScheduling.Workers/QueueSize` 为零时沿用其 `RunWorkers/QueueSize`；两者均未设置时为表内 4/32。媒体队列继续使用原 `QueueSize`，不因调整聊天队列而改变。独立文本网关 HTTP 连接池的总空闲、单主机空闲和单主机连接上限与文本 worker 数一致；没有新增覆盖整条流的 `http.Client.Timeout`，执行仍受原 `RunTimeout` 上下文限制。

排队容量只计等待执行项，执行预算计已分派且执行函数尚未退出的项。两者均不等于[资源准入](admission.md)的持久未终态占用、钱包额度、token 配额或供应商 QPS。当前只有一个文本网关凭据，`Workers` 同时形成该共享凭据的全局执行并发上限；没有新增多凭据路由。

## 工作区轮转与模型分组

调度器在有候选且具备容量的工作区之间轮转，每次选择一个可执行 Run。一个工作区受限时继续检查其他工作区，不让其等待项独占全局 FIFO 的队首。公平性针对具备执行条件的等待项，不抢占已开始的模型请求，也不承诺固定完成时长。

同一工作区通常按入队顺序执行；如果队首的上游模型并发已满，允许选择该工作区后续使用其他可执行模型的项，以避免模型间阻塞。这不是严格的工作区全队列 FIFO，且不能越过已受理请求的权限或内容审核约束。

模型并发按**受理时冻结的私有 `upstreamModel`**分组。两个公开模型 ID 映射到同一上游模型时共享模型容量，不能通过别名增加并发。已受理 Run 不使用当前目录重算分组、请求体或模型；目录启停和配置重启不使原请求自动重发。模型名与分组身份仅留在服务端内部。

## 受理、分派与释放

调度器的容量检查、入队、取出、取消移除、完成释放和快照均在 `a.mu` 内完成；其中没有网络调用或等待外部容量的操作。等待唤醒和实际 Provider 执行在锁外进行。调度器不持有全局锁等待模型、内容审核或数据库背压消退。

1. 原幂等查询仍优先于新的调度容量判断。同键原请求返回原资源，不重复入队；同键异参保持冲突语义。
2. 新请求在原工作区限制、审核、资源准入及账务流程内检查调度容量。锁外审核后重入仍重新检查原键和当前条件；容量拒绝不创建 Run、消息、幂等或新冻结，不消费报价。
3. 持久受理事务确认成功后才入队。会话、消息、冻结上下文、Run、幂等、审计、Outbox 与账务仍遵循原原子受理流程，调度器不另建可漂移的持久预留。
4. 分派时取得全局、工作区和模型执行预算。`executeRun` 从准备执行直到输出审核、终态保存及其背压处理全部结束后，才释放预算。
5. 已排队 Run 成功取消后立即从等待队列移除，释放排队容量。正在执行的 Run 取消后仍占执行预算，直到执行函数确实退出；不能在下游尚未结束时提前启动替代请求。

调度预算包含输出审核和终态持久化时间，因此 `running` 不等于当前活跃 HTTP 连接数。这个保守边界防止终态背压或取消期间实际工作超出配置并发。

| 拒收代码 | HTTP | 含义 |
| --- | --- | --- |
| `RUN_QUEUE_FULL` | 503 | 全局等待队列已满，本次新请求确定未受理 |
| `EXECUTION_WORKSPACE_QUEUE_LIMIT` | 429 | 当前工作区等待队列已满，本次新请求确定未受理 |

这些明确的容量拒收仍允许已有原键回放；不能把所有 503 都当作确定拒收，数据库提交确认不明须按下述恢复规则处理。

## 故障与恢复

COMMIT 确认不明时不入队；沿用数据库故障熔断，不能把未知受理当作失败并立即再次发送模型请求。用户仍保留原请求和幂等键核对状态。

调度队列、轮转游标、活动计数及等待时长统计只存在于当前进程。持久 Run 的恢复规则保持：重启后未完成文本运行进入 `INTERRUPTED`，不自动恢复执行、再次 POST 或延续旧 TCP 流；原键回放返回已有资源。已开始但未交付的审核候选、待核实账务继续遵守[文本审核执行](moderation-execution.md)和[权益规则](billing-operations.md)。

只支持现有单控制写者；多实例不能各建一个同样大小的内存调度器并据此宣称共享配额有效。应用锁、数据库控制写者与私有目录归属保护继续保留。本批不新增数据库格式或修改媒体租约规则。

## 观测

内部 `ExecutionSchedulerSnapshot` 仅提供总排队数、执行数、活动工作区数量、配置上限、已分派数和等待时长聚合。受保护运维指标使用固定名称，不带工作区、模型、凭据、请求或内容标签。

| 指标 | 含义 |
| --- | --- |
| `studio_chat_scheduler_queued` | 当前进程等待执行数 |
| `studio_chat_scheduler_running` | 占执行预算的数量，包含审核和终态持久化 |
| `studio_chat_scheduler_workspaces` | 有等待或执行项的工作区数量，不包含其身份 |
| `studio_chat_scheduler_workers_limit` | 全局执行上限 |
| `studio_chat_scheduler_queue_limit` | 全局等待上限 |
| `studio_chat_scheduler_workspace_concurrency_limit` | 每工作区执行上限 |
| `studio_chat_scheduler_model_concurrency_limit` | 每冻结上游模型执行上限 |
| `studio_chat_scheduler_workspace_queue_limit` | 每工作区等待上限 |
| `studio_chat_scheduler_dispatched_total` | 本进程累计分派次数 |
| `studio_chat_scheduler_wait_seconds_total` | 已分派项累计等待秒数 |
| `studio_chat_scheduler_wait_seconds_max` | 本进程已观察的最大排队等待，不是 P95/P99 |

统计随进程重启重置，不能替代持久资源准入计数、供应商账单或生产容量报告。用户工作区容量接口不因此变成全局运维入口。

## 本批限制与待验收项

V16-A1 不拆媒体 submit/query/import/审核执行通道，不实现多凭据分配、供应商自动限流重试、持久 token 日志、断点续接生成或全站多实例。媒体执行现状见[任务租约](scheduler.md)。单个慢请求仍可占用其预算直到超时或结束，轮转不是抢占式调度。

六项调度器与 HTTP 池单元检查已通过，覆盖轮转游标删除、工作区与模型预算、模型阻塞跳过、队列边界、取消、5000 步状态转换和无全流短超时。Run、Conversation、Moderation、Admission、Cancel 与 Billing 等普通回归通过。真实 App/PG 联合验证另覆盖原键优先、事务失败零入队、运行取消迟返不提前释放及同上游别名容量；完整命令、结果与尚未运行项见 065 及关联集成台账。任何本地结果都不代表真实网关容量或 V16 整批验收。

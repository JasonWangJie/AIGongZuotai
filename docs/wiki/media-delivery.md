# 媒体持久私有交付

本页主体保留已验收A3.1/018交付规则。当前已验收A3.2将首次审核进一步交接到独立review通道，019 READY/STARTED规则见[契约](../planning/v16a32-contract.md)与[079](../changes/2026-11-14-079-media-review-dispatch-integration.md)；下文同步审核占delivery的描述是v0.18阶段行为，当前四通道独立验收见079。

V16-A3.1 将原生异步媒体的结果查询与下载导入拆成持久交接：查询只取得原结果清单，事务提交加密清单及计划资产身份后，独立 delivery 通道才读取、校验和导入文件。单件完成收据逐件保存；重启继续同一份清单，不再 Query 取得另一批结果，也不再 POST 生成。

核心实现与验证记录见 [072](../changes/2026-11-14-072-media-delivery.md)，适配器、维护和根联合证据分别见 [073](../changes/2026-11-14-073-media-delivery-provider.md)、[074](../changes/2026-11-14-074-delivery-storage-maintenance.md)、[075](../changes/2026-11-14-075-media-delivery-integration.md)。完整 V16 仍进行中；首次审核分派、渠道公平退避及 token 持久流不在本次范围。

## 配置与启用

| 配置 | 作用与限制 |
| --- | --- |
| `MEDIA_DELIVERY_WORKERS` / `MediaScheduling.DeliveryWorkers` | 默认 2，显式范围 1—16；独立工作线程、执行预算和 PG 连接容量。 |
| `MEDIA_DELIVERY_KEY` / `MediaDelivery.EncryptionKey` | 32 字节密钥的规范标准 base64；PG 原生分阶段适配器必须配置，禁止复用网关、邮件队列或 SMTP 凭据。 |

没有另一个默认关闭开关。PG 使用实现 `MediaDeliveryProvider` 的适配器时自动进入该链路，缺失或非法密钥在迁移之前拒绝启动。数据库已有任意交付记录时，即使关闭供应商仍须提供原密钥；存在 READY 交付还必须配置兼容适配器。密钥错误不回显密钥或原 URL。

内存模式的原生 Async 也使用三个阶段，没有配置密钥时用本次进程的随机密钥；这不提供重启恢复。普通 SVG demo 和没有分阶段接口的旧测试适配器保持旧行为，不能用于证明本批持久交付。旧 Go `TaskWorkers` 仍分配 submit/query 的最小预算，另加默认 delivery 2，最终总数包含三个通道；旧值 1 实际最少为 1+1+2。公开配置应分别设置三个 lane。

## 持久边界

1. Submit 使用受理时冻结的请求；无 handle 的 SUBMITTING 恢复仍为未知，不再次提交。
2. QueryStatus 只读取原 handle 状态。成功或 PARTIAL 时校验 1—4 个有序描述，私有来源 URL 每件不超过 8 KiB。返回的公开 `MediaResult` 不含这些 URL，也不含产物。
3. 在当前 lease 的控制写事务内保存加密 manifest、连续位置与确定的 `asset_id`，同时把任务置为 INGESTING 并写 Outbox。提交确认后才交给 delivery。
4. delivery 从同一加密清单读取每件来源。完成原件、缩略图及配置的 S3 写入后，存储写入完整完成标记；随后同 lease 事务冻结完整 `AssetInfo` 收据，再处理下一件。
5. 已有收据必须校验现有原件和缩略图的真实完整字节、身份及存储版本。PG 已登记而文件或完成标记缺失时，直接隔离，禁止重新下载替换。文件已完成但 SQL 收据未确认时，可校验原完成标记后补回同一收据。
6. 整组完成后才进入原 B2 候选持久化和审核。整组允许时，公开产物、资源库注册、权益、Outbox 与交付 COMPLETE 同事务；任一失败不泄露部分产物。

`018` 新增 `studio_media_deliveries` 和 `studio_media_delivery_items`。交付状态为 READY、COMPLETE、PARKED，私有交付版本与任务版本、审核版本分开。header 的身份、来源摘要、密文及原结果状态不可修改；单件收据只能从 NULL 写入一次。缺少私有字段的旧保存路径必须加载并保留已登记证据，不能清空后回到 Query。

AES-GCM 的不可变 AAD 绑定稳定数据库存储 UUID、作用域、任务、交付、handle 摘要、清单摘要、结果状态及格式版本；不绑定会变化的进度版本。清单明文上限 64 KiB，私有表只存密文；普通 Task、事件、审计、指标、资产 manifest 不存来源 URL。恢复原数据库必须同时保留其存储 UUID 与原密钥，不能仅把同一密文拷贝到另一个身份。

## 并发、取消与确认不明

预算在领取之前保留。submit、query、delivery 各有固定 worker 与独立 PG 连接；查询提交清单后结束该步，慢下载不能继续占用 query 预算。delivery 预算覆盖导入、当前同步审核、终态保存背压及心跳退出。取消或撤销 lease 不提前释放仍在工作的槽位；迟到结果仍必须满足 owner/epoch/generation 和预期任务版本。

Outbox 满只重试当前保存，保留原清单或收据，不重复外发。真正的 COMMIT ACK 丢失使存储失败关闭，不更新缓存或发布通知；恢复按数据库已提交事实继续。清单或收据已经存在的任务不可用户/运营 reconcile 回 Query。没有交付清单、没有 B2 候选且原规则明确许可的旧 handle 才能继续原 Query。

若清单事务实际回滚，数据库没有交付记录，且尚未下载任何文件，恢复可以再次查询同一原 handle，再冻结该次响应的完整集合。这与已有清单后换批不同，也不是重新提交生成。四阶段 ACK 测试验证已提交但确认丢失，原子回滚测试另外验证未提交分支，二者不可混用。

保留原 B2 隔离边界：已有候选的重领或进程恢复不会重新审核，仍转 REVIEW。关闭审核、财务 charge/release、解除工作区限制均不能放行隔离内容。财务操作可以改变权益决定，但不改交付来源或内容决定。

## 保留与恢复

所有状态的计划资产身份均在 GC 保护集合中；计划尚未完成时允许文件不存在，但已存在文件不能被当作孤立文件清除。已登记收据的原件、缩略图和完整身份是强制可达内容，即使任务已取消、失败或 PARKED 也必须保留。维护精确摘要包含私有交付证据。

018 升级和恢复需联备 PG、ASSET_DIR、REFERENCE_DIR、交付密钥以及其他已启用队列密钥。离线工具精确格式栅栏升级到 001—018；不得删除迁移、owner、候选、计划或收据强行回退。改变完整收据中的 backend/object locator 会破坏不可变身份，因此本批 S3 迁移拒绝处理已登记 delivery 收据，不能用迁移覆盖它们。

## 验证范围与后续

核心普通测试覆盖 AEAD 篡改、数据库/任务/作用域/handle 绑定、四件长 URL 清单与独立密钥。真实 PG COMMIT ACK 故障覆盖清单、单件收据、B2 候选及最终放行四处；详细命令、耗时及事务回归见 072。根另行验证实际 Async HTTP 的慢下载、两件恢复、图/视频与审核、权益和联备，最终以 075 为准。

真实 017→018 专项使用同一 embedFS 的原 17 份 SQL 建旧库，再由当前加载器升级，已通过 1.364s。旧任务/请求/幂等/政策/候选的数据库规范 JSON 及私有 PNG 字节均保持；新增交付表为空，旧原 handle 仍仅查询，未知提交和已隔离候选不恢复执行，旧 017 写者拒绝 018。该证据没有删除迁移登记来模拟回退。

仍为单控制写者，三个连接池不是全站多实例。delivery 当前含同步首次审核，独立审核 READY/STARTED 分派属于 A3.2；工作区/渠道公平、持久 Retry-After、自适应降级和大样本领取 EXPLAIN 属于 A3.3。018 的 READY 查找索引并未证明混合任务到期索引在积压下有扫描成本隔离。fixture 不代表真实供应商、真实审核准确率或生产容量。

未完成项仅能冻结协议给出的来源、类型和大小声明；协议没有可信文件版本或预期内容哈希时，不能证明远端 URL 在导入前一直返回同一字节。完成导入后才由实际内容哈希和完整收据约束恢复。过期 URL 不自动换签、不重新 Query 寻找替代文件；来源不再可验证时隔离待核实。

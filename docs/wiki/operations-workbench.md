# 运营异常核实台

V14-A / H01、H03、H05、H06、H08。本页记录星图工作台中已接线的运营前端；服务端权限和事务规则见[V14-A接口契约](../planning/v14a-contract.md)。完整V14还包括后续内容审核、申诉、封禁与风控，本页面不提供这些未实现入口，也不提供在线角色管理或支付退款。

## 入口与权限范围

登录后只读获取 `/api/v1/operations/access`。只有具体授权列表中存在 `read` 的工作区才显示“运营核实”导航；`enabled=true`只说明服务配置，不自动授予角色。没有权限或服务停用时不显示入口，服务端仍逐次核验所有资源权限，导航隐藏不是鉴权。

运营页有独立的授权工作区选择器，不继承创作项目的 `X-Project-ID`。同一工作区的多个角色取服务端明确permission并集；observer只读，operator按investigate核对原任务或仅关闭工单，finance按finance核实冻结。建立工单另需case_open。客户端不根据角色名字自行扩权，权限变化仍以服务端重核结果为准。

界面沿用品牌暗色底与Bahnschrift数字字体，以amber标识待核实。独立工作区条、左侧队列和右侧顺序处置区域形成操作台；运营页隐藏创作参数Inspector，避免将创作项目与运营范围混淆。移动端改为上下布局，支持键盘焦点及reduced-motion。

## 队列、工单与证据

异常资源按all/run/task筛选，工单按all/OPEN/RESOLVED筛选；默认每页20，客户端每列表最多保留200条，继续需要缩小筛选或刷新。工作区、筛选变化取消旧读取；组件按账户与运营工作区隔离，晚到回包不能覆盖新范围。

仅显示资源/项目/公开模型ID、模式、状态、版本、冻结摘要等安全元信息。不显示提示词、模型输出、邮箱、上游handle、原始URL或凭据。异常含open_case_id时直接打开现有未结工单，避免重复建单。

开单携带当前resource_version、固定原因、证据编号和独立Idempotency-Key。原因仅五项：上游状态不明、交付结果异常、计量缺失或矛盾、冻结额度核实、人工复核。证据编号使用1—128安全ASCII字符，例如ticket:001，不接受网址或任意证据正文。真实证据需要运营在外部核实，此处仅保存可追溯短编号。

工单详情读取当前安全资源快照，开单绑定版本与当前版本分开显示。处置收据及分页审计展示服务端已经提交的元信息；空审计列表不等于操作未执行。

## 预演与明确提交

1. 选择服务端permission及当前资源状态允许的动作，填写原因和证据。核对原任务只恢复原handle查询，不创建新的生成；no_action只关闭工单，不改变任务或余额。
2. 财务动作必须显式确认外部证据。真实LLM输入/输出/总token均手工填写已核实的整数且总和一致，不根据文字长度估算；mode来自安全资源元信息，demo synthetic与live gateway来源分别标明。媒体填写真实交付产物数量，不用请求数或进度替代证据。
3. 请求预演并校验case/version/action、64位hex摘要、有效期和固定精度金额。页面显示本次新增消费及释放冻结的0→增量，不把它称为最终钱包余额。输入变化立即清除旧预演和密码。
4. 操作员再次勾选“明确执行”并输入当前账户密码，才POST execute。密码在网络请求序列化后立刻从临时对象及输入控件清除；不进入localStorage、sessionStorage、URL、恢复仓或生成任务重试机制。
5. 成功必须是匹配工作区、工单及plan_id的服务端Case收据，不能只依据HTTP 200宣布成功。服务端权限、凭据、版本或预演变化时停止，重新读取并预演。

密码核验失败使用明确提示，不将403错误误作退出登录。敏感操作进行时禁止切页、切项目、切工作区或退出；浏览器刷新/关闭仍会提示。预演过期只禁用确认，不自动重新预演或执行。

## 受理不明和离开保护

网络错误、5xx或不能确认的成功响应保留“结果待核对”，不自动重发开单、预演或execute。只能GET工单/收据核对；开单不明先查工单列表，按资源选择关联单。输入中的密码、用量证据和完整执行正文不会保存在恢复仓；原开单的安全body/key、execute的caseID/planID仅在当前App实例内存按user+workspace保存，最多64个待核对范围，满额拒绝新增而不丢旧项。

离开当前工作区、页面或退出前提示已发请求不会撤回；密码清空，同账号同工作区返回可继续核对内存编号。刷新/关闭浏览器会丢失该内存记录，需要从服务端工单列表定位；不是离线持久恢复。其他账号不能读取原账号恢复项。每次请求带独立的内存attempt标识，旧组件的迟到回包只清理自身记录，不能擦掉同账号重新登录后建立的新待确认操作；授权工作区列表保留服务端上限内的完整范围，不在64项处静默截断。已经确认的execute收据匹配原plan_id后解除阻断；不会用另一工单或另一计划的成功结果冒充原请求成功。

人工核销仍遵循V12政策：原冻结单处置为最终决定，后续按原handle找回成果不再收费。客户端不添加赠额、任意收费、退款或核销范围之外的动作。

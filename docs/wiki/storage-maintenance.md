# 私有存储离线维护

维护用于清理**数据库完全不再引用的旧本地文件**，不等于清空回收站。入口为[cmd/maintenance](../../cmd/maintenance/main.go)，实现及证据见[029台账](../changes/2026-11-13-029-storage-maintenance.md)和[ADR0005](decisions/0005-private-library-lifecycle.md)。当前没有远端S3对象删除、在线定时GC或用户永久删除。

## 运行前提与双锁

必须先停止工作台写入进程。维护按顺序取得REFERENCE_DIR、ASSET_DIR的跨进程OS租用锁，再取得应用使用的PG session advisory writer锁；任一锁失败即拒绝。目录路径会解析已有符号链接并排序去重，两个私有目录不得相等/互相嵌套，也不得与APP_WEB_DIR或Vite public重叠。

`.studio-writer.lock`只是OS锁的载体，进程关闭后文件仍存在；不能凭它存在判断“死锁”，也不能删除它绕过互斥。应用、离线维护和存储迁移必须使用相同租用约定。操作系统会在持有者退出时释放锁，本机子进程测试已验证互斥；它不是多机分布式租约。

维护需要DATABASE_URL，不能使用memory元数据猜测可达性。当前数据库必须恰好含001—015版本；CLI不会运行迁移、启动worker、登录供应商或发起生成。它不自动读取.env，终端应先提供与实际工作台一致的私有服务端环境。

## 数据库与目录归属

007迁移建立studio_storage_identity中的UUID。正常PG应用启动在双锁下核对REFERENCE_DIR与ASSET_DIR的`.studio-storage-owner.json`，标记包含UUID、版本和references/assets角色。两个目录不能交换角色，不同UUID的数据库不能接管；memory启动拒绝已经归属PG的目录。

首次绑定允许新空目录，或旧目录的全部已发布文件都能被该数据库可达集合解释。未知已发布文件拒绝绑定；符合严格命名的未发布临时文件可以留待旧文件维护。维护本身只接受已有且匹配的owner标记，不自动创建或改写它。

首次升级遇到拒绝时，应停止写入，保留数据库和完整文件备份，核对是否选错数据库/目录、是否缺少元数据或存在历史孤立文件。先恢复配套记录或经过人工审核隔离未归属文件，再按正常启动规则绑定；不能通过删marker、改UUID或删除schema登记消除报错。owner标记是成套备份的一部分。

## 保护与候选规则

数据库可达集合包含全部reference的原图和缩略图、全部task的不可变编辑正文BodyFileID、全部task的私有artifact IDs。**没有按active/trash或任务终态过滤**：回收站仍可恢复，终态任务仍有历史结果和原请求，全部保留。

扫描前核对这些引用对应的本地文件是普通文件。产物需要原件.bin与收据.json，收据声明缩略图时还需要.thumb.png；缺文件、损坏收据或错误目录都先拒绝维护。已迁移S3的内容本批仍保留本地原件，因此这里不会用S3地址或URL有效期判断可删除。

只有同时符合以下条件才成为候选：

1. 不属于以上任何可达引用。
2. 文件名严格属于已知blob原件、asset原件/收据/缩略图，或实现定义的随机临时文件名。
3. 是非符号链接的普通文件，且最后修改时间严格早于最低年龄截止。
4. 打开前后是同一个文件，读取期间大小和mtime没有变化，能完整计算SHA256。

未知名字、目录、非普通文件及锁/owner标记不成为候选。扫描只处理私有目录的直接条目，不递归删除目录。

| 预算 | 当前限制 |
| --- | --- |
| 最低年龄 | 默认24小时，允许24小时至3650天；不能降低至24小时以下 |
| 枚举条目 | 两个目录合计最多100000项，包括受保护/近期/忽略条目 |
| 数据库可达集合 | 最多100000项身份，超过拒绝并要求受审查的分区维护方案 |
| 候选数量 | 不会超过枚举上界；没有独立无限候选队列 |
| 单候选读取 | 最大256 MiB，64 KiB缓冲计算hash |
| CLI执行 | 总context两分钟；取消/超时返回错误和当前报告 |

这些上界是拒绝条件，不是已通过100000文件或大容量压测的成绩。

## 操作顺序与计划摘要

在已设置正确DATABASE_URL、REFERENCE_DIR、ASSET_DIR、APP_WEB_DIR的私有终端执行。命令不会回显数据库连接串，但JSON报告含解析后的本地路径、文件名、大小、SHA256，应作为运维文件保管，不公开发布。

```powershell
go run ./cmd/maintenance > .runtime/storage-maintenance-plan.json
```

默认dry-run仅报告。检查进程退出码及JSON中的候选、目录、受保护/近期/忽略数量、总候选字节和plan_digest。不能只看报告文件存在就认定成功；CLI遇错误也输出当前报告，错误写stderr，退出码为1。无关命令行参数退出2。

确认候选和备份后，使用该次报告的确切摘要显式执行：

```powershell
go run ./cmd/maintenance --apply --plan-digest="替换为已审阅计划中的64位摘要"
```

`--min-age=48h`可以使用更长保护期；apply必须保持与审阅计划一致。这里展示命令，不代表已经授权或执行真实数据删除。仓库测试只在自身临时目录执行apply。

apply会重新取双锁、验证owner、查询可达集合、扫描文件并生成新摘要。摘要涵盖schema、真实目录、年龄条件、排序后的可达集合与候选的内容/身份信息。新摘要与传入值不同则拒绝；新文件跨过年龄截止也可能改变候选，须重新审阅dry-run。

摘要一致后，在第一项删除前再次打开并核对**全部**候选的身份、长度、mtime和SHA256，再检查PG连接。此后只删除os.Root内已核对文件，不删除数据库业务记录或远端对象。plan_digest是变更检测值，不是绕过归属、锁或权限的凭证。

## 失败和恢复

预检查失败时不开始删除。删除阶段不是文件系统事务：某项移除失败或context取消后，前面已移除的文件不会自动还原。JSON的removed_files、removed_bytes和applied区分部分完成与全部成功。保留报告，查明原因，必要时从备份恢复；之后重新dry-run，不自动反复使用旧摘要。

备份必须联合覆盖PG数据库、REFERENCE_DIR、ASSET_DIR及对象存储对象/本地收据，并保留同一storage UUID与目录角色标记。只恢复数据库无法恢复原文件或编辑正文，只恢复目录也不能证明正确引用关系。007后旧程序拒绝启动；回退用匹配旧版本的独立库和私有目录备份，保留升级后的原库与新作品。

数据库损坏、失联、可达文件缺失和错库应先修复再维护。不要通过删marker、删锁文件、关闭摘要校验、降低年龄保护或改迁移登记强行删除。备份恢复与生产RPO/RTO仍需独立演练，本批本机测试不替代灾备放行。

相关用例已包含在子代理实际执行的32.302秒真实PG全量测试和go vet中；根最终独立构建、PG与浏览器结果见030台账。当前Windows缺少创建符号链接权限，相关子例未执行并明确记录。没有运行用户目录apply、远端删除或生产灾备演练。

## V14-A阶段格式与运营边界

在012权益账本之后，013/014加入作用域运营授权、审计、工单、预演和不可变回执，V14-A交付时维护工具只接受完整001—014。这些元数据不改变既有私有文件可达性保护；异常任务已结案、冻结已释放或租约已撤销，都不能推导参考原件、编辑正文或历史产物可删除。线上异常核实范围见[运营权限](operations-access.md)和[异常队列与工单](operations-cases.md)，运营角色也不因此获得文件删除权限。

013/014升级与回退仍要求停写并联合备份数据库、私有目录、同一storage UUID/owner以及启用邮件时的必要队列密钥。关闭运营入口不会撤销已提交处置；恢复历史版本需使用对应联备，不删除迁移登记、审计、回执或owner强行降级。历史029/030/034/038/042验证保持原有范围，V14-A格式的联合验证见[050集成记录](../changes/2026-11-14-050-operations-integration.md)；没有执行用户目录apply或新增线上GC能力。

## V14-B1当前格式与文本隔离

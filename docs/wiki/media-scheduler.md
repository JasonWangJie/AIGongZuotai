# 媒体公平调度与持久退避

V16-A3.3在原submit/query/delivery/review四通道上增加工作区轮转、冻结渠道执行预算及持久退避。当前核心及完整联合验收已通过，事实见[083](../changes/2026-11-15-083-media-scheduler-integration.md)；完整V16仍进行中。范围以[本批契约](../planning/v16a33-contract.md)及[任务源](../planning/tasks.json)为准，实际修正记录见[080](../changes/2026-11-15-080-media-scheduler.md)。

## 预算与公平

`MEDIA_WORKSPACE_CONCURRENCY`默认1、`MEDIA_CHANNEL_CONCURRENCY`默认2，均支持显式十进制1—32。每个lane分别取配置值与该lane worker数的较小值。预算覆盖真实外部调用、审核、保存背压及清理；用户取消不能提前归还仍在工作的槽位。

生产仍只有一个配置的Async媒体网关。submit/query使用原受理快照的ProviderIdentity分桶，同网关不同模型别名共享预算；review使用原冻结审核adapter身份。私有指纹不进入公开JSON、日志或指标。没有增加多渠道路由、自动换模型、凭据热切换或POST健康探测。

旧适配器可能保存opaque身份。相同opaque或仅一侧旧身份使用保守legacy桶，原串仍完整交原适配器校验；这不代表任意身份获得原生网关认证。两侧非空身份冲突时，控制事务明确转待核实、保留原字节及权益，不让任务永久留在活跃队列中。已有结果审核不依赖重新启用生成网关。

每次选择最多16个工作区、每工作区8个活跃任务。工作区与任务游标按keyset推进，遇到未来到期、租约、冷却或预算繁忙也不回到同一队首。固定活跃集合能持续轮转；全局工作区数无硬上限，不能承诺与集合大小无关的绝对等待时间。

## 退避、查询探测与恢复

HTTP适配器报告封闭的gateway/source/storage/review事实。默认3秒不是服务端Retry-After；取消不处罚渠道，下载和存储错误不污染生成网关。正常查询的无进度计数与失败计数分开，实际进度增加后恢复基础间隔。

临时查询/交付失败使用指数退避，基数从3秒到最多5分钟，增加0—25%的确定性正向抖动；还要取配置基础间隔及原服务端截止的最大值。无进度查询的递增基数最多1分钟，同样增加正向抖动。已经算出的时间持久保存，重启和事务重试不会重抽成更短等待。

429或连续故障降低有效并发，硬上限仍由配置限定。失败query通道到期后仅允许一个原handle GET探测；匹配探测成功后逐步恢复，较早请求的迟到成功不能抹掉更新的冷却。submit没有POST探测；当前POST429仍不自动重投，未知提交继续隔离。没有原handle时，只能等冷却结束执行其他原本尚未首次发送的合法任务。

下载成功恢复仅依据实际完整HTTP读取与导入事实。完整收据重放、本地原件复用不伪造源HTTP成功。多件审核合并最严重观察和最晚服务端截止，失败观察时间取实际后件响应，不用第一件成功时间提前结束冷却。

服务端要求超过24小时：若截止可表示，原样保存，不截短；当前任务停自动查询，原handle及无候选的输入策略保留，权益待核实。普通用户及运营显式核对在原截止前均拒绝且不改变资源，截止后仍只查询原handle。超大整数等无法表示的协议值不伪造截止：当前任务停止自动查询，其他任务进入明确、有界的协议故障降级；不能宣称遵从一个无法表示的时间。没有无限、不可恢复的全渠道封锁。

## 审核和交付边界

共享审核仍只有两个物理许可。input/output都有等待时轮转，输入类别内按工作区轮转；最多16个输入等待、每工作区2个、最长10秒，输出等待不超过两个review worker。容量拒绝是业务错误，不是内容BLOCK/REVIEW。任务输入和参考上传均接有作用域入口。

冷却不产生新审核授权。新READY才可首次审核；STARTED发生429、取消、失租或确认不明仍整组REVIEW，不重新审核。原交付描述不因冷却重新Query换批；完整收据不重下。旧候选不补READY。关闭审核、财务处置或人工核对都不能放行隔离内容。

# V17 固定速率媒体任务的完整生命周期

259 从两个工作区经正式注册和新会话登录使用普通图片任务 API。驱动按固定时隙投放，同一任务的受理、供应商 POST、原 handle 轮询、数据库终态与原键收据一一核对。测试在新的 PostgreSQL schema 内运行，模型对端与应用仅监听本次创建的环回地址。

| 档位 | 输入速率 | 预热／稳态 | 上游任务寿命 | 查询提示／回环处理 | 计划新任务 |
| --- | --- | --- | --- | --- | --- |
| `pilot` | 1 项/秒 | 各 12 秒 | 12 秒 | 3 秒／200 毫秒 | 24 |
| `1ps` | 1 项/秒 | 各 600 秒 | 600 秒 | 10 秒／200 毫秒 | 1,200 |

两档共用相同驱动和调度路径，最后停止新投放，独立排空任务及原查询。计时从回环端接受该任务的初始 POST 开始。进入终态由真实经过时间决定；工作区任务通过平台查询得到已知的供应商失败 `UPSTREAM_GENERATION_FAILED`。报告分别测量任务创建至已持久终态的文档时间，以及正常 202 回执至独立 PostgreSQL 读者首次看到终态的时间。查询间距另含处理、保存、退避和调度等待。

## 串行复测

集成人先为当前 PowerShell 会话设置专用环回测试库的 `TEST_DATABASE_URL`，确认同一数据库的其他测试已经退出。下面的命令从当前待测源目录运行，短档通过后才启动长档。每档新建独立 schema 和独占报告。常规测试默认跳过。

```powershell
$openLoopOutput = New-Item -ItemType Directory -Path (Join-Path ([IO.Path]::GetTempPath()) ("v17-media-259-" + [guid]::NewGuid().ToString("N")))
$env:STUDIO_MEDIA_OPENLOOP_FAULT = ''
foreach ($openLoopTier in 'pilot','1ps') {
  $env:STUDIO_MEDIA_OPENLOOP = $openLoopTier
  $env:STUDIO_MEDIA_OPENLOOP_REPORT = Join-Path $openLoopOutput.FullName "$openLoopTier.ndjson"
  go test -count=1 -p 1 -parallel 1 -timeout 42m -run '^TestPostgresOpenLoopMediaLifecycle259$' -v ./internal/studio
  if ($LASTEXITCODE -ne 0) { throw "259 $openLoopTier failed" }
}
```

基线通过后可另开新报告，选用 `STUDIO_MEDIA_OPENLOOP_FAULT=one429` 做一次受控上游限流。普通任务 API 的 429 与网关原查询的 429 分开计数。所有未知受理保留原键，本工具没有自动补投时隙或替换缺失 handle 的动作。

## 读报告

NDJSON 的配置和采样进度在运行中写盘。逐窗记录分为预热、稳态和排空，最后一个窗口按实际时长计算。结论需同时有测试成功退出及最后的 `complete=true`。计划、漏投、实际发送和收到的首次 202 分开统计。收到 HTTP 202 之后单独核对真正的上游 POST 和持久身份。每个在途样本由独立 PG 读取，窗内显示最小、最大与采样均值。每个终态的业务时间和首次读到的时间分别归窗。原键回查另在负载结束后执行。

原 handle 的每次写出、网关到达、回复和终态提交属于不同阶段。判断是否积压时，先看与成功返回无关的 PG 采样，再看 HTTP 写出及当前网关并发。调度快照可能跨过短促的投影轮次，报告保留实际采到的轮次、缺口与窗末样本。未见过某个到期轮次，无法据此判定它从未到期。报告中的 `ProjectionObservedBeforeWrite` 给出全部成功 WroteRequest 数、在写出前后都独立读到同一投影版本的可证实数及覆盖率下界。窗内最后一次独立查询的时刻、距实窗末的新鲜度以及最老未写等待一起解读；没有采样的窗口返回空前沿。网关按每个 GET 实际进入至作出响应的时段在窗内积分，给出平均同时处理数。计数、分位和速率均应以对应窗口及样本量解读。

## 固定环境验收条件

1 项／秒、平均 600 秒在途、10 秒一个查询轮次、平均 200 毫秒服务的规划值，约对应 600 个在途任务、60 个 GET／秒和 12 个并发 GET。档位参数是输入，实际在途、查询速率、相邻原 handle 的写出间距和观察到的终态时间均由报告给出。无鉴权外部负载入口和 100 项／秒等高档未开放。

正式的 100 项／秒、60,000 正常在途、6,000 原 GET／秒及约 1,200 查询并发仍需在固定部署上持续投放，以独立负载机和可用的网关真实配额分别验收。若单渠道最多 2,000 成功 GET／秒，60,000 个任务平均最多约每 30 秒查询一次。成功吞吐、限流拒绝和冷却分开计算。此处使用同机真实 HTTP 回环，目标容量、真实供应商限额、成功资产交付及 24 小时稳态保留各自门槛。

## 本机实测

短档各 24 次正式受理，基线 96 次原 GET，受控限流档 95 次原 GET、1 次供应商 429，两档均收到全部原键收据。

长档每秒 1 次新受理，预热和稳态各 600 秒。稳态 600 次 202、596 项持久终态，在途均值 604.78 项，独立采样范围 600–610 项。稳态写出 34,512 次原 GET（57.520 次/秒），对端 2xx 为 57.502 次/秒，同时处理均值 11.52。

全程 1,200 次 202、1,200 次原 POST、69,312 次原 GET、1,200 个已知供应商失败终态及 1,200 份匹配原键收据。停止投放后 605.006 秒排空。全程有 68,112 个同句柄查询间隔，中位 10.431 秒、P95 10.831 秒。回环 GET 服务实测均值 200.344 毫秒。

独立 PostgreSQL 采样 1,806 次。全程 16,542/69,312 次写出被同一版本前后采样夹住，覆盖下界 23.87%，其余 52,770 次保留为未匹配。稳态 10/10 个窗口有窗末采样。这些时点已过有效时间门禁、可证实尚未写出的项数下界最大为 17。采样间隙内的积压峰值未知。

应用、驱动、模型回环共用一台机器，PostgreSQL 独立进程。实际成功资产交付、固定部署的每秒 100 个新任务及 6,000 次原 GET、24 小时持续运行仍需独立验收。

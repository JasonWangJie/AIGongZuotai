# 工作区生成限制与申诉

关联 V14-C1，横切 H01 身份与权限、H03 模型与执行、H06 审核与运营、H07 可靠性、H08 工作台和 H09 交付治理。C1覆盖工作区新生成限制、解除、用户申诉和有实际效果的运营复核。核心Go、017迁移和HTTP接口已落盘，普通及真实PostgreSQL专项通过；浏览器和最终联合验收仍由集成人确认，完整V14仍未完成。证据见[059](../changes/2026-11-14-059-generation-controls.md)。

现有文本与媒体内容审核分别见[文本审核执行](moderation-execution.md)和[媒体审核执行](media-moderation-execution.md)；运营身份基础见[权限与角色管理](operations-access.md)。C1 不改变这些内容决定，也不提供隔离内容人工放行。

## 限制的对象与效果

限制对象是明确的工作区，不是登录账户或当前项目。工作区处于 `RESTRICTED` 时，所有项目的新单轮聊天、多轮回复、编辑消息后生成、显式继续、图片生成、图片编辑和视频生成均应在受理前被拒绝；不能通过切换项目绕过。`OPEN` 仅表示没有工作区生成限制，不替代模型目录、资源配额、权益、文本审核或媒体审核检查。

此前已受理的 Run/Task 继续使用原请求、模型快照及既有状态机。原幂等键与相同请求返回原资源，优先于当前限制状态；同键异参仍拒绝。已受理任务不会因为限制或解除再次 POST 供应商。原 handle 的查询、核对、取消以及原有下载门禁保持原规则，不以工作区限制推定任务免费、取消成功或内容可见。

登录、账号安全、历史读取、已获准产物下载、账务查看、申诉及结果查询继续可用。C1 不扩展到账户登录封禁、自动风控、支付或退款；C2/C3 和真实渠道验收另行推进。

## 状态、限制轮次与版本

| 对象 | 状态或约束 | 含义 |
| --- | --- | --- |
| 工作区生成状态 | `OPEN` / `RESTRICTED` | 缺少状态行按 `OPEN`、版本 1 解释；首次实际变更为版本 2 |
| 限制轮次 | `grst_...` | 每次从开放进入限制建立独立轮次；解除后再次限制产生新轮次 |
| 申诉 | `OPEN` → `RESOLVED` | 每轮次、每申请人最多一份；原申诉正文不被后续决议改写 |
| 申诉结果 | `UPHELD` / `LIFTED` | 分别表示维持限制或解除限制，不代表批准某个生成内容 |
| 业务版本 | 各自独立 | 工作区状态、申诉版本、计划ID和收据定位不能互相替代 |

解除必须绑定当前限制轮次及工作区状态版本。旧轮次的申诉、旧预演或旧执行收据均不能解除后续新轮次。解除时，在同一事务内解决该轮次全部仍为 `OPEN` 的申诉，结果为 `LIFTED`；既有 `RESOLVED/UPHELD` 历史保持不变。读取历史申诉时应区分“该次申诉当时的结果”和“工作区现在的状态”。

缺行默认开放只是读模型约定，读取不会创建控制行。`lockGenerationWorkspaceSQL`直接锁稳定的`studio_workspaces`行：生成准入使用`FOR SHARE`，治理变更使用`FOR UPDATE`，即使尚无控制行也有共同的串行核验点。状态最大版本为JavaScript安全整数9007199254740991；新增限制需为下一次解除保留一次修订，不能把最后一个版本用于限制。真实PG独立连接已通过`pg_blocking_pids`验证双向等待及提交后读取新状态，见059。

## 普通用户的申诉链路

用户先读取当前工作区的生成状态及公开原因，再对明确的当前限制轮次提交申诉。目标工作区由已认证身份确定，不接受任意客户端工作区冒充；申诉详情同时校验工作区、轮次及申请人归属。

申诉说明 `statement` 和公开回复 `public_reply` 各最多 1024 UTF-8 字节，拒绝无效编码及控制字符，允许换行。长度按字节计算，不承诺 1024 个汉字。正文只在经过授权的详情读取中返回；列表和站内通知使用安全摘要。申请人应避免填写密码、密钥或与申诉无关的个人资料。

提交使用独立幂等键，绑定申请人、工作区、限制轮次及完整原始请求；同键异参拒绝。网络受理不明时保留原请求和原键，先只读查询该轮次已有申诉，不自动换键重提。每轮次每申请人仅一份申诉的唯一性约束，不能只由前端禁用按钮实现。

申诉被维持后保留原结案记录。后续若工作区被解除，用户仍可看到当前状态已开放，但原 `UPHELD` 不改写为另一个历史结果。C1 不实现补充材料往返、多级申诉、自动重审或无限重复开单。

## 运营复核与明确执行

新增独立 `moderator` 角色，由既有停机角色管理流程显式授予目标用户和工作区。工作区 owner、注册用户及现有 observer/operator/finance 不自动获得新权限。运营范围来自独立授权选择器，不继承创作项目，也不依赖界面入口隐藏作鉴权。

本批只有三类动作：`restrict_future`限制新生成、`uphold_restriction`维持目标申诉对应限制、`lift_restriction`解除当前限制。限制和解除要求`generation_restrict`权限，维持要求`appeal_resolve`；两项均由显式moderator授权提供，不沿用财务动作的名称表达内容治理。

操作沿用“读取 → 预演 → 核对效果 → 当前密码确认 → 执行 → 读取已提交收据”的流程。预演在SAVEPOINT内实际应用决议并检查延迟约束，然后回滚业务试算；保存5分钟有效计划及64位小写十六进制摘要。计划绑定数据库身份、操作者、会话、凭据和授权版本、目标工作区、当前限制轮次、完整开放申诉ID/版本集合及完整输入。执行前在事务外进行有界密码核验，事务内重新核对用户、会话、授权、计划和目标状态；申诉集合变化也要求重新读取并预演。

维持只解决目标申诉，不解除工作区。解除同时更新工作区状态和当前轮次的全部开放申诉，并保存收据、审计及可供用户读取的公开结果。不能只把工单标成已结而没有执行实际决议。事务确认提交前不显示成功；提交确认不明时仅按原计划/收据标识只读核对，不自动重发敏感执行，不保存密码作为重试材料。已执行计划再次执行返回`GENERATION_PLAN_CONSUMED`，应GET原收据。

同一工作区只有一个未执行的解除计划槽。新解除预演成功提交会替代该工作区先前未执行的解除计划，包括其他操作员的旧计划；旧页面必须重新读取/预演，不得把旧计划消失当成已执行。已消费计划及其收据不删除。失败或回滚的预演不应留下替换效果，此边界列入PG验收。

运营私有证据引用与面向用户的公开原因/回复分开保存和投影。授权的复核详情可读取本批所需申诉内容，但不会因此获得生成提示词、模型输出、参考原件、隔离候选或私有下载权限。证据引用不作为内容访问凭证，也不作为用户可见文案直接广播。

## 受理、事务与并发

新生成先完成原幂等查找，再检查工作区生成状态。最终受理事务应再次锁定并核验状态，并在创建资源、冻结权益、登记幂等、审计和 Outbox 之前拒绝受限新请求。报价可以提前提示受限，但旧报价不构成继续生成的授权；消费报价的受理事务仍需核验。

文本/媒体输入审核、参考素材检查、图片编辑正文准备等锁外工作完成后，需要在重新受理时再次检查工作区状态；在等待过程中新增的限制不能被旧检查结果绕过。单轮和多轮聊天、普通媒体生成和图片编辑须覆盖相同边界。

工作区限制是持久业务事实。停用运营入口不能解除既有限制；关闭文本或媒体审核也不能解除。数据库不可读取、事务结果不明或版本冲突均不得默认开放。解除仅影响之后的新受理，不取消未知任务、不释放其容量或冻结，也不重建既有不可变上游请求。

## HTTP接口与有界资源

接口需要PostgreSQL和`AUTH_MODE=required`；运营接口另需启用运营及实时授权。普通用户作用域取当前会话，不使用运营目标工作区或创作项目头来扩大范围。

| 方法与路径 | 请求及结果 |
| --- | --- |
| `GET /api/v1/workspace/generation-access` | 当前工作区`workspace_id/state/version/restriction/can_appeal`；限制摘要含公开原因与`public_notice` |
| `POST /api/v1/restrictions/{id}/appeals` | `Idempotency-Key`和`reason_code/statement`；原因仅`request_review/restriction_error/issue_resolved` |
| `GET /api/v1/appeals` | 仅本人申诉安全列表；`state=all/OPEN/RESOLVED`、`cursor`、`limit` |
| `GET /api/v1/appeals/{id}` | 本人详情，含原`statement`及已结案`public_reply` |
| `GET /api/v1/operations/generation-access` | `workspace_id`查询参数；读取获授目标工作区状态 |
| `GET /api/v1/operations/appeals` | `workspace_id`及同类分页参数；运营安全列表 |
| `GET /api/v1/operations/appeals/{id}` | `workspace_id`查询参数；授权复核详情 |
| `POST /api/v1/operations/generation-plans` | 预演输入，返回计划、摘要、有效期及效果 |
| `POST /api/v1/operations/generation-executions` | `workspace_id/plan_id/plan_digest/password`；成功返回已提交收据 |
| `GET /api/v1/operations/generation-plans/{id}/receipt` | `workspace_id`查询参数；只读核对原计划收据 |

`GenerationPlanInput`公共字段为`workspace_id/action/expected_version/reason_code/evidence_ref/public_reply`。`restrict_future`不接受轮次或申诉字段；原因仅`manual_review/policy_concern/abuse_concern`。`uphold_restriction`另需当前`restriction_id/appeal_id/expected_appeal_version=1`，沿用上述三种原因。`lift_restriction`只附当前`restriction_id`，不能附单个申诉，原因仅`review_complete/restriction_error`。`public_reply`必填且须有非空白文本；限制动作将其作为公开`public_notice`。证据引用使用1—128安全ASCII字符，不接受URL。

计划效果为`from_state/to_state/version/restriction_id/affected_appeals`，收据携带`id/plan_id/workspace_id/action/effect/executed_at`。成功核对需匹配原工作区和计划，不把任意200响应当作原执行成功。限制拒绝新生成返回403 `GENERATION_RESTRICTED`；业务变更、计划过期或被消费均要求显式恢复处理。

| 有界对象 | 当前代码限制 |
| --- | --- |
| 申诉分页 | 默认20，每页1—50；游标绑定身份、工作区、用户/运营模式及state |
| 限制轮次历史 | 每工作区10000、全局100000；到限拒绝新限制，仍允许解除 |
| 申诉历史 | 每工作区10000、全局100000、每轮次128；每轮次每申请人仍只有一份 |
| 非解除预演 | 有效未消费计划每工作区64、全局10000；该类全部计划全局100000 |
| 解除预演 | 独立每工作区一个未执行槽，不受非解除计划配额阻断；新计划替代旧未执行解除计划 |
| 过期计划清理 | 每次容量检查最多清理1000条未消费且过期超过一天的计划；不清理已消费计划/收据 |

解除槽替换与过期清理是两种明确行为；不能把“只清理过期一天”误用于仍有效旧解除计划的替换规则。限制、申诉、已消费计划与收据历史不提供本批删除入口。上述限制是代码边界，不是生产容量成绩。

## 审计、通知与隐私

限制、解除、申诉提交、维持/解除决议及相关收据应在对应业务事务内登记审计。审计只记录有界标识、固定动作/原因码、版本和私有证据引用，不记录申诉正文、公开回复正文、密码、提示词、原始 URL 或模型输出。

C1以持久的工作区状态和申诉记录作为站内告知来源，公开结果与决议同事务落盘，客户端通过状态、列表及详情接口只读拉取。017没有独立通知表、已读状态或推送投递队列，读取成功不等于用户已阅读。现有项目Outbox仍用于原Run/Task等通知；本批不将私有申诉正文或运营证据广播到项目SSE，也不虚构project来发送工作区治理事件。

普通用户只得到本人可见的申诉结果和工作区公开限制状态。运营证据、其他用户申诉说明、操作者身份及内部授权信息不得进入普通用户通知。列表游标绑定身份、工作区和筛选，切换账号或范围后迟到响应不得覆盖新状态。指标标签保持固定有界，不加入工作区ID、申诉内容或证据引用。

## 升级、恢复与验证边界

017新增`studio_generation_controls/restrictions/appeals/appeal_idempotency/plans/receipts`六表，并扩展运营角色和审计闭集。SQL通过复合外键与延迟一致性触发器核验控制状态和活动轮次一致；限制轮次只能单向解除，申诉只能从OPEN结为RESOLVED，原始证据/正文及已执行收据不可改删。预演显式检查延迟约束后回滚。测试库迁移及约束已有PG验证，本地预览016→017已联备并比对旧业务数据一致，见062；生产环境升级仍须独立验收。

升级前停写并联备PostgreSQL、私有目录、owner及已启用队列所需密钥；启用S3时保留对象版本与收据。维护工具需与017精确格式相匹配，由集成人核对同步。不能删除迁移登记、限制历史、审计或owner来绕过旧程序格式栅栏。

恢复必须同时保留当前限制和不可变历史，不能只回退代码却继续写入不兼容的新库。关闭配置不是解禁或数据回滚方式。实施和验收情况见[059台账](../changes/2026-11-14-059-generation-controls.md)，完整V14状态仍以[任务源生成的TODO](../../TODO.md)为准。

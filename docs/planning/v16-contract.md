# V16 · 分布式流与配额公平调度

V16 于 2026-11-21 完成单控制写者范围内的本地验收。V05/V09 依赖已验收。模块H03/H07，相关治理H09。

## A1：聊天公平排队与执行预算（本地已验收）

对真实新受理的单轮/会话Run提供workspace轮转；同workspace内按入队顺序选择可执行项，模型预算阻塞时允许后续其他模型获得机会。全局、每workspace、每冻结上游model执行数量分别有界，总队列及单workspace队列也有界。单一chat凭据共用全局预算，平台不同别名映射同上游模型时共用model预算。

原幂等优先于队列、当前模型及限制；锁外审核后重核全部受理条件。持久业务提交成功才入队，回滚或确认不明不能凭内存推断受理成功。排队取消成功后释放等待位置；正在执行的取消必须等实际provider调用和清理返回才释放执行预算。worker等待、网络请求、全文审核均不在全局业务锁内。

chat HTTP连接池按worker预算限定，保持run context长超时与SSE流解析，不使用短全局Client.Timeout截断流。进程重启继续原INTERRUPTED/未知语义，不自动POST重试；持久逐token日志由B另验。

显式空/0/非十进制/超界拒绝启动；未设置才使用默认。执行预算与已受理未终态资源准入、浏览器SSE连接数不同。更小执行预算可使已有合法Run排队，不自动重新生成或取消。配置重启生效，没有热更新或跨实例配额。

### A1验收

- 真正App受理和可控Provider验证深队列workspace不能无限压住后入workspace；同模型别名合并预算、不同模型可执行；global/ws/model峰值均不越界。
- 单轮与会话原键在满队列、目录变化和已限制时重放；新请求满队列无新增资源、账务冻结、持久审核或审计副作用；提交失败不入队。
- 排队取消释放容量，执行中取消不能提前复用仍在工作的预算；停机退出无goroutine等待泄漏；终态Outbox背压保留槽位直到执行返回。
- 严格配置、只读安全指标、原LLM流解析及审核/权益/会话/PG故障注入回归通过。
- 构建和docs/TODO检查通过后填写实际证据。只报告确定性排队实验，不宣称生产吞吐或万级容量。

## A2：媒体提交、查询隔离（本地已验收）

分离工作线程和Transport，先获取执行预算再claim，避免已写SUBMITTING但还在排队而制造受理不明。已有handle查询不被慢POST挤占。保留租约owner/epoch/generation/版本条件，旧提交未知不得重POST。

## A3：导入与渠道公平策略（分阶段推进）

私有下载导入、审核内存/字节/并发预算分离；多租户媒体公平、供应Retry-After、自适应轮询和降级实测；不生成无界等待goroutine或无界secret派生标签。需要保留可恢复原handle和B2隔离语义。

A2沿用009混合到期索引，未证明lane筛选的数据库扫描成本隔离；A3须覆盖大积压EXPLAIN与generic plan，需要新增索引时走正式迁移，不改既有SQL字节。

A2集成时将A3顺序细分如下；A3.1的实现与实际验收见[专项契约](v16a31-contract.md)及[075](../changes/2026-11-14-075-media-delivery-integration.md)，A3.2已通过[079](../changes/2026-11-14-079-media-review-dispatch-integration.md)的独立联合验收，A3.3已按[本批契约](v16a33-contract.md)通过083独立联合验收：

1. **A3.1查询到私有交付**：Query只取状态，原租约事务冻结一次交付描述，交付通道处理下载及当前B2审核。签名URL视为私有访问凭证，独立密钥加密并绑定数据库/任务/交付身份，不入公开JSON/审计/Outbox。按delivery+slot预分配资产，冻结描述和完整字节收据；部分下载只补原集合，不能重新Query后把相同下标当相同内容。当前协议无可信产物版本时，旧URL失效只能待核实。
2. **A3.2首次审核分派**：新记录明确区分REVIEW_READY和已外发的REVIEW_STARTED；开始前提交证据。只有未启动过的READY允许首次审核。STARTED后宕机、失锁或确认不明转REVIEW；旧候选保持原规则，不能因新worker重新审核。事务背压只重试保存。
3. **A3.3公平与渠道退避**：工作区轮转、原冻结渠道身份预算、持久Retry-After/有界退避与抖动、查询探测及渠道冷却；无POST探测、自动换模型/凭据或绕过审核。大积压实测阶段索引与generic plan，记录吞吐/时延口径。

A3.1必须同时处理GC与联备：计划保护集允许文件尚不存在，完整收据集必须存在且校验；保护“文件已写、收据提交不明”的窗口，不能事后才登记引用。新的私有描述/收据表、格式栅栏、所有离线CLI及备份密钥同步升级。四个提交断点（描述、单件收据、B2候选、最终发布）、取消/失租/重启、S3确认不明、整组PARTIAL门禁及URL换签/顺序变化均需真实故障验收；独立首次审核STARTED提交属于A3.2。不得用本设计说明代替功能完成。

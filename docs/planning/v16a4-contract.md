# V16-A4 · 大积压恢复与PG缓存边界

状态：2026-11-15开始设计；085已实现并接线私有阶段有界批读，完整A4.1/A4.2尚未验收。依赖A3.3已本地通过083；属于V16的H01/H02/H03/H04/H07/H09支撑工作，不改变23个纵向批次的唯一状态源。下一项先做A4.1，再A4.2；B持久流与C综合测量继续保留。

## 设计启动时核实的问题

1. `internal/studio/persistence.go`的restore整体在一次5秒store.do内：项目、活跃Run和Task全部进入缓存，Task逐个读019、018及其items、审核候选。020的有界预选并没有修复这条启动路径。
2. `internal/studio/app.go`在restore之前调用一次prepareOutbox，后台消费要等恢复和租约初始化完成；恢复生成超过10000项事件可使当次New返回EVENT_BACKLOG_FULL。已提交记录可下次继续，但尚无一次启动内排空并继续的完整链路。
3. `internal/studio/task_leases.go`在一次5秒事务里更换executor generation并撤销全部旧lease；大积压同样可能影响启动。
4. PG模式仍按`len(a.runs/tasks)`与MaxRecords（默认512）拒收，只淘汰终态，冷读还能扩大缓存。已有工作区积压可能误拒其他工作区的新受理，不能用调大内存参数冒充有界缓存。
5. 项目权限、项目列表及100项目限制依赖`a.projects`，不能直接去掉项目预加载；先设计数据库范围查询和事务约束。

## A4.1：一次启动内完成分页恢复

目标是保持全部安全事实，把恢复改成有界页协调器；每个业务事务继续5秒，不对整个启动套一个任意大超时。进程控制写锁、私有目录排他锁、DB UUID及原交付/队列密钥检查仍必须先通过，HTTP和执行worker只在恢复成功后开放。

- 稳定ID keyset分页，限制每页记录数及累计编码字节。018/019/审核私有数据按页批量加载，不能把N+1换到新helper里。坏记录或必要key失败关闭；私有文件保持执行前同文件描述符/真实对象核验，缺失或篡改任务不得外发，不通过启动时急切读取全部媒体来冒称性能改进。
- Run恢复仍明确INTERRUPTED，未审正文隔离，不自动续连模型；媒体保留原handle、冻结请求、候选、完整收据、READY/STARTED差异与020截止时间。
- 每次保存通过既有同事务业务/权益/审核/调度/Outbox hook。只有确认提交后推进页进度、替换缓存；确认不明退出并由下次启动读真实持久状态，不能盲目重放副作用。
- 页间真实消费Outbox。EVENT_BACKLOG_FULL先回滚本事务，再退出store互斥区消费，再读取未提交恢复项；不得在持有store.mu时重入projectOutboxBatch，不删除未消费事件。
- executor generation用短事务先撤销旧执行授权，再分批清旧lease；新worker等清理和恢复完成才启动。旧epoch/generation任何阶段不得写入。提交ACK不明时不猜成功、不外发。
- A4.1可以暂保留现有热缓存策略，必须明示它不等于内存有界或十万任务完整容量验收。A4.2不因A4.1通过自动完成。

验收至少包括：真实New超过10000条需要恢复的Run/Task，单次启动内Outbox真实排空并继续；每页SQL次数/记录与字节边界；页边界Kill、回滚及COMMIT确认丢失后重新New不重复恢复版本/冻结处理/外发；旧lease并发写入拒绝；原handle、部分delivery、READY、STARTED、旧候选、模式变化、身份冲突与冷却中的完整矩阵。保留已有恢复/GC/S3/权益/审核测试，不以单个迁移入口冒称完整启动。

## A4.2：有界PG热缓存与完整容量

在A4.1后设计实际执行pin/占位：聊天排队和在途、媒体lease及未退出I/O、活动订阅不能因缓存淘汰失去控制。PG队列以持久事实为准，闲置资源可冷读；缓存淘汰不释放权益、数据库准入或真实执行预算。

取消PG对全局缓存条数的业务误限，保留工作区/模型的真实准入。项目授权、列表与创建数量在PG范围查询/事务内重核；冷读回锁后比较资源版本，迟到读不能覆盖新状态。普通memory演示边界继续明确。

实际验收100k活跃+100k终态的完整New，记录启动时长、每页成本、峰值缓存/编码字节；跨512历史的新工作区受理、原键回放、取消、运营核对、项目权限及SSE补读完整通过。不是跨实例或真实供应商生产容量。需要新索引时走下一可用迁移并同步所有维护栅栏/联备，不改001—020来隐藏升级。

## 不可改变的事实

- 无handle的SUBMITTING转未知，不POST；已持久清单不重新Query换批，完整receipt不重下覆盖；只有兼容且从未STARTED的READY可首次审核。
- 原任务幂等/请求hash/模型快照/multipart原正文身份保持；LLM继续生成仍是显式新请求。
- 冷却、server_not_before、单次观测与probe不得因分页恢复缩短或重算；新调度锁与外键兼容语义保持。
- 控制写锁与私有目录锁不因新页协调器解除；终态交付仍需要原密钥。缓存不是业务权威。
- 日志/指标不用提示词、输出、租户、原URL、key或channel hash作为标签。

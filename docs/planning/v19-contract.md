## A · 从模板运行到人工选图

首个可独立验收的用户链路是选择模板或旧草稿、编辑文本与图片节点及连接、保存版本、显式运行、取得该项目的真实图片产物、换一个已授权会话打开待确认步骤并选定图片。用户可以从运行详情回到对应的定义版本、文本 Run、图片 Task 和产物。

1. 模板可重复实例化。服务端验证节点与端口唯一、边的源和目标存在、输入类型与数量相容、依赖无环。节点、边、展开数量、输入字节和并行步骤均有上限。拒绝跨项目的定义、素材和子执行 ID。无效图在启动前返回具体错误，数据库无新增子执行或冻结。
2. 启动事务绑定项目、不可变流程版本、模板版本、用户输入、模型能力与参数、素材版本。按稳定操作键受理并保存流程快照。运行后并行编辑画布、更新目录或模板，已有执行仍按原快照推进。旧草稿读写、CAS 与版本恢复继续按 V03 验收。
3. 节点每次有效尝试都有独立身份，关联对应的 Run 或 Task、项目和输出版本。执行复用现有幂等受理、生成限制、报价/冻结、审核、租约及后台查询。工作流通过已提交终态或授权补读推进，接到重复或乱序通知时同一尝试只前进一步。启用权益时，每个可能收费的步骤须在有效报价与用户确认的授权范围内受理。[受理与取消](../../internal/studio/app.go) · [项目资产登记](../../internal/studio/asset_library.go)
4. 文本只有在允许公开后才能成为图片输入。图片输出将已批准、已登记的项目资产版本交给确认节点。服务端持久记录等待和选择，确认时复核身份、候选集合、资产可见性及流程/节点版本。跨账户读写被拒；刷新、重新登录、并发确认或确认回执丢失，可读取原选择且只产生一次后续推进。

## B · 让选中的图片真正进入视频请求

完整模板将已确认的图片资产版本接到视频节点的图像输入端口，同时绑定脚本、模型、时长等已验证参数。服务端构造并冻结渠道支持的输入，使用现有提交、原 handle 查询、私有导入与审核路径；视频及海报回到同一项目，并可追溯到原图片、节点尝试与流程版本。

当前普通媒体生成拒绝 `reference_asset_ids`，图片编辑只接受 image。实施前要定义视频模型的受支持输入类型、引用项目资产的授权与版本语义、实际适配协议和冻结方式。验收时由受控供应端解析其真正收到的图像输入；若协议传文件标识，则核对标识绑定的实际文件、版本和字节。以两张不同的已批准图片运行，分别对照上游输入、视频资产、权限及流程记录。仅在 UI 展示选图、仅传文本提示或仅登记资产 ID 都无法满足该用例。[现行媒体校验](../../internal/studio/app.go) · [模型能力](../../internal/studio/catalog.go) · [媒体适配器](../../internal/studio/media_http.go)

能力不支持、资产失效或无权读图时，在任何视频外发前返回明确的节点状态。受控环回协议与真实渠道验收分别记录。真实验收需要已开通相应视频图像输入的模型、服务端凭据、输入传输协议以及授权的受控调用；条件不足时保留具体缺项。

## C · 节点重跑、取消和恢复

从已交付的 A/B 路径实际操作。上游节点修改后，展示受影响的下游结果，再由用户选定重跑范围。同一操作键回放原尝试；显式新尝试有新身份、独立报价/冻结和新结果，旧版本、选择与资产仍可对照。分别覆盖待确认、排队、正在外发、已持 handle 以及受理不明的取消与重启。取消阻止后续节点启动；已执行步骤的账务、审核和供应方取消状态按原资源实况呈现。

在真实 PG 上用进程故障和环回计数验证已提交但响应丢失的启动、节点受理、人工确认和重跑。恢复时查询原有 Run、Task 与原 handle；没有可核对的上游受理证据时保留待核实。校验无重复 POST、无重复扣费、旧尝试迟到不能推进新一代节点、未批准内容不能进入下游，工作流和项目通知均可按权限补读。

## 复跑与交付判定

| 验收面 | 实施后须交付的证据 |
| --- | --- |
| 图与版本 | Go 用例列出并实际执行图结构、环、端口、上限、项目隔离、模板复制及运行快照冻结。检查拒绝时子执行、账本和审计的实际行数。 |
| 完整模板 | 隔离 PG、带真实图片/视频字节的环回适配器，记录原始输入摘要与各节点尝试/外发计数，核对素材与成品的项目归属、审核状态及私有下载。真实供应商结果另列。 |
| 重跑与恢复 | 并发确认/重复通知、未知受理/回执丢失、进程 Kill、取消后迟到结果、收费和原键重放专项。保留实际用例名、耗时和未执行条件。 |
| 工作台 | 通过实际 UI 完成选模板、编辑连线、运行、等待选片、跨会话确认、视频预览和局部重跑。验证离线重连、冲突、跨项目切换、窄屏和旧草稿，记录浏览器和运行环境。 |

复跑入口为 `npm run check` 和集成人串行运行的 `npm run test:db`。已有 `npm run smoke:catalog`、`npm run smoke:references`、`npm run smoke:library` 可验证相邻模块。随实现登记新的 PG 故障用例、工作流浏览器冒烟及实际命令；核对匹配用例数量、SKIP 和渠道身份。每个子批提供对应台账、README/Wiki 及任务源证据。设计、数据表、编辑器或执行接口单独完成均不足以验收用户链路。

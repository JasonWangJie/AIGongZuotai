# V16-A3.1 · 查询与持久私有交付

状态：2026-11-14本地已验收，见075和v0.18联合证据。依赖A2；三通道、018、故障、升级及联备均有实际验证。首次审核独立分派A3.2、渠道公平A3.3及B/C与完整公众产品范围继续保留。

## 完整链路

原生异步网关QueryStatus只查询状态和校验结果清单，不下载。完成响应在原有效任务租约及控制事务内冻结一次私有交付描述和有序计划asset ID，确认提交后才允许delivery通道下载。两条原通道和第三通道各自有有限worker、PG连接与预算。交付通道仍包含B2审核与最后保存；独立首次审核分派留给A3.2。

每个计划asset ID绑定delivery ID与slot。清单中的URL先按原gateway解析为绝对地址，单项最多8KiB，整组1—4项，重新下载仍使用原清单，不能重新Query后用同下标拼接新结果。私有原件、真实编码、长度、完整SHA256与缩略图，以及启用S3时完整指定版本，都必须校验。上游type/size只作提示，不充当真实字节收据。

## 持久化与密钥

新增018正式迁移：studio_media_deliveries冻结密文、摘要、原handle身份和READY/COMPLETE/PARKED阶段；studio_media_delivery_items先登记计划ID，再单向写不可变完整AssetInfo收据。任务、租约fence、交付元数据、审核、权益、审计和Outbox保持事务边界。私有记录不进入Task JSON、SSE或公共列表。

签名URL作为访问凭证，用独立32字节标准base64的MEDIA_DELIVERY_KEY加密；AAD绑定稳定数据库存储UUID、任务、交付及不可变描述身份。原生phased provider在PG模式自动使用本链路，缺失或错误密钥拒绝启动；不能关闭provider来绕过已有密文。memory原生异步媒体也走阶段交接，但密钥和任务仅当前进程，不能宣称重启恢复。旧SVG demo及非phased测试provider没有真实下载，保留原接口并明确能力差异。

MEDIA_DELIVERY_WORKERS默认2，显式十进制1—16；原submit/query各默认2。旧TaskWorkers仅用于原两通道兼容默认，加上第三通道后不再代表旧总数。预算先于领取，取消、失租和背压不能提前释放仍执行的槽。指标只允许submit/query/delivery三个固定标签；没有用户、模型、URL或密钥标签。

## 恢复规则

- 描述提交未确认：不下载；重启只采用确实已提交的原描述，不能内存猜测提交成功。
- 描述实际回滚且无已登记清单、无候选、零下载：允许再次查询同一原handle并冻结一次完整新回应；仍禁止POST。未提交响应不等于持久身份，不将此情况与“已提交但ACK丢失”混为一谈。
- 已有描述但未下载：领取delivery，按原清单下载；不得转回Query或POST。
- 部分文件完整但PG收据尚未确认：只有磁盘完整交付标记与实际字节均匹配，才复用并补写原收据；已完成标记缺失或篡改不能下载替换。
- 已有B2候选：保留原REVIEW隔离，不能因第三lane自动重审；迟到ALLOW不得复活取消/失租资源。
- 原URL失效且无稳定产物版本证据：待核实，不自动换签、换序、重生成；权益按已执行但未交付保持REVIEW。
- 完整终态：公开产物、资产目录及结算仍以整组批准和确认提交为准。

## 私有文件治理与联备

计划保护集允许文件尚不存在；完整收据集必须存在并校验。已登记项包括取消、回收和终态均保留可达性，GC摘要覆盖计划及完整收据，不能只列asset ID。维护/权益/角色/资产迁移CLI使用精确018栅栏和数据库/目录身份，旧程序不可写丢字段。

迁移不能改变已登记交付项的冻结存储定位，包括尚未写回PG收据的文件；PG绑定目录不能绕开DB检查使用旧无DB入口。联备需PG、全部私有目录/owner、已启用邮件队列密钥、独立交付密钥及对应S3版本。新的独立本机恢复演练不能冒称原开发数据库或生产灾备已恢复。

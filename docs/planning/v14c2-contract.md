# V14-C2 · 账户与内容申诉

V14 的原验收同时包括申诉、封禁和额度风控。C1 已交付工作区新生成限制；C2 分内容申诉和账户治理两段，C3 仍有独立风控验收。完整批次及依赖以[任务源](tasks.json)为准。

## C2a 已执行输出的内容申诉

申请人须是同项目原 Run 或 Task 的实际受理人，通过原审核版本提交。只接受已有持久证据的输出 BLOCKED 或 REVIEW。输入拒绝没有已受理资源。项目操作记录、冻结策略及决定可以证明处理经过；历史文本隔离未保存原文。申请说明与公开答复单独持久化，列表、日志、财务队列不携带私有说明。

独立 moderator 在授权工作区查看证据摘要、预演并重新输入当前密码，可维持原决定、登记独立复核意见或将仍有争议冻结的原资源转交财务。finance 独立开立或绑定同资源真实工单，沿现有财务流程核实并执行。本人只能看到实际已提交回执与从原冻结释放的数量。申请本身不能改变原审核决定、开放文件、重新生成、赠送额度或自动解冻。无财务证据的申诉仍可取得独立正式复核意见。

本地验收使用三个独立账户、真实 PostgreSQL、环回审核/生成、私有文件与内部 CREDIT。核对原键、撤权、过期版本、重复确认、财务回执、跨项目保密、备份恢复和窄屏。真实审核商、实际语义准确度和外部结算仍单独验收。[既有运营处置](../wiki/operations-cases.md)

## C2b 账户限制与申诉

账户限制、工作区生成限制与内容决定各自独立。账户治理须明确授权主体才能跨工作区生效；已有工作区 moderator 没有全站账户封禁权限。受限账户应保留仅本人可用的身份核验、查看状态和申诉入口。每次限制应有独立轮次，解除前重新核验账户和最新轮次；旧回复不能解除新限制。027 将离线授权精确到操作人与目标账户。限制和解除会撤销目标的全部会话，本人可重新登录处理申诉与账户安全。已受理的生成保持原业务状态，解除后重新登录可以访问原项目。专项涵盖普通访问、事件流、锁外审核返回后的受理、独立密码确认、正式回执与停写恢复。[027 决策](../wiki/decisions/0027-account-governance.md)

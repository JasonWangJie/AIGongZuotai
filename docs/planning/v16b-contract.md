## 020 基线

Go 的 `executeRun` 接收供应商文本增量。无审核的 Run 在进程内追加输出并广播，定时检查点约每秒保存一次；启用审核的 Run 将候选留在有界私有内存。现有 `Run.Seq` 是客户端归并增量和快照的依据。冷读或进程重启后，旧版本以快照和恢复序号间隔衔接已发出的易失事件。项目 Outbox 有独立的项目顺序和订阅范围。[执行与检查点](../../internal/studio/app.go) · [恢复](../../internal/studio/recovery.go) · [SSE](../../internal/studio/http.go) · [前端归并](../../apps/workbench/src/state.ts)

## B1 · 单控制写者下，从提交到断线回放

交付一条完整 PG 链路，涵盖普通聊天与多轮会话的原键受理、上游增量、审核、终态、取消、断线补读和重启。保留现有 Run 快照、事件名称、项目鉴权和浏览器显式继续语义。内存演示仍使用进程内回放。

1. 新格式为每个新 Run 登记流的持久身份。启动外部请求前，在同一业务事务确认本次唯一执行授权和运行状态。受理原键仍优先返回原 Run。重新连接 SSE 只发 GET；受理或执行提交确认不明时，下次启动从 PG 读取原事实，原模型请求不自动重发。
2. 以应用实际收到的每个非空文本增量为写入单位。一个增量可能含多个模型 token。日志按 Run、执行代次和序号唯一，重入相同序号要核对原内容。提交前验证当前授权、前一已提交序号和业务状态，事务内推进日志及持久水位。落库可有界合批并保留各增量的顺序；进程只在提交确认后向读者发布。存储等待受已有聊天执行预算约束，避免持应用全局锁等待慢客户端或无界积压。
3. 快照记录其覆盖的最后序号；从该快照和已提交的后续增量可重建最新公开输出。业务终态、最后可见内容、权益、审核和必要的 Outbox 同事务。项目通知保持元数据与项目顺序，Run 文本走独立的鉴权回放。运营核实推进 Run 序号时也要产生可补读快照。[原保存事务](../../internal/studio/persistence.go) · [运营快照](../../internal/studio/operations_cases.go)
4. 冻结了输出审核策略的 Run 只在私有内存收集候选，整段 ALLOWED 且 COMPLETED 的事务确认后发布正文快照。拒绝、待核实、取消、恢复及审核事务确认不明均沿用原门禁。任何未审候选正文都不得写入增量表、快照、Outbox、SSE、历史、日志或遥测。
5. 保持 `GET /api/v1/runs/{id}/events` 的 `Last-Event-ID` 优先级及越前 409。对窗口内游标，从已提交水位按页补读并衔接实时写入；窗口外游标返回带当前序号的 `run.snapshot`。裁剪已覆盖日志、保存可恢复快照、推进窗口下界必须原子。为读取页、保留日志和待提交缓存设置记录及字节边界，并覆盖慢读、停顿和断线。旧 020 Run 只有原快照/序号，保留原恢复间隔，避免为其合成历史增量。

## B2 · 有效租约、旧执行者与故障恢复

在 B1 的单次外发与持久水位基础上，用数据库条件写入约束执行者 owner、epoch、generation、租约有效期和预期序号。领取、续约、追加、终态与撤销均以已提交证据为准。取消或重启使旧授权失效；等待旧提供方、审核和保存实际退出后才释放本地执行占位。租约到期不能据此再次调用已启动的模型。根据 PG 的已提交前缀恢复 INTERRUPTED 或原终态，保留原报价、权益和审核结果。独立 PG 连接的租约竞争可在现有控制写锁和私有目录锁下验证；跨实例控制写和生产容量仍需各自验收。

B2 从 021 已有的 `execution_id`、`head_seq` 和单控制写锁出发。首先以两个 PG 连接验证同一 Run 首次领取互斥，再验证数据库时钟上的续约、到期、撤销与旧连接恢复发送。只有持有效授权的原执行可追加；已启动但失权的模型请求保持原身份并保守收尾。需覆盖旧审核在到期后才返回 ALLOWED 的场景，确认没有新增正文、结算或上游调用。022 使用独立的聊天执行代次。旧 021 记录保留原执行身份，只有新 Run 首次领取时才授予租约。

## 验收与交付

| 子批 | 实际验收 |
| --- | --- |
| B1 可见顺序 | 真实 PG 与环回流逐块发送；热订阅、冷读取、跨页补读、窗口过期、从补读切到实时均无丢失或正文重复。跨项目读拒绝。核对批准、拒绝、待核实和取消对应的日志、快照及 SSE；覆盖运营财务更新、原键重放和旧游标。 |
| B1 提交边界 | 在提交前回滚、提交成功后回执丢失、页边界 Kill、终态 Outbox 背压后重新 New；从真实数据库核对输出前缀、最终账务、版本、事件及上游调用次数。一次执行只能有一次上游请求。 |
| B2 失权边界 | 两个独立 PG 连接争用同一 Run；实际持有方续约、暂停至过期、取消后迟到增量/审核/终态写入，以及切换 generation 中途 Kill。确认所有过期写被拒、已提交正文可回放、旧请求无重复外发，直到执行退出才释放本地预算。 |
| 格式与回归 | 下一可用增量迁移同步应用与离线维护精确格式栅栏。联备并恢复 PG、私有目录及启用的独立密钥。旧格式升级、旧程序写入拒绝与备份恢复均由集成人串行实测。保留 Run 幂等、多轮分支、审核公开门禁、权益、A4 进程及冷缓存回归。 |

各子批先运行隔离的 `npm run check`；真实 PG 专项与 `npm run test:db` 由集成人确认上一进程退出后串行执行，并记录实际执行用例、SKIP、故障点与命令。新增测试名在实现时登记，可以复用现有 `TestPostgresModerationUnknownCommitRecoversOnlyCommittedDecision`、`TestPostgresOperationsRunSSEReplaysCommittedBilling` 和 `TestPostgresPeriodicAndTerminalCheckpoints`。补齐适用的前端断线回放、六套本地冒烟和文档治理后，按 B1/B2 分别登记证据和状态。B1 已完成上述范围的本地验证，故障与回归记录见 [099](../changes/2026-11-21-099-run-stream-integration.md)。B2 的独立竞争、锁等待过期、首次领取提交回执丢失、换代中途 Kill 和原键回放按同一验收范围实测。详见 [103](../changes/2026-11-21-103-run-lease-integration.md)。[设计台账](../changes/2026-11-21-095-durable-run-stream-plan.md)

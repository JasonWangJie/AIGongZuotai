# V16-A3.3 · 媒体公平调度与持久退避

状态：2026-11-15开始实施并通过本地联合验收，详见083。A3.1/A3.2已经独立验收，075/079及各自证据保持历史事实。本批属于H03/H07/H09；完整V16-B/C、V17生产容量与其他产品批次继续保留。设计取舍见[0018决策](../wiki/decisions/0018-media-fair-scheduling.md)。

## 业务范围

四个执行阶段按工作区轮转；同一冻结渠道的别名共用并发预算。网关限流、临时查询失败、无进度查询分别处理；到期时间、冷却与恢复状态写入数据库，重启不能缩短等待。审核输入/输出沿用原两个物理许可并双向公平，不能通过增加输出池扩大总并发。

当前生产配置仍只有一个Async网关。本批不实现多供应商路由、凭据热切换或自动换模型；结构化渠道预算也不能被描述成已提供这些能力。

## 调度和事务

020新增任务投影、工作区游标、lane游标和渠道运行态，原001—019 SQL不变。任务、原冻结请求、handle、交付清单、候选、019派发与权益继续是业务事实，调度投影不能覆盖它们。

固定大小工作区页和任务页采用keyset轮转；遇到尚未到期、冷却、活跃租约或预算满必须推进游标，禁止反复只看全局队首。终态历史不参与活跃选择；四lane使用可索引的固定SQL。先短事务预选并确认游标，再获取非阻塞工作区/渠道预算，再严格claim重核due、投影、阶段、cooldown和租约。显式任务ID入口不能绕过生产调度限制。

锁序避免持有工作区游标等待任务锁：业务先task fence，再私有阶段/调度/资产/权益/Outbox；调度预选提交后才进入任务领取事务。提交确认不明不能发出外部请求，必须只读数据库事实；资源版本、调度投影版本、游标和lease独立。

固定活跃工作区集合的轮转需证明不会饥饿；未限制全局工作区数，不能承诺与工作区总数无关的绝对最大等待时间。

## 渠道观察与恢复

HTTP只提供私有事实：gateway/source/storage/review作用域，success/rate_limit/temporary/protocol/identity/cancelled分类，有效服务端Retry-After及超上限标记。无真实响应头的默认3秒不是渠道限流；调用者取消不惩罚渠道，下载/存储故障不污染生成网关冷却。

渠道键取受理时冻结的provider身份；提交和查询共享原身份，审核使用冻结审核adapter身份，交付不被生成网关冷却阻塞。缺失旧身份使用明确保守兼容分组，冲突隔离，不能从当前目录猜测或重新构造请求。

仅原handle的GET可有限退避和半开探测。临时失败指数退避与正向抖动只计算一次并持久化，Outbox背压只重试原保存。连续无进度延长查询间隔，真实进度恢复基础间隔；自适应只降低配置硬上限。新的冷却不能被较早请求的迟到成功清除。服务端要求超过平台支持范围时暂停待核实，不能截短后提前探测。

POST 429不自动重投当前生成，可影响同渠道尚未提交的其他任务；503、断连、受理响应不完整继续受理不明。没有原handle不能发POST探测。STARTED审核失败、429、取消或确认不明继续REVIEW，不再次审核；READY才允许第一次调用。所有自动处理保持原计费、幂等和隔离门禁。

## 有界资源与配置

保留四lane worker上限。新增MEDIA_WORKSPACE_CONCURRENCY默认1、MEDIA_CHANNEL_CONCURRENCY默认2，均显式十进制1—32，每lane实际不超过该lane worker数；前者每工作区，后者每冻结渠道。重启应用配置不能缩短已提交冷却或释放未退出调用。

共享审核仲裁最多16个输入等待者、单工作区最多2个、等待最多10秒；输出等待最多既有2个review worker。两类轮转，输入类别内按工作区轮转；等待不占App锁/数据库事务，不写STARTED。容量或超时用业务错误返回，不制造内容BLOCK/REVIEW决定。取消后实际读/HTTP退出才归还许可。

观测只报告四个固定lane和审核input/output类别的本进程统计，不输出工作区、渠道指纹、模型、URL、提示词或密钥，不冒称全库队列实时长度。

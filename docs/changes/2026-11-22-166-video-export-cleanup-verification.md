# 166 · 核对下载处理结束后的私有临时文件

## 目的

让私有导出测试在服务器确实结束响应后检查临时目录，准确区分仍在传输的文件与遗留文件。

## 范围

V20-A 的 PostgreSQL、真实 FFmpeg 与私有下载集成测试。浏览器接收完所有字节时，服务端可能还在退出响应处理函数。

## 实际文件

`internal/studio/video_timeline_private_http_test.go` 在最后一个真实 MP4 响应后关闭本用例的 HTTP 测试服务器并等待请求处理完成，然后执行原临时目录检查。

## 接口与数据影响

对外 API、数据库格式、成片响应、原件鉴权和服务端清理逻辑均沿用 030 的实现。测试仍检查完整字节、范围下载、回收拒绝和已完成目录只保留锁文件。

## 验证结果

修正两项夹具的等待边界后，032 完整 PostgreSQL 累计回归通过，工作台 1639.820 秒，编解码包 2.652 秒，无失败或跳过。

031 首次累计回归在读取完整响应后立即检查目录，出现“export retained an operation spool”。执行器与真实 HTTP 的 030 累计测试此前已经通过。原测试使用 Content-Length 判断客户端读完；服务端关闭文件、删除目录的 defer 发生在处理函数返回时。修订等待该边界后仍使用同一个严格检查。独立 031 副本三次真实导出与回收专项分别为 9.92、10.51、16.09 秒，均通过。与 165 分别运行三次，合计 94.400 秒。032 累计回归继续包含两项。

## 风险与限制

该专项核对正常结束的单次 HTTP 传输。进程在写入期间遭强杀时，未清理文件仍应按专用目录的启动保护处理。

## 回滚方式

回退测试中的 HTTP 服务结束等待即可恢复原测试时序。业务数据无需迁移。

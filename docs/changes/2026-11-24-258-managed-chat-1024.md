# 258 · V17 受管聊天 1,024 位本机档

## 目的

253 已在 8 个子进程、9 个真实注册工作区上验收 512 条模型连接。为下一个 1,024 路业务连接档保留原单写者、逐段确认和真实租约，分别检查进程池的物理资源与完整业务链。

## 范围

V17-J 受管聊天单控制写者。显式配置的子进程数量上限由 8 增至 16，单进程 1—64 个执行位。正常业务验收增加 `integrated-1024` 档。省略两项仍然关闭受管模式。既有 8×64 档可直接用原命令重测。

## 实际文件

- `internal/studio/chat_child_scheduling.go` 调整显式进程上限，`cmd/server/chat_children_config_test.go`、`internal/studio/chat_child_scheduling_test.go` 核对开关与拒绝边界。
- `internal/studio/chat_child_acceptance_test.go`、`internal/studio/chat_child_integrated_acceptance_test.go` 加入 17 个正常工作区及 16 个冻结模型的档位和真实注册等待。权益、正常受理、延迟读者以及故障验收复用 253 的标准程序试具。
- `internal/studio/chat_child_process_acceptance_test.go` 将 Windows 内核 TCP 观测的对端数量和结果大小约束扩至 1,024 个对端、64 KiB。覆盖原 PID、父进程、可执行文件与对端端口的核验。
- `internal/studio/chat_child_1024_test.go` 覆盖配置组合、16 个真实子进程的满池与回收，以及实库中同一代次全部原执行的续租。
- `docs/wiki/decisions/v17j1-managed-chat-execution.md` 更新配置、背压和实测入口。

## 接口与数据影响

保留每工作区、每冻结上游模型 64 个执行的上限。新档 16 个模型各 64 个执行；17 个工作区各 60—61 个；每工作区与模型组合各 3—4 个。单一已认证会话按每工作区预算保留正常 SSE，额外一个迟读者占独立连接。每进程仍按最多 64 个 slot 检查 IPC 标签、代次、序号和逐段确认；每个预留位的收件队列为 3。进程启动失败仍清理此前的进程，关闭等待每个已拥有的进程退出。服务仍有一个控制写者；数据库格式、001—040 迁移、320 项/8 MiB 的增量待存量、5 秒背压期限、审核和权益语义沿用原实现。

## 验证结果

- Go 1.26.11、清空 `TEST_DATABASE_URL` 后执行 `go test -count=1 -run '^(TestChatChild.*|TestRunDeltaCoordinator.*)$' -timeout=5m -v ./cmd/server ./internal/studio`。首次编译纠正了测试中嵌入拓扑的初始化，复跑有 22 个顶层通过。含下述 16 进程显式用例的最终整组运行通过 23 项，一个仅供子进程调用的内核取证 helper 在父进程中跳过。范围包括独立管道、回执、乱序、进程退出、父进程中断、增量队列满及持久提交边界。
- 设置 `STUDIO_CHAT_CHILD_POOL_1024=1` 后，`go test -v -count=1 -timeout=2m ./internal/studio -run '^TestChatChild1024(SlotsAndReap|Topology)258$'` 两项通过。在 16 个已启动子进程中实际预留 1,024 个不同的进程/槽位组合，第 1,025 个预留被拒绝，释放后关闭并确认 16 个进程都已被等待回收。此检查没有发出模型请求。
- `go vet ./cmd/server ./internal/studio` 和 `go build -trimpath -o chat-server-258.exe ./cmd/server` 通过。
- 完整业务入口使用 Windows、独立本机 PG，编译本次候选的标准服务程序，设置 `STUDIO_CHAT_CHILD_SERVER` 为该程序绝对路径，`STUDIO_CHAT_CHILD_REPORT` 为新的私有报告绝对路径，`STUDIO_CHAT_CHILD_ACCEPTANCE=integrated-1024`，执行 `go test -p 1 -v -count=1 -timeout=35m ./internal/studio -run '^TestPostgresChatChildAcceptance$'`。原对照使用相同入口和 `integrated-512`，报告分别保存。实库结果待集成人串行登记。
- 验收要求普通注册后取得的真实会话、冻结报价与账务、原模型 POST、每一条独立真实 TCP 和当前 PG 租约归属逐项匹配。所有 1,024 项须在相同 owner/epoch/execution/generation 下观察到实际续租，12 波真实增量经持久化后由各 Run 的授权 SSE 收到。原键收据、回放没有新增账本分录、排队取消、已开始取消、子进程与控制器故障均需复核。

## 风险与限制

1,024 个 IPC 位与真实同时推理连接分别验收。17 名用户沿用同一环回来源普通注册，第 11 名之前等满 15 分钟窗口，注册耗时独立记录。新档对子进程、套接字、调度、日志积压及数据库租约提出更高要求，真实准入、同时活跃、零重复发起、结算和延迟必须以本档实库结果为准。万业务模型连接、外部供应商、多机写入和持续压力另验。

## 回滚方式

安排服务停机，恢复原版本并将显式进程数设为至多 8，或省略有关配置恢复原本地执行器。重启、回放及旧执行故障沿用原租约和核对流程。

## 集成人实库结果

同一标准服务制品串行通过 512 与 1,024 档。1,024 档由 17 个正常注册工作区、16 个冻结模型和 16 个受管子进程组成，每个子进程实际持有 64 个原模型 TCP 连接。1,024 个执行均在原 owner、epoch、execution 与 generation 下完成续租。1,025 个授权 SSE 读者同时在线，普通读者收到 12,288 个增量，来自 387 笔 PG 提交，P95 193.28 毫秒、P99 242.55 毫秒。1,024 个执行全部结算，原键重放未产生新账目。上游重复或意外 POST 为 0，两档退出后各自新增的所有子进程均已回收。 512 档同制品 P95/P99 为 131.80/218.93 毫秒。512、1,024 两个 Go 命令分别实测 68.00、987.95 秒，后者含 901 秒的正式注册等待。[两档制品散列和完整测量](../wiki/assets/performance-integrated-chat-1024-040.json)

主树与专项副本的标准构建分别附带现有 Git 提交和空临时仓库的版本信息，原始制品散列不同。对这两份源各执行 `go build -p 1 -buildvcs=false -trimpath ./cmd/server`，得到逐字节相同的可执行文件，SHA-256 为 `0493c242b05872626d3853a74320a9f4b523bb454c39bae427577c60a6954ca2`。两档业务专项使用同一份带临时仓库标记的制品。本机主树的常规构建和版本中性构建散列见报告。

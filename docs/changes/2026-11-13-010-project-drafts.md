# 2026-11-13-010：项目云端草稿与不可变版本

## 目的

关联 **V03 项目云端草稿与版本恢复**，覆盖 H01、H02、H08、H09。解决浏览器本地节点草稿无法跨会话持久保存、覆盖并发修改和恢复旧版缺乏记录的问题。每次成功保存生成不可变版本，冲突显式返回，恢复保留中间历史。

## 接口与数据影响

新增 GET/PUT `/api/v1/projects/{project}/draft`、GET `/draft/revisions` 与 GET `/draft/revisions/{revision}`。所有写入要求 `Idempotency-Key` 与 `expected_revision`，成功 HTTP 200。相同请求重放返回原版本，同键异参和过期版本分别返回 409；恢复旧版通过新 PUT 生成新版本。

PostgreSQL 003 增加三表与不可变触发器；保存正文、当前指针、幂等映射和脱敏审计同事务提交。不接受调用方用户身份，沿用会话和项目授权。内存模式返回 501，不伪造云端保存。节点数 40、标题 80/正文 5000 Unicode 字符、请求体 1 MiB、每项目 1000 版本、历史页 1—50 条；达到版本上限返回 429，不自动删历史。

## 风险与限制

仅保存文本节点，尚无可执行工作流或协作合并；冲突需显式处理，不能自动覆盖。版本为完整快照，1000 个版本是当前硬限制，尚无归档/差分/组织级配额。当前仍为本地单写 PostgreSQL 服务，不是公网生产发布、备份恢复演练或高并发容量放行。数据库管理员可以改变表/触发器，历史保护不等同抗管理员篡改证明。

## 回滚方式

本批未删除旧数据。若仅回退 UI，可继续保留服务端表与历史，不触碰用户草稿。003 已应用后，旧迁移加载器版本会拒绝未知数据库版本；不得直接回退旧二进制或删版本记录绕过检查。需要回退服务端时先停服务、备份并在副本验证兼容版本/显式逆向迁移，保留草稿历史和幂等关系；本轮未实现自动向下迁移或清理命令。

# 187 会话分支的可变高度消息窗口

## 目的

在 V17 的已有会话分页中支持连续翻阅长短交错的历史消息，保留正在增长的回复、键盘落点以及未发送输入。窗口以实际像素定位。

## 范围

H07、H08 / V17。同一会话最多 256 个节点，单分支最多 128 个。工作台继续每次读取 20 条，沿原项目、会话、固定叶节点及服务端游标逐页向前访问。读接口的 SQL 成本由 188 单列。

## 实际文件

- `apps/workbench/src/messageLayout.ts` 以高度前缀和定位像素与下标，单行高度修正和偏移查找为对数复杂度，保存每个已加载节点的有限数值信息。
- `apps/workbench/src/ChatTimeline.tsx` 与 `chat.css` 实现滚动窗口、稳定消息锚点、变宽重测、真实行焦点与显式回到末尾。
- `apps/workbench/src/ChatWorkspace.tsx` 继续使用原有消息组件、授权动作、分支和输入框；订阅由选中的真实叶节点决定。
- `apps/workbench/src/useConversations.ts` 提供稳定的消息 ID 列表，保留同分支读到最早页后的结束状态。输入框的本地改变复用已有消息投影。
- `apps/workbench/src/ChatTimeline.test.tsx`、`conversationPaging.test.tsx` 覆盖高度索引、窗口交互及实际 hook 的异步分支行为。

## 接口与数据影响

当前视口上下各多渲染一个视口，辅以最多一个有焦点的消息和一个活动尾消息。已加载消息仍由原 hook 管理。每次改行高、插入旧页、改变字号导致行高变化或改变行宽时，按首个可见消息 ID 及其行内像素差恢复阅读位置。留在底部时随新正文前进，主动上翻后由读者决定何时跳到末尾。旧行操作仍指向真实消息 ID。切换分支卸载上一个窗口并停用观察器。草稿、分支父节点、受理不明操作和过期响应守卫沿用原逻辑。

同一固定叶刷新只读取最近页。旧实现把已经读至最早一页的空游标当成首次加载，刷新后会再次显示旧分页入口。现在初始化与切换叶节点才从最近页设置历史游标；同一分支已加载的历史保持原顺序与进度。

## 验证结果

在隔离前端目录运行 `node node_modules/vitest/vitest.mjs run --maxWorkers=1 src/ChatTimeline.test.tsx src/conversationPaging.test.tsx src/conversationState.test.ts src/moderation.test.tsx`。定向测试包括 128 个节点的可变行高与视口、390 CSS 像素宽度、插入旧页后的同一焦点与阅读位置、变高的活动尾行、切换分支和键盘穿越窗口。首轮组件用例发现前插时沿用旧数组下标会临时卸载首个可见行；窗口边界改存消息身份后，同一个 DOM 行及其像素位置均保留。旧分支请求晚于新分支返回时，实际 hook 正确保留新分支及本页未发送草稿的原父节点。10,000 个轻量索引只验证高度查找、更新和窗口规模。集中生产构建、真实 PostgreSQL / Chromium 与全量测试由集成人另记。

上述四个定向文件终版共 41 项通过，Vitest 实测 3.71 秒。对 `ChatWorkspace.tsx` 及两份新测试执行 TypeScript 严格模式的定向 `--noEmit` 检查通过。

## 风险与限制

高度测量使用浏览器的实际布局。窄组件测试注入几何值，真实浏览器结果单列。单页读取仍受 1 MiB 应答预算约束，本批未扩大同会话容量或模型上下文。索引试验没有写入一万条会话消息。已加载的消息正文仍受现有分支上限约束；提高容量时需再落实可回读的正文缓存与大规模分页。

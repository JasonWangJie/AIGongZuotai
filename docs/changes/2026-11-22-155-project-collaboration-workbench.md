# 155 · V21-A1 站内邀请与共享项目草稿工作台

## 目的

让两个已有账户通过明确的项目邀请共同查看或编辑节点草稿。创作者保留原个人项目，协作者的草稿权限由当前成员轮次决定。

## 范围

2026-11-22，V21-A1，涉及 H01、H02、H08、H10。「项目协作」显示本人账户编号、站内邀请、已加入项目和个人当前项目的成员管理。共享对象限于该项目的节点草稿及其修订。

## 实际文件

- [App.tsx](../../apps/workbench/src/App.tsx)、[types.ts](../../apps/workbench/src/types.ts) 接入独立侧栏入口与个人项目离开保护。
- [ProjectCollaboration.tsx](../../apps/workbench/src/ProjectCollaboration.tsx)、[SharedDraftEditor.tsx](../../apps/workbench/src/SharedDraftEditor.tsx)、[collaboration.css](../../apps/workbench/src/collaboration.css) 实现项目邀请/角色、显式接受、当前草稿、修订历史、编辑冲突和 390 像素布局。
- [collaboration.ts](../../apps/workbench/src/collaboration.ts) 提供独立作用域路由、回执核对和输入投影。[collaboration.test.tsx](../../apps/workbench/src/collaboration.test.tsx) 验证 UI 范围与状态变更。
- [project-collaboration-browser-smoke.mjs](../../apps/workbench/scripts/project-collaboration-browser-smoke.mjs) 在实际 Chromium 中运行两个账户、三个独立会话并保存桌面及手机截图。

## 接口与数据影响

所有者按对方显示的账户编号创建指定项目、角色的站内邀请，显示拟授项目与权限后明确发送。对方曾加入、过期或被撤权时，界面先按目标账户编号精确读取最新轮次和版本，再展示本次邀请确认，历史行不必出现在当前列表。收件人主动接受后才可打开共享草稿。所有者可撤回待接受邀请、将编辑者降为只读、收回项目权限。提高权限需重新发起邀请并由本人接受。历史收据显示当时轮次和状态；界面重新读取当前有效关系后才提供可用入口。

已有个人项目的选择器、创作任务及普通业务权限保持原作用域。协作路由携带共享项目路径，不发送宿主项目头或项目查询参数。页面可见时每 7 秒、窗口重新聚焦及手动刷新时复核关系。降权后关闭原编辑控件并重新读取只读版本，撤权后关闭相应共享草稿。本页已知的拒绝立即处理。

草稿沿用云节点与资源修订，保存携带预期修订和稳定键。版本冲突时可核对服务器全部节点，再选择采用服务器草稿或保留本页编辑并基于最新版另存。成员操作、草稿保存均不自动重发。回执未知时，只按原操作及原键读取；草稿本地核对记录绑定本人、项目和邀请轮次，仅含编号与修订。

- 环回模拟 API 与本机真实 Chromium 验证两账户、三个会话，实际完成邀请失联查原收据、撤回再邀、只读加入、撤权后重新接受编辑邀请、编辑保存失联查原键、双窗口冲突留稿、读取 r1 历史、降为只读与撤权。两个既有会话都退出被收回的草稿，桌面与 390 像素截图经检查。该验证使用模拟 API，持久账户、真实 PG 数据与恢复证据由集成人独立记录。

## 风险与限制

已在用户窗口展示的文字无法远程撤回。已打开的页面在轮询、聚焦或手动刷新时感知权限变更，服务端在每次请求中复核权限。未保存的节点只保留在当前编辑页。该批为站内既有账户邀请；没有发出验证邮件、加入全工作区或授权资产、生成与计费接口。

## 回滚方式

可先撤回前端入口。角色、收据和草稿修订应连同对应版本的数据库保存。恢复旧后端时使用升级前停写联备及匹配的数据库、私有目录、对象版本与已启用的密钥。

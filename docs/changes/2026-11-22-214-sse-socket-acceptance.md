# 2026-11-22-214：SSE 慢 TCP 客户端与订阅准入验收

## 目的

实测普通 SSE 连接停止读网络后，平台能否在写截止时释放席位，持续读取的客户端能否逐字收到同一 Run 的结果，以及断线客户端能否从实际收到的原游标接回。

## 范围

V17-J3，关联 H03 聊天与 H07 性能。覆盖单控制写者下的活跃 Run 授权订阅，以及 Run 和项目通知共享的工作区和全局准入。独立的内存样本用于校准本机 TCP 行为。

## 实际文件

- `internal/studio/sse_socket_fixture_test.go` 建立本机私有测试监听器、受控 HTTP 模型、快慢客户端并逐条比对。
- `internal/studio/sse_socket_acceptance_test.go` 通过普通业务路由检查慢写、原游标重连、幂等、共享席位及释放。
- 本台账记录测试边界和实测结果。

## 接口与数据影响

测试使用现有 Run 创建、Run SSE/快照、项目通知及登录接口。独立慢端监听器运行同一 App 的完整 HTTP handler。只有该监听器的发送缓冲和配对客户端的接收缓冲请求缩小为 1 KiB，超时由真实 TCP 写入报出。普通端采用独立正常连接。测试不需要新的配置、迁移或生产代理。

## 验证结果

| 检查 | 结果 | 证据 |
| --- | --- | --- |
| 初轮内存调试 | 修正一处验收断言 | 原 Run 键回放实际返回 201 并带 `Idempotency-Replayed: true`，首次用例误期望 200。修正后同时验证响应头、原资源及模型请求数。 |
| `go test -count=3 -timeout=50s -run '^TestSSESocketMemoryWriteDeadline$' -v ./internal/studio` | Windows 本机内存仓、真实回环 HTTP 模型和 TCP 通过，15.875 秒 | 三次底层 Write 超时分别为 5000.14、5000.07、5000.21 毫秒。每轮平台 `write_timeout` 增一、`buffer_full` 增零。快端逐条收到 13 段原文及序号 14 的终态；停读端从实收序号 1 恢复，模型实际 POST 一次。 |
| 共同源码最终复跑 | 通过，5.530 秒 | 独立 Go overlay 编译两项 PG 专测并复跑内存用例。该次 TCP 写超时 5000.99 毫秒，快端接收 12 个后续增量用时 45.31 毫秒。 |
| `go test -count=1 -p 1 -timeout=120s -run '^TestPostgresSSESocket' -v ./internal/studio` | 待集成人真实 PG 串行执行 | 要求隔离回环 `TEST_DATABASE_URL`。覆盖登录权限、跨账户拒绝、原 PG 事件恢复、5 个工作区，使用默认每工作区 32、全局 128 的真实连接和原业务错误码，关闭一个 Run 订阅后第 5 个工作区以项目订阅取得席位，释放后再验两种路由。 |

## 风险与限制

请求缓冲与内核实际分配大小可能不同。专项要求底层写返回超时、正式指标递增、仍未读的客户端对应服务端席位已经释放三项同时成立。指标按应用缓冲已满和真实 socket 写截止分别记录。单机 128 个订阅可由少数 Run 的多位读者组成，万条不同生成运行的容量与 24 小时稳态需另验。

## 回滚方式

停用该批测试即可恢复原测试集合。生产 SSE、数据库与既有运行均继续使用原版本。

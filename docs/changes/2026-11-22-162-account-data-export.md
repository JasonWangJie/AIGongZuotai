# 2026-11-22-162 账户本人资料导出

## 目的

V22-A 为仍能登录的本人提供可保存的账户资料、安全历史和账户申诉副本。每次读取都要持有效会话并重新输入当前密码，申请人可以检查每一页文件的完整性。

## 范围

H01 负责身份和凭据重核，H07 的事务、超时和容量约束用于限制导出占用。数据库沿用 033 格式。仅导出三类账户级资料，有限制的账户可以读取同一范围。工作区、共享项目、业务产物及平台审核材料均不进入数据源。完整 V22 的客服、财务、真实渠道和公开发布另行验收。

## 实际文件

- `internal/studio/account_export.go` 实现窄会话查询、限流、密码证明、最终事务与附件响应。
- `internal/studio/account_export_page.go` 定义分区白名单、数据库查询、游标及精确编码预算。
- `internal/studio/account_export_test.go` 覆盖范围、字节、会话、凭据竞争、受限账户及隐私隔离。
- `internal/studio/http.go` 由集成人注册具体 POST 路由。浏览器工作台与批次联验分别记账。

## 接口与数据影响

`POST /api/v1/auth/data-export` 接受 `section`、`password` 和可选 `cursor`。请求上限 8 KiB，拒绝额外键、重复键及无效编码。分区 `profile` 包含本人编号、姓名、邮箱、注册和验证时间；`security_events` 包含本人事件编号、动作和时间；`account_appeals` 仅包含本人申请编号、限制轮次、状态、结果、版本、理由分类、本人陈述、公开答复和两个时间。未填的申诉文本保持空串。

每份 UTF-8 JSON 使用 `studio.account-export.v1`，包含 `account_id`、`section`、`read_at`、`created_through`、`items` 和 `next_cursor`。附件名为 `account-<section>.json`，响应标记 `private, no-store`，附完整字节数及 `X-Content-SHA256`。每页最多 100 项、512 KiB，计入转义后的内容、元数据和游标。单条无法容纳时返回 413。事件与申诉都使用已有的本人索引，按创建时间和编号双降序读最多 101 条。达到任一边界时，下一页从最后一条实际附入文件的记录之后继续。

当前会话定位仅查询用户和会话。bcrypt 位在数据库锁外使用，按既有认证限流器，导出独立计数，每身份 10 次、同来源 30 次／15 分钟。本进程同时最多两份导出，含下载写入，附件写入期限 15 秒。业务事务按用户、会话的顺序持锁，重核真实散列、凭据版本、会话编号、令牌哈希和有效期，返回前再次核验时效。生成完整附件并确认读事务后才写下载头。接口不生成导出记录、审计正文、后台任务或重试数据，也不写入文件系统。

## 风险与限制

首页由数据库给出创建时间范围的上界，每次续页按该上界读当时已提交的记录。每页单列本次读取时刻。跨请求没有长寿命快照，迟提交的早期记录及后来更新的公开答复按实际可见性处理。游标用当前用户凭据的私有验证值做分域认证，不含密码、散列或会话令牌，同一账户的有效登录可续读，更换密码后从首页重新申请。文件完整性验证不等于服务端知道用户已保存；下载后的文件由用户管理。

## 回滚方式

撤回前端导出入口及 HTTP 注册，并恢复本批变更前的同格式服务制品。已有账户、会话、申诉和业务数据均无迁移或清理步骤。已经由用户保存的附件由其自行保留。

# 191 长会话的有界正文缓存与旧页回读

## 目的

在 V17-F2 中让同一固定分支的用户翻阅已发现的历史时，保留消息身份、阅读位置和原操作，但允许离屏正文退出浏览器缓存。

## 范围

H03、H07、H08 / V17，基于 187 的可变高度窗口及 188 的有界历史分页。工作台识别 036 支持的单分支最大深度 16,384；标题栏显示实际节点数。原工作区的认证及生成受理规则继续由服务端执行。

## 实际文件

- `apps/workbench/src/messageBodyCache.ts` 保留分支索引、服务端选定的原页游标、消息及审核版本，并限制常驻正文。
- `apps/workbench/src/readMessagePageText.ts` 与 `api.ts` 按 fetch 实际解码响应体大小限制消息分页。
- `apps/workbench/src/useConversations.ts` 管理可见范围、原会话读取、取消、失败后的显式核对与权限失效。
- `apps/workbench/src/ChatWorkspace.tsx` 和 `ChatTimeline.tsx` 回读进入窗口的旧消息，保留待取正文行的实测高度，并提供聚合计数。
- `apps/workbench/src/messageBodyCache.test.ts`、`conversationBodyReads.test.tsx`、`ChatTimeline.test.tsx` 覆盖多页淘汰、回滚位置的原页读取、旧状态与作用域，以及原位焦点与占位高度。

## 接口与数据影响

每个已发现消息只需保留稳定身份、来源游标和状态水位。当前工作台每页 20 条，120 个热消息相当于六个普通页面，能保留前后近期浏览区。缓存通过 UTF-8 正文实长再限制在 8 MiB。既有单次公开输出最多 128 KiB，目录输入最多 16,000 字节；64 个最大正常输出仍在 8 MiB 内。窗口保留至多 56 个连续行，额外可以保留当前焦点、活动尾消息与草稿目标，总计上限 64。仅热数据保存原消息正文。索引和高度表的大小随当前已发现节点数量增长，并受格式支持的单分支上限约束。

重新进入离屏页时，通过原会话 URL、项目头、固定叶及原服务端 `before` 发送 GET。首次页原游标为空。若响应因 1 MiB 页预算而缩短，可沿该响应实际返回的下一游标继续；同一窗口回读中每个游标只 GET 一次，总数有界。单页先按可用的 Content-Length 检查，再对实际收到的解压后字节逐块计数；超过 1,048,576 字节即取消读取。流式 UTF-8 解码支持多字节字符跨块。公开事件、审核投影、生成请求和数据库格式沿用本来接口。

正文在途时占位行沿用实测高度。定位依据保持 ID 与像素偏移，键盘焦点和输入表单独立于回读。正文恢复后只投影挂载行、当前叶与草稿来源；普通键入或单次 Run 增量不遍历或复制整个分支正文。暂时失败后由用户显式重新读取当前窗口。隐藏、分支/项目/身份切换使旧回读失效；权限拒绝清除已加载会话、正文与旧订阅，草稿按原身份及项目保存在现有恢复仓。冷页数据的较旧序号或缺失审核版本不能覆盖已观察的限制决定。

## 验证结果

在独立隔离工作台目录运行 `node node_modules/vitest/vitest.mjs run --maxWorkers=1 src/ChatTimeline.test.tsx src/conversationBodyReads.test.tsx src/messageBodyCache.test.ts src/conversationPaging.test.tsx src/conversationState.test.ts src/moderation.test.tsx`。500 页、10,000 个消息身份依序载入，检查每页读取后的热正文计数和字节。跨两个中间页的旧正文按预设输入逐字核对，重复在原窗口读取 50 次仍总计两次 GET。每条 120,000 UTF-8 字节时缓存保留 69 条、8,280,000 字节；极短正文先触达 120 条上限。测试也覆盖无 Content-Length 与虚假长度的超额响应、回读时分页变短、隐藏后的迟到结果、失败后的显式重取、按角色撤权、跨人草稿隔离、已测行高、版本和审核保护。定向严格 TypeScript 检查使用 `tsc --noEmit --strict`。

上述 6 个定向文件终版共 48 项通过，Vitest 实测 5.68 秒，严格 TypeScript 定向检查通过。

## 风险与限制

8 MiB 衡量会话缓存内可显示正文的 UTF-8 大小。浏览器总堆另含 JS 字符串表示、每条有界元数据、可见 DOM、当前请求暂存、既有工作区 Run 缓存及未发送草稿。10,000 条的单元场景使用合成消息页；实际 036 单分支建立、真实 PostgreSQL、浏览器现场回读及服务重开由集成人独立验收。

## 回滚方式

恢复 187 的工作台并重新构建可移除热正文淘汰和自动只读回填。客户端回滚不改已保存的消息及服务端格式；长期使用前须核对旧工作台对 036 长历史的内存占用。

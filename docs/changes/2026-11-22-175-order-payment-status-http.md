# 175 · 本人查看订单的资金记录与 CREDIT 处理

## 目的

V13-B2。让购买人分开核对意向、平台已认证来源的收退款记录及实际 CREDIT 发放。本人查询既有订单时无需重新提交支付、退款、取消或下单请求。

## 范围

新增 `GET /api/v1/order-intents/{order}/payment-status`。沿用 033 普通账户的会话和本人工作区隔离。页面可区分无绑定来源、已绑定待证、已确认收款、退款待匹配及资金待核实，单独显示 CREDIT 处理。测试来源带 `test` 标识。目录关闭后，本人历史仍可读取。

## 实际文件

- `internal/studio/order_payment_status_http.go` 在经 033 实时会话校验的事务内，读取指定本人订单的 035 资金和账务投影。
- `internal/studio/order_intent_http.go` 注册新增 GET，集成人维护此单行接线。
- `internal/studio/order_payment_status_http_test.go` 新增演示前置条件和两账户真实 HTTP 验收用例。
- `docs/api/openapi.yaml` 登记 GET、成功返回、普通账户限制、脱敏错误以及原取消操作的资金保护冲突。
- `docs/changes/2026-11-22-175-order-payment-status-http.md` 记录范围与复验入口。

## 接口与数据影响

公开返回原订单 ID、其冻结币种及小数位、绑定环境和三组独立状态。收款、退款以最小货币单位的十进制整数字符串表示；实际授予与已冲回的 CREDIT 以微点字符串表示，每 1000000 微点等于 1 CREDIT。035 保留原发放，退款进入账务复核，冲回数为零。支付状态 `UNBOUND` 表示无绑定，`AWAITING` 仅表示绑定后尚待收款证据。意向的 `PENDING` 或 `CANCELLED` 均不能推出实际资金状态。没有已记录收款时金额“0”仅指当前记录。

每次 GET 重新锁定并核验当前真实账户与会话，再按用户、工作区和订单，在一条 SQL 中读取原订单、认证经济事实和原发放记录。返回 `Cache-Control: no-store`。外人、越工作区和未知订单在相同账户条件下返回相同的 404 业务码和消息；未登录 401、受限账户 403、内存模式 501。公开 JSON 有 11 个固定字段，排除商户、事件、原交易/退款身份、原始通知、账本 ID 和私有凭据。新取消操作遇到已认证资金记录返回 `409 ORDER_PAYMENT_RECORDED`，原收据仍可按原键只读核对。

## 验证结果

- 增量 OpenAPI 已用 PyYAML 6.0.3 检查重复键并与 034 逐项比较，仅新增一个 GET、一个响应 schema 和原取消的一个 409 说明。166 条路径、190 个唯一 operationId、905 个本地引用解析通过；JSON Schema Draft 2020-12 对 9 组正反例验证通过，覆盖金额格式、环境、状态、必填项与私有额外字段。
- `go test -p 1 -count=1 ./internal/studio -run '^TestOrderPaymentStatus' -v` 两项无数据库专项通过，包耗时 0.299 秒。断言公开字段必须完整且固定、零位币种与空环境可读，演示模式返回 501。
- 真实 PG 由集成人在隔离数据库串行执行 `go test -p 1 -count=1 -v ./internal/studio -run '^TestPostgresOrderPaymentStatusPrivateReadOnlyHTTP$'`。用例创建两个真实账户、三个普通会话，独立校验用户和工作区两个归属条件，并覆盖匿名/受限会话、取消未绑定意向、已绑定待证、已收款、退款先于原款、退款后原发放仍在、旧收据、新取消保护、伪造普通回调路径、重复读取和停用目录后重开。执行结果以本批集成台账为准。

## 风险与限制

该端点只展示在本平台已经受理的经济事实。缺少已选商户的正式验签、授权凭据和受控资金交易，当前没有对外回调、收款或退款执行入口。`test` 环境的隔离回执不代表真实资金或商户验收。CREDIT 状态仅针对当前订单的处理。

## 回滚方式

停止暴露新增 GET 可关闭本人查询。保全原订单、035 经济证据、原发放及操作收据，数据库按集成记录的整套恢复流程处理；不得删除迁移登记绕过格式栅栏。

## 035 本机专项复验

本人状态 HTTP 在真实 PG 通过（3.49 秒），跨账户/工作区隔离、退款先于收款、重复读取及目录停用后回读均维持原断言。完整专项与前次失败在 [177](2026-11-22-177-order-payment-integration.md) 留痕。

随后在同一固定制品上再串行两轮，实际本人状态接口分别 3.72 和 3.98 秒，真实视频浏览器分别 21.34 和 22.48 秒，合计 51.669 秒，四次均通过。

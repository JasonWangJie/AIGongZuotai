# 142 · 本机单写者候选放行与故障回退

## 目的

用两个实际编译的制品验证工作台何时可以停写、切换和重开，验证候选检查不合格时旧制品可以重新读取原图与原收据。

## 范围

V18-B 覆盖本机独立 TLS 入口、受控账户、两个目录锁与 PostgreSQL 控制写者。环境为隔离的 PostgreSQL 16 和程序私有目录。两套制品使用同一套数据库迁移与业务源，各自有独立的 Go 构建身份、前端身份与文件清单。

## 实际文件

- `scripts/release/workbench-release-drill.mjs` 协调入口封流、正常退出、实际三锁核验、候选探针、原制品回退以及再次开放。
- `docs/wiki/assets/release-handoff-2026-11-22.json` 保存三次真实交接的去敏结果，`docs/wiki/release-operations.md` 说明各阶段的放行条件和时间口径。
- 制品构建、服务生命周期与入口分别由同批 139—141 台账登记。根 README、Wiki、唯一任务源及生成项维护本机与真实环境的进度。

## 接口与数据影响

演练生成自有临时数据库、应用账户与私有目录。经 TLS 校验回环证书，以原账户和原操作键读取私有图片、不可变工作流收据，使用部署身份文件区分实际服务的制品。数据库迁移摘要不同的制品不能采用本机原地回退流程。

## 验证结果

集成人执行 `node scripts/release/workbench-release-drill.mjs --previous <旧制品目录> --candidate <候选制品目录>`，在独立回环 TLS、PostgreSQL 16 和两套实际构建制品下完成联合演练，主进程退出码为 0。三次交接均确认 PostgreSQL 控制写者锁和两个私有目录锁能同时取得，指定账户均读回了原私图与原业务收据。[脱敏报告](../wiki/assets/release-handoff-2026-11-22.json)

| 交接 | 计时 | 入口结果 |
| --- | ---: | --- |
| 首次启动候选，额外必验路径故意缺失 | 2061 毫秒 | 两项私有读取通过；缺失路径未返回 200，入口拒绝统一放行，匿名请求仍被拒。 |
| 回到原制品 | 3478 毫秒 | 原制品完成身份、就绪和私有读取核对，统一放行后再次核对成功。 |
| 再次启动候选 | 3949 毫秒 | 候选完成相同核对，统一放行后再次核对成功。 |

计时从该次封流前开始，到该次放行／拒绝的全部检查结束。最后再次进入维护、停止写者并取得三锁后，程序才输出报告。演练使用本机一次性环境，报告保留制品摘要、耗时、状态与计数。

准备阶段的 Node 语法检查通过。归档时逐字段比对公开 JSON 与原始演练输出，两者一致。运行 `npm run check:docs` 和 `npm run check:changes` 通过，当时检查 264 份文档、144 份台账。

## 风险与限制

本机证书凭据只用于本轮演练。运行期间仅一套控制写者持有数据库与目录锁，封流和切换会有停机窗口。真实 DNS、生产证书、跨可用区复制和对外切换需要相应环境及授权。

## 回滚方式

未向公众放行前，保持入口维护。确认候选停止并能取得数据库写者锁和两份目录锁后，重新启动原同格式制品，重新登录、核对原件与原键收据再开放。涉及格式变更时，从升级前配套备份恢复并核对备份点后的写入。

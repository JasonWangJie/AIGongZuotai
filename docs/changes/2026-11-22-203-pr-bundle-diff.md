# 2026-11-22-203 每个 PR 的工作台 JS 制品差异

## 目的

落实总体方案第 257 行的 PR 制品差异要求。在合并前看到启动 JS 的身份、gzip 字节和增减量，并检查候选在 300 KiB 启动预算内的余量。

## 范围

对应 V17-H1 及 H08 工作台。既有 GitHub Actions 工作流在 `pull_request` 事件上独立运行制品比较，保留原有验证任务。H1 的认证冷浏览器仍负责发现实际条件加载及验证网络传输。

## 实际文件

- `.github/workflows/ci.yml` 增加只读 `pr-bundle-diff` 任务，在工作流摘要展示结果。
- `apps/workbench/scripts/pr-bundle-diff.mjs` 离线读取两份公开 dist，建立静态依赖闭包、核验压缩侧件及预算，生成按逻辑块排列的差异。
- `scripts/perf/workbench-startup-profile.json` 保存认证冷首页实测条件、证据来源和观察到的独立块逻辑名。
- `scripts/perf/pr-bundle-diff.test.mjs` 覆盖真实格式的 Vite 制品、历史估算、不可比基线和超预算退出。
- `docs/changes/2026-11-22-203-pr-bundle-diff.md` 记录口径、本机验证及远端验收状态。

## 接口与数据影响

CI 分别检出事件指定的 `base.sha` 和 GitHub 正在验证的 PR 合并 SHA，两个目录各自 `npm ci` 后执行 `npm run build`，摘要显示两份依赖锁的 SHA-256。新任务仅有 `contents: read`，两个 checkout 都禁用凭据留存；不持有部署凭据。输出仅追加到该任务的 `GITHUB_STEP_SUMMARY`，不会写评论、推送提交或发布。运行步骤只调用仓库的正常构建、静态比较和离线测试，提交标识通过环境变量作为参数传入。该任务不需要 PG、外部模型或其他业务服务。

HTML 直接指定的 JS、`modulepreload` 与 `preload as=script` 先列为入口，再遍历真实 JS 语法中的静态 import 和 re-export 并去重。另以 H1 认证首页冷样本记录过的逻辑块形成条件集合，把其额外静态依赖一并计入预算。其余独立公开 JS 分开列出。行为或分包变化时，重新读取 H1 正式冷样本中实际发起的启动脚本，更新观测清单及其依据；旧逻辑名在某侧无法匹配时报告会指出。动态触发顺序和实际网络字节数仍由 H1 验证。

摘要列出根 HTML、入口 JS、gzip 身份、每个逻辑块的文件名及 SHA 前缀、gzip 字节与有符号 B/KiB 差值。候选的每个 JS 必须有与其原文逐字节匹配的 .gz。旧基线缺侧件时按 199 的 gzip level 6 离线估算并逐项标明；损坏的现存侧件会使相应快照无法核验。基线取不到、构建失败或格式无法核验时，候选仍须计算预算，差值留空。已识别的候选启动集合超过 307,200 字节，或候选制品无法核验，任务失败。扫描限制为 4,096 个目录项、256 个 JS、单件最多 8 MiB、JS 原文合计最多 64 MiB。未知脚本布局、链接或外部静态依赖无法当作完整清单通过。

## 风险与限制

模块逻辑名按 Vite 指纹前缀分组。改名会呈现为删除和新增，同名多产物合组计量，报告仍列出全部独立文件。静态分析可以确认无条件导入，但无法预言所有登录状态、授权、特性开关和网络时序触发的动态加载。历史估算可能因构建环境或 zlib 版本而与当时的服务传输量不同。仅当基线快照可核验时才报告差值。

## 回滚方式

独立移除 `pr-bundle-diff` 任务和其比较脚本、测试与观测清单即可恢复原 CI 流程。服务、数据库格式和公开制品内容不发生迁移。保留本记录。

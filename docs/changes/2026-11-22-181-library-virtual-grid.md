# 181　V17 作品库可见卡片与项目退出清理

## 目的

作品库首次读取 24 条。此前每次加载更多都会把已读卡片全部挂到页面，继续翻页会增加 DOM、缩略图元素和浏览器布局工作。离开详情后，先前发出的元数据核对和历史读取还会继续到响应或超时。原方案第 247、257 行要求作品虚拟列表、首屏至多 30 个缩略图、至多一个活动预览视频，并在切换 30 个项目后核验资源回落。

## 范围

V17 本机前端作品库，覆盖 H08 前端体验与 H07 可靠性与性能。沿用 H04 已鉴权的项目资产、缩略图、原件和软删除门禁。PG 的 10,000 条资产索引与真实浏览器的项目切换测量由同批集成验收。

## 实际文件

- `apps/workbench/src/LibraryGrid.tsx` 实现按主工作区视口挂载卡片、滚动占位、稳定资产标识、跨窗口键盘导航和尺寸变化的锚点恢复。
- `apps/workbench/src/LibraryPage.tsx` 将已加载的项目索引交给栅格。按钮仍逐页读取 24 条，元数据编辑、已读成员判断、原键与恢复路径沿用原实现。
- `apps/workbench/src/library.css` 给响应式卡片预留一致的元数据空间，包含审核状态、名称、日期、版本和标签。页面由资产锚点控制滚动位置。
- `apps/workbench/src/LibraryDetail.tsx` 释放离开或权限变化前的原播放器，并统一取消该详情的只读请求。
- `apps/workbench/src/api.ts` 为 `libraryAsset`、`libraryRevisions` 增加可选 `AbortSignal`。
- `apps/workbench/src/LibraryGrid.test.tsx` 覆盖深页视窗、尾页、追加与响应式列数变化、键盘跨窗、视频释放和详情读取消。

## 接口与数据影响

沿用项目、当前会话、审核可见性、资产修订和原有 API。卡片稳定键为资产 ID，实际挂载范围为可见行加上下各一行；首批仍至多 24 卡。上下留白按实际卡片高度、列距与行距计算，使同一资产在加载下一页后保持位置。存在同一锚点时，列数或卡片大小变化会重新定位到该资产所在行。Tab 或 Shift+Tab 可以继续到相邻、尚未挂载的已读卡片。

同次只打开一个详情。视频须显式点击播放；关闭详情、退出项目或审核/回收撤销内容访问时暂停原播放器、移除其媒体源并调用 `load()` 释放媒体加载。详情的当前修订、冲突补读和历史读取共用仅作用于这一次详情的取消信号。已受理或结果未知的修改保留原请求及原键。

## 风险与限制

浏览器仍保留本项目用户已主动读取的轻量资产索引，以支持滚回已读页和编辑恢复；详情和缩略图随视口和项目退出而释放。浏览器可能保留自己的网络缓存，内存分配器也可能复用已释放空间。资源回落应结合存活卡片、视频、连接和可达内存观测。PG 的标签/名称子串搜索及全局控制连接开销不在本次前端修改范围。

## 回滚方式

整体恢复作品库组件、两个 API 读方法和配套样式，重新构建前端制品。项目资产、审核决定、原事务、付款或写入状态均无需数据库迁移。回滚后频繁深翻页仍会累计挂载卡片。

## V17-D 作品库实测

035 在本机 PostgreSQL 与 Chromium 上验证 10,000 个独立索引，认证分页 100 次。浏览器实际加载 20 页共 480 条，首屏 24 条索引中挂载 4 张卡，发出 2 个缩略图请求；深翻时最多挂载 10 张卡，追加页后可见锚点偏移 0 CSS 像素。两个真实私有视频先后播放，同时播放峰值为 1。切换 30 个不同项目后，旧订阅、未释放旧播放器和关闭标签页后的服务端活动处理器均为 0。深页至末次切换，强制 GC 后 DOM 少 187 个、JS 堆少 161,888 字节。专项 30.391 秒。 其中 9,975 条历史记录共用一份私有原图。独立项目分别使用真实上传的不同图片。环境、逐阶段样本与 GC 前提见[聚合测量](../wiki/assets/performance-library-035.json)。

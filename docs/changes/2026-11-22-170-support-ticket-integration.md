# 170 · 三账户工单与撤权后的联备恢复

## 目的

让用户在工作台提交问题、追问和关闭工单，让获得本工作区授权的客服回复，并检验撤权在恢复后的数据库中继续有效。

## 范围

V22-B 涉及 H01、H06、H08 与 H09。站内工单记录双方公开给对方的信息。工单没有调整额度、执行退款、修改审核或发布生成任务的能力。

## 实际文件

- `internal/studio/http.go` 注册用户及客服工单接口；授权、字段与操作见 [168](2026-11-22-168-support-ticket-access-http.md)，持久表与快照见 [167](2026-11-22-167-support-ticket-store.md)。
- `internal/studio/support_ticket_integration_test.go` 启动三个真实登录账户与 Chromium，并在停写期间通过正式离线管理入口预演和执行客服授权。第二个场景撤销授权后完整备份至新库，重开服务核对原始收据、公开答复、撤权和关闭。
- `internal/studio/storage_maintenance.go`、`ledger_admin.go`、`operations_admin.go` 与 `storage_maintenance_delivery_test.go` 更新离线工具的精确格式栅栏。
- `docs/wiki/database-migrations.md`、`docs/wiki/decisions/0034-support-tickets.md`、OpenAPI、README、协作规则、Wiki、台账和规划同步接口和恢复要求。

## 接口与数据影响

034 添加工作区客服角色、工单及不可变消息和按操作者隔离的收据。每个账户在同一工作区最多同时持有八个开放工单。关闭操作保留独立修订容量。客服查询和回复按当前工作区授权，答复时须重新确认当前密码。提交结果不明可按原键核对。工单正文保存在该工单消息内，授权范围外的账户无法读取。

## 验证结果

034 工单专项十项通过，共 48.800 秒。三账户真实 Chromium 10.69 秒，停写撤权后在新库恢复 10.57 秒，四种操作丢失提交确认后的原键回读共 11.57 秒。浏览器核对四个版本及原收据，数据库确认追问和答复各自的操作者，权益与媒体均无新增。

- 集成人执行 `go test -count=1 ./internal/studio -run '^TestSupportTicket'` 通过，0.184 秒；编译了浏览器与联备程序。
- 最终冻结源码的 `npm run check`、518 项前端测试、155 模块构建和六套冒烟通过。撤权清屏后迟到详情、队列和回复均未恢复内容。
- 真实 PostgreSQL、三账户 Chromium、停写授权与撤权后的新库恢复以及累计回归，按进程串行执行后补记。
- 实际范围按[工单工作台验收](2026-11-22-169-support-ticket-workbench.md)及本条集成核对分别登记。

## 风险与限制

已显示或经授权取得的正文可能已由收件人保存。工单详情只提供站内沟通；公司人手、响应时限、合同、隐私与真实运行责任需由实际运营方确认。此项没有发邮件或对外发布。

## 回滚方式

停止写入并保存 034 联备。需要运行 033 制品时，在独立目标恢复当时完整的 033 数据库、配套私有目录、对象版本和密钥。新工单历史保存在 034 备份，不能靠删除迁移登记或改写不可变记录降级。

## 034 累计运行与剪辑选择问题

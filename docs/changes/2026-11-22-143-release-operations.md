# 143 · 本机单写者值班排查与恢复交接

## 目的

让接班人从可重复的观察判断应该继续维护、读取原收据、恢复匹配副本，还是可以开放候选。将健康探针、数据库写入、入口排空与实物恢复区分开来，避免用一个绿色探针代替整个切换结果。

## 范围

V18-D，关联 H01 身份与权限、H04 资产与交付、H07 可靠性与性能、H09 工程与交付治理。以本机工作台已有探针、固定指标、原业务收据、对象版本和私有目录锁编写值班步骤。真实多区值班、外部服务与环境目标仍待独立验证。

## 实际文件

- `docs/wiki/release-operations.md` 汇集接警、复测、排查、停流交接、同格式回退、跨格式恢复和交班字段。
- `docs/changes/2026-11-22-143-release-operations.md` 记录本次文档与本机验证。

## 接口与数据影响

手册调用已有 `/healthz`、`/readyz`、`/metrics`、账户作用域 `/api/v1/runtime`、制品核验与既有本机交接工具。数据库示例仅读取 Outbox 的 pending/retained 聚合值。离线私有目录预演和额度 inspect 仅在持有指定库、目录及停机条件时使用。

## 风险与限制

进程指标重启清零；缓存、作用域运行占用、Outbox 消费水位和用户收到的事件属于不同观察范围。手册引用的本机恢复时间只用于解释一次工作的测量边界。实际值班环境需另备权限、受信任证书、数据位置、恢复对象、排班及环境目标。

## 回滚方式

该变更只增加操作手册与台账。需要纠正某项现场流程时，在手册标记适用版本、修正步骤并保留历史证据。数据库与制品的业务回退按手册中的匹配格式和联备步骤处理。

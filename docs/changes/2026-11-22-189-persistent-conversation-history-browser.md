# 189 · 035 单分支 128 条消息的持久化与浏览器验收

## 目的

为 V17 长会话阅读补上 035 现有分支上限的集成试具。把真实受理的消息、认证接口的分页结果和用户在 Chromium 滚动时实际进入视口的文字逐条核对。

## 范围

一个账户、两个独立项目。主项目同一会话沿同一助手叶新增 64 轮，另一项目单独新增一轮。登录、逐轮受理、模型执行、快照和历史读取均走工作台现有入口，模型响应由仅监听本机环回的兼容端点生成。计量页面使用 1280 × 900 的真实 Chromium。

## 实际文件

- `internal/studio/conversation_history_browser_test.go` 建立隔离 PG 和环回聊天夹具，核对 64 个主会话终态及其冻结上下文，驱动浏览器，输出聚合报告。
- `apps/workbench/scripts/conversation-history-browser.mjs` 读取一次性登录参数，验证工作台真实分页、可视行、键盘焦点、草稿和迟到响应。
- `docs/changes/2026-11-22-189-persistent-conversation-history-browser.md` 记录复跑方式与计量范围。

## 接口与数据影响

试具在独立测试 schema 中通过标准 HTTP 请求建立 65 个已完成 Run。PG 用独立连接核对主会话 128 条消息、64 个终态与 64 份冻结执行上下文。认证 GET 依次读取 7 页（20 × 6 + 8），按每次原受理的 ID、顺序、角色、文字逐一比对，并核对同一用户在兄弟项目作用域读取原会话被拒绝。浏览器独立从实际会话列表进入；首屏读 20 条，显式向前加载 6 次，把主会话全部消息至少一次滚入视口并比对真实正文。每次追加测量同一消息相对滚动容器顶部的位置，允许误差 1 CSS 像素。可见窗口采样要求挂载行数最多 24。

真实键盘 Tab 从离屏但仍持焦点的首条消息最后一个动作进入原本尚未挂载的下一条。草稿由 Chromium 输入事件写入。一次受控延迟先收全真实认证 GET 的响应体，再切换到另一项目并确认该项目的两条消息，随后放行旧结果；原请求信号须已取消，新项目内容和输入仍对应本项目。返回原项目复核草稿。浏览器期间生成 POST 数须为零。

## 验证结果

- 准备区用 Go overlay 执行 `go test -overlay <本机映射> -count=1 -run '^$' ./internal/studio`，包编译通过，0.185 秒。浏览器驱动通过 `node --check apps/workbench/scripts/conversation-history-browser.mjs`。
- 真实 PG/Chromium 由集成人串行执行。将 187、188 与此试具整合并构建工作台，设置 `MESSAGE_HISTORY_BROWSER_TEST=1`、环回 `TEST_DATABASE_URL`，可选 `WORKFLOW_CHROME` 及报告文件的绝对路径 `MESSAGE_HISTORY_BROWSER_REPORT`，再执行 `go test -p 1 -count=1 -timeout 8m ./internal/studio -run '^TestPostgresConversationHistoryBrowser035$' -v`。
- 准备时尚无真实 PG/Chromium 成绩。报告记录原库数量、分页次数、实际可见过的消息数、采样挂载峰值、最大锚点位移、键盘和切换结果；只保留聚合字段，私有输入、标识、游标、地址与口令留在夹具内。

## 风险与限制

本项以 035 已有产品界限为输入，仅覆盖一条 128 节点分支与一个用于隔离核对的兄弟项目。每轮输出以变量行数生成、正文较短，未触及单页字节上限；不代表万节点会话、任意高度、长期泄漏或真实供应商。受控延迟发生在完整本机 HTTP 响应返回后，用来重现应用处理结果与项目切换之间的时序。

## 回滚方式

取消 `MESSAGE_HISTORY_BROWSER_TEST` 可跳过独立专项。试具沿用测试创建和清理的私有 schema、目录与浏览器 profile；移除此试具无需变更应用数据格式。

## 035 工作台与持久会话实测

035 本机 PostgreSQL 经正常入口生成单分支 64 轮，Chromium 在 7 页中逐条核对 128 条消息。首屏 20 条仅挂载 4 条，采样峰值 8 条。6 次前插与缩窄至 390 像素时，锚点最大偏移分别为 0.140625 和 0.140625 CSS 像素。键盘跨窗口、项目切换、未发送草稿和迟到读取均通过，浏览器生成 POST 为零。 两轮首跑未通过：驱动发出的 Enter 只有 rawKeyDown，未产生按钮所需的字符事件。补齐 Chromium 的原生 Enter 文本并保留真实按键和原断言后，用例通过，18.76 秒，包耗时 18.948 秒。试具按所属进程树收尾，聚合报告独占创建。 [聚合报告与工作台制品摘要](../wiki/assets/performance-conversation-history-035.json)。

## 037 有界正文缓存回归

首轮在第六次加载较早页后看到仍在补读的占位行，原 035 试具立刻读取角色而失败（12.615 秒）。浏览器现等待行的原授权正文就绪，并逐一验证相同游标的每次返回。原 7 个不同授权页与 6 次前插的验收保持；回到这些内容时可发生额外同游标 GET。执行 go test ./internal/studio -run ^TestPostgresConversationHistoryBrowser035$ -count=1 -v，最终通过 15.670 秒。本次切换前共读 11 页，其中 4 次原游标回读，128 条实际可见；桌面与窄屏锚点偏移均 0.140625 CSS 像素，原草稿保持，额外生成请求为零。

# 183　V17-E 持久会话的 30 分钟活跃回复

## 目的

核对同一次已受理的聊天能否连续输出 30 分钟，用户在此期间能否持续看到新增文字、输入草稿并滚动页面。通过独立平台 SSE 读者、实际用户界面和 PostgreSQL 记录交叉验证，保留能复查的测量范围。

## 范围

V17，H03 模型执行、H07 可靠性与性能和 H08 前端。服务从正常 cmd/server 入口启动，登录合成账户，通过本机 OpenAI 兼容流接口发送一份模型请求。正式实验使用真实墙钟、隔离 PostgreSQL 和 Chromium。真实供应商、万个同时活跃会话和 24 小时生产稳态各有独立条件。

## 实际文件

- `internal/studio/long_reply_browser_test.go` 建立隔离 schema 和私有目录，独立观察执行租约及序号，检查终态、保留窗口、登录原库重新读回同一回复并生成报告。
- `internal/studio/long_reply_process_test.go`、`long_reply_process_guard_test.go` 与 Windows、Unix、其他系统的三个测试后缀文件控制验证子进程。Windows 用 Job 对象，Linux 与 macOS 用独立进程组。运行驱动须等父进程接管后再启动服务及浏览器。
- `docs/wiki/performance.md` 记录当前范围与运行方法。配置解析、数据源与浏览器逐段证明分别见 184、185 和 186。
- 任务源、生成的 TODO、进度、README、Wiki 与台账索引同步本项的验证状态。

## 接口与数据影响

现有 Run、会话、用户身份、持久流、执行租约及版本序号继续使用原契约。默认期限保留 600 秒，正式实验显式设置 2,100 秒。测试只在自己创建的 schema 内写入一条 Run，原件与报告均由此次实验单独管理。公开报告仅含聚合数字、合成输出摘要和制品身份。

## 验证结果

首轮 PostgreSQL 短档完成 25 段，终态序号 26，采到 13 个租约样本，原库重开后读回相同正文；包耗时 24.878 秒。首次正式运行在 117 秒时由集成人停止，用于加强每分钟浏览器正文增长与驱动退出的核对；没有把这次中断计入 30 分钟成绩。第二轮短档通过，25 段、终态序号 26、12 次租约采样，原库重开一致，耗时 19.493 秒。Windows 下分别验证正常退出、取消与父进程被终止后真实子进程释放文件锁，三种情形各跑三次，共 0.917 秒。另完成 Linux amd64 和 macOS arm64 测试程序交叉编译，这两个系统未做实际进程退出演练。正式运行按实际结果登记。

## 风险与限制

流式端返回可逐段核对的合成文本。测试使用一个工作区、一个账户、一个模型、一个服务进程和本机网络。强制 GC 的瞬时数值不能代表长期无泄漏。本次不测真实 AI 语义、费用、跨实例调度、单会话万条历史或正式容量环境。

## 回滚方式

删除显式期限配置后重启下次本地服务即可恢复原默认值。开发验证程序不创建产品数据库迁移或新写入协议。实验结束后释放本次进程、独立 schema 和私有目录，历史报告可继续复核。

## 035 正式墙钟实测

035 正式服务对本机兼容端发出一次请求。1,801 个增量持续 1,800.26 秒，Chromium 独立接收序号 1 至 1,802。30 次逐分钟采样均显示新增正文，输入至两帧的 P95 为 30.2 毫秒，滚动至实际位移的 P95 为 31.2 毫秒。PostgreSQL 独立观察 120 次租约，确认终态后从原库、原私有目录重开，25,214 字节回复逐字相同。 集成人的正式 Go 用例耗时 1,806.06 秒，包耗时 1,806.218 秒且进程退出码 0。上游首末增量相隔 1,800.26 秒。数据库终态保留 256 条流事件，floor 为 1546，原租约到期时间推进 1,780.0 秒。切换项目后旧 Run 订阅、待刷新的计时器和旧消息 DOM 均为零。浏览器报告保留各阶段强制 GC 后的内存值；此结果来自单机单标签的合成模型流。 [完整聚合报告](../wiki/assets/performance-long-reply-035.json)。

## 036 工作台短档复核

在包含可变行高列表、有界正文缓存与 036 格式的服务上重跑 12 秒短档。25 个增量与终态、12 次数据库租约观察及原库重开均通过，测试包耗时 17.733 秒。035 正式 30 分钟成绩保留其对应制品身份。

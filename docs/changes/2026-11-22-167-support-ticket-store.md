# 2026-11-22-167 站内客服工单与操作收据

## 目的

V22-B 为本人和获得指定工作区授权的客服提供一条可回读的沟通记录。用户能在同一工单里查看自己的陈述和客服的公开答复，也能在连接中断后核对某次操作是否已提交。

## 范围

H01 身份与权限、H06 审核与运营、H09 工程与交付治理。本子项交付 PostgreSQL 存储、授权核验与专项。HTTP、停机授权及工作台分项记账。支持人员只能向工单追加公开文本，账户限制的申诉继续使用既有专门入口。

## 实际文件

- `db/migrations/034_support_tickets.sql` 增加支持角色以及工单、消息、操作收据和范围索引。
- `internal/studio/support_ticket_store.go` 定义输入、公开投影、事务授权、分页、变更及原键读回。
- `internal/studio/support_ticket_store_test.go` 验证字符和数据投影、同空间不同账号、角色范围、撤权、CAS 和容量。
- `internal/studio/support_ticket_store_transactions_test.go` 覆盖带原订单的 033 升级及四类 COMMIT 确认丢失。

## 接口与数据影响

本人按有效会话的工作区创建、查阅、追加和关闭自己的工单。每个本人账号在同一工作区可同时保留 8 个开放工单，已关闭历史按创建时间和编号双降序分页，每页 20 个。分类支持账户、账务、生成和其他；主题最多 120 字符且 480 字节，正文最多 2000 字符且 6000 字节。主题在列表可见，所有消息正文仅进入详情及本人有权读取的操作收据。返回消息只含版本、种类、正文与时间。

每单从版本 1 起步，最多 32 条消息。建单、用户跟进、客服答复占用前 31 项，第 32 项始终留给本人关闭。写入带操作者原键，跟进、答复、关闭还须提供所见版本。事务先锁用户和当前会话，客服额外锁工作区的有效 `support` 授权，回复时在同一事务重核刚验证的密码及凭据。相同的原键在当前授权下优先回读；异参冲突。撤权后，客服不能再获取原工单详情、收据或重放原答复。

034 新建 `studio_support_tickets`、`studio_support_messages` 和 `studio_support_receipts`。每次变更将新版本、消息和收据一起提交，数据库延迟约束在提交时重核三者一致。消息与收据不可更改，收据固定执行版本，并从不可变消息重建原时刻的状态和全文，避免在每张收据重复保存整段历史。新增的 `support` 角色由现有停机授撤流程明确授予；迁移不生成客服授权或虚构工单。

## 风险与限制

用户应为列表选择简短主题，把个人细节放入正文。受权客服可接触该工作区工单正文，撤权只阻止其之后读取。回复由客服按实际情况填写，系统不接受额外的关系实体、外部证据、付款信息、审核指令或附件字段。本机存储专项不承担真实客服人员值守、响应时限和外部服务验收。

## 回滚方式

上线前可恢复原程序及其对应的 033 联合备份。已有 034 新工单、消息或收据的环境应先停写、保全并核对新增记录，再决定迁移或恢复，保持旧程序的格式拒绝。不得通过删除迁移登记或消息历史强行倒退。

# 121 · V14-C2a 内容申诉工作台

关联 V14、H01、H05、H06、H08。C1 工作区新生成限制与复核继续使用原有入口。

## 目的

让原生成申请人对已执行且输出审核受限的 Run 或媒体 Task 申请人工审议，读回自己的申请、原审核版本、独立意见与实际财务收据。工作区审核员与财务人员分别在“运营核实”中处理各自授权的部分。账户限制轮次和全局账户申诉另列 C2b。

## 范围

V14-C2a，申请人、审核员和财务工作台。

## 实际文件

- `apps/workbench/src/App.tsx`、`types.ts`、`ChatWorkspace.tsx`、`WorkflowRun.tsx`、`ContentAppealLink.tsx` 接入账户/项目范围、本人申请导航和原资源入口。
- `apps/workbench/src/ContentAppealPage.tsx`、`ContentAppealOperations.tsx`、`contentAppeals.ts` 与 `content-appeals.css` 实现受理、本人列表详情、工作区审议与原财务工单转交，适配窄屏。
- `apps/workbench/src/OperationsPage.tsx`、`operations.ts` 按当前工作区的角色及显式权限开放页面；关联工单进入既有 013 财务预演和当前密码执行。
- `apps/workbench/src/contentAppeals.test.tsx` 验证资格、项目边界、预演归属、财务展示与原收据核对。
- `apps/workbench/scripts/content-appeal-browser-smoke.mjs` 与 `local-browser.mjs` 运行三个独立浏览器登录环境；`workflow-browser-smoke.mjs` 共用本地 Chromium 启动和退出逻辑。

## 接口与数据影响

本人视图使用项目作用域和 `/api/v1/content-appeals`，从已持久受限输出进入申请；项目历史中原资源归属、审核决定、执行证据仍由服务端确认。列表仅展示摘要，正文经受权详情 GET。输入拒绝没有原资源。浏览器展示申请人的说明和公开答复，不读取受限文本、私图原件或审核候选。

运营视图使用 `/api/v1/operations/content-appeals` 和显式工作区。审核员核对原决定后预演维持、记录意见或转交财务，勾选确认并输入当前密码才执行。原决定、资产门禁和账务按既有规则保留。财务队列仅展示转交的资源和申请编号，关联工单后复用原冻结核实。本人详情只有看到已释放状态、正式收据编号和正整数微单位结果才展示实际释放数量。意见、转交或单纯结案分别显示。

浏览器同标签会话存储仅保存用户、作用域和原操作编号。未知申请和财务关联通过原键 GET，未知审议执行通过原计划 GET。敏感表单离开时清空，密码、正文、内部证据和预演摘要不进入会话存储。

## 风险与限制

列表补读每页 20 条、单次视图至多 200 条。正文只在已授权详情和页面内存中显示；重新登录后通过当前作用域重读。没有输出资源、缺少可证明的执行记录或原决定版本已变化时，后端可拒绝受理。跨项目、跨工作区、授权撤销及同一主体兼任多种角色的限制最终在服务端执行。C2a 不提供账户全局封禁、旧内容放行或自动生成。财务显示 CREDIT 创作点，以已提交收据为准。

## 回滚方式

先核对所有已发出的原申请和已消费的计划；联备保留 026 申请、计划、处置、财务工单关系及原账本。前端与兼容存储/服务版本一起切换。切换界面不撤销已提交的审议或财务收据。

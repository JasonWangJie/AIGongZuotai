# 174　V13-B2 已认证收退款事实与购买权益事务

## 目的

收到同一笔付款的多份通知时，工作台只给原购买发放一次权益。已认证退款可以早于付款抵达，也可能在该笔购买的权益已经消费后抵达。收件、资金事实、权益发放和人工待核各有独立证据。

## 范围

V13-B2 的本机持久事务部分，涉及 H01 身份范围、H05 账务与支付、H07 可靠性与恢复，复用 V12 权益账本和 V13 订单。本人 HTTP 读取权限与公开字段由 175 记录，浏览器交互由 176 记录。测试中的通知全部来自包内测试夹具。

## 实际文件

- `db/migrations/035_order_payments.sql` 新建环境、原意向绑定、经济身份、事实、通知收件、冲突隔离、购买权益关联、复核标记及待处理名额表。
- `internal/studio/order_payment_store.go` 实现私有绑定、输入校验、通知事务和原通知回执读取。
- `internal/studio/order_payment_store_facts.go` 归并经济身份、保留冲突观测、调用原 V12 双分录方法并处理账本上限。
- `internal/studio/order_payment_store_projection.go` 按同一 SQL 快照分别投影订单币种下已确认归属的金额、退款进度及已发权益。
- `internal/studio/order_intent_store.go` 在创建容量和取消处使用新证据。原键读取顺序、旧商品和意向收据沿用 033。
- `internal/studio/order_payment_store_test.go`、`order_payment_store_refund_test.go`、`order_payment_store_transactions_test.go` 覆盖输入、跨连接同笔重复、冲突、退款、容量、取消竞争、丢失提交回执及 034 升级。

## 接口与数据影响

普通程序没有绑定、核验或收取商户通知的 HTTP、CLI、配置开关或后台任务。将来需由正式适配器先独立验证来源并解析已登记的订单，再显式调用包内 `bindOrderPayment` 与 `recordAuthenticatedOrderEvent`。启用订单商品目录、生成计价、用户新建意向或使用 173 对账文件均不会触发这两个操作。首次显式绑定把数据库固定为 `test` 或 `live`；同库的其他商户仍各自拥有独立的交易和通知命名空间。

通知 ID 绑定完整的来源、商户、环境、订单、工作区、本人、交易、退款标识、币种、整数金额和纳秒发生时点。相同通知原样读取第一次提交的快照。同笔交易的另一通知可留下独立收件，经济事实按同一交易只计一次。通知身份与原内容冲突时，原件与矛盾观测分存，相关订单和经济身份留待核实。真实发生时间早于绑定或晚于首次入库的数据库时间，按照冻结的首次接收时间核查。日后读取不会随墙钟改变判断。

同一正常意向仅在已绑定、单笔全额、原币种、时间一致且没有退款或争议时，才按原 `credit_micros` 向原工作区发放 CREDIT。权益 journal、两条平衡 posting、订单关联、事实与收件一并提交。余额容量不够时回滚本次发放的保存点，保留确认的到款和待核标识。每笔发放有订单唯一约束。

用户主动取消和收件锁同一原订单。先取消后到账，保留已取消的意向与已到账的资金证据，权益待核。先有资金记录再发新取消请求，返回 `409 ORDER_PAYMENT_RECORDED`。旧取消键仍可核对第一次的收据。本人最多 32 笔待处理意向，只由明确取消或已登记的原购买权益 journal 释放一席。升级时沿用原待处理席位，未创建收款绑定，也未改变 033 的 `PENDING/CANCELLED` 及原收据。

金额使用商品货币的最小单位，权益使用六位 CREDIT。币种不一致或经济归属不清时，资金待核且该金额不混入别的币种或账户。多笔实际同币到账可见合计与待核状态。退款按原交易核对先后、唯一退款流水及累计金额；部分或全额退款事实独立留存。权益尚未发放、已花用、被 HELD/REVIEW 占用或来自另一购买时，均无自动扣回权限。已发的权益和消费 journal 保留，退款权益处理进入待核。

## 风险与限制

付款事实只能由未来具备正式验签、商户/环境白名单、原结账会话关联与防重放能力的适配器提供。本批没有商户密钥或可配置的录入器。生产资金额度、结算状态、退款业务政策及人工解决争议的权限与执行流程仍需确认。接收时刻使用数据库时钟，渠道与本机时钟不一致会保守转入待核。账本是工作区共享 CREDIT 账户，不能由余额推断原购买的权益仍完整可退。

## 回滚方式

先停写、保留 035 以后新增的商户事实、权益流水、提交回执和同期其他工作区业务，核对最后处理位置与备份边界。若必须回到 034，在隔离环境恢复升级前匹配的完整数据库、两私有目录、对象版本及已启用密钥，再制定和核对新写处置方案。034 旧写者会拒绝 035。不得清除迁移登记、修改不可变流水、直接回填退款或推定已完成追回。

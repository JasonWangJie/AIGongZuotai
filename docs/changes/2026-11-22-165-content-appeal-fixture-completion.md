# 165 · 内容申诉浏览器验收等待原任务提交

## 目的

内容申诉的浏览器验收需要一笔已审核拦截、仍保留原冻结额度的媒体任务。夹具先确认该任务的持久状态，再打开浏览器进行本人申诉、运营复核、财务核实及原收据读回。

## 范围

V14-C2a 的 H05、H06、H08 本机回归。031 全量中，原夹具在 5 秒内未等到 FAILED，测试于浏览器启动前失败。原日志未保留最后一个实际任务阶段，无法据此判断当时任务最终如何落库。正常提交首次查询已有 3 秒间隔，交付和首次审核还有各自的调度与提交步骤。

## 实际文件

- `internal/studio/content_appeal_integration_test.go` 为这一浏览器夹具提供原项目通知、独立数据库读取和限时诊断，继续使用原来的网关、审核、权益、申诉及账务流程。

## 接口与数据影响

先订阅原项目 Outbox，再按任务、项目及工作区在独立连接上读原任务文档及调度、交付、首次审核状态。通知到达即补读；250 毫秒定时器应对合并或未及时到达的通知。只有原任务已提交为 FAILED、首次审核 FINISHED、决策 BLOCKED、账务 REVIEW、冻结 200000 微点且释放 0、公开产物为零，才进入浏览器操作。

错误终态、上游受理不明和待核实立即失败，其余等待以 60 秒为限。诊断只输出固定状态类别、版本和请求或产物计数。测试不改变调度时间、审核超时、原请求或用户 API。

## 验证结果

修正两项夹具的等待边界后，032 完整 PostgreSQL 累计回归通过，工作台 1639.820 秒，编解码包 2.652 秒，无失败或跳过。

`go test -count=1 ./internal/studio -run '^TestContentAppeal(BoundedInputAndPublicProjection|FinancePublicFields)$'` 本地通过，0.203 秒，含改后夹具编译。真实 PostgreSQL 与 Chromium 的单项复跑命令为 `go test -p 1 -count=3 -v ./internal/studio -run '^TestPostgresContentAppealBrowserAndOriginalFinancialReceipt$'`，需启用 `CONTENT_APPEAL_BROWSER_TEST=1`、独立测试库及已构建工作台。三次串行复跑及后续全量由集成人执行并归档。

集成人在独立 031 副本运行原浏览器场景三次，20.23、18.66、18.75 秒均通过。真实任务进入 FAILED、BLOCKED、REVIEW 200000，解除原冻结并读回原收据。

## 风险与限制

本机等待边界仅用于准备测试数据。不同主机负载和数据库进展仍可能使其超时；超时时保留最后一次已提交状态的去敏诊断。该项不验证真实商户或外部审核渠道。

## 回滚方式

可单独还原浏览器夹具的等待与诊断改动。生产代码、数据库格式及已受理任务均无需迁移。

# 230 · 根 TODO 显示批次验收子项和最近台账

## 目的

V02 的根导航此前只显示批次状态。批次内的验证通过或追加台账后，根 TODO 可能仍逐字相同，变更同步检查会报告缺少根导航。开发者也需要翻阅完整清单才能找到该批最近的记录。

## 范围

根导航为进行中批次列出已登记验收子项的总数与通过数，并为已有台账的批次提供编号最大的记录链接。整批的勾选继续取自任务源的批次状态。

## 实际文件

- `scripts/tasks.mjs` 从同一批次的 `checks` 和 `ledgers` 生成根导航。
- `scripts/tasks.test.mjs` 新增进行中状态、验收计数和台账选择回归。
- `docs/changes/2026-11-22-230-todo-entry-acceptance.md` 记录该项治理调整。集成时同步根 README、Wiki、索引、任务源、两个生成入口和推进记录。

## 接口与数据影响

根导航把 `passed` 计入通过数，已登记总数包括待验、阻塞和失败记录。台账按文件名的三位编号选择，链接从根目录指向记录正文。脚本读取现有任务源结构，完整 TODO 继续保留每条命令、结果、证据和依赖。

## 验证结果

- 新增两项回归在旧生成器上均失败，修正后 `node --test scripts/tasks.test.mjs` 共 12 项通过、0 跳过。用例覆盖部分通过、全部子项通过但批次进行中、空清单、无台账、日期与编号逆序、源列表无序以及追加新编号。
- 在隔离副本复制当时的任务源及实际引用文件，执行 `npm run todo:sync` 和 `npm run check:todo` 均通过，共 10 个模块、24 批，14 批已验收。V21 的 3 项子项全部通过，根导航仍正确显示进行中。
- 原有变更治理用例继续检查代码修改必须同步任务源、根导航和完整清单。主工作区合入后另运行 `npm run check:changes` 检查实际变更集合。

## 风险与限制

数字描述当前已登记的验收记录。完整放行还取决于批次依赖、验收条件与外部实测。原有台账记录的文字补充可在完整清单及对应正文回查。

## 回滚方式

恢复该项修改前的根导航渲染与对应测试，再用保留的任务源执行 `npm run todo:sync`。已有任务和历史台账继续保留。

## 文档同步

集成人同步 V02 任务源、台账索引、根 README、Wiki 和推进记录，重新生成根与完整 TODO。

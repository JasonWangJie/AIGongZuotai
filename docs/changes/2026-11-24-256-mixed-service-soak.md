# 256 · 同一持久服务的分窗混合运行

## 目的

V17 的短时固定规模测量已分别记录聊天、原媒体查询和受理成绩。此次给持续混合运行增加可执行入口，让同一组账户、会话、数据库和本地服务跨越正常、突发、控制进程故障及恢复窗口。

## 范围

V17，H03/H07/H08。通过标准控制器、正式登录及正常项目 API，在同一隔离的 PostgreSQL schema 内交替投放两工作区负载。短档固定 108 秒；长期档固定 24 小时。两者共用窗口、收据、终态、故障和资源观测代码。

## 实际文件

- `internal/studio/soak_acceptance_test.go` 组织正式登录、两工作区请求、分窗、重启、原键原游标恢复及独立 PG 对账。
- `internal/studio/soak_gateway_test.go` 实现只接收本次预定模型协议和输入的环回 HTTP 上游，核对原提交及原查询，覆盖受控 429 和上游失败。
- `internal/studio/soak_window_accounting_test.go` 绑定事件计数和样本的时间戳，逐窗核对断言，并验证漏投与实际故障的时间边界、90 秒终态观察及旧服务 PG 连接释放。
- `internal/studio/soak_measurement_test.go` 定义两档时隙、分位统计、GC 聚合、数据库活动与通知积压观测，逐行写入专属 NDJSON。
- `internal/studio/soak_resources_test.go`、`internal/studio/soak_resources_windows_test.go`、`internal/studio/soak_resources_other_test.go` 提供有界的自有进程资源采样和平台边界。
- `internal/studio/chat_child_process_acceptance_test.go` 将已有自有服务启动函数的标准错误增加受控诊断写入端。
- `docs/wiki/mixed-service-soak.md`、本台账说明命令、结果口径与条件。项目入口、生成待办和索引由集成人随实测同步。

## 接口与数据影响

复用 040 格式、本机私有目录锁、控制写锁和现有认证/幂等/SSE API。测试配置只在驱动进程生效。工具创建并清理本次 schema，只终止自己启动的控制器；报告按排他新文件写入，内容为固定类别计数、分位、摘要和资源聚合。商业支付、外部供应商及业务运行时配置均沿用当前状态。

## 风险与限制

两档共用同机 Windows 控制器、测试驱动和环回 HTTP 上游，负载有界且固定。图片由供应商返回已知失败，成功的产物交付和真实供应商吞吐需另验。每个服务代次生成独立 PG 标签，重启前要求旧代关联的全部服务连接归零。漏投只在实际 Kill 与替代服务就绪之间到期且原因为过期时豁免。资源和尾延迟记录用于后续对比，没有预设通过阈值。CPU 为进程累计时间，驻留量、句柄、PG 状态为边界采样；GC 记录可能受实现格式影响，未解析行数单列。参考机、独立负载机、目标并发曲线和持续 24 小时仍按 V17 原条件验收。

## 回滚方式

撤出本台账新增的验收文件和 Wiki 说明，将既有子进程测试辅助函数的 stderr 恢复为 `io.Discard`。业务 API 和 040 数据格式均可由原版本继续读取。

## 集成人实库结果

集成人从主树构建标准服务，通过本机实库 `STUDIO_MIXED_SOAK=pilot`。6 个 18 秒窗口实测 108.008 秒，14 对计划全部投放，14 条正常聊天完成，14 个图片任务按受控上游的明确失败收尾。另 1 条故障聊天从保留的原增量读取中断终态。原键核对聊天 17 次、图片 16 次。上游累计 15 个聊天 POST、14 个图片 POST、15 次原 GET，含 1 次受控限流，重复生成与无效请求均为 0。杀停服务到核实原收据为 869 毫秒，旧代 PostgreSQL 连接归零，排空时活动任务、活动聊天和未投影通知均为 0。 [分窗实测](../wiki/assets/mixed-service-pilot-040.json)

合入 256 和 257 后，主树在隔离外部渠道的环境中三次串行执行 7 个混合负载单测及 1 个查询窗口单测，共 24 项次通过。`go vet ./cmd/server ./internal/studio` 退出 0。

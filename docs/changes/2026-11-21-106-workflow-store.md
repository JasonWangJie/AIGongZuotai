# 106 · 工作流固定版本、节点意图与选图存储

## 目的

在 PostgreSQL 中保存首条「文本生成 → 图片生成 → 人工选图」流程。用户可以回到同一固定版本，跨会话核对原有的子 Run、Task、图片候选和已经确认的选择。

## 范围

V19-A，涉及 H02、H03、H09、H10，承接 [105 实施契约](2026-11-21-105-workflow-execution-plan.md)。普通草稿仍按 V03 的格式保存。项目内可创建多个定义，每个定义有独立的不可变版本；第一版执行器一次处理一个生成节点。

## 实际文件

- `db/migrations/023_workflows.sql` 新增流程定义、不可变版本、运行、节点意图和操作收据。DB 复合外键约束定义、原 Run 和原 Task 都属于同一项目；子资源的唯一部分索引定位原流程。
- `internal/studio/workflow.go` 定义图、节点、端口、运行与候选，校验固定模板版本、节点身份、参数、边、类型和大小。
- `internal/studio/workflow_store.go` 实现项目内版本保存、CAS、读取列表、启动、配置冻结及原键收据查询。`internal/studio/workflow_steps_store.go` 处理节点原键、冻结输入、实际子受理核对、候选读取与人工确认。
- `internal/studio/workflow_outcomes.go` 在子受理事务中绑定父运行，并在终态事务中推进父状态和冻结原候选。`internal/studio/outbox.go` 接入 Run、Task 已提交状态和原有项目通知的共同事务。
- `internal/studio/workflow_store_test.go` 覆盖图校验、跨项目访问、原键、固定版本、重用私有子键、候选版本变化和两个数据库连接竞争确认。

## 接口与数据影响

每个项目最多 64 个定义、每定义 64 个版本、每项目 128 次运行。图为三节点、两条有类型的边，单个提示指令最多 4096 字节，编码后的完整图最多 24 KiB，运行输入最多 16000 字节，图片展开数量为 1 至 4。定义保存原键指向最初保存的版本；启动原键指向原运行，重读仍保留启动时的输入、模型版本、公开能力、参数、模板和渠道模式。

每个生成节点预留唯一的、仅服务端可见的子业务键。用户操作键、预期版本、完整 Run 或 Task 请求及报价身份在子受理前冻结。已确认无原子资源的拒绝可以重新提供报价，沿用原私有子键。普通子受理事务同时绑定父运行、占用适用的权益和登记子幂等。子 Run 的公开终态决定图片步骤能否开始。成功交付图片的媒体事务在完成资产登记时写入等待状态与完整原候选。事务失败时父状态、审核、权益、资产和对应项目通知一并回滚。

候选保存原 Task、产物和项目资产身份。内容版本由该资产身份和原字节摘要派生；没有字节摘要的本地演示资产使用不可变来源标识。详情刷新时，原内容仍可见的图片显示当前元数据修订，用户改名后仍可选择原图。人工确认在项目锁内复核运行版本、原候选、内容版本、用户看到的当前资产修订、可见性及审核状态，保存唯一选择和收据。已回收或已换内容的候选保持不可选。详情 GET 读取持久事实，原操作收据可跨会话读取。父状态推进通过子资源索引完成，没有逐流程轮询。

## 验证结果

- `go test ./internal/studio -run '^TestWorkflowGraphValidatesPortsBoundsAndDAG$' -v -count=1` 通过，包耗时 0.217 秒。正常图和 14 个反例涵盖重复节点、环、错误端口、缺失目标、模板版本、展开数与字节预算。
- 集成人首次真实 PG 升级复测 `TestPostgresWorkflowUpgrade022` 通过，用时 1.27 秒。原子推进组合用时 4.265 秒，其中 `TestPostgresWorkflowFrozenVersionsAndNodeIntent` 通过，用时 0.96 秒，原候选与双连接确认首轮通过，用时 1.08 秒。原始记录为 `.runtime/v19a-atomic.log`。加入改名刷新、归档及内容变化回归后的结果随集成人最终检查登记。

集成人于最终源码组合重跑上述两项真实 PG，冻结版本与节点意图用时 1.05 秒，原候选及双连接确认用时 1.09 秒。后者覆盖改名后旧修订拒绝、刷新再确认、回收及字节身份被替换；两者所在最终组合用时 39.793 秒，记录于 `.runtime/v19a-focused-final.log`。

## 风险与限制

达到存储上限后，新增对应资源会被拒绝，历史仍可读取。当前流程只支持两个生成节点和一次确认。已受理的非确定结果保留原子执行和收据，用户仍须核对原资源。V19-B 的图片输入视频、V19-C 的显式重跑与取消另行验收。演示资产来源身份和本机环回验收各有边界，真实供应商及生产容量需独立验证。

## 回滚方式

停机后还原升级前同一时点的 022 数据库、私有资产和参考目录、owner、适用密钥及已启用存储的对应对象版本，再运行匹配的旧程序。回退前核对 023 期间新增的定义、运行、子资源及额度记录；保留迁移登记和目录归属。

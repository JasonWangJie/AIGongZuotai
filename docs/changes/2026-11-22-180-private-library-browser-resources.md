# 180 · V17 作品库万条索引、私有媒体与项目切换资源观测

## 目的

用真实 PostgreSQL、Go 平台与 Chromium 检查原方案第十四章作品库目标。一次测量固定一个账号的一个万条作品库、首屏不超过 30 张缩略图、最多一个活动预览视频，并在同一浏览器标签依次切换另外 30 个项目后核对资源释放。

## 范围

V17 涉及 H03 模型与执行、H07 可靠性与性能及 H08 前端体验。试具使用本地账户认证、项目选择器、作品素材页面、生产分页接口、私有文件入口与项目 SSE。依赖可用的私有媒体交付、既有工作台构建及同期的可视区栅格和视频清理。

## 实际文件

- `internal/studio/library_resource_browser_test.go` 构造隔离项目、生成可播放原片、加载历史索引、用生产接口逐页校验，并统计浏览器请求对应的项目 SSE handler 从进入到实际退出。
- `apps/workbench/scripts/library-resource-browser.mjs` 驱动一个新 Chromium 配置目录及同一标签，记录真实网络、已解码缩略图、播放进度、渲染窗口、原锚点和各阶段 CDP 内存计数。
- `docs/changes/2026-11-22-180-private-library-browser-resources.md` 记录这次测量协议及证据边界。

## 接口与数据影响

沿用现有 API 与数据库结构。试具要求显式启用，先核对数据库连接目标为环回，再由现有测试工具创建随机 schema。主项目在真实 HTTP 入口取得 22 张不同参考图、一个已批准的生成图片及两段已批准的不同 MP4。额外装载 9,975 个各自有 ID 的历史终态任务、作品索引及首个不可变修订，使用历史无审核记录的存储形状并共享一份实际私有原图与缩略图。30 个分区各自通过 HTTP 上传一张不同色卡。匿名、另一账号及当前账号的另一个项目分别读取图库缩略图和视频均须被拒绝。

同一主项目的认证键集查询每页读 100 条，连续一百页校验不重复的 10,000 个身份和正确项目，并从末页实际打开原件、比对完整字节、解码缩略图。浏览器单独打开首屏的 24 条，通过“加载更多素材”追加 19 次，实际加载 480 条记录，记录虚拟化后挂载的卡片数量。追加前后的首个可见资产身份须一致，锚点位移至多 2 个 CSS 像素；深页可返回同一首条记录。

## 验证结果

- 无 PG 的定点命令 `go test -count=1 ./internal/studio -run '^TestLibraryLoad' -v` 两项通过，隔离源码使用 Go overlay，包耗时 0.239 秒。覆盖仅接受环回地址、SSE 实际处理未退出与已退出的计数。浏览器驱动通过 `node --check apps/workbench/scripts/library-resource-browser.mjs`。
- 完整 PG 与 Chromium 由集成人串行验证。先在含作品虚拟栅格的源码中构建工作台，设置 `LIBRARY_PERF_TEST=1`、隔离回环 `TEST_DATABASE_URL`、本机 `TEST_VIDEO_FFMPEG` 的绝对路径，另可设置 `WORKFLOW_CHROME` 与 `LIBRARY_PERF_REPORT` 的绝对路径，后者使用已有输出目录。执行 `go test -p 1 -count=1 -timeout 10m ./internal/studio -run '^TestPostgresLibraryTenThousandBrowserResources$' -v`。此记录初稿未取得真实数据库或 Chromium 测量数值。
- 成功的 JSON 含数据量、游标页数、六次私有授权负例、首屏 DOM 图与实际响应计数、移动画面解码与真实视频响应数、480 条加载后的挂载数与锚点位移、30 项目各自私图可解码及旧资源退出。JS 堆字节和 DOM 节点在相同 CDP 回收动作后对比首屏、深页与切换第 1、10、20、30 次。浏览器原生订阅关闭与 Go 服务端处理实际退出分别记录；浏览器结束后所有 31 个项目都须有真实已结束的服务端订阅。

## 风险与限制

9,975 条历史索引共享一份真实已登记的图片原件，测量索引规模、分页和鉴权读取的成本。真实解码另用多张独立上传的 PNG 及两段本机生成、播放时间实际前进的 H.264/AAC MP4。首屏和深页使用 1280 × 900 视口。活动资源采用在场卡片、解码画面、旧播放器与旧订阅的实际清理作为判据；JS 堆计数包含整个标签的存活对象，单次差值不能作为长时泄漏结论。报告只存数值、浏览器版本及固定字段，不存账号、项目、资产 ID、地址或连接凭据。此试具未测生产供应商、广域网络、GPU 原生显存、万条并发流或 24 小时稳态。

## 回滚方式

关闭 `LIBRARY_PERF_TEST` 即跳过真实负载。试具在退出时停止本次自有浏览器、服务与 PG 连接，沿用既有清理流程清除本次创建的测试 schema 和私有目录；用户可保留独立的聚合 JSON 证据。移除上述两项测试文件可恢复原测试范围。

## V17-D 作品库实测

035 在本机 PostgreSQL 与 Chromium 上验证 10,000 个独立索引，认证分页 100 次。浏览器实际加载 20 页共 480 条，首屏 24 条索引中挂载 4 张卡，发出 2 个缩略图请求；深翻时最多挂载 10 张卡，追加页后可见锚点偏移 0 CSS 像素。两个真实私有视频先后播放，同时播放峰值为 1。切换 30 个不同项目后，旧订阅、未释放旧播放器和关闭标签页后的服务端活动处理器均为 0。深页至末次切换，强制 GC 后 DOM 少 187 个、JS 堆少 161,888 字节。专项 30.391 秒。 其中 9,975 条历史记录共用一份私有原图。独立项目分别使用真实上传的不同图片。环境、逐阶段样本与 GC 前提见[聚合测量](../wiki/assets/performance-library-035.json)。

## 同阶段其他性能目标

当前产品允许每会话 256 个节点、单分支 128 个，工作台每次加载 20 条，服务端最多 40 条且设约 1 MiB 响应预算。历史消息按页追加，尚未实现万条消息的单列表虚拟化。正式服务的单次运行默认期限 10 分钟，公开输出上限 128 KiB。30 分钟活跃回复需要先确定服务期限及预算。V03 草稿允许 40 个节点，当前执行工作流使用固定 3 节点/2 边或 4 节点/4 边；2,000 个节点/4,000 条边的自由画布需要相应的产品数据模型、视图和固定图集。035 的作品库测量只覆盖作品资产。 原设计指标与当前可复验输入的差异见[性能 Wiki](../wiki/performance.md)。

## 035 启动 JS 与直连传输

从各版 HTML 的模块脚本和 modulepreload 入口递归统计静态依赖，每版启动只需要一个 JS，动态导入另计。033、034、035 的原始字节为 498,657、499,696、502,972，同一 gzip 级别 6 下为 158,410、158,635、160,040。035 相对 034 增加 3,276 原始字节、1,405 gzip 字节。035 的压缩预算低于方案的 300 KiB。直连 Go 服务分别发送 gzip 和 identity 时，均没有 Content-Encoding，实际响应体都是 502,972 字节。正式环境的传输量需要从配置好的入口实测。 [三版制品与响应记录](../wiki/assets/performance-startup-js-035.json)。

## 固定 035 累计验收

固定 035 完整回归通过，629 个顶层用例，零失败、零跳过。studio 包 1670.146s，视频导出包 2.669s。实际启用 PostgreSQL、版本化本机对象存储、真实 Chromium、FFmpeg、十万调度积压、二十万旧任务迁移和编译出的只读订单核对命令。该制品的 553 项工作台测试、157 模块生产构建、Go vet 和六套冒烟均通过。

# 103 · 聊天执行失权、升级与联备集成

## 目的

确认执行中断、旧审核返回和进程换代后，用户只读到原 Run 已提交的内容，原模型请求最多外发一次。

## 范围

V16-B2，涉及 H01、H02、H03、H04、H07 与 H09。核对原键、聊天回放、权益和 Outbox，保留现有控制写锁及私有目录锁。

## 实际文件

- `internal/studio/run_lease_recovery_test.go` 覆盖真实 021 升级及代次切换中途 Kill。`internal/studio/run_stream_recovery_test.go` 在联备恢复时核验聊天代次表和流头，并验证原会话、原键和原游标。
- `internal/studio/storage_maintenance.go`、`ledger_admin.go`、`operations_admin.go` 和 `storage_maintenance_delivery_test.go` 将离线工具精确格式推进至 022。
- `internal/studio/media_schedule_test.go` 在普通到期测试夹具中按 PG 和 Go 两个时钟设置可领取时间。
- `docs/api/openapi.yaml` 在 Run 订阅说明补充租约中断的游标与原键语义。
- [决策 0022](../wiki/decisions/0022-run-execution-leases.md)、数据库迁移、私有存储维护、后端、鉴权持久化、批次契约与项目入口同步。

## 接口与数据影响

HTTP 地址、SSE 事件名和浏览器游标保持兼容。022 在独立启动事务更新聊天代次，并在新 Run 的流头记录持有者、轮次、代次和截止时间。旧 021 有流头和日志但没有租约，恢复其已提交前缀；旧 020 仍按快照恢复。

## 验证结果

- 集成人独占本机 PostgreSQL 16.14 串行运行。首组 11 个专项耗时 32.519 秒，审核服务没有收到输出。领取时只取公开 Run JSON，遗漏了独立存储的冻结审核策略。修正在同一事务读取并核验原策略后，原用例与另外两项审核、账务及可见性测试 5.051 秒通过。
- 最终 22 个定向 Go 用例合计 62.704 秒通过。覆盖两个 PG 会话真实同时争抢、持锁等待到期、过期 ALLOWED、取消后迟到写入、终态阻塞 Outbox 时越过租期（2.54 秒），以及运营释放与旧执行争用同一冻结行（1.08 秒）。普通热订阅和持久日志核对相同中断事件、序号与载荷。
- 首领提交成功且回执丢失，重启读原键，模型调用 0 次（2.05 秒）；有公开前缀后换代中途 Kill，第二次重启后原模型共调用 1 次（3.63 秒）。升级含活动/终态的原 021 库、拒绝旧写者、拒绝旧版/有缺口/超前的离线工具、pg_dump/pg_restore 连同目录与密钥均通过。
- 首次全量 studio 包用时 682.897 秒，媒体整组审核的 image-review 单例报告首次审核未领取。该日志未记录具体拒绝原因。测试 helper 对普通轮询的 due 取 PG 与 Go 时钟较早值，避免两种时钟的偏差干扰显式领取；真实服务端冷却、有效租约与原审核断言均保留。该整组用例复验 4.27 秒通过。
- 加强首领回执丢失断言后，保留原进程直到其 /readyz 返回 503，确认模型调用仍为 0；进程强杀、重启和原键回放连续三次通过，6.212 秒。
- 终版常规 `npm run check` 60.35 秒通过，含 Go 检查与构建、305 项前端测试、10 项治理测试；同一构建的六套隔离 smoke 全部通过。

- 最终 `npm run test:db` 串行退出 0，studio 包 814.555 秒，开启 A3 计划与 019 大升级、A4 大数据启动、混合负载以及本机 S3、真实 pg_dump/pg_restore。470 个顶层用例通过，顶层 SKIP 为 0。Windows 缺符号链接权限，引用存储和维护的两个符号链接子场景未执行。20 万记录完整启动 6.166 秒、外发 0 次。V16 按任务源本地验收，跨实例能力与真实供应商另验。

## 风险与限制

模型已经开始而后失权时，无法用租约推断供应商是否收费。已执行但未交付的冻结继续待核实。所有外部调用验证均使用本机 fixture，实际网关、审核商与公开服务容量另验。

## 回滚方式

停机后，使用升级前同一备份点的 021 数据库、私有目录、owner、已启用密钥及对应对象版本，恢复配套旧程序。保留迁移历史和既有租约证据；清除登记或重新 POST 均不能用于回退。

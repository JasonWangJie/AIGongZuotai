# 178 · 固定工作台制品的依赖清单与许可证证据

## 目的

为 V22 的供应链验收提供能对应固定二进制和前端输出的依赖明细，供实际发布时检查包来源和许可证据。

## 范围

本地 034 Go 服务与 Vite 生产工作台，归属 H07/H09。外部 New API 和部署附属软件需要各自的实际制品身份。

## 实际文件

- `apps/workbench/scripts/release-sbom.mjs` 读 Go 编译信息、锁文件和实际许可证文本，重建前端输出并逐文件校验。
- `docs/wiki/assets/workbench-034.spdx.json` 保存本次 SPDX 2.3 清单；`docs/wiki/release-dependencies.md` 记录生成方式和待确认的许可范围。
- README、Wiki、规划、生成 TODO 和台账索引登记本地检查与外部条件。

## 接口与数据影响

本地 Node 命令以明确的服务制品、前端目录和新输出路径为输入。生成结果只包含制品摘要、包版本、依赖关系与许可证证据；不读取数据库或运行服务，不需租户数据或供应商凭据。

## 验证结果

- 在主树运行生成命令，两个制品、1 个 Go 运行时、20 个 Go 模块和 22 个 npm 生产依赖，共 45 个包、47 条关系。33 个前端文件逐字节一致。
- 使用 SPDX 官方 2.3 JSON Schema 验证通过，Schema SHA-256 为 `239208b7ac287b3cf5d9a9af23f9d69863971102a5e1587a27a398b43490b89b`。另查所有关系端点有效且包标识唯一。
- 将固定目录复制到独立测试目录，只修改 `index.html`，同一命令明确拒绝且未生成清单。
- 本地 npm 锁中 5 个包在输出分块中被直接观测，22 个生产依赖均登记；抽查 JSZip、pako、isarray 和 https 的声明或许可文件。实际网关、可选编码器和生产部署环境另验。

## 风险与限制

包清单不识别上游压缩文件内部没有可追溯模块标识的全部 vendored 代码。项目自身授权、https 包缺少独立许可文件、实际网关及部署附属制品由发布负责人核对。首页和 Wiki 保留公开发布的待验状态。

## 回滚方式

停止使用该本地生成命令即可；业务数据、服务端接口和运行制品不受影响。历史清单按对应制品保留。

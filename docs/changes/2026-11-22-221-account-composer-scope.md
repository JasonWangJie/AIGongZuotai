# 221 · 项目创作描述首次输入与账户草稿隔离

## 目的

V14-C2b 累计真实浏览器验收在限制账户之前超时。图像工作室已有可编辑的描述框，登录态正常，实际正文和 React 字节计数却都是 0，期望为 33 字节。原验收用同一账户与项目核对解除限制后的未发送草稿。

## 范围

工作台切换账户或项目时，在浏览器能够编辑新作用域的输入框之前，完成该作用域的创作描述和图像操作类型切换。相同身份和项目的重新登录可恢复本页暂存。其他界面的清理继续使用原时机。

## 实际文件

- `apps/workbench/src/App.tsx` 将现有草稿转换从被动 effect 移到 layout effect。首次可输入时，旧转换已经完成，无法再覆盖新的编辑。
- `apps/workbench/scripts/account-composer-browser-regression.mjs` 在本机 HTTP 夹具上运行实际构建的工作台，独立控制项目载入和旧会话读取的应答时序。
- `docs/changes/2026-11-22-221-account-composer-scope.md` 记录此修正及复验。

## 接口与数据影响

继续使用原身份、项目和当前页面内存中的草稿。未修改 API、持久格式、项目选择、生成请求及正式账户治理浏览器脚本。

## 验证结果

- 冻结 213 累计失败用例 `TestPostgresAccountGovernanceBrowserAndRestore` 在 26.53 秒退出，诊断为输入框可见且可编辑、唯一、图像视图和登录正常，预期 33 字节、实际及计数均 0。
- 新增脚本先选图像工作室，再在项目响应使 `#creation-prompt` 首次启用的提交后触发一次原生输入。针对相同冻结制品的 Chromium 回归出现已选正确项目、输入前为空、派发后 0 字节，期望 33，按预期退出 1。夹具只使用环回，无业务写入。
- 在 `apps/workbench` 执行 `npm run build` 通过，Vite 转换 169 个模块。`npm test` 的 51 文件共 588 项全部通过（22.96 秒），其中账户治理、项目偏好与鉴权 3 个文件另单独跑过 20 项。
- 修正后执行 `node scripts/account-composer-browser-regression.mjs` 通过。在登录载入及切项目首次启用时均保持输入和 React 计数一致；同一人的原项目会话读取晚于新项目输入返回也不能清空新文字；会话失效隐藏输入框，同一人同项目重新登录恢复，另一人登录后为空。仅测试登录产生 POST，业务写入 0。可给脚本传另一构建的 dist 目录重放。

## 风险与限制

此处以 DOM 启用时刻稳定复现同类丢字，并验证相同制品与修复版的差异；原累计日志没有微任务级调度记录。此项本地实验覆盖 UI 作用域切换，真实 PostgreSQL 账户限制、处置、申诉与联备依原专项由集成人串行复验。暂存随当前页面关闭而释放。

## 回滚方式

整体恢复 App 中的原被动草稿转换并撤销新增回归脚本即可；数据库无需回退。

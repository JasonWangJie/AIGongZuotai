# 173 · 订单意向与离线商户资料核对

## 目的

V13-B1 允许财务人员拿一份人工归一的本地资料，对照工作区内真实保存的订单意向和冻结商品条款。报告区分资料吻合、缺证和矛盾，供财务逐项回到来源核查。材料真实性、收款、退款、会计收入和权益发放均须另有依据。

## 范围

每次指定一个商户别名、`test` 或 `live` 环境、一个工作区和一个带时区的时间范围。时间窗按事件实际发生时刻计算，起点包含、终点排除，最长 31 天。只核对材料中引用的订单，允许这些订单早于窗口创建。未被材料引用的本地订单、窗口外的支付和退款记录均不在本次覆盖内。033 订单没有商户/渠道归属字段，商户及环境取自操作员指定范围和材料头，两者须一致。

## 实际文件

- `cmd/order-reconcile/main.go` 和 `cmd/order-reconcile/main_test.go` 提供独立命令、帮助和脱敏的出错输出。
- `internal/studio/order_reconciliation_input.go` 校验本地文件、作用域、事件身份和金额。
- `internal/studio/order_reconciliation.go` 读取冻结订单快照，按交易与退款分别核对，输出汇总和摘要。
- `internal/studio/order_reconciliation_test.go` 和 `internal/studio/order_reconciliation_postgres_test.go` 覆盖资料校验、分类组合、输出隐私、工作区隔离与在线只读行为。
- `config/order-reconciliation.example.json` 给出完全合成的格式示例。

## 接口与数据影响

从环境中读取 `DATABASE_URL`，在独立连接上开一个只读可重复读事务。只需读取 `studio_schema_versions`、`studio_workspaces`、`studio_order_intents`；检查连续 001—034 版本，再按工作区和材料中的订单 ID 查询当前快照。命令不运行服务启动、迁移、运营维护或账务逻辑。整体数据库操作限时 15 秒，单条 SQL 限时 5 秒，等待锁限时 1 秒。原订单及收据、钱包和流水均保持原状态。

使用已设置对应只读数据库连接的终端，在项目根目录执行。示例中的工作区和订单 ID 是合成值，实际运行需同时替换文件与命令范围。

```powershell
go run ./cmd/order-reconcile -statement config/order-reconciliation.example.json -merchant synthetic-shop -environment test -workspace ws_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa -from 2026-11-01T00:00:00Z -to 2026-11-02T00:00:00Z
```

`studio.order-evidence.v1` 只接受本地常规 UTF-8 JSON 文件，至多 1 MiB、1—2000 行事件。商户、事件、交易、退款使用 1—64 字符的 ASCII 别名。`occurred_at` 填该经济事件的生效时刻，多份通知使用各自的 `event_id`，保留同一经济事件的时刻。货币沿用 033 目录接受的币种，金额用最小货币单位的十进制正整数字符串，最大 10¹²，不能带小数点、符号或前导零。文件没有付款人账号、姓名、通知原文和密钥字段；未知字段与重复 JSON 键均拒绝。重复事件 ID 的规范化内容相同只计一次，内容冲突则整份失败且无报告。

`matched_clue_orders`、`missing_evidence_orders`、`contradictory_evidence_orders` 以不同订单计数，三者合计等于引用订单数。仅吻合的订单再分为仅付款材料、部分退款材料及全额退款材料。`affected_orders_by_finding` 各项独立累计，允许同一订单同时出现多项。相同交易或退款的不同通知不会重复加金额；另列同交易跨订单、同订单多笔付款、错币/金额、资料中的付款缺失、早于订单创建或不早于取消时刻的记录。文件中先列退款与退款生效早于付款分别判断。对于原交易或退款身份冲突，仍保留可确证的独立异常；只有归属、币种和数额清楚才标记部分或全额吻合。

报告固定标记 `source_authenticated:false`。`input_sha256` 核对完整资料字节，`scoped_order_snapshot_sha256` 核对排序后的已读取订单快照，`report_sha256` 核对未附本字段时的规范化汇总 JSON。输出限于固定字段、分类计数及摘要，诊断不回显连接串、文件名、商户别名、订单/交易身份或付款人资料。

本机最终验证通过 4 个顶层单测，其中 11 个分类子用例全部通过，命令包 0.146 秒、核心包 0.166 秒。Windows CLI 实际构建耗时 4.54 秒，运行成品 `-h` 成功。

`go vet ./cmd/order-reconcile ./internal/studio` 通过，2.19 秒。单元验证命令为 `go test -p 1 -count=1 -v ./cmd/order-reconcile ./internal/studio -run '^TestOrderReconcil'`；真实 PG 专项为 `go test -p 1 -count=1 -v ./internal/studio -run '^TestPostgresOrderReconciliationReadOnlyWorkspace$'`。PG 专项由集成人在隔离数据库串行执行，实测结果登记于最终验收记录。专项通过两个真实注册账户创建本人、外部及未被资料引用的意向，持有在线控制连接和订单行锁连续核对两次，再比较订单、收据与权益七表的全行快照摘要。

集成人从修正后的固定源码构建实际 CLI，并在真实 PostgreSQL 上运行。应用持有控制写锁、目标订单行也处于锁定时，可执行文件与同一范围的只读核心返回完全相同的聚合 JSON，订单、原收据及七张权益表逐表全行摘要均一致。该用例 3.15 秒，含严格时间及退款下界的核心专项 3.333 秒，CLI 参数测试 0.149 秒。此前修正前的基础专项 3.00 秒也通过。

## 风险与限制

没有实际商户选型、官方签名或独立来源完整性证明。报告不判定资金已到账、退款成功或权益应入账。窗口中只有退款时，报告明确原付款缺证；需要人工取得相关付款证据再核对。报告只显示汇总，不包含供逐笔转发的支付账号、原通知或明细。库读取权限是离线操作者的授权前提，命令本身不分发数据库凭据。

## 回滚方式

停止使用 `order-reconcile` 或移除新增命令与合成样例即可。此次没有新增迁移、持久操作或待恢复作业。

## 交付前复核修正

CLI 的两个窗口参数、文件头的时间范围与每行生效时刻统一校验 RFC3339 日期、时分秒及偏移，秒小数支持 1—9 位，分隔符为点。超过纳秒精度、逗号小数以及小时达到 24 或分钟达到 60 的偏移会使整份输入失败。合法不同时区表达的同一时刻按 UTC 比较，同一事件精确到纳秒的真实差异仍会拒绝。

核对退款超额时，每个退款 ID 仅在订单、原付款和币种均可归属时贡献一个最小可能金额。对同订单、同付款、同币种累加下界，再和原付款的最大可能金额比较。以原付款 1200 为例，同退款 ID 两条资料分别写 1300 和 1400，报告会同时给出身份冲突和超额。若两条写 1199 和 1400，则只能确认冲突。跨原付款、跨币种或跨订单的归属分歧独立登记，金额有争议时不会计入确定的部分或全额退款。

新增 `TestOrderReconciliationStrictTimeInputs` 和 `TestOrderReconciliationRefundLowerBounds`。修正前复现 8 个失败子用例，修正后运行 `go test -p 1 -count=1 -v ./cmd/order-reconcile ./internal/studio -run '^TestOrderReconcil'`，6 个顶层测试、26 个子用例全部通过，命令包 0.123 秒、核心包 0.173 秒。`go vet ./cmd/order-reconcile ./internal/studio` 通过（2.85 秒），Windows 成品构建通过（3.03 秒）。在清空数据库连接变量后直接调用成品，三种无效时间在参数环节拒绝，合法等价时区通过输入校验并提示缺少连接，均无报告输出。本次修正的真实 PostgreSQL 专项由集成人另行串行复跑。

## 035 只读范围补验

`TestPostgresOrderReconciliationReadOnlyWorkspace` 新增一组先行数据。包内测试入口在本人的原意向上提交合成付款和同额退款，两次发生时刻都取自绑定后的 PostgreSQL 时钟。专项先查两笔资金事实、两份事件收据、唯一购入权益记录及已释放的等待席位，再开始核对离线资料。资料按原口径输出 `source_authenticated:false`。在线写者与订单行锁、另一工作区、已取消订单及未被材料引用的订单继续参与原测试。

每轮签名在一个只读可重复读事务内采集。核对结束后逐表比较原两张意向表、七张权益表与 035 新增的九张资金和等待席位表，共 18 张，比较覆盖全部列和行。比较范围包括成功、重复读取和工作区不存在的失败路径。可执行文件验证沿用 `ORDER_RECONCILE_TEST_BINARY`。静态核对 18 个互不重复的表名，完整包含 035 创建的 9 张表；`go test -p 1 -count=1 ./internal/studio -run '^TestOrderReconcil'` 的无数据库单测通过，耗时 0.204 秒。此扩展的真实 PG 结果由集成人另行登记。

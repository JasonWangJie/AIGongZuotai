# 160 · 订单意向、本人历史与关闭目录后的恢复

## 目的

让用户在接入商户前能核对确切条款、登记或取消本人购买意向，并按原收据核对结果。

## 范围

V13-A 使用 H01 账户、H05 权益单位、H06 业务记录和 H08 工作台。固定商品条款、持续存储、两账户访问控制及真实浏览器为本地验收范围。真实收款、退款、渠道回调、对账和权益入账单独跟踪。

## 实际文件

存储与 033 迁移见 [157](2026-11-22-157-order-intent-store.md)。可信目录与 HTTP 见 [158](2026-11-22-158-order-intent-catalog-http.md)。前端构建、浏览器脚本与两账户工作流由 159 登记。

- `internal/studio/app.go`、`cmd/server/main.go`、`internal/studio/http.go`、`.env.example`、`scripts/lib/process.mjs` 接入默认关闭的目录配置及自动化配置隔离。
- `internal/studio/order_intent_integration_test.go` 对真实账户运行浏览器，并用停写备份和新库恢复核对原始订单、原收据、取消与零权益变动。
- `internal/studio/storage_maintenance.go`、`operations_admin.go`、`ledger_admin.go` 与 `storage_maintenance_delivery_test.go` 维护连续 001—033 的精确栅栏。
- `docs/api/openapi.yaml`、`docs/wiki/decisions/0033-order-intents.md` 和迁移说明记录公开字段、展示口径和配置方式。

## 接口与数据影响

本人订单按真实用户及其工作区分开读取。新意向的货币单位和 CREDIT 数量由原目录快照决定。目录变动或关闭后仍可核对原收据、历史及当前状态。该阶段不会登记支付交易或更新已有权益账本。

## 验证结果

集成人对冻结的 033 运行 15 项订单与个人资料专项，共 62.099 秒。两账户 Chromium 7.58 秒，关闭目录后的新库恢复 7.53 秒；真实数据库中未产生权益分录或媒体任务。

目录、协议和存储边界已有非数据库测试。Vite 构建 149 个模块、前端 42 文件 488 项通过。真实 PostgreSQL、账本零副作用、浏览器下载或截图、恢复及累计回归按集成人实际运行结果登记。

## 风险与限制

示例定价只用于本机演练。录入意向不保证商户可用，也没有真实资金流转。后续需要指定商户和验证环境后再实测支付、退款和原交易对账。

## 回滚方式

移除目录配置并重启后，停止接受新意向，原 033 本人记录和取消入口仍可用。降级到 032 时停写并恢复升级前数据库、私有目录、对应对象版本和密钥，核对备份点后的订单变化。

## 034 累计运行与剪辑选择问题

固定 034 累计运行 studio 1702.178 秒，视频导出包通过（2.465 秒）。611 个顶层用例通过，1 个失败，0 个跳过。唯一失败是视频剪辑 Chromium 用例（14.72 秒）：核对首次保存的原回执后，页面已显示固定版本，项目选择框在目录响应前读到空值。订单、资料、客服和只读对账均实际通过。该轮完整结果为失败，后续制品保留原浏览器断言复验。

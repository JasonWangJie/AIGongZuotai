# 185 · V17 单条活跃回复的真实时长、逐段传输与终态核对

## 目的

验证标准 Go 服务能否把同一个模型请求的文本持续投递 30 分钟，并在原会话中完整读回。这项单流实验对应原方案第十四章的活跃回复目标。V17 的万级连接、目标媒体在途量与 24 小时稳态分别验收。

## 范围

H03 模型与执行、H07 可靠性与性能、H08 前端体验。测试启动真实 `cmd/server` 制品及生产工作台，使用正式 OpenAI 兼容聊天适配器。模型输入来自真实工作台的首次会话发送，模型输出来自本次实验专用的环回 SSE 服务。正式测量使用 PostgreSQL 和真实账户，另提供 12 秒的内存或 PostgreSQL 接线验证。

## 实际文件

- `scripts/perf/long-reply.mjs` 管理环回服务与测试网关，校验上游请求、逐条 SSE、Run 快照及会话消息，合并浏览器证据。
- `scripts/perf/long-reply.test.mjs` 测试两种计划、活跃时长与节奏判定、测试库地址边界和分片 UTF-8 SSE 顺序。
- `scripts/perf/frontend.mjs` 导出现有的制品指纹函数。启动基准和持续回复基准采用同一目录遍历及摘要算法。
- `docs/changes/2026-11-22-185-long-reply-gateway-and-observation.md` 记录测试方法、运行条件与证据。服务期限配置和浏览器交互分别见同期对应台账。

## 接口与数据影响

只使用现有工作台和只读核验 API。已经建立的连接使用正式适配器的响应读取机制，其 TCP 建连期限为 10 秒，等待响应头最长 45 秒，连接池回收 90 秒内未使用的空闲连接。单 Run 执行仍受独立上下文期限限制。实验在标准入口设置 `CHAT_RUN_TIMEOUT_SECONDS=2100`，默认服务期限为 600 秒。

自有网关只在随机的环回端口接受一笔带本次随机凭据的 `POST /v1/chat/completions`，校验消息、冻结模型、流式开关及输出预算。独立读者取得原 Run SSE 响应头且真实浏览器的原生 EventSource 已触发 OPEN 后，网关才写入首段。两个读者未在 20 秒内就绪则结束本次实验。正式档按单调时钟每秒写一段，编号从零开始，1,801 段各带两行和末尾换行，共 25,214 UTF-8 字节。计时从首个到末个真实增量；最后一段留 250 毫秒传输余量。上下游均逐段记录到达时间、间隔及每分钟数量，跨度至少 30 分钟，任一相邻段的间隔超过 5 秒即失败。序号、每段完整内容、唯一成功终态、Run 快照、原会话助手消息和浏览器终态互相核对。短档以 500 毫秒节奏发送 25 段，单独标记 `quick-12-seconds`。

PG 档限定测试作用域。集成人的 Go 包装负责临时 schema 和两个空私有目录的生命周期；服务验证数据库地址为环回、`search_path` 精确指向单一随机 `studio_test_` schema，使用现有注册 API 创建合成账号。独立读者保留该次会话的凭据，浏览器登录同一账号。报告只保存固定统计、字节数、摘要、制品指纹及浏览器观测。进程输出使用阶段名和计数。

Go 包装启用 `LONG_REPLY_TEST_CONTROL_PIPE=1`，待子进程纳入专属进程组后写入 ASCII `start\n` 并持有写端。Node 在收到完整指令前不会开启网关、Go 服务或 Chromium。写端关闭或收到协议外数据时，Node 取消实验并等待自有 Go 服务和 Chromium 退出。上游提前断开会立即取消读者。制品报告的 `dist_sha256` 覆盖所有前端文件的有序相对路径及各自 SHA-256，`dist_files` 是文件数，`index_sha256` 和兼容字段 `dist_index_sha256` 均指实际校验的入口 HTML，`server_sha256` 是 Go 制品摘要。

## 验证结果

- `node --test scripts/perf/long-reply.test.mjs` 的四项无 PG 专项通过，涵盖唯一短段、实际跨度、异常停顿、缺失或重复末端事件及隔离 schema 等边界。
- 在已构建的工作台上运行 `node scripts/perf/long-reply.mjs --quick --server <本机正式服务制品> --dist <生产构建目录> --out <全新报告文件>`。首轮内存测量通过，真实兼容适配器发送一次请求、收到一个结束标志；上游与独立平台 SSE 的首末增量跨度分别为 12,260.48、12,260.52 毫秒。两个读回入口和 Chromium 均核对完整的 25 段、350 个 UTF-8 字节，最后序号为 26。
- 设置 `LONG_REPLY_CANCEL_TEST_SERVER` 为本机服务制品路径，再运行同一 Node 测试命令，六项全部通过（1.777 秒）。其中真实管道专项先在授权前关闭写端，检测到零个业务子进程；另一次正常握手后收到真实首段再关闭写端，Node 退出后以操作系统检查确认该次 Go 和 Chromium 的原进程均已结束。复跑带双读者就绪校验的正常短档，33 个前端文件参与摘要；上游、独立 SSE 与 Chromium 的首末跨度分别为 12,260.92、12,262.44、12,262.70 毫秒，25 段全部读回。
- 另用真实父进程写入启动指令并始终持有管道，直到子 Node 在整个短档成功后自行退出。退出码为 0，完整报告生成，父进程的 30 秒保护计时未触发。
- 正式测量去掉 `--quick`，由集成人的独立 Go 测试创建隔离 PG schema，并以进程环境传入 `LONG_REPLY_TEST_DATABASE_URL`、`LONG_REPLY_TEST_ASSET_DIR`、`LONG_REPLY_TEST_REFERENCE_DIR`、`LONG_REPLY_TEST_PASSWORD` 和 `LONG_REPLY_TEST_DELIVERY_KEY`。输出文件须事先不存在。初稿仅以上述短档为实测，正式 30 分钟及关闭服务后的原库核对由集成人按实测补登。

## 风险与限制

回复文本为测试网关可重现的已知片段，使用实际经过的时间，不测试模型推理质量、外部供应商响应、语义审核、真实收费或生产容量。JS 堆和浏览器交互只代表该机、该制品和本次单标签窗口。正式测量只向一个已有原模型执行追加测试文本，不改变用户的会话节点、上下文或 128 KiB 单 Run 输出上限。

## 回滚方式

生产环境无需运行这项独立测试。中断时驱动关闭自有浏览器、Go 子进程与环回网关，清理自己创建的临时目录。集成人的 Go 试具持有并清理 PG 临时 schema 及其私有目录。移除驱动和专项测试即可撤回这项测量。

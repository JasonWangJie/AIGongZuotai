# 219 · 实际 SSE 读者的会话复核与撤权验收

## 目的

V17-J4 对 218 提供的高于默认上限的持久订阅进行业务验收。使用真实登录、正常会话发言、项目草稿事务和独立 HTTP 连接，核对同一会话下多个 Run 与项目订阅的权限、恢复及模型调用次数。

## 范围

H01、H03、H07。测试只配置本机环回模型与隔离 PostgreSQL，将全局连接数设为 192、每个工作区设为 96。Run 回放池和会话复核池各有一个独立物理连接。测试沿用 214 的真实 TCP 慢读者、模型帧与游标工具。

## 实际文件

- `internal/studio/stream_session_acceptance_test.go` 通过两个账户与三个有效登录会话建立实际响应体，在客户端逐帧区分 Run 增量与持久项目事件，检查共享预算、选择性注销、回放等待和认证连接断开。
- `internal/studio/stream_session_socket_test.go` 检查项目观察器对游标范围和顺序的判定。在 192 的配置上另用暂停读取的 TCP 客户端触发写超时，再用原游标补读。

## 接口与数据影响

两个工作区分别用 `POST /api/v1/conversations` 和 `POST /api/v1/conversations/{id}/runs` 发出一次普通提问。96 个 Run 读者收到对应 Run 的非空增量，96 个项目读者收到所在项目真实的 `draft.saved` 事务通知。三组登录会话分别占 64、32、96 个读者。稳定期间至少两个完整复核周期都须呈现每轮三个唯一会话。额外已登录工作区遇全局限额，同工作区另开 Run 遇工作区限额，匿名及外工作区读取分别核对 401、404。

第一组显式退出后，须观察到其 64 个 HTTP 响应自行结束。其余两个会话的 128 个响应仍可分别接收第二段回复或下一版草稿。占住已核对的唯一回放连接，并使一个真实 HTTP 回放请求在其上等待；其间另一个连接仍须完成正常权限复核。物理断开本试具持有的会话复核连接后，须观察到受该轮影响的读者结束，控制写者仍通过原接口提供服务。用重新登录的账户和另一账户，以原 Run、原游标恢复；后续正常复核须使用替换的物理连接，两份完整快照可读，环回模型共接到两个 POST。

慢读者专项使用受限 TCP 收发缓冲，在收到真实首段后停读。普通读者须继续取得余下 12 个增量，可观察到实际套接字写超时且应用订阅队列未溢出。以原游标恢复后两个客户端取得同一终态，公开快照符合完整原文，环回模型只接到一个 POST。

## 验证结果

隔离源码与 218 的认证、读池、控制写者及准入接口对齐。清除进程级 `TEST_DATABASE_URL` 后运行以下普通用例，观察器与 214 内存模式的真实 TCP 控制组通过，studio 用时 5.214 秒。控制组实际写超时 4,999.58 毫秒，普通客户端接收突发段用时 21.49 毫秒，模型 POST 一次，应用队列溢出零次。

```powershell
go test -count=1 ./internal/studio -run '^(TestStreamSessionProjectObserverRequiresScopedEvents|TestSSESocketMemoryWriteDeadline)$' -v
```

在已设置专用本机环回 `TEST_DATABASE_URL` 的串行集成环境执行以下两项。192 读者、共享复核、撤权、连接故障与数据持久性只以该次真实 PostgreSQL 结果为准。

```powershell
go test -count=1 -timeout=4m ./internal/studio -run '^TestPostgresStreamSession(Shared192AndFailure|SlowSocketAndOriginalReplay)$' -v
```

## 风险与限制

192 计量同时持有且已读到业务事件的 SSE 响应，其中两笔模型执行产生 Run 增量。该测量只覆盖本机单控制写者的订阅和复核。慢套接字和物理连接故障另设受控阶段；输出只记录人数、轮次、耗时及调用数。真实撤权检测时间受复核周期及正在进行的 I/O 影响。

## 修正后真实 PostgreSQL 复跑

228 修正位置列后 192 个已鉴权订阅实测通过（96 个运行、96 个项目）。注销关闭 64 个，复核连接故障关闭其余 128 个，随后重新接入 2 个。慢读者实测 5000.32 ms 触发写截止；原游标补回 12 个增量，缓冲丢弃 0。 192 订阅用例 10.40 秒，慢 TCP 用例 11.35 秒。

## 编写规则

使用[模板](TEMPLATE.md)，文件名为 `YYYY-MM-DD-NNN-short-name.md`。编号在同一天内唯一；标题可以中文，文件短名用小写字母、数字和短横线。

每份记录至少包含“目的、范围、实际文件、接口与数据影响、验证结果、风险与限制、回滚方式、文档同步”八个二级章节，内容不能留空。实际文件列出本次改变的路径；验证结果区分通过、失败、未运行和环境限制。

同一逻辑变更在交付前的修正追加同一记录；交付后新增变更建立新记录。禁止覆盖既有记录来隐藏历史。首次初始化中的 001/002/003 是同一轮并行建设的三个逻辑模块，模块作者负责各自证据，汇总负责人同步根 README 与本索引。

运行 `node scripts/check-docs.mjs` 检查结构，运行 `node scripts/check-docs.mjs --changed` 检查本地变更集合中的同步项。CI 可使用 `--base <git-ref>` 检查已提交的变更。检查通过不等于台账语义完整，仍需人工比对 diff。

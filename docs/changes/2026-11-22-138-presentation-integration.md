# 138 · 项目文稿的版本导出与独立文件验收

## 目的

创作者能把一个已保存版本交给其他人继续编辑，独立读取下载的文件即可检查标题、正文、备注和图片。

## 范围

V21-C，H01、H02、H08、H10。使用现有账户及项目。团队邀请、多人实时协同、漫剧创作按其他子项跟踪。

## 实际文件

- `internal/studio/storage_maintenance.go`、`ledger_admin.go`、`operations_admin.go` 与 `storage_maintenance_delivery_test.go` 更新 029 精确格式与前一版、缺号、未来版本的拒绝用例。
- `scripts/verify-presentation.py` 独立读取浏览器下载的 PPTX，检查原生文本、讲者备注、图片与旧版，并将编辑后的副本重新打开。
- `docs/api/openapi.yaml`、`docs/wiki/decisions/0029-project-presentations.md`、`docs/wiki/database-migrations.md`、根 README、任务源和生成清单记录合同及进度。

## 接口与数据影响

029 新增项目文稿、不可变修订、单页私图来源及操作收据。保存采用原操作键和编辑基线。导出读取指定修订，按当前权限核对源图；已交付给用户的本地文件由该用户保存。

## 验证结果

已确定独立验证方法。项目范围和旧版导出由 PostgreSQL 与真实浏览器验收。从同一次浏览器下载打开 PPTX，用第二套库改写文本、保存并重新打开，并单独渲染原文件。证据随实际执行更新。

前端 HTTP 夹具阶段，Chromium 下载 v1、改稿 v2 和再次读取的 v1。用 python-pptx 1.0.2 逐版核对 3 张原生文本页、讲者备注和 1 张同 SHA-256 的嵌入私图；实际改写首标题并重新打开副本。LibreOffice Impress 26.8.3.1 独立打开 4 个文件，连同浏览器打印稿共 5 个三页宽屏 PDF，正文及私图均可读，讲者备注未出现在公开页。Office 工具使用工作区内独立副本和配置目录。PG 账本与导出联动仍须用认证环境实测。

真实 PostgreSQL 专项 46.647 秒通过。浏览器 10.28 秒完成原身份保存三页、下载两个修订和重新打开首版；私有目录与数据库旧版联备 7.67 秒，增量升级 2.54 秒，隔离与账户权限 8.87 秒，丢提交回执 2.87 秒。对这次实际下载重复独立编辑与 Impress 渲染，3 份原下载及编辑副本各 3 页，有图页 SHA-256 与输入原件一致。脱机 HTML 无脚本、仅内嵌原图，打印与 Impress 的 15 页均回读正文、页数及宽屏比例。029 固定源码 npm ci、npm run check（426 项前端、10 项治理和生产构建）、六套冒烟通过。[文件核验报告](../wiki/assets/presentation-export-2026-11-22.json) · [改稿渲染](../wiki/assets/presentation-render-v2-2026-11-22.png)

## 风险与限制

一份 PPTX、离线 HTML 或 PDF 允许用户在平台外查看已经导出的内容。桌面办公套件的字体和布局实现存在差异。人工确认所用阅读器、实际文件和测试输入须随结果记录。

## 回滚方式

停写并联备数据库、参考及资产原件、目录归属、相应对象版本与已启用的独立密钥。恢复到 028 需要恢复对应时间的整套备份，先核对升级后新增文稿和其他业务收据。

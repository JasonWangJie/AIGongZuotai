# 198　V17-G 项目自由画布集成

## 目的

在工作台正常入口完成图文档的编辑、保存、原版读取、私有预览及实际运行状态展示，并在同一实现上测量多节点平移，不用静态截图替代可交互的画布。

## 范围

V17 的 H03、H07、H08。195 提供 PostgreSQL 授权接口和不可变修订，196 负责工作台，197 负责真实 Chromium 测量；本项登记路由、协议、精确格式、停写联合恢复与集成验证。PNG 截图只用于查看真实页面布局。

## 实际文件

- `internal/studio/http.go` 从标准服务注册 7 个画布操作；`internal/studio/storage_maintenance.go` 的统一格式栅栏升至 037。
- `internal/studio/canvas_restore_test.go` 核对两版实际画布、Run 与私有图片在 pg_dump/pg_restore 联备后的作用域、原确认键与真实预览字节。
- `docs/api/openapi.yaml` 登记 6 条路径、7 个方法及图、来源、历史和收据响应结构。
- 037 决策、性能 Wiki、任务源、生成的 TODO、README、进展、协作规则与台账保持一致。

## 接口与数据影响

在需要登录的 PostgreSQL 服务中，由工作区所有者按项目编辑。节点的有向关联、分组、坐标、私有版本身份同版保存；不受理节点自带的上游 URL、运行结果或其他项目的资源。按版本查询来源有独立轻量接口。幂等、CAS/容量、来源、审计与项目通知的边界见 195；前端未知响应和旧授权读取见 196。

## 验证结果

集成人第一次串行验收通过新图并发/回执、来源权限、联合恢复及离线精确栅栏，升级夹具因缺少普通 036 启动时已建立的演示项目产生额外行。改用具有真实启动基线的 036 旧项目，保留对整表快照的严格比较。随后六项真实 PostgreSQL 案例全部通过，包耗时 26.426 秒。联合恢复耗时 10.00 秒，实际移至新数据库、复制原私有目录和启用的交付密钥，重登核对原图、运行状态、两个修订与保存回执，再回收图片并核对旧链接 404。036 升级 1.79 秒；上一版、缺 019 和未来迁移版本均被离线工具拒绝。实际浏览器和构建结果在本轮验收后补录。

## 风险与限制

图片和运行来自本机隔离账户、私有目录与回环渠道。画布中的关系表达创作素材组织，执行入口仍由既有工作流或生成业务提供。集显、独显、远程桌面与软件合成的帧间隔需各按实际硬件、网络及样本数记录。单项目保留 64 个修订，有界限额不能当长期存储估算。

## 回滚方式

先停写并联备新库与原私有状态。需要退回 036 时使用升级前匹配的库、目录、密钥、适用对象版本及 036 制品。不得清空画布来源、删除登记或绕过格式栅栏直接由旧服务写新库。

## 037 画布实际平移验收

在本机 Intel 集显、Chromium 157、1920×1080 下，两档各实际拖动平移 60 秒，期间私有缩略图已解码、已受理 Run 持续活动。500 节点/1,000 边的 3,599 个帧间隔 P95 为 16.8 毫秒，最多 25 个详细节点；2,000 节点/4,000 边的 3,601 个间隔 P95 为 16.8 毫秒，最多 100 个详细节点。两个项目实际保存并重开 4 个修订，编辑与平移新增生成 POST 为零。 两组最大间隔分别为 67.2 和 33.3 毫秒。137.271 秒专项通过。报告使用前台浏览器 rAF 间隔，系统可用内存约 31.5 GiB；当次网络按 20 Mbps / 80 ms 配置，实际往返与吞吐校准单列。桌面与 390 CSS 像素截图已人工核对。 [全部帧间隔与逐秒样本](../wiki/assets/performance-canvas-037.json)。

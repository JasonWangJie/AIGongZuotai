# 147 · 分镜原片预览与私有成片传输

## 目的

在项目内预览已保存镜头的原片，并按指定的不可变版本导出 MP4。当前会话、来源任务的已公开产物和原件身份均参与交付检查。

## 范围

V20，H02、H03、H04、H08、H10。146 的持久项目来源查询与 144 的本机编解码执行器之间建立同步传输链。此导出不产生模型任务、报价、外部供应商请求或新登记的资产。

## 实际文件

- `internal/studio/video_timeline_export.go` 处理工具启用、私有临时目录、原件读取、限额、单镜预览、整稿导出和关闭清理。
- `internal/studio/video_timeline_export_test.go` 覆盖已冻结原件的重复读取、相同大小的篡改、并发容量、关机等待及临时目录归属。
- `internal/studio/video_timeline_private_http_test.go` 用本机合成双原片、正式账户与真实项目查询覆盖历史版本、字节范围、匿名和外人拒绝及回收后的导出边界。
- 共用 144 的 `internal/videoexport` 及现有本机和 S3 私有资产读取器。应用配置、路由与工作台接线由本批集成人和对应模块记录。

## 接口与数据影响

在 `/api/v1/projects/{project}/video-timelines/{timeline}/versions/{version}` 下，GET `clips/{clip}/source` 按当前身份核对单镜、私有原件收据、SHA-256 及字节数，最后重新检查会话和项目来源，再提供支持 Range 的 MP4。此单镜预览独立于 FFmpeg 启用状态。读取失败不会公开部分原件。

POST `export` 接收空正文，按版本内固定顺序读取最多 8 个镜头。每片原件最多 32 MiB，合计 128 MiB；先查库与申请占位，再读取和写入私有快照。逐个取回、核对并关闭同一份原始媒体，释放共享读取许可后才读取下个镜头。144 在再次核验快照摘要后编码，返回前重读原版本的全部来源和会话。成片返回 `video/mp4`、附件名、`X-Content-SHA256`、`X-Video-Duration-Ms` 及真实 `Content-Length`。

每个工作台最多 2 个预览和 1 个导出。两项工具都未配置时仅保留原片预览；启用时需要 Windows、本地工具绝对路径、持久登录模式和独立临时目录。目录与 Web、资产、参考路径分离，持有 OS 排他锁，发现遗留或其他文件即拒绝继续导出。关闭时取消请求并等待实际退出，之后才释放占位和目录锁。传输有写截止时间。

## 验证结果

`go test -count=1 -v ./internal/studio -run '^TestVideoTimeline(SourceReadsFrozenOriginalWithBoundedSlots|IOShutdownWaitsForReadCleanup|TempDirectoryBoundary)$'` 三项通过，0.249 秒。实测连续读取 8 次后共享许可全部释放，同大小替换文件拒绝读取，两个预览占满时第三项被拒，服务关闭等到两个读者退出，目录重叠、第二个写者和遗留文件被拒。144 另有真实逐帧、音轨及取消核验。项目授权、公开素材和浏览器下载的真实数据库联验由集成人串行执行。

专项 `TestPostgresVideoTimelinePrivateRangeAndRevokedExport` 需 `TEST_DATABASE_URL`、`TEST_VIDEO_FFMPEG` 和 `TEST_VIDEO_FFPROBE`。测试从两项环回已批准视频任务创建两个不可变版本，逐字节核对旧版单镜整片与部分范围、成片摘要与时长，验证原项目和外人、匿名、源回收与未受影响的第二版。无工具参数时编译通过并按预期跳过，集成人随后配置真实 PG 与两项本机工具，专项 11.76 秒通过。

## 风险与限制

当前在 Windows 本机导出。运行期间两层快照和两个输出文件合计至多约 320 MiB，S3 读取原件时另有单片临时数据。私有目录沿用管理员配置的操作系统访问权限。多个进程不能共用同一临时目录。若进程强杀留下数据，服务保留原文件，人工确认归属后可选新的专属空目录恢复。终次权限检查后已开始传出的下载，按既有私有传输语义处理。外部视频供应商和云环境另行验收。

## 回滚方式

停止入口并等待现有传输退出，移除两项编解码工具配置即可关闭导出。已有不可变分镜与允许读取的原片仍按当前账户和项目授权访问。跨数据库格式降级须走配套联备恢复。

# 176 · 本人订单资金与权益记录

## 目的

V13-B2 让用户在本人订单中核对该笔意向的资金资料和已执行的 CREDIT 变动。创建收据、当前意向状态、实际记录金额分别展示。即使目录变价，也能看到原订单的标价、已记录收款及原来发放的权益。

## 范围

持久账户从「本人订单」选择一条记录，点击「查看资金记录」。收款、退款、创作权益各占一行。未关联订单明确显示「无已核实资金记录」；已绑定但尚无收款证据的订单显示「已关联渠道，尚无已核实收款记录」。已认证的退款先于原付款到达时，显示退款金额与「待匹配原款」。已收款后部分退款可与「权益待核对」、原已发放数量和零冲正同时出现。测试与正式环境使用不同的来源标注。

## 实际文件

- `apps/workbench/src/OrderIntentsPage.tsx` 在原详情中接入记录，按账户、工作区和能力重建私有状态。已获知资金资料的订单关闭取消意向入口。如果在取消确认期间读到资金证据，撤去该确认。
- `apps/workbench/src/OrderPaymentRecords.tsx` 使用订单专属的安全投影，校验身份、冻结币种、单位、环境和状态枚举；服务器返回错误与资料字段不完整时均隐藏金额。操作只有读取和重新读取。
- `apps/workbench/src/order-intents.css` 沿用意向页的排版，将退款和权益核对状态分别显示，390 像素宽界面纵向排列金额。
- `apps/workbench/src/orderIntents.test.tsx` 增加资金状态、过期读取、撤权、单位、目录变价及取消确认相关用例。
- `apps/workbench/scripts/order-payment-browser-smoke.mjs` 使用两个互相隔离的真实 Chromium 会话读取三个订单，在桌面和 390 像素宽度保存截图。

## 接口与数据影响

本人选择订单时发起 `GET /api/v1/order-intents/{order}/payment-status`，请求禁用浏览器缓存，使用当前会话，没有请求体或操作键。结果仅在当前选中订单的组件中保留。切换订单、切换账户或收到拒绝后会清除私有记录并作废旧读取。状态显示和金额分别取服务器结果，现金按冻结币种的精度显示，CREDIT 按六位小数显示。界面没有发起支付、退款和权益调整的操作。新意向、取消和原键收据继续走 033 原接口；服务端已记录资金时，新取消被拒绝，用户可返回只读核对。

## 验证结果

专用浏览器脚本先创建一笔未关联意向，再核对两条由测试接入生成的已记录订单：一笔 CNY 12.00 对应 10.000000 CREDIT，另一笔已记录 CNY 3.00 退款、原权益 10.000000 CREDIT 待核对、已冲正 0.000000 CREDIT。第二个账户查询三个订单均须返回 404，列表中没有这些订单。浏览器计数要求本人明确创建意向一次，后续只读。真实 PostgreSQL 与隔离接入夹具由集成人串行验收，结果登记在本批集成记录。

## 风险与限制

本页只能展示后端有权公开给本人的记录。尚未选择商户的部署可以继续登记意向和查看已有历史，实际商户接入、支付页面、退款审批和自动冲正分别以相应业务验收为准。前端拒绝无法核对的响应后需要重新读取；请求丢失不会触发自动交易、发放或退款。

## 回滚方式

撤下本次详情区、样式和新增脚本可以恢复原意向工作台。前端未写入新的资金数据、权益流水或恢复仓。数据库、旧写者及服务端格式回退遵守 035 批次联备要求。

## 交付前复核修正

收款和退款各自处于 REVIEW 时，金额现标作「可归属的同币种收款」或「可归属的同币种退款」，并说明有归属争议或币种不同的部分未计入。这样即使汇总为零，用户仍可分清资料待核与从未收到资料。原已发放和已冲正的 CREDIT 数继续独立显示。

工作台每次选中订单都会读取该笔最新投影；「查看资金记录」展开同一次结果。取消入口只有在当前查询明确允许、各项金额为零且没有退款或权益记录时出现。换单、重新读取、查询失败及会话结束会使旧允许状态失效。刷新期间收起已打开的取消确认。旧订单仍可按原流程确认取消，关闭目录后也能核对；内存演示继续显示持久账户条件。页面只保留当前选择，没有新增订单历史缓存。

修正前，新增的争议金额及两订单间往返用例实际失败。修正后在主树执行 `node node_modules/vitest/vitest.mjs run --no-cache --configLoader runner src/orderIntents.test.tsx`，45 项全部通过，5.84 秒；`tsc --noEmit` 通过。工作台在全新忽略目录构建，156 个模块、4.89 秒。用同构建与两个本机合成账户依次执行原 `order-payment-browser-smoke.mjs` 和 `order-intent-browser-smoke.mjs`，实测分别为 4.17 秒与 4.42 秒，双账户读取隔离、待核权益、原键收据、已核对的旧意向显式取消与 390 像素界面均通过。本轮没有运行 PostgreSQL，真实专项仍由集成人串行执行。

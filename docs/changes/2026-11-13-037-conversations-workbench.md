## 目的

将原单轮运行界面扩展为真实平台 API 驱动的多会话、消息路径、历史编辑分支及显式继续。保留原运行恢复和原请求幂等保护，清楚区分上下文估算、实际模型输出与演示结果。

## 范围

当前项目会话列表、新建会话、当前分支消息时间线、祖先分页、叶子分支分页、下一轮回复、历史用户消息编辑为兄弟分支、停止运行、部分输出后确认继续、上下文摘要、旧单轮记录入口。沿用暗色星图视觉和原模型设置，新增窄屏会话展开区及流输出自动跟随／手动回到末尾。

本模块不提供消息就地改写、永久删除、工具调用、附件、自动摘要、Markdown／代码高亮或自动付费重试。尚未把整批 V10 标为验收完成；后端、真实 PostgreSQL、HTTP fixture 和实际浏览器结果由集成人记录。

## 接口与数据影响

按 [V10 契约](../planning/v10-contract.md)接入 `GET/POST /conversations`、会话详情、`messages?leaf_id&before&limit=20`、`branches?cursor&limit=20` 及 `POST /conversations/{id}/runs`。创建会话与受理新轮次使用不同幂等键；新轮次发送原 `expected_version`、模型版本、父消息、操作和编辑来源。继续提交空 input，由服务端固定指令创建新运行。所有读取携带当前项目作用域，同源 Cookie 仍由浏览器管理。

消息按选中路径祖先顺序合并，加载更早页时去重；Run 只更新精确匹配 conversation／assistant／run 三重关联的消息，不降低 seq，不把终态退回运行态。运行 SSE 仍使用原数字 seq，与持久项目通知 opaque cursor 分离；保留 40ms 增量批次。新的会话／轮次审计和运行终态合并刷新当前会话摘要／必要路径，普通检查点只读取对应 Run。

原请求在 POST 前保存到 App 页面内存恢复仓。网络或 5xx 不明保持原 body/key；原未知重试后的 401／429／409 不能清除已有未知身份。切换账户、项目或分支的旧 GET 不可应用，迟到 POST 只确认自己的原操作，不能抢当前选中会话或清除后来编辑。会话 CAS 冲突保留输入与父消息，刷新后由用户明确确认新版本，不自动生成。

会话输入、编辑／继续目标及未确认请求仅在当前页面内存保留；401 后同用户同项目可恢复，其他用户不可见。关闭／刷新有 beforeunload 提醒，但浏览器可能限制该提示，不能承诺跨关闭恢复。localStorage 只存按用户／项目隔离的会话与叶子 ID，用于恢复显示偏好；它不保存正文、令牌或请求键，也不参与服务端权限判定，恢复后仍通过鉴权 API 读取。

## 风险与限制

新接口缺失或服务不可达时呈现明确错误，不回退为计时器模拟。上下文显示服务端 `utf8_bytes_v1` 预算估算、预留输出和省略消息数；不是精确 tokenizer、模型实际窗口探测或消费账单。前端不重建已受理上下文。模型能力变化只影响新的发送；原未知请求可直接原样重试。

消息页大小由服务端 1MiB 预算限制，可能少于 20 条；会话／路径总上限由服务器执行。当前仍为有限分页 DOM，无万级消息虚拟列表性能承诺。输入只存页面内存；显式切换分支不偷偷改输入的父消息，需要返回原路径或明确清空后回复新分支。演示输出逐 Run 标记，缺失历史 Provider 信息时显示“来源待核对”。

## 回滚方式

前端回到上一版本构建可恢复原单轮 UI，但不会删除新会话数据；原接口继续兼容。数据库010升级的回退必须由后端按备份与格式栅栏处理，不删除迁移登记强行启动旧程序。前端发布前保留前一份 dist，回退仅替换静态构建，不清理用户私有文件或 PostgreSQL。

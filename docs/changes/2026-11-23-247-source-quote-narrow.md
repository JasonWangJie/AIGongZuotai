# 247　窄屏核对原视频报价中的完整素材编号

## 目的

让用户在窄屏工作室确认报价之前看清原片身份、修订和延长方向。

## 范围

V20-C/H08，工作台报价的文字换行与真实浏览器回归。沿用现有服务端报价、受理及收据。

## 实际文件

`apps/workbench/src/billing.css` 允许过长的连续字符在报价段内换行。`apps/workbench/scripts/source-video-browser.mjs` 在第二次报价前切换为 390×844 像素，使用浏览器 Range 核对完整编号的所有行都落在正文边界内。同步本台账与项目、Wiki、TODO 导航。

## 接口与数据影响

报价继续展示完整的项目素材编号，不截短标识。服务、接口、数据库和权益无变更。

## 验证结果

本机 Chromium 在 390×844 窗口加载修正前的生产制品，发现两个选择框与确认按钮均可见，但原片编号超出卡片。用浏览器 Range 对同一完整标识逐行测量，旧制品显示为一行，超出 304 像素宽的正文框 177 像素。修正版按两行显示，超出 0 像素。修正后重新构建 183 个模块，针对同一环回 HTTP 样本运行相同检查通过。两次显式报价、两次任务提交、一次收据 GET 均完成；选择框宽 306、高 36 像素，确认按钮宽 147、高 38 像素。真实 PostgreSQL 联合验收单独登记。

## 风险与限制

像素尺寸来自桌面 Chromium 的窄视口。本项验证文字换行及工作台操作；真机浏览器、不同系统字体与供应商视频效果仍应在对应环境验收。

## 回滚方式

撤销报价段落的断行规则并恢复原浏览器验收程序，即可回到之前的布局。此前的报价在窄屏上可能截去编号末端。

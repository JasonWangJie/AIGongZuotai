# 110 · 图片编辑服务端配置准备页

## 目的

V07 的渠道配置由用户在服务器完成，真实编辑由用户另行实测。本次提供可直接打开的配置准备页，供用户核对参数、生成配置文件并查看当前服务公布的能力。

## 范围

V07 服务端配置材料的准备、下载、目录检查与工作台入口。

## 实际文件

- `apps/workbench/src/App.tsx`、`types.ts` 新增“图片编辑配置”导航，并从图像工作室“配置编辑模型”进入。
- `ImageEditSetupPage.tsx`、`image-edit-setup.css` 提供媒体服务根地址、可信结果域名、稳定凭据标识、模型与参考数、多个完整规格组合、配置预览、下载和公开目录刷新。
- `imageEditSetup.ts` 按当前 Go 目录 v1 格式生成 JSON 与环境片段，校验服务根、域名、模型 ID、显示名、上游映射、规格唯一性与数量/字节边界。以上文件均位于 `apps/workbench/src/`。
- `apps/workbench/src/imageEditSetup.test.tsx` 验证生成文件、输入拒绝、公开状态和现有模型保留规则。

## 接口与数据影响

配置只在本页内存中编辑。导出使用浏览器本地下载，无服务器写配置接口。既有服务默认导出独立的新增模型条目，已存在的公开 ID 和已满的公开目录无法追加。独立实例可以下载完整的 `models.image-edit.example.json` 和对应的 `image-edit.env.example`。既有环境须在服务器合并条目及可信结果域名，保留原有模型、网关和凭据身份。公开状态沿用现有目录读取，展示运行模式、能力与规格版本。

密钥由用户在服务器私有环境配置。页面没有读取私有目录和现有环境文件的入口，也没有密钥输入框。用户手动重启后核对公开目录，再在图像工作室执行受控的上传、编辑、原 handle 查询和下载。

## 验证结果

- 工作台 `npm run test -- --run src/imageEditSetup.test.tsx` 17 项通过。全前端 `npm run test` 32 个文件、329 项通过，3.69 秒。
- `npm --prefix apps/workbench run build` 通过 TypeScript 和 Vite 构建。配置页面按需加载。
- 本机 Chromium 的环回前端夹具通过桌面表单、修改规格、校验、三种真实文件下载及 390 像素宽布局检查。对比下载的条目与完整目录内容一致，检查环境片段未含密钥赋值，截图和下载位于 `.runtime/v07-setup-visual/`。
- 将浏览器下载的目录作为 `MODEL_CATALOG_FILE` 传给本机 Go 服务。通过只读 `GET /api/v1/bootstrap` 核对 `demo/memory`、图片编辑能力、参考数和 1024x1024 的规格；私有映射未进入公开响应。没有提交生成或上传请求。

## 风险与限制

页面校验配置形状。供应商是否开通该编辑模型、支持的参考图数量、图片质量及实际交付，需要用户提供服务器端配置并完成真实验收。表单离页后清空。公开目录只包含当前运行时公开信息，不能从它重建服务端已有的其他私有模型映射。

## 回滚方式

移除配置页路由、入口、表单导出及对应测试即可回退界面。若用户已手动应用导出配置，请按保留的原环境变量和模型目录恢复并重启，同时保留在途任务的原渠道身份和凭据。

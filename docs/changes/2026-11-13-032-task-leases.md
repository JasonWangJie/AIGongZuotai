# 2026-11-13-032：持久媒体领取、租约与旧写隔离

## 目的

V09 / H03、H07、H09：让实际媒体工作线程从 PostgreSQL 领取到期任务，防止过期、取消、核对和重启后的旧执行结果覆盖新状态；保持未知提交不自动重发。

## 范围

数据库独立连接竞争、续租、同事务 fencing、App 启停和恢复接线、固定标签指标调用、事件背压时保留结果仅重试保存、真实数据库竞争与故障测试。单写控制面和目录排他锁保留，多实例部署仍未完成。Outbox仓储/SSE在031，配置环境/进程崩溃联合验收在034。

## 实际文件

- `internal/studio/app.go`：TaskLeaseDuration与私有执行字段，PG worker 分支、Outbox启动/关闭顺序、取消/核对撤销；LLM开始和终态保存的背压处理。
- `internal/studio/task_leases.go`：连接池、数据库领取、续租、generation激活、同事务有条件任务写入。
- `internal/studio/task_leases_worker.go`：实际媒体worker、提交前持久化、失效上下文取消、过期提交停放、结果保存重试、缓存仅提交后替换。
- `internal/studio/migrations/009_task_leases.sql`：私有lease列、执行generation与到期部分索引。
- `internal/studio/task_leases_test.go`：普通配置/分类以及真实PG竞争、恢复边界、背压、迟到结果测试。
- `docs/wiki/scheduler.md`：实际范围、配置、状态、限制与验证。

## 接口与数据影响

无新的用户修改接口。内部 `writeTaskWithLeaseSQL` 在原业务事务核验 owner/epoch/expiry/generation/Version/status，零更新返回普通 `TASK_LEASE_LOST`；事务后续资产、审计、Outbox随其一起回滚。可信控制保存撤销租约。租约字段不进公共任务JSON。

`TASK_LEASE_SECONDS`默认30，公开范围5—300，续租固定三分之一。`TaskWorkers`各占一条独立PG连接，控制业务仍通过原advisory lock连接。迁移009需要与008一起应用；旧二进制遇未知迁移版本拒绝启动，不得删登记强行降级。

## 风险与限制

PostgreSQL可验证本平台提交权，但不能撤销已经发出的上游HTTP。失效时可能产生未登记私有文件；业务资产目录和事件不会被旧写污染，文件仍需保守维护。并发领取不是公平调度；连接数随TaskWorkers增长。LLM仍进程内流和检查点，事件元数据持久化不等于token日志持久化。

Outbox满时只重试原事务，已完成结果暂占原worker；发生停止或真正DB/COMMIT不明错误时不盲目续跑。重启无handle的SUBMITTING转待核实，避免重复计费。单写控制面、目录owner及排他锁意味着此版本不能多实例运行。

## 回滚方式

停机并联备数据库、REFERENCE_DIR、ASSET_DIR及S3收据/对象。若需回退旧程序，恢复迁移前一致备份；不能只删009/008登记或租约列。未知提交保持原记录与幂等快照，不以回滚为由重新调用模型。

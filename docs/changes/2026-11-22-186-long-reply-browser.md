# 186 持续回复中的输入、滚动与浏览器资源

## 目的

在 V17 的正常工作台中测量一个持续输出的会话。用户在回复出现期间继续输入和翻阅消息，最后核对完整正文、未发送草稿和切换项目后的旧资源。

## 范围

H07、H08 / V17。本项使用 1280 × 800 的桌面 Chromium、标准工作台生产构建和单个活动回复。185 总控提供有序的环回文本、实际 Go 服务、独立的平台 SSE 读者及终态只读核验。正式模式为 30 分钟，短测为 12 秒。正式模式通过普通登录页进入自己的项目，独立内存短测可使用无认证的本地工作区。

## 实际文件

- `apps/workbench/scripts/long-reply-browser.mjs` 管理本次 Chromium 标签、页面交互和聚合采样。
- `apps/workbench/scripts/long-reply-browser.test.mjs` 验证每次交互的文本完整性、段数增长、滞后和活动状态。
- `apps/workbench/scripts/local-browser.mjs` 接受可选的子进程环境。本场景只传 Chromium 所需的系统路径、临时目录、用户目录及语言环境。
- 本台账记录浏览器测量边界与验证结果，父级采样见[185 的总控脚本](../../scripts/perf/long-reply.mjs)。

## 接口与数据影响

普通界面新建一个会话并点击一次发送。观测器分别计数会话创建和会话 Run 的 POST、原生 Run EventSource 的打开、增量、终态事件及关闭。合成输出分段换行。正式流中约每分钟使用 Chromium 输入命令追加一个 ASCII 字符，检查 React 字节计数和原输入。随后在可滚动的真实消息容器发送滚轮，检查非零且与滚轮同向的位移。每次交互前后都检查本轮仍活跃。终态时对比界面完整正文，包括换行，并核对未发送草稿，之后通过界面创建并进入第二个项目。

在发送前、流中三个时间点、终态和切换后分别请求 CDP 垃圾回收，记录 JS 已用堆、DOM 节点、文档、监听器、挂载消息、媒体元素、活动 Run 订阅和 40 毫秒正文合并计时器。计时器按实际触发与清除计数。切换后核实页面只保留新项目的一个已打开订阅，旧 Run、消息和合并计时器已经退出。计数器和交互样本有界，正式模式各保留至多 30 份输入和滚轮延时用于汇总。报告包括浏览器版本、延时分位与 CSS 像素位移，账号、提示词、输出正文、原始地址和资源身份均留在本次验证进程内。

## 验证结果

两个浏览器脚本的 `node --check` 通过。完整执行由总控加载同一浏览器模块。正式记录以实跑墙钟、独立 SSE、最终 Run 和原会话消息共同核验。

独立内存短测命令为 `node scripts/perf/long-reply.mjs --quick --server .runtime/long-reply-185-quick.exe --dist .runtime/v17d-035-library-source/apps/workbench/dist --out .runtime/long-reply-186-memory-verified.json`。Chrome 157.0.8103.79 实际收到 25 个增量，首末间隔 12,257.5 毫秒，350 字节终稿与服务端 Run、会话消息一致。一次会话创建和一次发送，三个未发送字符均保留。三次输入到渲染检查为 17.9–31.3 毫秒，三次滚轮到位移为 25.6–31.2 毫秒，实移 101–160 CSS 像素。25 个合并计时器中 24 个触发、1 个清除，并发峰值 1。终态关闭唯一 Run 订阅。换项目后原项目订阅已关闭，挂载旧消息、媒体和活跃合并计时器均为 0。终态与切换后强制 GC 的 DOM 节点为 677 与 561，JS 堆为 3,363,584 与 3,363,020 字节。

### 持续渲染与实际 SSE 序号

第一版只验证每次抽样为合法前缀，某次渲染长时间停留在旧前缀也能满足这条断言。修正后，正式模式的全部 30 个交互、短测的全部 3 个交互都保存原文长度、当时的已发送段数、浏览器已收段数和 DOM 已呈现的完整段数。相邻样本的可见 UTF-8 字节和完整段数必须严格递增。页面必须仍显示本轮正在生成，正文逐字匹配原序列对应前缀。本机试具允许渲染落后夹具最多 2 段。

首段等待独立 SSE 读者和原生浏览器 EventSource 均已连接。浏览器对每个实际增量核验 Run 身份、SSE ID、事件序号及完整编号文本，对结束事件核验状态和独立序号。报告保留实收数字序号（含终态，最多 1,802 项）、首末增量跨度与最大间隔。首末跨度至少达到所选墙钟时长，相邻增量间隔最多为设定间隔的 5 倍。

修正后的内存短测沿用上述命令，输出文件为 `.runtime/long-reply-186-prefix-verified.json`。三次交互各自的已发送、已收到与已呈现段数均相同，依次为 8、15、20 段，对应 112、210、280 字节。实收序号完整覆盖 1–26；其中 25 个增量的首末跨度为 12,262.5 毫秒，最大间隔 754.1 毫秒。浏览器终稿、Run 快照与会话消息一致。`node --test apps/workbench/scripts/long-reply-browser.test.mjs` 两项通过，覆盖冻结前缀、半段、错误段、超出容许滞后、提前显示与终态补读。只允许本机来源的测试还会等自有 Chromium 进程真正关闭后才清临时目录；独立短测在进程启动后主动中断，通过原 PID 确认进程已退出。

## 风险与限制

输入延时从可信 input 事件的浏览器时间戳到两次动画帧回调中读到正确草稿与 React 字节计数。滚动延时从可信 wheel 事件时间戳到动画帧中首次看到同向位移。计量包含事件排队和帧调度，未测物理屏幕扫描。JS 堆为整个标签在各采样点的存活对象。此处单独计数 40 毫秒合并计时器，工作台的周期性会话及目录刷新另有生命周期。纯文本对话记录当时挂载的媒体元素数，真实视频释放另见[180 作品库实测](2026-11-22-180-private-library-browser-resources.md)。硬件、网络和数据量均以本次执行的环境与报告为准。

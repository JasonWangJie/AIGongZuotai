# 224 · V20 已确认分镜的视频生成与剪辑替换工作台

## 目的

让作者从已确认分镜的一次具体尝试出发，核对使用的故事、角色、镜头文字、视频规格与报价，取得该尝试已交付的项目 MP4，显式替换现有剪辑稿中的单个镜头。

## 范围

从原侧栏「漫剧分镜」选择版本和镜头。待确认或正在编辑的分镜须先按原流程保存及确认。已确认固定版本以服务端的原文字为准；此入口只发送文生视频请求。当前作用域有未核对操作时可查看原回执。登录人、项目、确认版和镜头共同限定恢复记录。

## 实际文件

- `apps/workbench/src/App.tsx`、`useComicEditor.ts`、`ComicWorkbench.tsx` 传入当前已鉴权的模型目录，将视频入口放在当前固定镜头编辑区之后。
- `apps/workbench/src/PanelVideoWorkbench.tsx`、`PanelVideoReplacement.tsx`、`panelVideos.ts`、`panelVideos.css` 负责预览、报价、受理、只读原回执、分版本尝试、私有成片以及剪辑镜头替换。
- `apps/workbench/src/panelVideos.test.tsx` 验证固定版、精确参数、真实收据形状、两类待核对操作及作用域隔离。
- `apps/workbench/src/locales/{zh-TW,en,ja}.json` 增补本功能的 50 条文案，简中使用原文。

## 接口与数据影响

镜头固定版本路径下，222 的 `POST /quote` 和受理 POST 沿用同一 Idempotency-Key。正式受理按预览中的 attempt 提交 expected_attempt，并沿用预览的模型、完整规格、权益报价 ID。已启用计价时核对项目、工作区、模型、环境、币种、到期和 CREDIT 微单位。

历史和原键核对分别走有界列表与 `GET /receipt`。只从该项目的活动生成视频中选择有同一 task_id、实际交付标识、可读原件和有效修订的 MP4。用户指定已有 030 剪辑稿、固定版本、目标镜头及新毫秒入出点，再通过 223 提交一次替换。返回的新版本应包含选定的镜头、来源和时间范围；响应未知时使用原时间线收据只读核对。原视频内容按同源项目授权读取。

写入之前，当前标签页的 sessionStorage 保存操作键与核对需要的标识、原规格和裁点。提示词、图片、视频与密码均未进入该记录；保存恢复信息失败时不会发起提交。单个操作记录确认后清理。该恢复信息随浏览器标签页的会话而定。

## 验证结果

- 本机 `npm test -- src/panelVideos.test.tsx src/comics.test.tsx src/videoTimeline.test.tsx` 在三个文件内 41 项通过。六项新增回归覆盖固定参数及报价范围、同键生成及异镜头回执拒绝、过时预览丢弃、未确认或已编辑分镜门禁、无法保存操作键时零写入，以及选取同任务成片和原键只读恢复单镜替换。
- `npm run build` 通过严格 TypeScript 与 Vite 生产构建，转换 179 个模块。新增语言词项共 50 条，繁中、英文、日文全部保留原占位参数。
- 真实 038 PostgreSQL、HTTP 受理与两次丢回执、Chromium 工作台操作、私有 MP4 下载、FFmpeg 独立解码及联备恢复由集成人串行登记。
- 首轮全量前端出现 11 项既有静态渲染失败，定位至并行 V23 旧快照的 `useLanguage` 缺少服务端快照参数。隔离树同步主树已有的 `locale.ts` 修正后，`npm test` 全部 52 文件、594 项通过（26.72 秒）；最终生产构建转换 179 模块，Vite 耗时 5.21 秒。

## 风险与限制

当前只支持已确认分镜的文字输入和已发布项目 MP4。原权益、隔离审核、交付可见性、版本冲突和指定任务的资产归属仍由服务端决定。核对时若未读到原记录，保持待核对。剪辑时刻须符合原 030 总时长与逐镜帧界，实际片源时长由服务端按原片核验。实际供应商可用性与生产费用另验。

## 回滚方式

恢复旧版工作台，保留已受理任务、原键、源分镜和剪辑版本；先核对已发送的原操作。数据库格式切换、业务收据和联备遵循 038 的恢复规则。

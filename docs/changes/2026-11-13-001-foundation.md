## 接口与数据影响

文档治理不改变业务 API 或任务数据。检查脚本增加结构检查，以及互斥的 `--changed` 和 `--base <git-ref>` 模式；前者读取暂存、工作区和未跟踪变更，后者比较 `base...HEAD`。脚本只读仓库文件和 Git 状态，不修改文档或暂存区。

当前第一阶段采用本地 Go 合并部署和内存存储；重启丢失任务与回放数据，demo 默认可跑，真实 LLM 需显式 live 配置，真实自定义媒体仍待 fixtures。没有引入生产登录、持久队列集群、真实支付或性能实测承诺。

## 风险与限制

文档检查只验证结构、链接与变更集合中的同步痕迹，不能证明每个语义修改都有充分记录，不能证明台账里的测试真正执行过，也不验证外网链接和 HTML 历史报告。`--base` 需要存在的 Git 基线和 HEAD；浅克隆缺少历史时明确失败。初始未提交仓库中的既有文件会出现在 `--changed` 集合里，应在首次交付中人工核对基线。

本地版本没有生产级鉴权、持久化、支付与容灾；总体性能指标仍是目标，禁止据此宣称达到一万活跃流或可直接收费运营。

## 回滚方式

本轮尚未发布生产版本。若文档规则或脚本需要调整，恢复该逻辑变更前的指定文件版本，并另建台账说明替代规则；不删除既有报告、用户文件或历史记录。根运行脚本和依赖的回滚应与 README、Wiki 和锁文件一起恢复并重跑构建，不使用批量清理工作区的命令。

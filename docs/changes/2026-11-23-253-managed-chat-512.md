# 253 · 512 路受管会话的完整执行与权益测量

## 目的

V17（H03/H07）以 240 已有的 8 个受管进程、每进程 64 个执行位为本机上界，检验全部执行位能否同时持有原模型连接，随后完成正常授权订阅、结算、原键重放与故障核对。

## 范围

增加显式 `integrated-512` 档。9 个正常注册的账户各持独立会话、项目和工作区，使用正常离线预演、摘要确认发放测试 CREDIT。注册总数处于现有同源 15 分钟 10 次限额内。正常波次在 8 个冻结上游模型和 9 个工作区之间交错，预定每模型 64 路，各工作区 56 或 57 个执行，每工作区与每模型的组合各 7 或 8 路。首工作区额外建立一个迟读 SSE，工作区订阅上限仍为 64。

每个正常 Run 通过会话、正式报价和幂等受理接口建立。回环网关检查原模型、消息、请求方法及流协议。持有模型响应时，将 512 个实际 TCP 对端与 Windows 进程归属、数据库执行代次、原模型和活动租约逐一关联，逐笔核验对应权益已开始、仍冻结、尚未费用结算。满档时，第 513 个请求从仍余一个工作区执行位的账户按普通接口受理，需观察 QUEUED、未启动的 HELD、原键回放、取消后的 RELEASED 及零上游请求。

## 实际文件

- `internal/studio/chat_child_acceptance_test.go` 按档建立正式账户，增加满档排队、逐笔原键、冻结状态及账本稳定性核验。
- `internal/studio/chat_child_integrated_acceptance_test.go` 登记新拓扑，并核对新旧档的用户、模型、执行、受理和订阅分布。
- `internal/studio/chat_child_process_acceptance_test.go` 对单次 512 项的 Windows 内核归属输出使用 32 KiB 上限。
- `docs/wiki/performance.md` 记录执行入口、验收范围与既有基线。

## 接口与数据影响

测试调用标准服务的账户、项目、会话、报价、受理、SSE、只读快照与取消接口。沿用原 12 个同步增量波次，512 个正常读者应取得 6,144 条普通增量，另一个迟读者应取得本 Run 的全部 12 条。独立 PostgreSQL 校验 6,144 个原始增量的顺序、正文、事务分布，逐次核对 512 个终态、完整重放、已结算的原报价和预留。所有正常原键再查一次，重新核对运行、两条消息、原预留及结算金额，读取与原键核验前后的不可变 journal 总数必须一致。报告仅记录业务与连接聚合、延迟和既有试具摘要。进程、调度、计费、批写及数据库均使用原服务制品。

## 验证结果

- Go 1.26.11、隔离 overlay、清空数据库和正式档环境后，新增拓扑、历史档、队列快照、联合读者屏障、指标、回环网关及 Windows 实际单子进程 TCP 归属共七项通过。标准服务构建及 `go vet ./internal/studio` 通过。默认正式入口按条件跳过，在清空数据库配置后显式选择 512 档按预期拒绝启动。
- 512 路 PostgreSQL 正式测量由集成人串行执行。需要可查询子进程 TCP 归属的 Windows、隔离的环回 PostgreSQL、标准服务的绝对路径和新的报告路径。以下命令从仓库根目录运行，数据库沿用当轮已配置的 `TEST_DATABASE_URL`。

```powershell
$trial253 = Join-Path $PWD ('.runtime/chat-253-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $trial253 | Out-Null
$env:STUDIO_CHAT_CHILD_SERVER = Join-Path $trial253 'server.exe'
$env:STUDIO_CHAT_CHILD_REPORT = Join-Path $trial253 'integrated-512.json'
$env:STUDIO_CHAT_CHILD_ACCEPTANCE = 'integrated-512'
go build -p 1 -o $env:STUDIO_CHAT_CHILD_SERVER ./cmd/server
if ($LASTEXITCODE) { throw '标准服务构建失败' }
go test -p 1 -parallel 1 -v -count=1 -timeout 12m -run '^TestPostgresChatChildAcceptance$' ./internal/studio
```

正式入口会把正常阶段和原故障对照跑完，直到重启、原代次失效、已启取消和进程故障的 REVIEW、全部子进程失联后的未领取回退，以及审核屏蔽决定均通过才写报告。2026-11-24 的实测见下节。

## 风险与限制

已归档的 80 路单读者档为 2 个子进程各 40 个原模型连接，80 个正常读者按序收到 960 条增量。264 路联合档为 8 个进程各 33 个连接、6 个冻结模型各 44 路，264 个正常读者收到 3,168 条增量。原配置、原受控负载和两份报告各自保留。512 路同波增量仍受现有 320 项、8 MiB 等待预算、单存储工作者与 5 秒等待边界限制。若出现拒绝、失约、错序或连接覆盖不足，按失败阶段记录。原规划中的 10,000 个活跃模型、真实供应商验收和 24 小时稳态分别需要实测。[80 路原报告](../wiki/assets/performance-managed-chat-037.json) · [264 路原报告](../wiki/assets/performance-integrated-chat-264-039.json)

## 回滚方式

移除 253 验收补丁或选用原档名可复跑既有规模。标准服务、持久格式和用户数据沿用原版本。

## 集成人实库结果

本机使用 Go 1.26.11 与 PostgreSQL 16.14，按 `integrated-512` 显式运行标准程序，专项 60.02 秒通过。8 个受管子进程各由操作系统观察到 64 个已建立的模型 HTTP 连接，8 个冻结模型各 64 路。9 个独立注册工作区覆盖全部 512 个同时执行的 Run。512 位正常 SSE 读者及 1 位迟读者同时占位，取得 6144 条正常增量。正常交付的 P95/P99 为 91.94 / 129.55 毫秒。独立数据库读取确认 6144 条原增量来自 194 个事务。512 个正常 Run 全部结算，按原键逐项复核后意外或重复的模型 POST 为 0，重放没有新增权益分录。取消、工作进程故障、代次更换及审核隔离均由相应用例检查。

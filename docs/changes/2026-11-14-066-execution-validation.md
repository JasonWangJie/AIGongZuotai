## 接口与数据影响

测试通过真实 HTTP 注册不同账户并提交单轮/会话运行；以可控 Provider 调用和调度器唤醒信号验证运行顺序，不用固定 sleep 假定已执行。所有数据位于隔离测试数据库的随机 schema，私有目录由每例临时目录提供；无外发 AI、邮件、审核或支付。

覆盖如下行为：

- A 工作区已占其执行预算且还有排队请求时，B 工作区可使用空闲全局 slot；取消 A 的运行后其下一请求启动，取消排队请求不会调用 Provider。
- 不同公共模型 ID 绑定同一个私有 upstream 时共享模型预算；同工作区受限模型前项不阻塞后面的其他 upstream。会话入口使用同一调度器，仍传完整消息请求。三个请求全部受理后，测试仅改变当前目录私有映射，排队运行仍使用受理时冻结的 upstream。
- 工作区/全局队列满分别返回 `429 EXECUTION_WORKSPACE_QUEUE_LIMIT` / `503 RUN_QUEUE_FULL`，附 `Retry-After: 3`。原键原输入仍返回原 ID 与重放头，异输入保持 409；新拒绝不创建记录或占用幂等键。
- 排队取消立即腾出等待容量。运行取消后，故意迟返的 Provider 在真正返回前仍占执行 slot，迟到正文不会复活 CANCELLED 状态。
- 真实审计 INSERT 故障使整次受理事务失败：没有运行、幂等、冻结、审核策略/决定、调度条目或 Provider 调用；原报价仍未消费，可用额度不变。
- 启用本地审核与 CREDIT 权益后，全队列拒绝的新请求不会多写审核记录、消费原报价或增加冻结；原已受理任务仍可完成，整段审核 ALLOWED 后正确结算 SETTLED。

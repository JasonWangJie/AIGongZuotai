# 107 · 工作流节点执行、报价与公开输出

## 目的

V19-A 将项目内已保存的文本、图片、人工选图流程接入真实子 Run 和 Task。用户在每个生成步骤确认后发起请求。登录另一会话后可以看到同一项目的持久进度和待选产物。本批使用 PostgreSQL 单控制写者，关联 H02、H03、H08、H10。[交付契约](../planning/v19-contract.md)

## 范围

V19-A 后端步骤受理、报价、已审核输出、项目内查询及事务一致性。

## 实际文件

- `internal/studio/http.go`、`workflow_http.go` 注册项目运行、节点输入、执行、选图和原键收据接口。
- `internal/studio/workflow_execution.go` 读取同一数据库快照下的公开子资源，构造冻结输入，并在子受理事务重新核对会话、项目、节点阶段与原意图。
- `internal/studio/app.go`、`persistence.go` 将工作流节点接入普通生成、审核、容量、权益与 Outbox 路径。子受理与工作流链接在同一事务内提交，提交后才排队。定义、候选、父阶段与存储见 [106](2026-11-21-106-workflow-store.md)。
- `internal/studio/workflow_execution_test.go` 覆盖审核后的节点输入、有效报价、错误报价的清理和同一步重放。

## 接口与数据影响

运行集合位于 `/api/v1/projects/{project}/workflow-runs`。启动绑定固定定义版本、输入、模型能力和渠道模式。节点的 `GET /input` 给出可直接报价的完整业务输入。文本输入由节点指令和工作流输入组成，图片输入由图片指令和已公开文本组成，两段间保留两个换行。

`POST /nodes/{node}/execute` 需要独立操作键、运行版本，以及启用权益时对应的报价。数据库在普通子受理事务用原键登记资源，并关联相同工作流；缺报价或报价不匹配时保持子资源、冻结和外发次数不变。查询收据使用 `GET /receipt` 和请求头 `Idempotency-Key`。单流程同时受理一个操作，全进程最多受理 64 个工作流操作。浏览器的读请求不会创建子资源。

读取运行详情使用只读一致性事务。文本通过现有输出审核门禁，图片只有在交付、审核和项目资产登记提交后进入候选。选图复核原任务、产物、内容版本以及当前资产修订。同内容改名后可以刷新并按新修订确认，原修订会冲突。已选择的产物保留确认时身份。已有子资源沿原执行身份运行；尚未受理的节点遇原模型版本、映射或渠道模式失效时停止，用户需基于可用模型另建运行。

## 验证结果

- `go test ./internal/studio -run '^TestWorkflowNodeInputUsesFrozenModelAndApprovedText$' -count=1` 通过，用时 0.218 秒。
- 集成人在独立 PostgreSQL 串行执行 `TestPostgresWorkflowBilledStepsUseFrozenInputsOnce`，用时 5.25 秒。错报价和无报价未产生子资源或冻结。正确报价按已公开文本及完整图片规格受理，两步各产生一条冻结和计费分录，重复请求和只读收据未增加外发。
- 集成人实测 `TestPostgresWorkflowBlockedTextNeverBecomesImageInput` 通过，用时 1.63 秒。文本审核屏蔽了生成正文，工作流停驻，权益保持 REVIEW；图片输入不可取，图片任务和收费分录均为零。

## 风险与限制

仅在要求登录的 PostgreSQL 模式提供工作流。测试使用本机环回渠道和演示权益费率，未产生外部消费。V19-B 的图片首帧进入视频请求仍待单独验证。遇到提交确认不明时，读取原键收据和运行详情。

## 回滚方式

降级须停服务，按相同时间点还原 022 数据库、私有资产/参考目录及对应密钥，再启动匹配写者；当前 023 数据须保留备份。

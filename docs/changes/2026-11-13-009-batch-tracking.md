# 009 · 横向模块、纵向批次与 TODO 治理

## 目的

响应用户“按模块横切纵切生成TODO，完成一批标记一批”，建立持续可检查的进度事实源。对应批次V02。

## 范围

10个横向模块、23个纵向批次的范围/依赖/验收/证据模型，任务状态校验与TODO生成，规则和工程检查集成。V00/V01保留既有验收证据，V03/V04并行开发，其他批次保留未完成状态。

## 实际文件

`AGENTS.md`、`TODO.md`、`docs/planning/tasks.json`、`docs/planning/README.md`、`scripts/tasks.mjs`、`scripts/tasks.test.mjs`、`scripts/check-docs.mjs`、`scripts/run.mjs`、`package.json`、README、Wiki导航/开发/路线、台账索引与本记录。

## 接口与数据影响

新增todo:sync/check:todo/test:todo命令。任务源是唯一可编辑状态，TODO为生成文件。完成批次要求依赖完成、所有check通过、证据文件/台账存在、完成日期且无阻碍。变更同步检查要求同时更新任务源和TODO，不修改业务数据库/API。

## 验证结果

2026-11-13：`npm run test:todo` 的8项测试通过，覆盖未通过检查/无证据不得完成、未知依赖、循环依赖、阻碍与日期、确定性勾选和变更同步要求。`npm run check:todo` 通过源与生成文件一致性；`node scripts/check-docs.mjs --changed` 通过27份文档、9份台账及115个路径的同步检查。V02验收后写入完成日期和证据，再生成TODO并重新校验。该检查数量是本批交付时快照，后续批次会增加。

## 风险与限制

自动校验只验证结构、文件存在和状态一致，不能证明命令实际执行或产品真实验收。批次大小不同，不把已完成批次比例作为整体工期百分比；真实网关联调仍需要外部配置。

## 回滚方式

保留任务源与所有历史证据；如需回退生成器，先保存TODO可读快照，再调整工程命令。不得通过删除待办/篡改已交付证据改善完成率。

## 文档同步

README增加TODO入口与命令，AGENTS写入逐批验收规则，Wiki记录执行方式，台账索引新增009并保持001—008历史不变。

# 2026-11-22-171 生产前端制品的本机浏览器基准

## 目的

V17-B 记录用户打开工作台、进入灵感对话和得到新会话的实际等待时间。用相同前端制品分别测量桌面、窄屏和浏览器缓存的影响，保留可以独立复算分位数的原始样本。

## 范围

H07 可靠性与性能、H08 前端体验、H09 工程与交付治理。本次使用 033 生产构建的 React 静态资源、Go 服务、回环 Chromium 和 memory/demo。前端真实调用会话 API，测试不启用模型、数据库、账户认证、权益、邮件、S3 或外部渠道。

## 实际文件

- `scripts/perf/frontend.mjs` 管理独立进程和样本、核对制品与服务端结果，生成 JSON 报告。
- `scripts/perf/workbench-browser.mjs` 测量渲染器事件和可见状态，通过 CDP 发送真实指针操作。
- `scripts/perf/frontend.test.mjs` 校验分位数口径和服务端环境白名单。
- `apps/workbench/scripts/local-browser.mjs` 给已有 Chromium 辅助程序增加可选的首屏尺寸、延迟导航、单源网络限制与 CDP 命令入口。既有烟测默认仍用 1280×900 并自动导航。
- `package.json` 提供 `npm run perf:frontend`。

## 接口与数据影响

默认读取 `.runtime/server.exe`（其他平台为 `.runtime/server`）和 `apps/workbench/dist`。可用 `--server`、`--dist` 指向本机已构建的对应制品，`--chrome` 指定本机 Chromium 可执行文件。前端检查 Vite 模块入口，并记录服务器二进制、HTML 及包含懒加载资源在内的整个目录 SHA-256。测试开始和结束时校验证据身份。脚本只接受本机文件和采样数量，不接受目标服务 URL。

每次采样分配新端口、新的内存服务、私有目录、Chrome 进程和无痕上下文。服务端确认已监听后才连接该端口，并核对 memory/demo、首页 HTML 和空会话列表。冷组首次导航前没有访问过该来源，预热组先加载到服务端数据已就绪，再经过空白页导航回同一来源，沿用同一浏览器上下文。每组报告浏览器实际观察到的静态资源与缓存命中数。两种视口均使用 DPR 1 和桌面指针，尺寸为 1440×900 与 390×844。样本顺序按轮交错，不并行运行。

报告以毫秒记录 DOMContentLoaded、FCP、首页“刷新历史”按钮首次可用并通过可见性命中检测、点击“新的灵感对话”到对话标题可见、点击“新建会话”到新标题被选中并可见。操作从浏览器捕获的可信点击事件计时，到动画帧中的 DOM 命中检测为止。滚动、展开窄屏侧栏、填写测试输入与 CDP 查询间隔均不计入两项点击延迟。新建必须恰好收到一次 201，随后由独立只读 GET 确认相同的版本 1 空会话。报告只保存制品和环境身份、固定指标、样本和分位数，省略项目编号、标题、正文、URL 和凭据。

## 风险与限制

两种视口均采用本机 headless Chromium，禁用 GPU，无人工网络限速。测量包含浏览器调度、React 更新、布局和本机往返，无法单独归因为服务端、网络或渲染瓶颈。动画帧中的可见性检查是屏幕呈现的近似值。冷组仅表示浏览器上下文首次访问，操作系统文件缓存和 CPU 状态取决于当时主机。样本上限每组 40；容量、真实移动设备、真实登录路径以及 24 小时稳态继续按 V17 剩余条件验收。

## 回滚方式

移除独立基准脚本、npm 入口和 Chromium 辅助程序的可选扩展即可恢复原测试工具。每例退出时关闭自己创建的进程和私有目录。绑定失败不会接管目标端口。没有数据库升级或用户数据回退步骤。

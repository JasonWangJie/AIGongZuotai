# 182 · 剪辑目录刷新期间保留已核对稿件

## 目的

修复 V20-A 在 034 累计运行中暴露的选择器问题。首次保存响应丢失后，工作台通过原键取得已提交的 v1，编辑器已经显示该版本，但当前目录页尚无对应选项，浏览器把下拉框显示为「新剪辑稿」。034 的 `TestPostgresVideoTimelineBrowserExport` 在验证实际选中稿件 ID 时失败，用时 14.72 秒。

## 范围

本次只调整工作台在读取固定版本或原收据后的剪辑稿选择和目录刷新。当前稿取自已核对的同项目固定版本。目录未返回、当前稿不在这页或目录摘要仍较旧时，选择器保留一项当前稿；收到相同或更新摘要后使用目录项。版本选择仍保持用户实际打开的版本。选「新剪辑稿」和切换其他稿件共用现有的未保存输入确认。

## 实际文件

- `apps/workbench/src/VideoTimelineWorkbench.tsx` 将已核对的当前稿纳入下拉选项，去重后显示；确认保存时立即恢复编辑，原有目录和历史查询仍由版本变化触发。
- `apps/workbench/src/videoTimeline.test.tsx` 补充目录延迟、翻页选旧版本和跨项目原收据断言。
- `docs/changes/2026-11-22-182-video-timeline-selection.md` 记录失败、修正和复验事实。

## 接口与数据影响

沿用项目、稿件和版本校验。当前选项来自已加载的已保存内容，不使用本页未保存的标题，也不写入额外缓存或数据库。目录刷新只读；原键核对不再提交保存。导出依然使用用户当前打开的已保存版本，取消下载和导出回执核对逻辑沿用原实现。

## 验证结果

修正前以确定性测试分别复现「首次保存原收据已到但列表仍在等待」和「翻页打开旧版本，刷新首页不含当前稿」。两项均出现页面版本已装入、实际选择值为空。跨项目收据拒绝用例在修正前后均通过。

主树工作台执行 `node node_modules/vitest/vitest.mjs run --no-cache --configLoader runner src/videoTimeline.test.tsx`，18 项全部通过，5.82 秒。新增测试实际读取 DOM 的项目稿件 ID、历史版本、是否重复选项、原键调用和未保存镜头名。`node node_modules/typescript/bin/tsc --noEmit` 通过。Vite 生产构建输出至新的忽略目录，156 模块、4.97 秒。

用同一生产构建和未改动的 `apps/workbench/scripts/video-edit-browser-smoke.mjs` 驱动真实 Chromium。环回 HTTP 在得到第一个已保存稿件的目录 GET 后一直挂起，直到浏览器实际请求导出成片才释放。脚本在目录尚未返回时通过原稿件 ID 断言，随后完成两次下载、双窗口冲突、旧版重开及 390 像素界面，10.57 秒通过。

## 风险与限制

本地浏览器复验使用隔离 HTTP 夹具与预制视频，真实 PostgreSQL、服务端合成和累计回归由集成人在最新冻结副本上串行复验。此项变更保留原浏览器脚本的真实 ID 断言。

## 回滚方式

可按版本回滚前端选择器改动。旧版本在回执已到而目录迟到或发生分页时会再次出现原显示问题。数据库格式、已保存剪辑及私有视频原件未因本次修正发生变动。

## 文档同步

集成人同步 README、Wiki、变更索引及 V20-A/V22 对应验收记录，并补记冻结副本的真实数据库结果。

## 035 本机专项复验

集成人在固定制品上复跑 034 首次发现故障的原 Chromium 程序；同一真实 PG、两个独立会话、回收原保存结果、原选择 ID、两次可解码 MP4 导出和 390 像素宽度均通过（21.21 秒）。

随后在同一固定制品上再串行两轮，实际本人状态接口分别 3.72 和 3.98 秒，真实视频浏览器分别 21.34 和 22.48 秒，合计 51.669 秒，四次均通过。

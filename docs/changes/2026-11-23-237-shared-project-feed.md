# 237 · 项目 SSE 订阅共享已投影事件页

## 目的

V17、H03/H07。原先每个已连接的项目订阅每秒向控制连接提交一个多语句只读事务。让读取相同项目、相同位置的订阅共享一次数据库查询，同时保持各连接的会话、原游标、慢写处理和断线补读语义。

## 范围

- PostgreSQL 项目通知的初连、原游标重连、心跳、遗漏唤醒时补查及连续翻页共用已投影的元数据页。每次读在只读事务内核验控制写者的身份、世代与锁，元数据查询在同一快照取得数据库身份、消费水位、窗口下界及最多 100 条按序事件。
- 消费/裁剪事务成功后，控制连接在释放前逐项目清除旧页并通知读者。裁剪波及的其他项目同样失效。被替换的在途读取不能重新填入旧页。各连接按共享页的绝对到期时间补查，查错不留缓存。
- 全进程至多缓存 256 个成功页。两类读取共享至多 256 个后台加载位置，包含正在取消、尚未归还资源的旧读取。额外等待仅占已准入的 HTTP 请求，等位与读库合计 5 秒。每个读者可独立退出，最后一个等待方退出时立即取消并移除在途加载，新读者不会加入已取消的读取。最后一个订阅离开时清除该项目页与监听器。
- 每个请求独立验证账户、工作区、项目与数据库游标，独立编码 SSE id。兼容的 `task.updated` 帧只在同时读当前项目同一任务时合并，稍后的读取重新取当前公开 Task 文档。任务快照及会话数据均不进入元数据页缓存。

## 实际文件

- `internal/studio/outbox.go`、`internal/studio/outbox_http.go`、`internal/studio/outbox_shared.go`
- `internal/studio/app.go`、`internal/studio/persistence.go` 负责项目通知只读连接的创建与关闭
- `internal/studio/outbox_shared_test.go`、`internal/studio/outbox_shared_cancel_test.go`、本台账

## 接口与数据影响

沿用原项目 SSE 接口和已投影水位。过期游标发 `stream.reset`，超前游标返回 409；任务变更的通知和兼容帧仍使用同一个请求专属游标。应用为项目通知提供独立 PostgreSQL 只读连接，固定上限 2，包含连接池等待的读取上限为 5 秒。读页和兼容任务帧均使用这组连接。控制写者、Run 重放与会话撤权各保留原连接预算，无新增配置或迁移。

## 验证结果

Go 1.26.11 在隔离 overlay 执行实际包编译、共享页单元用例和既有游标隔离用例；重复 20 轮通过。单元覆盖在途旧页晚到、等待方取消、错过通知后到期再查、错误移除、不同游标/项目、全局淘汰、关闭重连、10,000 个内存读取位置在 80 个作用域各查询一次。该计数使用测试加载函数。

取消回归使用受控阻塞的元数据页及兼容任务帧。覆盖第一位读者离开、同页其他读者继续、最后一人离开后取消数据库工作、旧 SQL 清理期间新读者立即读取，以及 256 个后台位置已满时排队者自己的超时。隔离 overlay 使用 Go 1.26.11 执行上述单元及既有共享页用例，重复 10 轮通过。已编译实库注销用例，实库结果由集成人登记。该用例先占满两条项目只读连接，再经普通 API 注销真实登录会话，核验空响应结束读取、释放 HTTP 占位，且授权监测连接可继续工作。

集成后用于复验的命令如下。

```powershell
go test -p 1 -count=20 -run '^(TestSharedFeed|TestDurableCursorRejectsForeignScopeAndUnboundedInput)' ./internal/studio
go test -p 1 -parallel 1 -count=1 -v -run '^(TestPostgresSharedFeed|TestPostgresOutbox)' ./internal/studio
```

第二条需要集成人设置本机隔离 `TEST_DATABASE_URL` 并串行执行。新增 PG 用例覆盖真实投影导致 2048 条旧窗口前移一条、重启后原游标重置及补读、写失败后仅释放该订阅、重放时读到更新的兼容任务版本。隔离开发期间已确认缺少 PG 配置时明确跳过。233 的 320/10,000 条真实 HTTP 连接另按其入口验收。

早版实库复跑中，共享页裁剪与写断试具在订阅计数断言失败，原 Outbox 用例通过。直接构造仅含相对路径的 HTTP 请求会被赋予 example.com，触发回环 Host 门禁，未到达写断注入点。现让该请求使用同一测试服务器的完整 URL，并分别报告未触发写断与剩余读者数。192 路注销试具显式配置其启动所需的 1 条 Run 重放读连接。两项的实库复验由集成人执行。

## 风险与限制

PG 连接预算需计入两条项目只读连接。排队或读取超时会终止当次 SSE，初连尚未发送帧时可返回 503 并保留原游标。相异项目或相异游标分别查询，活跃页超过 256 时可能淘汰后重读。快照位于单控制写者的本进程内；慢读者的下一页仍检查持久窗口。当连接的请求速率、工作区分布或主机条件改变时，应据实际数据库与 HTTP 负载记录吞吐。此项不产生模型请求、生产容量或 24 小时稳态证据。

## 回滚方式

恢复旧的逐订阅读取与投影唤醒实现，撤回本条共享页及关联测试。保留数据库中已有 feed、消费 checkpoint、下界、业务记录与旧游标，无数据回填。

## 一万真实连接的广播结果

039 在同一台 Windows 主机及隔离 PostgreSQL 上，以 80 个工作区各 125 位读者建立 10,000 个真实 HTTP/SSE 订阅。2 次完整复核覆盖 320 个不同会话，共 640 次；10,000 位读者全部收到自己的第一版草稿。注销读者 32 个均见 EOF，同项目其他 93 位收到第二版，原游标成功补读且最后占位归零。建连 6.846 秒、广播 1.117 秒，专项 30.04 秒。[完整报告](../wiki/assets/performance-project-sse-10000-039.json)

## 控制写者与故障补读复验

初次裁剪试具使用相对 URL，被 Host 门禁以 403 拒绝；新版注销试具另遗漏扩展准入所需的 1 条 Run 重放读连接。修正为本机测试服务器的实际 URL 和完整配置后，真实锁位注销、裁剪与失败写两项分别以 3.17 秒、2.97 秒通过。

# 192 · V17 持久长分支受理与精确上下文

## 目的

允许明确启用该能力的持久工作台在同一真实分支写入 10,000 个消息节点后继续提问，使选中分支的消息数、模型实际纳入的完整轮次与历史分页保持各自准确。

## 范围

036 对持久消息增加只含身份、深度、前序与字节数的不可变索引。原默认每会话 256 个节点、单支 128 个节点；显式启用持久长会话时分别为 32,768 和 16,384。内存演示原有全局 2,048 条保护继续生效。关闭开关后，长链原幂等重放和历史分页仍可读，新写入按当前配额受理。配置、维护命令精确栅栏及联备由 193 登记。

## 实际文件

- `db/migrations/036_durable_conversation_history.sql` 扩充持久节点计数约束，按祖先先于子节点的顺序回填原树，并在后续消息插入事务中创建派生行。结束前核对每个旧节点都有投影。
- `internal/studio/conversation_ancestry.go` 选择实际父节点和最新可纳入轮次，核对原正文与预算。 `internal/studio/conversation.go` 和 `internal/studio/billing_http.go` 让报价、锁外审核准备及最终受理共用该路径。
- `internal/studio/conversation_message_page.go` 在 188 的窄分页读取前核验原 v1 游标属于实际选中的项目、会话与叶。
- `internal/studio/conversation_ancestry_test.go` 覆盖预算等价、035 原树升级、深分支、错误游标、审核隔离、普通与继续请求的差异。

## 接口与数据影响

对话 API 与游标格式沿用原契约。保存用户与助手节点时记录该路径从根起的准确深度、128 级分块祖先、严格在本轮之前最近可公开非空的助手，以及该完整轮次的实际 UTF-8 字节数。助手受理时尚未终结；下一轮受理时才依据其已提交终态决定是否加入候选。这让连续隔离或空答之后的新问题仍能找回较老的可公开轮。未审核的已结束部分回复继续沿原规则参与上下文；已审核输出须为 ALLOWED 且 COMPLETED。

直接父的真实状态始终核对，继续请求还要求父回复去空白后有内容且完整放入模型窗口。旧轮按最近到最旧检查，遇首个装不进的完整轮便停止。请求最多 129 条，含本次用户消息；模型正文按实有需要读取，隔离直接父仅保留标识与审核状态。原预算估算与最终 `ValidateChatRequest` 作用于真实请求，冻结原先顺序的消息及身份，审核回程重新比对整份请求摘要。省略数是实际选中叶的祖先数减去最终纳入的旧消息数。

消息或游标身份不当仍返回原错误。向前读页先验证游标与当前实际叶的祖先关系；使用前缀块指针跨过整块，再逐级确认最后一块。仅按此前 188 的数量/JSON 字节预算加载本页正文，页面读取独立于写入配额。幂等、版本、项目范围、审核、权益与 Outbox 原子受理保持原入口。

## 验证结果

- 准备区合并 192 与 193 Go overlay 后，`go test -overlay <本机映射> -count=1 ./internal/studio -run '^(TestChatAncestryBudgetMatchesWireValidation|TestConversationContextTrimsTurnsAndProtectsContinue|TestConversationEmptyStopCanReplyButCannotContinue|TestConversationMemoryBranchReplayAndCapacityPreserveHistory)$' -v` 四项通过，包耗时 0.205 秒。`go vet -overlay <本机映射> ./internal/studio` 通过。比较多种窗口、消息条数及字节临界值与真实 Go 校验器结果。
- 真实 PG 由集成人串行执行 `go test -p 1 -count=1 ./internal/studio -run '^TestPostgresConversationAncestryUpgradeAndBoundedContext$' -v`。用例从 035 的 64 轮旧树升级，比较原会话、Run、消息行，再写 70 个连续隔离或空输出轮、公开新轮和兄弟分支。检查 270 深分支纳入 128 条旧消息、精确省略 142 条、只水合 64 个可公开轮；包含错分支游标、旧库无流头、关闭开关仍能回读和超预算继续等边界。准备时尚无实 PG 成绩。

## 风险与限制

回填会读旧会话与相关 Run，异常根、错误角色、未结束父或无法从合法根抵达的行会使升级事务回滚。已有 021 流的终态输出和审核摘要受原持久保护；既有财务与申诉动作保留原审核结果。未来如引入对已经公开的终态正文进行追溯变更，需要同步考虑既有候选指针和历史执行快照。默认限额与显式大限额都受原模型独立窗口约束。本项只交付单写者上的持久树与模型上下文；真实万节点经普通 HTTP 的产生、浏览器读取、内存和退出表现按 194 独立验收。

## 回滚方式

已升级 036 时可以关闭长会话写入开关继续读取。完整回到 035 应使用与 035 匹配的数据库和私有目录联备恢复；保留迁移记录、目录 owner 及密钥的对应关系。

# 125 · V14-C2b 账户限制与复核工作台

关联 V14，以及 H01、H06、H08。账户治理的目标是独立身份，可跨工作区。C1 工作区新生成限制和 C2a 内容申诉继续拥有独立入口和记录。

## 目的

受限用户仍可完成身份认证，随后进入专属页面查看限制轮次、公开说明、本人复核记录和答复，访问现有账户安全工具或退出登录。只有拥有指定目标授权的治理员看到“账户治理”。目标选择器只包含当前操作者获准管理的账户。

## 范围

覆盖 027 账户状态、本人申诉、定向治理权限、预演/执行及浏览器会话切换。恢复原稿仅限同一页面、重新认证的同一用户与原项目。

## 实际文件

- `apps/workbench/src/App.tsx`、`types.ts`、`api.ts`、`useStudio.ts` 根据身份响应和会话变化切换入口，受限登录跳过项目初始化、历史和流订阅。创作、内容申诉与原运营工作台退出受限身份的页面树。
- `apps/workbench/src/accountDraftHold.ts` 在当前页面内存暂存因身份中断的编辑器文字和操作；相同本人及原项目重新认证后才恢复。显式退出、身份切换、项目切换分别清空。
- `apps/workbench/src/AccountGovernancePage.tsx`、`accountGovernance.ts`、`account-governance.css` 提供本人当前状态与历史、定向治理员的限制/维持/解除预演、当前密码执行和只读原回执，以及窄屏布局。
- `apps/workbench/src/accountGovernance.test.tsx` 与 `apps/workbench/scripts/account-governance-browser-smoke.mjs` 覆盖初始身份分流、作用域隔离、待核对操作、桌面交互和 390 像素页面。

## 接口与数据影响

受限会话的 `/auth/session` 或登录响应包含 `account_restricted`。原有会话被撤销后重新登录，读取 `/account/access` 和本人 `/account/appeals`；正常身份也可从“账户状态与申诉”读回既有历史。提交申请绑定原限制轮次，未知响应用当前本人和原请求头读取 `/account/appeals/receipt`。

定向治理使用 `/operations/account-targets` 及其目标子路由。限制绑定目标和当前版本，维持另绑本轮开放申请及版本，解除另绑当前轮次。浏览器核对预演效果、目标、意向和有效期，操作者确认并输入当前密码后执行。回执未知仅 GET 原计划，页面重开时只恢复编号。正文、密码、证据和预演摘要不写入恢复索引。普通 CREATION/工作区角色仍须独立目标授权。

## 验证结果

- `npm --prefix apps/workbench run test -- --run src/accountGovernance.test.tsx` 已通过 11 项，3.08 秒。涵盖同人同项目原稿、换人/换项目隔离、退出时清除、受限初始不读创作 API、原轮次收据、错误作用域、异目标预演和执行回执丢失。
- 全部前端 `npm --prefix apps/workbench run test` 为 36 个文件、381 项，9.33 秒；TypeScript 和 Vite 构建通过，Vite 4.02 秒、主包 491.11 kB。真实 PostgreSQL、两个独立账户、撤销旧会话、联合恢复及完整 PG 回归由集成人串行登记。

## 风险与限制

编辑器内容和未决创作请求的恢复依赖当前页面内存。刷新浏览器不会保存这一原稿。重新登录和获取身份状态均不自动发送模型或媒体生成。普通已打开页面通过前台重新聚焦、限权响应、会话流错误及周期性身份检查识别身份变化，服务端在每次受保护请求上执行授权。解除账户限制后仍按原项目、内容审核及财务权限访问。

## 回滚方式

先核对已发送的账户处置和申诉原回执，保留全部限制轮次、授权和原操作收据。前端须与兼容的身份控制和持久格式一并回退，已提交限制由正式授权操作处理。

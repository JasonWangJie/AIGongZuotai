# 095 · V16-B 持久聊天流契约

## 目的

聊天增量当前先在内存广播，进程重启后按已保存的 Run 快照恢复。本记录明确后续如何验收已提交增量的回放、审核正文公开门禁和旧执行者隔离。

## 范围

设计覆盖 V16 的聊天执行、持久存储、恢复、鉴权与前端回放。B1 交付从单次执行、增量提交到重启补读的完整链路；B2 验证有效租约、撤销与并发迟到写入。两项均待实施。

- `docs/changes/2026-11-21-095-durable-run-stream-plan.md` 记录本次设计变更。根 README、Wiki、台账索引、`docs/planning/v16-contract.md`、`docs/planning/tasks.json`、两份生成的 TODO 和 `docs/planning/progress.md` 同步入口与当前进度。

## 接口与数据影响

本次交付设计文档，现行接口及 020 表结构继续运行。后续方案沿用 Run 快照与 SSE 访问入口、原键和项目权限；逐增量日志、持久水位、裁剪与执行授权需要新增持久格式并覆盖旧游标兼容。

只读核对 `executeRun`、`checkpointRuns`、Run 保存事务、SSE 回放与前端增量归并；核对旧序号恢复、运营快照和输出审核事务故障用例。已检查本契约中的本地文档及代码链接。本轮没有 B1/B2 实现，未运行其功能测试；设计不能作为通过证据。

集成时运行 `npm run todo:sync`、`npm run check:todo` 和 `npm run check:changes`。生成结果一致，23 批中 11 批已验收，201 份文档、95 份台账及 49 个变更路径通过治理检查。

## 风险与限制

直接把未审正文写入流日志会破坏隔离；先广播后提交会使重启回放缺失已上屏内容；用项目序号替代 Run 游标会混淆作用域。契约要求分别验证这三项，并验证提交确认不明时的外发次数。独立 PG 租约竞争和环回供应商的结果仅用于本地验收。

## 回滚方式

本轮仅增加设计和导航。需调整方案时建立后续台账，保留本次记录及既有 A 阶段验收。数据库和私有存储无迁移操作。

# 109 · 固定版本工作流、跨会话选图与联备

## 目的

让用户从已保存的项目模板实际执行文本与图片生成，并在刷新、重新登录或联备恢复后从原候选中确认图片。

## 范围

V19-A，H02、H03、H10、H08。关联 106 存储与图校验、107 子资源与权益、108 画布工作台。V19-B 视频输入和 V19-C 重跑、取消与故障恢复独立验收。

## 实际文件

- `internal/studio/workflow_definition_http.go` 负责工作流定义的保存、列表、不可变版本和原键收据，以及项目/账户/存储模式门禁。`internal/studio/workflow_integration_test.go` 覆盖原 022 升级、审批前联备恢复、子受理提交确认丢失和真实浏览器。
- `internal/studio/storage_maintenance.go`、`ledger_admin.go`、`operations_admin.go` 及 `storage_maintenance_delivery_test.go` 更新 023 精确格式和不兼容库拒绝测试。
- `docs/api/openapi.yaml` 登记定义、运行、节点、报价输入和收据接口。[决策 0023](../wiki/decisions/0023-project-workflows.md)、Wiki、README、任务源、推进记录和生成清单同步。

## 接口与数据影响

项目工作流入口位于 `/api/v1/projects/{project}/workflow-definitions` 与 `workflow-runs`。公开端点不接受调用者指定子资源、私有路径或上游凭据。内容与可见性在现有 Run、Task 和资产层核验。新增 023，不回填旧草稿，也不自动启动已有创作。

## 验证结果

- 真实 PostgreSQL 16.14，串行从原始 001—022 建库并升级。原草稿、不可变修订、保存回执及项目表快照一致，旧写者拒绝新库。维护、账本与运营工具拒绝 022、缺版本和未来 024；两项合计 4.220 秒。
- 真实 HTTP 文本增量经审核后进入图片网关的实际 POST，参数沿用原模板 v1。执行期间另存 v2，原收据仍指向 v1。用户在实际 pg_dump/pg_restore、私有目录和交付密钥还原后重新登录，确认原两张候选之一；媒体文件字节与源 PNG 一致，跨工作区读取拒绝，原子资源各调用一次。
- 针对父子受理事务中子资源关联的 PostgreSQL COMMIT 丢回执，HTTP 返回 503，数据库留下一个原子资源。重启后通过原键查到已中断的同一 Run，重复原操作无第二次外发。
- 浏览器首轮停在生成图片前，查明自动化用子串点击了历史记录。改成精确按钮匹配后，同一条真实 Chromium 路径通过，覆盖注册、编辑节点与连线、固定版本、明确授权两个节点、私有缩略图、独立会话选图及窄屏。

- 最终 11 项工作流及维护专项 39.793 秒通过，其中真浏览器 13.61 秒、联备 8.70 秒、子受理丢回执 2.10 秒。启用本机版本化 S3、真实备份、20 万条恢复、十万积压与混合负载的全量 PG/Chromium 实际结束通过，studio 包 881.522 秒。
- Go vet/test/build、10 项治理、32 文件 329 项前端及六套冒烟通过。首次 npm run check 的最后一项发现三份台账的复合标题不符合治理规则；拆开标题后 npm run check:changes 复验通过，含 220 份文档及 110 份台账。

## 风险与限制

用户授权逐步执行；额度报价、工作区限制、模型变化和审核结果均可能阻止新受理。保留原工作目录和私有内容版本。实测使用环回模型及审核服务和真实 PNG；供应商计费、实际图片质量与生产容量仍需各自条件。

## 回滚方式

停写，恢复升级前同一时点的 022 数据库、私有文件、owner、已启用密钥及对象版本，再使用对应程序。保留 023 证据，不清除迁移、不删除真实候选来回退。

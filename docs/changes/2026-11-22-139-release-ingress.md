# 139 · 本机 HTTPS 发布入口、停流与按账户验收

## 目的

单写者工作台换版时，先停止向旧进程派发新请求，让已提交的写操作和正在下载的文件有机会正常结束。新进程启用后，指定账户应先能读回自己的受保护资源，随后才对全部用户开放。

## 范围

V18-B 覆盖 H01 的候选账户核验、H07 的入口切换与 H09 的本机交付演练。HTTPS 和后端 HTTP 均绑定本机 IPv4 回环。制品、数据库、进程生命周期及私有目录锁由同批独立组件和集成演练验证。

## 实际文件

- `scripts/release/local-ingress.mjs` 提供 HTTPS 入口、维护排空、候选探针、开放控制和校验证书的请求客户端。
- `scripts/release/localcert/main.go` 用系统随机源生成 24 小时有效的回环测试证书，经私有管道交给演练程序。
- `scripts/release/local-ingress.test.mjs` 用真实本地 HTTPS 客户端和 HTTP 服务端验证在途交接与权限。
- `docs/changes/2026-11-22-139-release-ingress.md` 记录本组件验收。

## 接口与数据影响

调用 `startLocalIngress({cert,key,initialTarget,port})` 可创建一个入口。提供显式旧目标时初始开放，省略时初始维护。接收 Host 必须对应本次绑定，浏览器提供的 Origin 必须精确匹配同一 HTTPS 入口。转发时移除来路代理头和逐跳头，按已指定的内部回环地址重建 Host 及同源 Origin，为响应 Cookie 补 Secure。

调用 `maintain({timeoutMs,streamGraceMs})` 立即拒绝新流量。正常写与下载等待已接入的真实请求和响应结束；上传已完整接收而客户端中途离开时，仍等后端写响应。对实际返回 SSE 的只读请求，宽限后断开该订阅。等待限期届满仍有请求时，入口保持维护，待有限请求完成后可再次显式排空。如果后端在写操作取得完整回复前断开，记录确认未知并拒绝切换。

调用同步的 `candidate(target,{userId,paths})` 指定唯一候选、一个本机演练账户与最多八条精确只读路径。候选期间每次转发先持当前 Cookie 请求新进程的真实会话接口，核对认证模式、账户 ID 及限制状态。必测路径包括 `/readyz` 和至少一条私有业务 API，所有探针须真实返回 200 并完成传输。就绪体还须呈现 `ready=true` 和 `state=ready`。上层核对制品身份、原始业务回执与私有字节，再显式调用同步的 `open()`。

同一时刻至多接入 64 个请求与 128 个 TCP 连接。入口控制对象只存在于编排进程，`snapshot()` 只返回阶段和计数；`close()` 关闭本次创建的监听器和本次转发的连接。端口被占用时启动报错。工作台 SQL 格式与 API 不受此组件影响。

## 风险与限制

本机编排必须先停止旧进程并实际核验数据库和目录的排他锁。入口独立于进程锁，只观察经它转发的客户端连接。使用 HTTP/1.1，外部 TLS、流量入口与跨可用区部署需在对应环境另验。已返回完整响应的业务含义及下载内容由上层按原请求/字节核验。

## 回滚方式

候选任一业务探针失败时保持受限，重新进入维护，待所有在途请求排空，再由编排者停止本轮进程。重新核实三把锁，选择与现有数据格式兼容的上一制品，完成同一组原始回执及私图检查后再开放。含数据库格式回退时应使用已演练的匹配联备，覆盖写入窗口的差额由维护人员核对。

01 项目结论与投入决策

建议建设一个面向个人创作者的 AI 创作工作台：先把商品图、内容配图和短视频素材做成稳定的收费业务，再逐步扩展画布、漫剧和生态。首期要证明用户愿意为可用作品持续付费。

推荐立项方式

总计按 12—16 周建设商业 V1，其中前 2 周完成场景访谈、供应商评测和可点击原型，再按验证结果投入后续研发。建议完整 V1 研发资金按 50万—60万元准备，经营储备另算。若首期总资金只有 30万—50万元，就收缩为图片＋固定模板＋轻视频，延后自由画布。

已确认的决策条件：面向普通用户对外收费，预算 30 万元以上，长期经营。地域暂按中国大陆主体、主要服务境内用户规划；主体所在地、现有团队、供应商合同、是否面向海外仍需立项时确定。

真正需要建立的资产有四类：经评测的模型供应体系、能复用的行业模板、用户项目和素材资产、可追溯的计费与运营数据。品牌页面可以较快实现，稳定交付和可持续毛利需要持续迭代。

优先决策本方案建议下一步验证
第一类用户个人电商经营者、接单设计师；自媒体创作者作为相邻人群各访谈10人，比较需求频率、支付意愿与现有渠道
第一种结果上传商品图，产出一套可通过提示词或参考图继续修改的主图、场景图、卖点图与配文用真实素材做20个任务，记录可用率和修改次数
产品形态PC创作为主，手机端查看、简单生成和下载先实现响应式Web，App与小程序后置
技术路线自有业务底座＋商业授权清晰的模型API关键能力至少两家可替代供应商
扩张原则达到留存和贡献利润门槛后，再增加产品线每四周一次阶段审查，未达标优先修主流程

03 产品定位与竞争切口

“聚合很多模型”能吸引尝鲜用户，但用户容易因价格换站。长期付费理由应是：熟悉自己的商品或角色、复用成功模板、修改方便、预算明确、交付可靠。对普通用户，首页最好先展示“我要做什么”，高级模式再展示模型和渠道。

人群高频付费任务优势与难点优先级
个人电商经营者主图、白底图、场景图、活动图、短广告结果可衡量、可批量复用；需保证商品结构和文案准确首选假设
接单设计师多个风格提案、局部修改、客户交付包复购频率潜力高；重视可编辑和授权首期共建用户
自媒体创作者封面、图文组图、脚本与视频素材容易做内容传播；价格敏感、同质化较强第二切口
漫剧和短剧作者角色资产、镜头、配音、续作项目黏性强；抽卡成本、角色一致性和支持成本较高二期专项验证
大众办公用户PPT、总结、文档问答人群广；需要单独的文件质量和获客策略三期或独立产品线

建议首发卖点：“上传一张商品图，做出一套可继续修改的营销素材；每一步提前知道费用，失败可恢复。”先挑一到两个类目，例如家居小物或包装商品，避免一开始承诺珠宝反光、透明瓶、服装上身、复杂机械都能准确还原。

如果你已有稳定的自媒体或漫剧客户渠道，首个场景应跟随真实渠道调整。决定优先级的证据是客户愿意带素材来试用、愿意付费和再次使用，而不是哪个模型名字更热门。

04 白标 源码与独立建设的选择

路线适合情况主要代价执行建议
购买白标/代理快速测试客群和渠道；研发资源不足受上游定价、可用性、账号与数据导出限制；通常不等于拥有产品可作短期验证工具，先核实商户归属、客户迁移、停服处理和品牌授权

购买前必须拿到的答案：能否取得源码和修改权；依赖哪些付费服务；用户数据如何导出；域名、云资源和支付商户归谁；是否可独立接新供应商；第三方授权是否允许商业转售；停服或涨价如何退出；历史订单和积分怎么迁移。任何“永久授权”都需要对应清晰的合同条款。

开发合作建议按“需求与原型15%—完整测试闭环25%—内测与异常处理30%—正式交付20%—质保尾款10%”讨论付款，比例是谈判示例。验收以交付和账务为准，代码仓库、设计稿、部署脚本、数据库迁移、文档、测试账号和第三方许可证清单应同步交接。

06 核心用户流程与异常处理

首个可收费流程

上传商品素材确认用途与卖点选风格与尺寸确认预算先做低成本样稿选片与局部修改生成成套素材下载交付包
  1. 访客先看到同一真实任务的输入、修改过程和最终结果；注册后用低成本额度体验，不默认赠送高成本视频。
  2. 用户上传后可选择“保持商品外观”；平台检查文件类型、大小、授权和适用性。文字、Logo、尺寸与卖点需要用户确认。
  3. P0交付图片原件与配文，可用提示词/参考图再修改，不承诺PSD或可编辑分层源文件。执行前显示预计消耗、最大消耗、输出数量、预计等待范围、保存期限和失败规则；预估发生实质变化时重新确认。
  4. 先生成可选草稿，用户确认构图和商品准确性，再执行昂贵的高清化或视频步骤。
  5. 结果支持对比、局部重做、复用参数与导出；一键导出原件、配文和素材清单。
  6. 首个项目完成后保存品牌/商品信息为项目备注，方便下次复用；跨项目品牌记忆与独立资产库在P1增强。
异常用户看到什么系统如何处理
余额不足可完成步骤与需要补足的额度暂停后续昂贵步骤、保留已产出结果，补充额度后续跑
技术失败失败原因、已退额度、继续选项按既定规则释放冻结额度，平台重试有成本上限
上游超时但可能已受理状态待确认及预计核实时间查询或对账，避免盲目换渠道重复生成
部分成功各节点/图片的成功数、费用和剩余步骤按事先展示规则结算成功部分，失败部分可续跑
输出不满意可调整参数及重做费用与技术失败区分；提供有限补偿策略，防无限抽卡
审核拒绝可理解的分类提示与申诉入口阻止交付违规内容；明确额度释放与上游已发生费用承担方
关闭网页或断网回到项目即可查看状态任务在服务端运行，恢复展示，不由浏览器保活
取消任务能否取消、是否已产生费用未提交可释放；已受理须按供应商实际取消能力处理

页面结构

一级导航建议为“创作首页、项目与作品、模板、额度与订单、帮助”。首页用商品图、图文、短视频等任务入口；模型、线路、种子、参数放到高级设置。移动端以向导和任务列表为主，避免把桌面画布等比例缩小。

07 技术架构与关键实现

推荐模块化单体业务服务＋独立任务Worker。前端采用React/Next.js与TypeScript；业务后端可采用NestJS，已有Java或Python团队时以团队熟悉技术为准。PostgreSQL保存权威状态和账本，Redis承载队列、缓存和限流，对象存储保存媒体，CDN负责预览和下载。具体版本在启动时锁定。

用户Web与运营后台
业务API
身份 / 项目 / 报价 / 订单 / 账本 / 权限
PostgreSQL + Redis + 对象存储
任务Worker
审核 / 工作流 / 模型适配 / 媒体处理 / 交付
已验证模型供应商 + 支付渠道 + 审核服务

API与Worker可以同库分进程部署，图片与视频任务分队列。首期使用托管数据库和基础容器部署即可；后续根据瓶颈扩Worker。界面上线、任务生成和数据库恢复是不同能力，分别测试与监控。

任务状态与一致性

草稿 → 已报价 → 已冻结 → 排队 → 提交中 → 生成中 → 输出审核 → 成功/失败/取消，另设上游待确认状态。任务、供应商尝试、回调事件、订单均有独立ID。服务端事务、唯一约束和事务消息表确保“记账成功但任务未派发”等故障可恢复。

重复点击、回调重放和Worker重启均不能重复入账或重复结算。上游返回超时不等于没有生成；必须先核实再重试。成功交付前将文件从上游临时链接复制到自有对象存储，校验可读性并完成内容审核。

画布的实质

基础节点可用React Flow实现；节点UI与执行引擎分离。首期只支持文本、素材、图片生成、视频生成和导出等有限节点，禁止循环依赖；保存工作流版本、节点参数快照和运行历史。上游素材变化时，下游结果标记为待更新，经用户确认费用后重跑。画布库不替代工作流调度和预算系统。React Flow官方文档

异步队列可以选择BullMQ等成熟组件，但幂等需由业务代码和数据库约束共同保证；安装队列库不会自动解决重复扣费。BullMQ幂等任务指南

安全边界

  • 每次作品、订单、任务和下载授权请求检查用户归属；预留workspace_id，团队能力开放前就落实数据隔离。短时签名链接在有效期内可能被持有者使用，需要立即撤销的分享应通过鉴权网关，不把不可猜测链接当作权限控制。
  • 供应商密钥仅保存在服务端密钥系统；前端、错误信息、日志和导出包均不得包含密钥。
  • 后台启用多因素认证，客服、审核、财务、系统管理员分权；退款、赠送、调价与渠道变更可审计。
  • 限制上传文件的实际类型、像素、大小与时长；优先用平台资产ID引用素材，控制外链抓取的SSRF风险。
  • Agent调用工具设白名单、最小权限和预算；用户上传内容是数据，不能覆盖系统权限。

09 模型供应采购与评测方案

首期控制在5—8个常用模型：1—2个文本、2—3个图片、1—2个视频，可按用户需求增加一个语音能力。每个模型都要明确真实模型ID、版本、接口地区、输入限制、价格和用途授权。以官方或合同授权清楚的供应商为主；“能调用”不等于“可长期用于面向公众的商业服务”。

可从火山方舟官方文档与阿里云百炼计费文档建立候选池。模型能力与价格按签约时文档和实际账单核验，不在系统里永久写死某个热门版本。参考站的渠道标签不能代替这一步。

采购维度验证内容
商业和数据授权是否允许服务终端消费者；输入输出保存多久、是否训练、数据去向、删除方式
计费与结算按token/图/秒/任务；参考视频、音频、高清化、失败与重试如何收费；退款凭证
技术可靠性幂等提交、任务查询、回调验签、取消、最大并发和速率限制
可替代性同能力第二供应商实测；迁移参数、风格和价格差异有记录
资金风险小额预付、余额告警、单日限额；避免把全部资金沉淀在一个渠道

建立100个有使用授权的固定评测任务：商品图40、内容配图20、人物/角色20、视频20。先盲评可用性，再比较成本。记录技术成功率、可用作品率、文字/商品准确性、P50/P95耗时、每个可用结果总成本和审核误拒；有需要时对同任务重复抽样。上线后每次换模型或大幅改价都跑回归。

对外显示成功率时必须同时显示统计时间、样本量和定义。技术返回成功与用户得到可用作品分别统计。经济/标准/高质量档可以简化用户选择，但涉及更高费用、不同数据目的地或模型能力时要告知并获得相应授权。

10 收费设计与单任务经济模型

长期推荐“低成本体验＋明确额度套餐＋超额加购＋存储权益”。P0采用手动充值与逐任务报价；下表中的月度套餐和存储权益作为P1测试商品。首期暂不做自动续费和全模型不限量。内部按成本核算，前台用易理解的额度与单次报价；明确人民币、积分及赠送积分的换算、适用范围和有效期。

试验商品价格假设设计目标与限制
新手体验免费少量低成本生成；可测试9.9元体验包完成一个小任务；限制设备与领取频次，不送无限视频
轻创作包49元面向低频用户；明确额度与适用模型，按权益消耗
常用创作包99元/月度权益模板与项目组织、一定额度、合理存储；视频单独扣额度
高频创作包199元/月度权益更高额度、有限并发、批量与品牌资产；仍有资源边界
额外收入按实际成本后定价视频额度、存储包、专业模板、商业交付包；不把法定AI标识当成付费去除项

这些是A/B测试价格，不是已证明的市场价。套餐不能先定死“多少张高质量图片”再采购上游；应按模型、分辨率、重试率和重度用户分布反推可承诺额度。

每个成功交付任务贡献＝对应净收入－所有模型尝试成本－审核/存储/流量增量成本－支付与售后增量成本。技术成功不等于可用结果，重做也必须纳入成本。

假设一个工作流净收入5元，初次生成1.6元、平均重试0.4元、审核和媒体0.2元、支付及售后增量0.3元，则贡献2.5元，贡献率50%。如果模型相关成本从2元涨至3元，贡献只剩1.5元。该例仅说明定价方法，实际应以试运行账单替换。

多节点工作流要给出总预算上限，并按节点锁定报价。充值余额、赠送额度、冻结额度、已消费额度独立记账；账本不可直接修改，纠错使用冲正。退款必须区分未使用额度和已履行服务，不能一概写“虚拟商品不退”。

13 上线后九十天运营与增长

北极星指标建议为“每周完成并导出可用作品的付费用户数”。同时看首次可用结果率、每个可用作品成本、七日复用、三十日复购、退款率和客服工时。注册数、生成次数和充值流水不能单独说明产品健康。

阶段重点动作建议决策门槛
上线后1—30天陪跑50名目标用户；每周分析失败与流失；制作10个可复现教程至少30个完成交付的真实项目；首次任务可用率≥60%作为改进目标
31—60天只扩大一个已有效渠道；测试49/99/199等价格与两类模板入口按同一注册批次观察七日再次有效创作≥25%；贡献率目标≥45%
61—90天验证复购与推荐，减少人工陪跑；决定是否投入画布增强或漫剧小试满30天的首次付费用户复购/续购≥25%；CAC回本目标≤3个月

上述数字是管理门槛假设，不是行业均值。小样本波动很大，先要求有不少于100名已成熟观察期用户再作较强结论。七日复用、付费复购和订阅续费分别统计，不能混用。

获客渠道顺序

  1. 创始人已有客户或社群：用真实素材一对一验证，并记录他们原本如何完成任务。
  2. 内容教程：发布“原图—操作—成品—用时—实际消耗”，每个教程对应一个可复用模板，减少夸张效果宣传。
  3. 垂直合作：与电商课程作者、接单设计师、小型服务商合作，先做单层推荐码和可核算佣金。
  4. 搜索与内容资产：围绕“某类商品场景图怎么做”等任务建立可索引教程与案例，使用已授权素材。
  5. 付费投放：先用小预算比较每个付费客户的贡献回收，稳定后再放量。

例如每月1万名合格访客，20%注册、40%完成首个任务、10%首付，仅产生80名新付费用户。若投放1万元，按此口径CAC为125元。按每月贡献54.45元计算，需约2.3个付费月才回收，真实回收还取决于流失和再次付费间隔。此为漏斗示例，不是流量预测。

团队每周复盘三张表：渠道到付费与复购、模型到可用作品和成本、任务失败到客服与退款。若连续两轮迭代仍低留存或负贡献，暂停增加渠道和模型数量，重新访谈与收缩产品承诺。

备份与发布真实恢复演练、迁移与回滚演练；不以存在备份文件替代恢复测试
用户体验从注册到首个可用结果有明确引导；等待、成本、错误、保存期限及客服入口清楚

初始服务设计目标可定为平台月可用性99.5%、数据库RPO≤15分钟、核心服务RTO≤2小时；这些是需经基础设施和演练验证的目标，并非模型生成时间承诺。压测用DAU×任务数×峰值系数和供应商并发反推，分别验页面访问、任务提交和生成并发。

风险场景提前措施触发后的动作
主供应商停服7天备用适配器与评测集，预付资金限额暂停问题渠道，展示可用替代并重新报价，保留历史结果
模型成本上涨30%价格版本、项目预算、单日亏损告警调整新订单价格或下架低毛利档；不追溯加价已承诺订单
成功率下降或重试暴增按模型/线路监控、重试限额、异常分类熔断、停止营销放量，优先核实在途任务
试用被刷或密钥泄露限流、风控、密钥隔离、全站费用上限停高风险入口、轮换泄露密钥、审计与补偿
支付通道受限正规商户、订单证据、备用合规渠道暂停受影响下单，保留可查询订单，处理在途退款
内容或权利投诉授权台账、举报入口、默认私有限制公开传播、保全必要证据、复核申诉并处置
资金不足每月现金预测，研发分阶段付款停扩品和无效投放，控制新预付与免费试用消耗

16 发散方向与长期壁垒

发散应围绕同一批用户、同一份素材、同一套资产反复使用，优先让一次创作变成下次创作的起点。下面按价值与依赖区分，避免把方向清单直接变成第一期需求。

机会用户价值与收入何时做及前提
品牌与商品记忆记住配色、Logo、文案语气与SKU，下次少重复描述P1；用户授权、可删除、商品准确性评测
一份素材多平台版本生成不同尺寸封面、图文、短视频和文案，提高单项目价值P1；先导出适配包，自动发布需官方接口和明确授权
预算模式用户给出预算，先样稿后精修，在预算内完成优先内容P1；报价引擎和节点成本已可靠
客户审稿链接接单设计师让客户圈点、批注、选图，提升复购P1；私有分享、权限和撤销完整
批量SKU与季节活动一次处理系列商品，按批量包收费P1；队列、预算、结果抽检与商品信息绑定
角色资产与连续故事固定角色、服装、场景、镜头语言，服务漫剧与绘本P2；先做3镜头样片，再扩多集；不保证天然一致性
创作质量检查检查错字、画面尺寸、字幕越界、商品不一致等P1/P2；给可解释提示，不把模型判断当质量保证
模板作者市场创作者出售可复用流程，平台收服务费P2；先运营精选模板，再做交易、授权、审核和结算
专家辅助交付AI结果可购买人工精修、排版或配音服务P2；明确交付标准、售后和人工成本，适合验证高客单需求
存储与项目备份权益延长保留、版本恢复、优先支持P1；明确容量、保留期限、恢复范围及客服承诺
团队工作区共享品牌素材、成员预算、审批、账单P2；个人业务稳定后，从2—5人的真实团队需求做起
代理白标借渠道伙伴触达细分用户P2；先验证单层推荐，明确客户归属、退款、余额和退出迁移
开发者API把已稳定能力向第三方收费提供P2；独立限流、账务、文档、服务承诺和客服体系
海外本地化语言、支付、模板与渠道扩展独立项目评估地区数据、税务、支付与内容政策

长期可积累的优势包括：某类商品的可用效果评测集、能提升成功交付率的模板与流程、用户授权保存的品牌资产、低返工率的编辑体验，以及稳定透明的服务。用户作品是否用于训练或优化需另有明确、可撤回的授权安排，不能默认占用。

17 立项后十四天行动清单

时间行动具体产出
第1—2天确定负责人、资金上限、主体与市场；盘点现有渠道和技术底座一页立项卡、预算上限、责任表、范围边界
第3—5天访谈20位候选用户，收集有授权素材及原工作方式任务频率、愿付金额、失败容忍度、保存需求表
第4—7天筛选两组供应商，验证价格、质量、授权、数据流和异常行为采购比较表、实测任务账单、供应商风险清单
第6—9天设计首个流程及全部异常页面，确定前后台信息架构可点击原型、10—20个模板清单、报价与退款规则
第8—11天技术设计与估工；与支付、属地主管部门/顾问核实接入条件架构图、表结构、接口表、验收用例、外部依赖排期
第12—14天邀请共建用户验证原型和样稿；复核预算与合同冻结P0需求、16周里程碑、首批用户名单、阶段拨款决定

需要补齐的业务信息：经营主体及所在地；现有研发/运营人员；可直接触达的第一批客户；现有模型API与合同；境内或境外部署；是否公开社区、真人形象/声音、创作者交易。它们决定方案的细化分支，但不妨碍先做访谈、原型和供应评测。

建议的启动决定

批准两周验证阶段，锁定一个付费场景和一条完整交付链路。验证通过后按商业V1拨款，并单列上线后现金储备。先把“买得明白、做得出来、失败能恢复、下次愿意再来”四件事做扎实。
